脳は休息中に記憶を統合します。寝ている間に、その日の生の経験は再編成、圧縮、統合されます — 最近の、うるさい事柄が耐久性のある構造に折り込まれます。Tesseraeのエンジンも同じです。プロジェクトが**アイドル**状態になると、常時実行されているデーモンは次の編集を待つのをやめ、既に知っていることを静かに再編成します：各エージェントのメモリを再編成、圧縮、安全に忘れる蒸留パスを実行します。

これまで、このパスは要求されたときだけ実行されました — メモリ不足時の `tesserae refresh`、または明示的な `tesserae distill`。エンジンはすべてのファイルとセッションイベントで再コンパイルされましたが、自動的に統合されることはありませんでした。**睡眠サイクル**がこのギャップを埋めます：`tesserae engine` を実行状態に保つと、休止中に統合が発生し、覚えるべきコマンドはありません。

[階層化メモリ](agent-memory.md)システムのすべてと同様に、これは**オプトインしない限り no-op**です — デーモンはアイドル時に統合しますが、その下の蒸留は `TESSERAE_AGENT_DISTILL` が設定されている場合のみ機能します。

## いつ発火するか

専用の統合スレッドは固定の**チェック間隔**（デフォルト 30 秒）で起動し、単調アクティビティクロックに対して 2 つの独立したトリガーを評価します:

- **アイドルトリガー。** プロジェクトが少なくとも `--consolidate-idle` 秒間、トリガーイベントもパイプライン実行も見ていません（デフォルト **300s = 5 分**）。これは「休止中に統合」のケースです — エンジンが作業を停止したことに気づき、静寂を活用しました。**床**は最後の統合以降のスラッシュを防ぐため、ちょうど静かになったビジープロジェクトは敏感なトリガーで統合されません。 - **上限トリガー。** 最後の統合から少なくとも `--consolidate-every` 秒が経過しました。**アクティビティに関係なく**（デフォルト **21600s = 6 時間**）。これにより、継続的にビジーなプロジェクトが静かな瞬間なしに周期的に統合されることを保証します。`0` に設定すると上限が無効になります — アイドルが唯一のトリガーになります。

すべての編集、セッションターン、または再コンパイルはアクティビティクロックをバンプするため、アイドルウィンドウは本当の休止中にのみ経過します。両方のクロックは**単調**で、ウォールクロックではなく、アーティファクトに永続化されることはありません — 統合タイミングがバイト決定性グラフを乱すことはできません。

## 何が実行されるか

各発火は `.tesserae/graph.json` から コンパイル済みグラフをロードし（ファイルが存在しない場合、パスはスキップされます）、`tesserae refresh` が使用する同じ `maybe_distill_on_refresh` エントリポイントを呼び出します。その関数は**三重ゲート化**内部であり、エージェントあたりのエラーに対して発生しません：

1. **オプトインゲート** — `TESSERAE_AGENT_DISTILL=1`（または `config.json` の `{"agent_distill": {"enabled": true}}`）。デフォルトはオフ; 全体のサイクルはあなたが設定するまで安全な no-op です。
2. **エージェントごとのウォーターマーク** — 最後の蒸留以降に調査結果が変わっていないエージェントはスキップされます。
3. **エージェントごとのメモリ圧力** — 蒸留されていない調査結果がコンテキスト読み取りの半分に収まらなくなったエージェントのみが統合されます（MemGPTスタイルトリガー）。

したがって、統合がスケジュール上で*発火*しても、オプトインしており、実際に十分な新しいメモリを蓄積したエージェントに対してのみ*機能*します。蒸留が生成するものについては、[階層化エージェント メモリ](agent-memory.md)を参照してください。

## 安全性と決定性

- **コンパイルゲートの下で実行。** 統合は再コンパイルと同じロックを取得するため、コンパイルと直列化され、**決してオーバーラップしません**。保留中のコンパイルは進行中の統合を待つ、その反対も同じです — グラフは書き込み中に読まれることはありません。
- **デーモンループに決して引き上げない。** パス全体がラップされます; エラーはログされ、スレッドはループを続けます。失敗した統合がエンジンを停止することはありません。
- **ゲートがオフの場合 no-op。** `TESSERAE_AGENT_DISTILL` が設定されていない場合、パスは高価なものを読み込まず、すぐに戻るため、睡眠サイクルを実行したままにすることは本質的にコストがかかりません。
- **決定性アーティファクト、変更されない。** 蒸留されたアーティファクトは、入力を考慮すると決定性のままです; 睡眠サイクルは蒸留が実行される*とき*のみ変更し、それが何を生成するか*は*変更しません。アイドルタイミングは `graph.json` または蒸留されたレイヤーにリークすることはありません。
- **クリーンシャットダウン。** 統合スレッドはデーモンの停止イベントを監視し、`Ctrl-C` / シャットダウンで速やかに終了します。これは長時間実行モード機能のみです：`tesserae engine ... --once` は決して開始しません。

## CLI フラグ

| フラグ | デフォルト | 効果 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | 睡眠サイクル全体を有効または無効にします。デフォルトで有効（蒸留ゲートが設定されていない場合 no-op）。 |
| `--consolidate-idle SECONDS` | `300` | 休止ウィンドウ：この多くの秒アクティビティがない後、統合します。 |
| `--consolidate-every SECONDS` | `21600` | 上限：アクティビティに関係なく少なくともこのように頻繁に統合します。`0` は上限を無効にします。 |
| `--consolidate-check SECONDS` | `30` | 統合スレッドがトリガーを再評価するために起動する頻度。 |

## フリートの動作（`--all`）

`tesserae engine --all` は 1 つのプロセスで登録されているすべてのプロジェクトを新しく保ちます。各プロジェクトのユニットは同じノブを使用して独自の統合スレッドを取得し、すべてのユニットは 1 つのフリート全体のコンパイルゲートを共有します — したがって、1 つのプロジェクトの統合はフリート全体のコンパイルと直列化され、決してオーバーラップしません。

## 実例

蒸留をオンにして、デモ用のより速い睡眠サイクルでエンジンを実行します — 60 秒アイドル後に統合し、無関係に少なくとも 30 分ごとに統合します:

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine \
  --consolidate-idle 60 \
  --consolidate-every 1800 \
  --consolidate-check 15
```

いつもとおりエディタとエージェントで作業してください; エンジンは監視、デバウンス、すべての変更を再コンパイルします。1 分間停止するとアイドルトリガーが発火します：統合スレッドはコンパイルゲートを取得し、メモリ圧力下のエージェントを蒸留します — 再編成、圧縮、安全に忘れます — その後は再びスリープに戻ります。30 分のマークを過ぎても一時停止なしで作業を続ける場合、上限も発火するため、無情なプロジェクトでも統合されます。

エンジンを実行状態に保ちながら、統合を手動の `tesserae distill` 実行に任せるには、`--no-consolidate` を渡します。アイドル時には実行するが、固定スケジュールでは決して実行しないようにするには、`--consolidate-every 0` を渡します。
