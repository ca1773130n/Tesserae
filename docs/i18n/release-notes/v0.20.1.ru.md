## Баг усечения после 300 оборотов

При импорте сессии (`_claude_turns` / `_codex_turns`) захват молча останавливался после **300 оборотов на сессию**. Всё, что идёт дальше по пути — чанкированный LLM-экстрактор, находки в сессиях, решения, типизированный граф — видел только первые 300 оборотов долгой сессии. Идеи, решения и TODO из более поздней части марафонской сессии никогда не извлекались, и ничто об этом не предупреждало.

Лимит предшествовал конвейеру чанкированного извлечения и был сделан устаревшим им: экстрактор читает историю окнами `max_turns_per_chunk` с лимитами текста за оборот, поэтому размер промпта каждого LLM-вызова ограничен **независимо от общей длины сессии**. Усечение при захвате просто выбрасывало знания.

## Исправление

Теперь по умолчанию импортер использует подпорку для убежавших файлов (`100,000` оборотов) вместо точки усечения, согласуясь со всеми явными местами вызова (сводка активности, чанки сессий, живой serve). Полная история разговора поступает в хранилище чанков и в экстрактор; LLM-контекст каждого вызова остаётся ограничен слоем чанкирования, где этот вопрос должен быть.

Пошаговые компиляции остаются дешёвыми: кеши чанков выравнены по индексу, поэтому ранее извлечённые чанки существующих сессий остаются попаданиями кеша — только заново видимые обороты извлекаются при следующей компиляции. Ожидайте, что первая перекомпиляция после обновления на 0.20.1 сделает больше LLM-вызовов, чем обычно, на проектах с долгими сессиями; это невидимая история из задолженности, извлекаемая один раз.

Никаких API или схемных изменений. `pip install --upgrade tesserae==0.20.1` (или `npm i -g @jokerized/tesserae@0.20.1`) и перекомпилируйте.
