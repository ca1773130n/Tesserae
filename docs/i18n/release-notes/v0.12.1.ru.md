Патч-релиз, который завершает историю многопроектного `serve` из v0.12.0. Полная замена v0.12.0.

## Каждый `/api/*` маршрутизируется к правильному проекту на простом сервере

В v0.12.0 простой `tesserae serve` (обслуживание всех зарегистрированных проектов) маршрутизировал только `/api/ask` — `/api/clip` и `/api/transcript-search` возвращали 404, поэтому **расширение Chrome не могло клипировать на многопроектный сервер** и поиск сессий отдельного проекта не работал. Теперь каждый эндпоинт маршрутизируется:

- **`/api/ask`, `/api/ask/health`, `/api/transcript-search`** — маршрутизируются по `/<alias>/` Referer страницы к этому проекту.
- **`/api/clip`** — клип приходит с *внешней* веб-страницы, поэтому нет Tesserae Referer для маршрутизации. Сервер определяет целевой проект из (1) alias `project` в теле клипа, (2) единственного зарегистрированного проекта, если он только один, иначе (3) `400` со списком доступных alias. **Расширение Chrome** получило параметр *Target project*, который заполняет `project`.

Однопроектный `tesserae serve --project X` не изменился — его безопасность (шлюз CORS расширения/loopback, токен клипа и ограничение размера тела 5 МБ) идентична на уровне байтов, так как оба режима теперь используют одну реализацию.

Поиск транскриптов **завершается с ошибкой `409`** когда два зарегистрированных проекта имеют одинаковое имя директории (memex разделяет транскрипты по basename, поэтому не может их различить) — вместо того, чтобы смешивать историю сессий одного проекта с другим.

## Также

- **Документация** — `docs/ingest.md` получил руководство "Построение слоя концепций (`--extractor`)" для LLM extractor v0.12.0; по умолчанию `GRAPH_COMPLETION` бэкенда Cognee и fleet live-ask теперь задокументированы.

## Обновление с v0.12.0

Полная замена. Чтобы клипировать в конкретный проект из простого `tesserae serve`, установите **Target project** в опциях расширения на alias этого проекта.
