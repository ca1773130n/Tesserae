发布于 **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.19.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.19.0) · `pip install --upgrade tesserae==0.19.0`

这是后端寿命终结版本。自 v0.18.0 起，默认的知识图谱更新与检索循环已完全内置——类型化的 ResearchGraph 管线负责写入图谱（包括原生代码图提取），而 `ask` 借助 LLM 在其上规划检索。本版本移除了两个不再物有所值的外挂后端。

## understand-anything：已移除

它唯一的贡献——把外部生成的、包含代码结构节点的 `knowledge-graph.json` 合并进 ResearchGraph——自原生代码图提取器发布以来就已冗余。适配器、refresh 模块、编译时合并、依赖检测和 setup 条目全部移除。`tesserae integrations refresh understand-anything` 会打印一行指向原生代码摄取的提示并以 2 退出。携带 understand-anything `external_tools` 条目的旧配置加载时只有一条说明；现有图谱中由 UA 生成的节点仍然有效。

## cognee：已移除

cognee 把图谱*向外*复制到它自己的存储中，却从未回馈任何东西；在 0.18 之前，它还在默认安装上向 `ask` 的输出泄漏日志噪音和一个 `OperationalError` 回退。经过一个版本的默认关闭宽限期后，它被彻底移除：adapter/direct/query 模块、编译时 cognify 过程和 bundle 导出、`[cognee]` extra、向导提示，以及 MCP schema 引用（约 1,100 LOC 和 6 个测试文件）。`query --backend cognee` 和每一个 `--cognee-*` / `--enable-cognee` 标志都会打印一行移除说明并以 2 退出。携带 `memory_backends.cognee` 段落的配置仍能加载和编译——每个进程恰好只有一条说明。

## rag-anything：有意保留

这是唯一具备知识图谱确实缺乏的能力的后端——多模态文档 RAG（PDF、图片）——它作为可选的 `tesserae[raganything]` extra 保留，默认关闭，可通过 `tesserae query --backend raganything` 访问。

## 破坏性变更

按照项目惯例，没有任何东西会静默失败——每个被移除的接口都会打印其替代品或解释并以 2 退出：`integrations refresh understand-anything`、`query --backend cognee`、`--cognee-search-type`、`--cognee-dataset`、`--enable-cognee` 以及其余的 `--cognee-*` setup/extract 标志。两次移除的净效果：**−5,500 行**对比 +1,600 行，且完整测试套件全绿（2,251 个通过）。
