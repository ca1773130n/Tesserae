Publié **2026-06-14** · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

Une version de fonctionnalité : une couche de mémoire multi-granularité portée depuis AgentRunbook de LongMemEval-V2, et un ensemble de corrections qui rendent le backend LLM visible et honnête au lieu d'échouer silencieusement.

## 1. Mémoire multi-granularité de style AgentRunbook

Une nouvelle couche de distillation optionnelle au-dessus des résultats de session bruts — trois granularités, toutes byte-idempotentes (identifiants dérivés du contenu, pas d'horloge murale/RNG, fallback déterministe) et optionnelles pour l'LLM :

- **`Event`** — enregistrements par transition extraits des tours d'une session (suivi d'état dynamique), intégrés dans l'extraction des résultats de session.
- **`Runbook`** — procédures réutilisables distillées pour les workflows récurrents (cross-session, ≥2 sessions par défaut).
- **`Gotcha`** — modes d'échec récurrents distillés / mauvaises hypothèses ici.

Plus **récupération multi-pool** : `compile_context(multi_pool=True)` décompose la requête et réserve des emplacements de budget pour les nœuds de mémoire distillée les plus pertinents. Configurable via `tesserae compile --distill`, `tesserae context --multi-pool`, `distillation.enabled` dans la configuration, et l'argument MCP `compile_context` `multi_pool`. Tous désactivés par défaut, donc une compilation simple est inchangée.

## 2. Un backend LLM visible et honnête

- **`tesserae config status`** — imprime le provider *résolu* + codex-home / claude-dirs avec la **source** de chaque paramètre (env > config du projet > `~/.tesserae/config.json` > default), et un **ping en direct**. Un backend limité en débit ou mal authentifié est désormais évident au lieu d'invisible.
- **Échecs d'extraction de session bruyants** — l'extraction distingue désormais « le modèle n'a rien retourné » de « le modèle n'a jamais répondu ». Un chunk échoué n'est **plus mis en cache comme vide** (il réextrait une fois que le backend fonctionne), et la compilation imprime un avertissement impossible à manquer. Auparavant, un backend étranglé produisait silencieusement un graphe avec des sessions mais **zéro résultats**.
- **L'effort de raisonnement Codex** est épinglé à `medium` pour les propres appels de Tesserae (configurable via `llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT`), donc un `xhigh` global défini pour un codex interactif ne rend plus chaque compilation beaucoup plus lente.

## 3. Durcissement du déterminisme

- Les gardes byte-idempotence exercent désormais la compilation déterministe (sans-LLM) qu'elles garantissent réellement — un LLM ambiant ne les rend plus fragiles.
- Une compilation sans-LLM **réemet des résumés de communauté mis en cache** au lieu de les supprimer, donc les recompilations restent stables à travers les fluctuations de disponibilité de l'LLM.

## Mise à niveau depuis v0.8.x

Drop-in. Tout ce qui est nouveau est optionnel ou additif ; une simple `tesserae compile` se comporte comme avant. Exécutez `tesserae config status` pour confirmer sur quel backend LLM vous êtes.
