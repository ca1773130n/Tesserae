Released **2026-07-26** · [PyPI](https://pypi.org/project/tesserae/0.26.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.26.0) · `pip install --upgrade tesserae==0.26.0`

v0.25.1이 컴파일이 멈추는 것을 막았습니다. 이 릴리스는 그들을 **빠르게** 만들고,
**그들이 무엇을 포함했는지에 대해 정직하게** 만들고, 쓰레기 수집을 멈춥니다.

## 더 빠르게

- **병렬 추출.** 배치 루프가 한 번에 하나씩 CLI 서브프로세스를 생성하고 차단했습니다.
  — 벽시계 시간은 모든 모델 왕복의 합계였으며, 161개 문서에 대해 약 2시간 40분으로
  측정되었습니다. 추출은 이제 기본적으로 4개 문서를 동시에 실행합니다
  (`TESSERAE_EXTRACT_CONCURRENCY=1`은 순차 실행을 복원합니다).

  동시성은 속도를 변경하며, 출력은 절대 변경하지 않습니다. 작업 목록은 경로 순서로
  고정되고 결과는 인덱스로 수집됩니다. `merge_graphs`는 위치에 따라 중복 노드 ID를
  해결하므로, 완료 순서 수집은 조용히 *다른* 그래프를 만들 것입니다 — 추출기가
  역순 경로로 완료되는 테스트로 고정됩니다.

- **응답 캐시가 실제로 캐시합니다.** `complete_json`은 항상 `cache_key`를 받았으며,
  두 CLI 클라이언트 모두 이를 받고 버렸습니다. Anthropic 클라이언트만 사용했습니다.
  동일한 내용이 매 컴파일마다 전액 비용을 다시 지불했습니다. 두 클라이언트는
  이제 `~/.tesserae/llm_cache` 아래의 콘텐츠 주소 캐시를 읽고 씁니다.
  콘텐츠 **및 모델과 추론 노력**으로 키가 지정되어 모델을 전환하면 이전 모델의
  답변을 제공하는 대신 다시 요청합니다. 해석 가능한 응답만 저장됩니다.
  `TESSERAE_LLM_CACHE=0`은 비활성화합니다.

## 정직하게

- **추출 실패가 명명되며, 무시되지 않습니다.** 실패 분류법은 일시적 결함
  (재시도됨)을 실제 결함과 구분하며, `--limit`은 더 이상 그래프 범위를
  포기하지 않으며, 홈별 인증 범위는 하나의 잘못된 프로필이 실행을 오염시키는
  것을 멈춥니다.

- **`graphed` 완전성 마커.** 매니페스트 행은 해당 콘텐츠가 실제로
  `graph.json`에 도달한 후에만 스탬프가 찍힙니다. — 따라서 중간에 죽는
  컴파일은 더 이상 그래프가 가지지 않은 범위를 주장하는 행을 남길 수
  없습니다. 삭제되고 이름이 바뀐 문서는 영구적으로 남아있는 대신
  무덤표시됩니다.

- **`--retry-fallbacks` 범위**는 이제 정확히 입력 추출이 실패한 문서만
  재시도하며, 다른 것은 없습니다.

## 더 깔끔하게

- **쓰레기 디렉터리는 코퍼스 밖에 머뭅니다.** pytest tmpdirs
  (`pytest-of-<user>/pytest-N/`)와 pip 스크래치 디렉터리는 `TMPDIR`이
  저장소로 해석될 때 구성된 소스 루트 내에 들어가며, 수천 개의 일회용
  픽스처 파일을 심어 매 테스트 실행마다 변합니다. — 후보 세트가 반복되지
  않으며 `--changed-only`는 절대 공회전할 수 없습니다. 한 실제 프로젝트
  매니페스트는 **25,269개 항목 중 16,110개(63%)가 더 이상 존재하지 않는
  파일을 가리켰습니다**.

  워커는 이제 재귀적 하강 중에 이러한 족속을 건너뜁니다. 이것은 **디렉터리**
  규칙입니다: `docs/pip-install-guide.md`는 일반 문서이며 색인된 상태로
  유지됩니다. — Tesserae의 자체 개념 슬러그화기는 모든 "pip install *x*"
  제목에서 정확히 그 파일명 모양을 만듭니다.

## 또한

- **Codex 모델 기본값은 `gpt-5.6-luna`입니다.**
- **[새로운 튜닝 참조](../tuning.ko.md)** 모든 29개의 `TESSERAE_*`
  환경 변수 문서화 — 기본값, 각각이 게이트하는 것, 그리고 언제 변경할지.
  v0.25.1에서 제공된 추출 타임아웃을 포함한 몇 가지는 전혀 문서화가
  없었습니다.

## v0.25.1에서 업그레이드

바로 올려도 됩니다. 알아야 할 두 가지:

**추출이 이제 4-폭으로 실행됩니다.** 공급자 계정에 타이트한 속도 제한이
있으면, `TESSERAE_EXTRACT_CONCURRENCY=1`을 설정하세요.

**업그레이드 후 첫 번째 컴파일은 평소보다 더 많은 작업을 할 수 있습니다** —
`graphed` 마커는 구형 매니페스트에 존재하지 않으므로, 이전의 행은 검증되지
않은 것으로 취급되고 다시 스탐프됩니다. 이는 하나의 교정 재컴파일이며,
영구적 비용이 아닙니다.
