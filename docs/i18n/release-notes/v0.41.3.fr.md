v0.41.2 a clos les douze constats les plus graves de l'audit des commandes.
Celui-ci clôt les dix-neuf autres, c'est-à-dire tous.

## Ce qui a changé

- **Sept commandes répondent à une erreur par une phrase.** Un chemin erroné, une
  date illisible, une valeur de configuration qui n'est pas un fournisseur :
  chacune se terminait auparavant par une trace d'appels. La pire était
  `tesserae compile`, qui interrompait tout un corpus à cause d'un seul fichier
  illisible ; elle nomme désormais ce qu'elle a sauté et compile le reste.
- **Sept commandes ont cessé de rapporter ce qui n'a pas eu lieu.** `status`
  affichait une heure de compilation pour un projet jamais compilé.
  `config status` attribuait à la valeur par défaut ce qu'un fichier avait fixé.
  `schema-drift` annonçait n'avoir trouvé aucun groupe pour un type qu'il n'avait
  jamais groupé. `graph-map` renvoyait un curseur de pagination identique à celui
  reçu, si bien qu'un appelant qui le suivait bouclait indéfiniment.
- **Cinq commandes ont cessé d'accepter ce qu'elles doivent refuser.** Un nom
  d'agent mal orthographié répondait comme s'il était réel. `projects register`
  désinscrivait silencieusement un autre projet quand deux répertoires
  produisaient le même nom. `domains status` disait à un répertoire qui n'est pas
  un projet de lancer une compilation.
- **Un aperçu montre ce qu'il prétend montrer.** `sessions prune-internal
  --dry-run` imprimait le nombre total d'enregistrements conservés là où il
  voulait dire combien il en supprimerait.

## Mise à niveau

Rien à migrer. Davantage de commandes sortent avec 2 là où elles sortaient
silencieusement avec 0, si bien qu'un script qui comptait sur ce silence
commencera à signaler des échecs qu'il subissait déjà.
