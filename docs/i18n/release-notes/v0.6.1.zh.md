发布日期 **2026-06-08** · [PyPI](https://pypi.org/project/tesserae/0.6.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.6.1) · `pip install --upgrade tesserae==0.6.1`

这是对 [v0.6.0 CLI 重新设计](v0.6.0.zh.md)的一个小型后续版本：为新的扁平动词 CLI 带来两项体验改进，以及为多账户 codex 用户修复了一个真实的缺陷。

## 1. `tesserae compile` 现在显示实时进度

以前长时间的编译过程是悄无声息的。现在它会在交互式终端上渲染一个多阶段、`codegraph index` 风格的进度显示：

```
◆ Scanning sources — 2036 found
  Extracting ████████████████░░░░░░░░  64%  1302/2036  0:12
◆ Extracted 2036 files
⠙ Finalizing — community summaries, vault, site…
◆ Compiled  ·  220243 nodes · 679073 edges  ·  41s
```

它由 `rich`（已是依赖项）驱动，仅在 TTY 上渲染——管道、CI、MCP 服务器和守护进程运行的输出保持逐字节一致（普通的 `Compiled project wiki: …` 摘要行得以保留），因此脚本的行为不会有任何改变。

## 2. `tesserae projects register` 会自动初始化

注册一个尚未成为 Tesserae 项目的目录时，会以 `No .tesserae/graph.json found` 失败。现在，如果该路径是一个不含 `.tesserae/` 工作区的现有目录，register 会先创建一个空白工作区（然后打印一条提示，建议运行 `tesserae compile`）。缺失或拼写错误的路径仍然会报错——它永远不会被自动创建——而已初始化的项目则保持原样。

## 3. 修复：现在每个 LLM 阶段都遵循 `llm_provider: codex`

如果你选择了 codex（通过 `tesserae config llm --llm-provider codex` 或项目的 `config.json`），有几个编译期 LLM 阶段仍然使用 Claude CLI——即使你选择的是 codex，也会产生 `ClaudeCLIJsonClient … You've hit your Sonnet limit`。原因在于：社区摘要阶段、Phase-5 内存阶段，以及 `lab schema-drift` / `lab evolve` / `query --llm` 命令在构建其 LLM 客户端时没有参考提供方设置，因此始终默认使用 Claude。现在它们全部以与引擎其余部分相同的方式解析后端——**环境变量 > 项目 `config.json` > 全局 `~/.tesserae/config.json` > 默认值**——因此 `llm_provider: codex` 在各处都会被遵循。

## 从 v0.6.0 升级

无需做任何更改——这三项都是即插即用的。如果你之前设置了 `llm_provider: codex` 但在编译期间仍看到 Claude 被调用，本次发布修复了这一问题；只需再次运行 `tesserae compile` 即可。
