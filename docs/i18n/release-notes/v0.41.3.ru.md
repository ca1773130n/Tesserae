Выпущено **2026-09-16** · [PyPI](https://pypi.org/project/tesserae/0.41.3/) · [GitHub релиз](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.3) · `pip install --upgrade tesserae==0.41.3`

v0.41.2 закрыл двенадцать самых серьёзных находок аудита команд. Этот закрывает
остальные девятнадцать, то есть все.

## Что изменилось

- **Семь команд отвечают на ошибку предложением.** Неверный путь, неразбираемая
  дата, значение конфигурации, которое не является провайдером — каждое из них
  раньше заканчивалось трассировкой стека. Хуже всего был `tesserae compile`,
  прерывавший весь корпус из-за одного нечитаемого файла; теперь он называет то,
  что пропустил, и компилирует остальное.
- **Семь команд перестали сообщать о том, чего не было.** `status` показывал
  время компиляции для проекта, который никогда не компилировался.
  `config status` приписывал значению по умолчанию то, что задал файл.
  `schema-drift` заявлял, что не нашёл кластеров для типа, который никогда не
  кластеризовал. `graph-map` возвращал курсор постраничного вывода, совпадающий с
  полученным, и следовавший ему вызывающий код повторялся вечно.
- **Пять команд перестали принимать то, что должны отвергать.** Имя агента с
  опечаткой отвечало так, будто оно настоящее. `projects register` молча снимал с
  регистрации другой проект, когда два каталога давали одно имя. `domains status`
  советовал каталогу, не являющемуся проектом, запустить компиляцию.
- **Предпросмотр показывает то, что он показывает.** `sessions prune-internal
  --dry-run` печатал общее число сохранённых записей там, где имел в виду число
  удаляемых.

## Обновление

Мигрировать нечего. Больше команд завершается кодом 2 там, где раньше они тихо
возвращали 0, так что скрипт, полагавшийся на эту тишину, начнёт сообщать об
отказах, которые у него уже были.
