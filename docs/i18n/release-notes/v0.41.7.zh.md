发布于 **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.7/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.7) · `pip install --upgrade tesserae==0.41.7`

v0.41.6 让第二次 Ctrl-C 或 SIGTERM 能在编译途中停下 `tesserae engine`，做法是在编译所在的主线程里抛出异常。
舰队模式 `tesserae engine --all` 保留了旧行为：那里每个项目都在自己的线程里编译，这种做法够不着，
所以舰队对第一次之后的每个信号都只是等编译结束。唯一的出路是 SIGKILL，而那会让每个
`claude -p` 子进程在自己的会话里继续运行、继续计费。

## 改了什么

- **第二次信号会停下舰队。** 它删除舰队的 pidfile 和自己写下的项目 pidfile，终止所有正在运行的 CLI
  代理并拒绝再启动新的，然后以惯例的退出状态退出。什么都不会丢：每个项目的下一次编译会通过清单差异找到改动过的源文件。
- **第一次信号会同时送达每个项目。** 以前项目是一个接一个停的，所以第一个项目完成编译期间，其余项目仍在监视改动，
  并可能在停止请求之后开始新的编译。每个项目仍会做完手头的工作，舰队现在会提示 `signal again to stop now`。

## 升级

无需迁移。正在运行的舰队需要重启才能生效。发给 `engine --all --once` 或普通 `tesserae compile` 的 SIGTERM
仍会立即结束进程，并可能留下一个仍在运行的 `claude -p` 子进程。Ctrl-C 两种情况都能处理。
