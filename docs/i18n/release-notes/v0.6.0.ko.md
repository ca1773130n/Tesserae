릴리스 일자 **2026-06-08** · [PyPI](https://pypi.org/project/tesserae/0.6.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.6.0) · `pip install --upgrade tesserae==0.6.0`

Tesserae 0.6.0은 **CLI 재설계**입니다. 엔진이 하는 모든 일이 `tesserae project <숨겨진 서브커맨드 26개>` 아래에 묻혀 있었고, `setup`은 플래그가 29개, `compile`은 26개에 달했으며, 맨 `tesserae`를 실행하면 원시 추출 파서가 그대로 쏟아졌습니다. 0.6.0은 이를 **평면적 동사 명령 트리**로 대체합니다 — 일상적인 동사는 최상위에, 소수의 작은 명사 그룹, 그룹화된 도움말, 그리고 모든 명령에 `EXAMPLES`를 둡니다. 이는 **호환성을 깨는 변경**이며, 1.0 이전이라는 점을 고려해 의도적으로 단행한 것입니다. 기존 명령은 조용히 별칭으로 연결되지 않고, 한 줄짜리 `… has moved → …` 리디렉트를 출력하고 종료 코드 2로 끝납니다. 그래서 마이그레이션이 모호하지 않고 분명하게 드러납니다. 엔진, 그래프, MCP 도구, `tesserae_mcp` 서버는 변경되지 않았습니다 — 이번 릴리스는 전적으로 사람이 입력하는 표면에 관한 것입니다.

## 1. 새로운 명령 트리

```
tesserae <command>

EVERYDAY    init compile context ask serve status
AUTOMATION  engine refresh research
ANALYSIS    query lint
GROUPS      sessions vault export code config projects integrations extract
LAB         lab
```

- **일상적인 동사는 최상위에 있습니다.** `tesserae compile`, `tesserae serve`, `tesserae ask`, `tesserae context "…"` — `project` 접두사가 없습니다.
- **`status`** 는 새로 추가된 읽기 전용 요약입니다(노드/엣지 수, 마지막 컴파일, 볼트, 사이트).
- **`serve`** 는 사이트가 없거나 오래되었을 때 자동으로 빌드합니다(`--no-build`로 건너뜁니다).
- **전문 명령은 작은 명사 그룹에 들어 있습니다:** `sessions import|discover|list`, `vault sync|export|prune|set-root|sync-all`, `export harness|graphiti|site`, `code ingest|sync`, `config llm|show`, `projects register|list|activate|unregister|mcp-config`, `integrations refresh <name>`, `extract`, `lab evolve|schema-drift`.
- **`export site`** 는 기존의 `build-site`, `deploy`(`--deploy`), `watch`(`--watch`) 동사를 흡수합니다.
- **그룹화된 루트 도움말 + `EXAMPLES`** — 인자 없이 `tesserae`를 실행하면 그룹화된 트리가 표시되고, 모든 명령의 `--help`는 실제로 실행 가능한 예시로 끝납니다.

## 2. 다이어트한 `init`과 `compile`

- **`init`: 29 → 8 플래그.** 기본적으로 마법사 방식이며, `--yes`는 비대화식으로 실행합니다(선택적 통합 — Cognee, RAG-Anything, Understand-Anything — 은 기본 **off**이고, TTY가 아니면 색상이 자동으로 비활성화되어 기존 `--no-color`/`--no-cognee`/`--skip-*` 플래그를 포섭합니다). `--bare`는 마법사 없이 워크스페이스를 작성합니다. LLM 백엔드 플래그(`--llm-provider`, `--claude-config-dir`, `--codex-home`)는 유지됩니다.
- **`compile`: 26 → 8 플래그.** 일상적인 플래그는 그대로 남습니다(`--changed-only`, `--no-sessions`, `--limit`, `--refresh-integrations`, 세 개의 LLM 플래그, 그리고 임시 `compile <paths>`). 제거된 모든 통합 노브(kuzu/cognee/trends/vault-pull/…)는 `.tesserae/config.json`의 **`compile_options`** 블록으로 같은 이름 아래에 옮겨졌으며 기존 기본값이 보존됩니다 — 따라서 동작은 동일하고, 표면만 조용해진 것입니다. 전체 `compile_options` 표는 [퀵스타트](../quickstart.md)를 참조하세요.

## 3. 깔끔한 단절식 마이그레이션 — 조용한 별칭 없음

모든 레거시 호출은 정확히 한 줄을 출력하고 종료 코드 2로 끝납니다:

```
$ tesserae project compile
tesserae project compile has moved → tesserae compile
```

리디렉트 표는 모든 기존 명령을 다룹니다(`project sessions import` 같은 3-토큰 형태와 기존 `wiki`/`llm-defaults` 최상위 명령 포함). 그리고 맨 마크다운 경로(`tesserae notes/x.md`)는 `tesserae extract`로 안내합니다. 훅, CI 스모크, 릴리스 흐름, 그리고 레포 내 모든 런타임 문자열이 한꺼번에 마이그레이션되었으며, 문서와 8개의 모든 README(그리고 모든 현지화된 사본)도 이제 새 트리를 말합니다.

## v0.5.0에서 업그레이드하기

- **스크립트에 쓰는 동사를 다시 익히세요.** 가장 흔한 교체: `project setup --yes …` → `tesserae init --yes`, `project compile` → `tesserae compile`, `project build-site` → `tesserae export site`, `project serve` → `tesserae serve`, `project obsidian-sync` → `tesserae vault sync`, `project sync-code` → `tesserae code sync`, `tesserae llm-defaults …` → `tesserae config llm …`, `tesserae wiki …` → `tesserae projects …`. 기존 형태로 명령을 한 번 실행해 보세요 — `… has moved → …` 메시지가 새 명령을 알려줍니다.
- **`compile` 플래그를 옮겼나요?** `compile --trends`, `--no-vault-pull`, `--cognee-*` 등을 스크립트에 썼다면, 대신 `.tesserae/config.json`에서 대응하는 `compile_options.<key>`를 설정하세요(표는 퀵스타트에 있습니다).
- **`init`의 통합 플래그는 CLI에서 사라졌습니다.** Cognee / RAG-Anything / Understand-Anything을 활성화하려면 `tesserae init` 마법사 프롬프트에 답하거나, `.tesserae/config.json`을 편집한 뒤 `tesserae integrations refresh <name>`을 실행하세요.
- **그래프, 볼트, 사이트, MCP 도구, `tesserae_mcp` 서버** 에 대해서는 아무것도 바뀌지 않았습니다 — 오직 사람이 마주하는 CLI만 바뀌었습니다.
