发布于 **2026-06-27** · [PyPI](https://pypi.org/project/tesserae/0.11.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.11.0) · `pip install --upgrade tesserae==0.11.0`

一个功能发布版本：**一次查询您注册的所有项目**，获得单个跨引用、有引文注解的答案。可直接升级自 v0.10.x。

## 跨项目联合

`tesserae ask --scope federated --scope-aliases research work "…"`（以及 MCP `ask` 工具中的 `scope: "federated"`）将您指定的项目组装成 **一个** 图，返回单个答案并进行跨项目交叉引用 — 而不是 `all-registered` 的扇出模式（每个项目返回一个答案）。您的每个项目的 `.tesserae/graph.json` 永远不会被修改；联合图在查询时在内存中组装。

项目之间的连接有两种方式：

- **身份合并（始终启用）。** 跨项目的相同 *实体* — 相同的 arXiv id、仓库、内容哈希或代码符号 — 折叠为一个节点。高精度、确定性、无嵌入。因此您在 `research` 中剪辑的论文和在 `work` 中引用的论文会成为单个被引用的节点。
- **语义链接（默认启用，可选禁用）。** 不同表述中的相同 *想法* — 例如 `work` 中的缓存决策和 `research` 中的缓存论文 — 获得嵌入支持的跨项目链接，检索可以桥接 *相关* 而不仅仅是相同的概念。权重降低，以便身份匹配始终优先于模糊桥接。传递 `--no-semantic` 仅用身份匹配。需要真实的嵌入后端（`pip install tesserae[semantic]`）；没有它会优雅降级并给出提示。

链接阈值（`0.55`）和桥接权重（`0.5`）不是猜测 — 它们来自精度/召回率 + 淹没评估（`evals/federation/`，在 CI 中受保护）。

## 检查联合图

- `tesserae federation status [aliases] [--semantic]` — 每个项目的节点数、身份合并、语义链接数。
- `tesserae federation explain <node> [aliases]` — 一个节点为什么桥接项目：它跨哪些项目进行身份合并及其语义链接（带相似度和目标项目）。接受命名空间 id 或已合并的 id。

联合语义链接缓存在 `~/.tesserae/federation/`，以项目内容为键，任何项目重新编译时缓存自动失效。

## 本次发布的其他内容

- **Chrome 扩展** — README 现已记录正确的默认端点（`http://127.0.0.1:8765`，IPv4）以匹配发货的扩展默认值。

## 从 v0.10.x 升级

直接升级。联合是每个查询可选的（`--scope federated`）；单项目使用无任何变化。对于语义桥接，执行 `pip install tesserae[semantic]`。
