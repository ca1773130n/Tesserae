Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

Keine Änderungen am Laufzeitverhalten in diesem Release. Es repariert die
Maschinerie, die Änderungen am Laufzeitverhalten eigentlich abfangen soll — eine
Maschinerie, die bislang nicht existierte.

## Niemand führte die Tests aus

Das Repository hatte zwei Workflows. Einer kompilierte das Demo-Wiki, einer
veröffentlichte bei einem Tag den npm-Wrapper. Keiner führte auch nur einen Test
aus. „`main` ist grün" war eine Behauptung, die niemand prüfte — 2.993 Tests
hätten an einem Dienstag rot werden können, und die Farbe des Badges wäre
dieselbe geblieben.

`tests.yml` führt die Suite jetzt bei jedem Push und jedem Pull Request aus, über
Python 3.10, 3.11 und 3.12 — genau die drei Versionen, deren Unterstützung
`pyproject.toml` behauptet. Auch diese Behauptungen waren nie ausgeführt worden.

## Zwei Abhängigkeiten existierten nur auf einer Maschine

Um CI hinzuzufügen, musste zuerst eingeräumt werden, dass ein frischer Clone die
Tests überhaupt nicht ausführen konnte:

- **`pytest` war nirgends deklariert** — weder in `pyproject.toml` noch in
  `uv.lock`. Die Suite lief, weil pytest vor vielen Commits von Hand in ein
  lokales `.venv` installiert worden war. Jeder `uv`-Befehl, der die Umgebung aus
  der Lockdatei neu aufbaute, erzeugte still eine Umgebung ohne Test-Runner.
- **`kuzu` hatte dasselbe Problem mit schärferen Zähnen.** Zwei Tests rufen den
  Kuzu-Store ohne `importorskip`-Wächter auf; fehlt er, *scheitern* sie, statt
  übersprungen zu werden.

Beide liegen jetzt in einer `dev`-Abhängigkeitsgruppe. Der entscheidende
Unterschied: die getestete Umgebung und die Umgebung, die ein Mitwirkender
bekommt, sind nun dieselbe — die einzige Bedingung, unter der eine grüne Suite
überhaupt etwas bedeutet.

## Die Lockdatei war abgedriftet

`uv lock --check` scheiterte an der committeten `uv.lock`: sie war mit
`pyproject.toml` nicht mehr synchron, `markdownify` und `model2vec` fehlten. Wer
`uv sync --locked` ausführt oder eine CI betreibt, die den Lock fixiert, lief
sofort dagegen.

Sie ist neu erzeugt, und der Workflow nutzt `uv sync --locked` — das lässt den
Build bei veralteter Lockdatei rot werden, statt sie still zu aktualisieren. Damit
kann dieser Drift nicht noch einmal unbemerkt bleiben.

## Was die CI in ihren ersten vier Minuten fand

Sie wurde auf allen drei Python-Versionen rot, mit identischen Fehlschlägen.
Versionsübergreifend identisch heißt: Plattform, nicht Version. Zwei Tests
kodierten Eigenschaften einer bestimmten macOS-Maschine.

Fünf steuerten `hooks/_lib.sh` über `zsh` an, das auf den CI-Runnern nicht
vorhanden ist — während die Bibliothek sich selbst als POSIX-freundlich
dokumentiert, gerade damit sie von niemandes Login-Shell abhängt.

Der sechste lohnt zweimal gelesen zu werden. Er patchte `subprocess.run`, doch der
getestete Code war längst auf `subprocess.Popen` umgestellt, damit ein Timeout die
ganze Prozessgruppe killen kann. Der Patch wurde still zum No-op, und seither rief
der Test die **echte `claude`-Binary** auf — er lief auf Maschinen durch, auf
denen sie installiert und eingeloggt ist, und behauptete über den Code, nach dem
er benannt war, schlicht gar nichts.

Keiner der beiden ist ein Produktfehler. Beide sind Tests, die aus dem richtigen
Grund gar nicht scheitern konnten — und ohne sie anderswo auszuführen, waren sie
nicht auffindbar.

## Die Demo-Site ist eingefroren

`build-demo.yml` wurde entfernt. Es kompilierte Tesserae bei jedem Push auf `main`
gegen den eigenen Quellbaum und deployte das Ergebnis auf GitHub Pages.

Die Konsequenz, deutlich gesagt, weil sie leicht zu übersehen ist:
[die Live-Demo](https://ca1773130n.github.io/Tesserae) antwortet weiterhin, und
die README verlinkt sie weiterhin — aber nichts deployt sie neu. Diese Seite ist
jetzt ein Schnappschuss des letzten Workflow-Laufs und wird still von `main`
abdriften. Neu veröffentlichen heißt: manuelles `tesserae export site` oder ein
neuer Workflow.

Damit entfiel auch die einzige automatisierte Abdeckung des Pfads `init` →
`compile` → `export site`. `tests.yml` führt die Unit-Suite aus und durchläuft
diesen Pfad nicht durchgängig; dort steht jetzt nur noch der manuelle Smoke-Test
aus der Publishing-Checkliste — und die Checkliste sagt das auch.

## Upgrade von v0.28.4

Drop-in. Keine API-, Schema- oder Verhaltensänderung — jeder Commit dieses
Releases berührt CI-Konfiguration, Testdateien, Abhängigkeitsdeklarationen oder
Dokumentation. Es gibt keinen Grund, neu zu kompilieren.

Wer aus den Quellen mit fixierter Lockdatei installiert: das ist das Release, das
`uv sync --locked` wieder funktionieren lässt.
