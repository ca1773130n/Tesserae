Released **2026-08-05** · [PyPI](https://pypi.org/project/tesserae/0.28.7/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.7) · `pip install --upgrade tesserae==0.28.7`

**別のツールが Tesserae ストアにセッション レコードを書き込む場合はアップグレードしてください。**
[#104](https://github.com/ca1773130n/Tesserae/issues/104) は 0.28.5 と 0.28.6 で 2 回修正されていますが、両回ともこれらのレコードが失われています。このリリースは、実際に 1 つのプロデューサを別のプロデューサから分離する軸でこれを修正します。

## 2 つの以前の修正が見落とした点

どちらもスキャンが見た*場所*に基づいて削除範囲をスコープしました：ディスカバリーは、歩いた harness ルートの下に存在するトランスクリプトを持つレコードのみを削除できるという推論でした。この推論は、異なるプロデューサーが異なるディレクトリを読む場合にのみ成り立ちます。

しかし、彼らはそうではありません。Tesserae のローカル スキャンが読む**同じ** `~/.claude` トランスクリプトについて説明するオーケストレーターは、独自のエージェント セッションをエクスポートします — スキャンが推測できないエージェント ID を持っているだけです。そのレコードは構成上範囲内にありました。

0.28.6 に対して実際の 375 レコード ストアで測定すると、損失の 2 つの形態が生き残りました：

- **削除済み。** スキャンがトランスクリプトを見つけることができなくなったレコードは削除されます。元のバグで変更されていません。
- **静かに上書きされた。** スキャンが*見つける*トランスクリプトを持つレコードは、スキャンのより簡潔なバージョンに置き換えられます — エージェント ID とメタデータが失われます。両方の書き込みツールはセッション ID から同じファイル名を導出するため、1 つが他方の上に着地します。何も削除されないため、削除カウントは 0 のままで、実行は成功を報告します。

2 番目の形態はまったく削除の問題ではなく、これが範囲の改善が到達できなかった理由です。

## 出典

すべてのレコードには **`producer`** があります — それを書き込んだインポーターです。
`sessions discover --import` は `tesserae:discover` にスタンプします; `sessions import <path>` は `tesserae:import` にスタンプします。ライターは生産したレコードのみにアクセスできます：

- 自分のものだけを削除します；
- 同じセッションの別のプロデューサーのレコードを**上書きしません**。受信書き込みはスキップされ、
  `Left alone (written by another producer)` として報告されます。

独自のツールからこのストアに書き込む場合は、`tesserae sessions import <file>` を使用すると、その時点以降はレコードが保護されます。他に何も必要ありません。

ルートと harness スコーピングは 2 番目のゲートとして残っていますが、レコードを安全に保つのはもはやそれではありません。

## アップグレード

**このリリースの前に書き込まれたレコードはプロデューサーを持ちません。** 所有されていないため、インポーターは削除または上書きしません — アップグレードはすでに持っているものを失うことができず、別のツールが書き込んだレコードも含まれます。

その選択の代償：ディスカバリーはレガシー レコードも更新しません。Tesserae 独自のスキャンがストアに書き込む唯一のものである場合は、

```bash
tesserae sessions discover --import --adopt-unowned
```

を 1 回実行して、これらのレコードをディスカバリーに引き渡します。**別のツールが同じストアに書き込む場合は実行しないでください** — フラグが正確に言うことをします。

ロスレスが正しいデフォルトでした。修正されるバグは無声のデータ損失であり、別のデフォルトはそれらを保護することになっていたアップグレード時に、レポート プロジェクトのレコードを最後にもう一度破棄したでしょう。

## クレジット

[Agented](https://github.com/ca1773130n/Agented) プロジェクトに取り組んでいるエージェントが報告、再現、診断しました。このプロジェクトは CLI 経由で Tesserae を消費します。フィクスチャではなく実際のストアに対して測定したため、2 ラウンドの修正と 5 人のレビュアーによるコード レビューで見落とされたものを発見できました — ここで書かれたすべてのテストは「別のプロデューサー」を「別のディレクトリー」を意味するようにしたので、テストは仮定を確認しました。彼らはまた、#104 が最初から提案していた方向である出典を提案しました。
