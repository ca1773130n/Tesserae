Выпущено **2026-09-08** · [PyPI](https://pypi.org/project/tesserae/0.39.2/) · [Релиз на GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.2) · `pip install --upgrade tesserae==0.39.2`

Две дыры в одном месте: ничто не говорило, работает ли ваш LLM-бэкенд на самом деле, а `doctor --fix` не доводил начатое до конца.

## Что произошло

`doctor --fix` применял каждую починку один раз, в порядке реестра. Починка, обесценившая более раннюю проверку, оставляла эту работу второму вызову, о котором никто не знал: починка линта переписывает `graph.json`, из-за чего сайт устаревает, а проверка сайта уже прошла. Ещё запуск с починкой печатал ту же таблицу, что и запуск только для чтения, так что понять, какие предупреждения намеренные, можно было лишь сравнив два экрана. При этом единственным, что трогало бэкенд, был `config status --ping`, делающий один вызов побочно при печати конфигурации.

## Что изменилось

- **`doctor --fix` сходится.** Починки повторяются, пока очередной проход не перестанет что-либо менять, максимум три, а контекст проекта пересобирается между проходами, так что починка, создающая то, что читает более поздняя проверка, ею и увидена.
- **Всё, от чего он отказался, названо.** Что осталось не так, попадает под **Still open** с командой и причиной. Причина честна относительно того запуска, который её породил: запуск только для чтения говорит, что находка чинится через `--fix`, а не что починка бежала и не справилась. Четыре постоянные причины покрывают каждую проверку без починки — spend, install, authenticate, destroy — и тест падает, если проверку добавили без причины.
- **Ещё три проверки чинят себя сами.** `config_valid` атомарно дописывает недостающие обязательные ключи значениями, которые пишет `init`; конфиг, который не разбирается, только сообщается и никогда не переписывается. `--fix --deep` добавляет медленные локальные починки, начиная с бэкфилла сессионных чанков. Ни одна починка ни на одном уровне не запускает компиляцию.
- **`tesserae test` доказывает, что бэкенд отвечает.** Он разрешает настройки так же, как компиляция, строит того же клиента, а затем тратит один JSON-вызов и один прозаический, потому что шлюз может обслужить первый и отказать во втором. Ни один не кэшируется. Выход 0 только если вернулись оба.

## Как пользоваться

```bash
tesserae test                 # resolve, build, one JSON call, one prose call
tesserae doctor --fix         # repeats until a pass changes nothing
tesserae doctor --fix --deep  # + the slow local repairs
```

## Обновление

Мигрировать нечего. `doctor --fix` держит своё старое обещание — только безопасные починки, никогда компиляция, никогда убитый процесс — он просто теперь повторяется и сообщает, что оставил. `--deep` без `--fix` завершается с 2.
