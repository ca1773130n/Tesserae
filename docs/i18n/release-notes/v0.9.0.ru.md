Released **2026-06-14** · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

Выпуск новой функции: многоуровневый слой памяти, перенесённый из LongMemEval-V2's AgentRunbook, и набор исправлений, которые делают LLM-бэкенд видимым и честным вместо молчаливых сбоев.

## 1. Память с множественной гранулярностью в стиле AgentRunbook

Новый опциональный уровень дистилляции над исходными находками сессии — три гранулярности, все байт-идемпотентные (идентификаторы на основе содержимого, без системного времени/RNG, детерминированный fallback) и опциональные LLM:

- **`Event`** — записи за переход, добытые из ходов сессии (отслеживание динамического состояния), интегрированные в извлечение находок сессии.
- **`Runbook`** — дистиллированные переиспользуемые процедуры для повторяющихся рабочих потоков (кроссессионные, по умолчанию ≥2 сессии).
- **`Gotcha`** — дистиллированные повторяющиеся режимы отказа / неправильные предположения здесь.

Плюс **многопулевой поиск**: `compile_context(multi_pool=True)` разлагает запрос и резервирует слоты бюджета для наиболее релевантных дистиллированных узлов памяти. Настраивается через `tesserae compile --distill`, `tesserae context --multi-pool`, `distillation.enabled` в конфиге и аргумент MCP `compile_context` `multi_pool`. Все отключены по умолчанию, поэтому простая компиляция остаётся неизменной.

## 2. Видимый и честный LLM-бэкенд

- **`tesserae config status`** — выводит *разрешённый* провайдер + codex-home / claude-dirs с **источником** каждой настройки (env > config проекта > `~/.tesserae/config.json` > default), и **живой пинг**. Ограниченный по скорости или неправильно аутентифицированный бэкенд теперь очевиден вместо невидимого.
- **Громкие отказы в извлечении сессии** — извлечение теперь различает "модель ничего не вернула" от "модель никогда не ответила". Неудачный чанк больше **не кэшируется как пусто** (он переизвлекается, когда бэкенд заработает), и компиляция выводит неизбежное предупреждение. Ранее ограниченный бэкенд молчаливо производил граф с сессиями, но **с нулевыми находками**.
- **Codex reasoning effort** зафиксирован на `medium` для собственных вызовов Tesserae (настраивается через `llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT`), поэтому глобальный `xhigh`, установленный для интерактивного codex, больше не делает каждую компиляцию во много раз медленнее.

## 3. Упрочнение детерминизма

- Охраны байт-идемпотентности теперь упражняют детерминированную (без-LLM) компиляцию, которую они на самом деле гарантируют — окружающий LLM больше не делает их нестабильными.
- Компиляция без-LLM **переиспускает кэшированные сводки сообщества** вместо их отбрасывания, поэтому переиспускание остаётся стабильным при колебаниях доступности LLM.

## Обновление с v0.8.x

Прямая замена. Всё новое опционально или аддитивно; простой `tesserae compile` ведёт себя как раньше. Запустите `tesserae config status`, чтобы подтвердить, на каком LLM-бэкенде вы находитесь.
