Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

Aquí llegan tres cosas. El código fuente deja de indexarse salvo que lo pidas.
Una superficie de recuperación que estaba escrita, probada e inalcanzable se
vuelve alcanzable. Y el grafo gana un organigrama, para que un agente de
propósito general pueda apuntarse a un dominio y actuar como experto en él.

## El código fuente ahora es algo que se pide

Tesserae construía una capa de código siempre que un proyecto *parecía* un
repositorio: `kind` era `CodeProject`, `Repository` o `Project`. Eso describe lo
que un proyecto es, no una declaración de que su dueño quisiera que se analizara
su código. La única salida era mentir sobre el tipo.

El coste se acumulaba donde nadie mira. `graph.json` lleva la partición de
investigación, así que mostraba **cero** nodos de código mientras la proyección
SQLite y las páginas generadas llevaban unas 220 000 filas y 220 000 páginas.
Nadie atribuye eso a un ajuste que nunca activó. En la máquina del propio
mantenedor eran 327 MB de artefactos para una función que ese proyecto tenía
desactivada.

Ahora el proyecto lo pide:

```json
"external_tools": [{"id": "codegraph"}]
```

La ausencia es «desactivado». El tipo de proyecto no se consulta en absoluto.
Esto reutiliza la forma que la integración de RAG-Anything ya lee, en lugar de
inventar un segundo interruptor.

**El mantenimiento sigue la misma puerta**, que es la mitad que de otro modo se
filtraría. Ambos hooks de sync-code comprueban la habilitación *antes* que su
propio ajuste `sync_code_on_*`, de modo que estos solo pueden estrechar un
permiso ya concedido, nunca convertirlo en uno. Una base de datos de CodeGraph en
disco no es consentimiento: un agente pudo ejecutar `codegraph init` para sus
propios fines sin opinión alguna sobre si Tesserae debe seguirla cada 30
segundos.

`code-graph.json` sigue el interruptor en ambas direcciones: se escribe cuando
está activado y se elimina cuando no. Uno obsoleto no lleva marca de tiempo y
sigue respondiendo con una instantánea de un repositorio que ya cambió.

No se ha eliminado nada. El adaptador de CodeGraph, el extractor, la caché y
`tesserae code ingest|sync` siguen aquí, detrás del interruptor.

## Los mandos de recuperación que siempre estuvieron

`facts_as_of` —consulta bitemporal, «qué creía el grafo en esta fecha»— estaba
escrita, era idempotente byte a byte y tenía siete pruebas, con **cero**
llamadores. `personalized_pagerank` ya respetaba `edge_type_weights`.
`compile_context` tomaba dieciséis parámetros y el servidor MCP reenviaba siete.
Tesserae tenía bitemporalidad y recorrido selectivo por vista, y no podía pedir
ninguno de los dos.

Ahora sí. `as_of` en `search_facts` y `timeline`, con `undated_included`
informando cuántas de las filas recibidas no llevan fecha. `strategy`, `scope`,
`edge_type_weights`, `tame_hubs` y `recency_weight` en `compile_context`.

`as_of` y `current_only` se rechazan juntos, deliberadamente: expresan relojes
distintos, y preguntar qué era cierto en una fecha pasada no debería devolver
silencio porque la respuesta fuera sustituida después.

## Un organigrama sobre el grafo

`tesserae domains status` muestra una estructura levantada sobre tu grafo de
conocimiento: divisiones derivadas de sus comunidades, división recursiva cuando
el resumen de un dominio supera lo que un agente puede leer de una vez, e
identidades que sobreviven a una reorganización: el slug que fijaste a un agente
sigue resolviéndose después de que el grafo se mueva.

Este es el sustrato. El enrutado que lo usa llega a continuación.

## La ingesta deja de informar éxito por trabajo que no hizo

Antes `tesserae ingest paper.pdf` copiaba el archivo, ejecutaba una compilación cuyo
recorredor lee solo `.md`, e imprimía recuentos de nodos del resto del corpus. Nada en
ese camino distinguía «ingerí tu PDF» de «no ingerí nada». Un directorio de PDF se
comportaba igual, y el `processed=1` que imprimía contaba el directorio.

Ahora rechaza, archivo por archivo, con un remedio ejecutable:

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

Obtener una URL también es más estricto. Antes, una URL de PDF se descodificaba como
texto, se escribía con sufijo `.md` y se aplicaba el hash sobre el mojibake, de modo que
el recorredor se lo pasaba al extractor como prosa. Ahora se rechazan un cuerpo que los
bytes declaran binario, un cuerpo cuyo tipo declarado es binario, y un 200 sin texto
legible.

Un nuevo lint `INTERVAL_COVERAGE` informa qué parte del grafo puede situarse en el
tiempo. En el grafo de este proyecto: **76 095 de 103 705 hechos (73,4%) no llevan
`valid_from`**, así que se ordenan bajo la cadena literal «undated» en `timeline()`.
Informa en nivel `info` y no hace fallar `--strict`; fijar un umbral requiere un número
de un corpus actual, y este todavía no lo es.

La importación de sesiones cuenta los bloques de contenido que no puede leer en lugar de
descartarlos en silencio. En 150 transcripciones reales eso sacó a la luz **9 bloques de
imagen antes invisibles**: están anidados dentro de `tool_result`, donde el contador
antiguo nunca miró.

## Actualizar

```bash
pip install --upgrade tesserae==0.30.0
```

Si venías usando Tesserae como plugin de Claude Code, **la puerta de los hooks
solo surte efecto una vez instalado el plugin de esta versión**: las copias
anteriores comprueban si existe una base de datos de CodeGraph y no pueden ver la
habilitación. Hasta entonces, `sync_code_on_edit: false` y
`sync_code_on_start: false` en `.claude/tesserae.local.md` son el interruptor que
esos hooks sí entienden.

Los proyectos existentes siguen funcionando. El que quiera recuperar su capa de
código añade la entrada `external_tools` de arriba; el que no, obtiene un grafo
más pequeño, una base de datos más pequeña y ninguna página de código, sin
cambiar nada.
