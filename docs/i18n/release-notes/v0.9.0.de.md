Released **2026-06-14** · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

Eine Feature-Version: eine Multi-Granularitäts-Speicherschicht, portiert von LongMemEval-V2s AgentRunbook, und eine Reihe von Fixes, die das LLM-Backend sichtbar und ehrlich machen, statt stillschweigend zu scheitern.

## 1. AgentRunbook-ähnlicher Multi-Granularitäts-Speicher

Eine neue, optionale Distillationsschicht über rohen Sitzungsergebnissen — drei Granularitäten, alle byte-idempotent (inhaltsabgeleitete IDs, keine Wanduhr/RNG, deterministische Fallback) und LLM-optional:

- **`Event`** — Pro-Transitions-Datensätze, die aus den Durchläufen einer Sitzung gewonnen werden (dynamische Zustandsverfolgung), integriert in die Extraktion von Sitzungsergebnissen.
- **`Runbook`** — Destillierte wiederverwendbare Verfahren für wiederkehrende Arbeitsabläufe (sitzungsübergreifend, ≥2 Sitzungen standardmäßig).
- **`Gotcha`** — Destillierte wiederkehrende Fehlermodi / falsche Annahmen hier.

Plus **Multi-Pool-Abruf**: `compile_context(multi_pool=True)` zerlegt die Abfrage und reserviert Budgetplätze für die relevantesten destillierten Speicherknoten. Konfigurierbar über `tesserae compile --distill`, `tesserae context --multi-pool`, `distillation.enabled` in der Konfiguration und dem MCP-Argument `compile_context` `multi_pool`. Alle standardmäßig aus, daher eine einfache Kompilierung ist unverändert.

## 2. Ein sichtbares, ehrliches LLM-Backend

- **`tesserae config status`** — druckt den *aufgelösten* Provider + Codex-Home / Claude-Verzeichnisse mit der **Quelle** jeder Einstellung (env > Projektkonfiguration > `~/.tesserae/config.json` > Standard) und einem **Live-Ping**. Ein drosseltes oder falsch authentifiziertes Backend ist jetzt offensichtlich statt unsichtbar.
- **Laute Sitzungsextraktionsfehler** — die Extraktion unterscheidet jetzt „das Modell hat nichts zurückgegeben" von „das Modell hat nie geantwortet." Ein fehlgeschlagener Chunk wird **nicht mehr als leer zwischengespeichert** (er wird erneut extrahiert, sobald das Backend funktioniert), und die Kompilierung gibt eine unübersehbare Warnung aus. Zuvor erzeugte ein gedrosseltes Backend stillschweigend ein Graph mit Sitzungen, aber **null Ergebnissen**.
- **Codex-Reasonably-Aufwand** ist auf `medium` für Tesseraes eigene Aufrufe festgelegt (konfigurierbar über `llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT`), sodass ein global eingestelltes `xhigh` für interaktives Codex nicht mehr jede Kompilierung um ein Vielfaches verlangsamt.

## 3. Determinismus-Verhärtung

- Die Byte-Idempotenz-Wächter üben jetzt die deterministische Kompilierung (kein-LLM), die sie tatsächlich garantieren — ein umgebundes LLM macht sie nicht mehr instabil.
- Eine No-LLM-Kompilierung **gibt zwischengespeicherte Community-Zusammenfassungen erneut aus**, anstatt sie zu verwerfen, sodass Neukompilierungen über LLM-Verfügbarkeitsschwankungen stabil bleiben.

## Upgrade von v0.8.x

Drop-in. Alles Neue ist optional oder additiv; eine einfache `tesserae compile` verhält sich wie zuvor. Führen Sie `tesserae config status` aus, um zu bestätigen, auf welchem LLM-Backend Sie sind.
