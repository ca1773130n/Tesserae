Publié **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.19.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.19.0) · `pip install --upgrade tesserae==0.19.0`

La release de fin de vie des backends. Depuis la v0.18.0, la boucle par défaut de mise à jour et de récupération du graphe de connaissances est entièrement interne — le pipeline typé ResearchGraph écrit le graphe (extraction native du code-graph incluse), et `ask` planifie la récupération dessus avec le LLM. Cette release supprime les deux backends greffés qui ne justifiaient plus leur présence.

## understand-anything : supprimé

Sa seule contribution — fusionner dans le ResearchGraph un `knowledge-graph.json` de nœuds de structure de code généré en externe — était redondante depuis l'arrivée de l'extracteur natif de code-graph. L'adaptateur, le module de refresh, la fusion à la compilation, la détection des dépendances et les entrées de setup ont disparu. `tesserae integrations refresh understand-anything` affiche un pointeur d'une ligne vers l'ingestion native de code et sort avec le code 2. Les anciennes configs portant une entrée `external_tools` understand-anything se chargent avec une seule note ; les nœuds créés par UA dans les graphes existants restent valides.

## cognee : supprimé

cognee dupliquait le graphe *vers l'extérieur* dans son propre store et ne renvoyait jamais rien ; avant la 0.18, il laissait aussi fuir du spam de logs et un repli `OperationalError` dans la sortie de `ask` sur les installations par défaut. Après une release de grâce en mode désactivé par défaut, il est entièrement supprimé : les modules adapter/direct/query, la passe cognify à la compilation et l'export de bundle, l'extra `[cognee]`, les invites du wizard, et les références au schéma MCP (~1 100 LOC et 6 fichiers de tests). `query --backend cognee` et chaque flag `--cognee-*` / `--enable-cognee` affichent un stub de suppression d'une ligne et sortent avec le code 2. Les configs portant une section `memory_backends.cognee` se chargent et compilent toujours — avec exactement une note par processus.

## rag-anything : conservé, à dessein

Le seul backend doté d'une capacité qui manque réellement au graphe de connaissances — le RAG documentaire multimodal (PDF, images) — reste comme extra optionnel `tesserae[raganything]`, désactivé par défaut, accessible via `tesserae query --backend raganything`.

## Changements incompatibles

Conformément à la convention du projet, rien n'échoue silencieusement — chaque surface supprimée affiche son remplacement ou une explication et sort avec le code 2 : `integrations refresh understand-anything`, `query --backend cognee`, `--cognee-search-type`, `--cognee-dataset`, `--enable-cognee` et les flags de setup/extract `--cognee-*` restants. Effet net des deux suppressions : **−5 500 lignes** contre +1 600, avec la suite de tests complète au vert (2 251 passés).
