Publicado el **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.0/) · [Versión en GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.0) · `pip install --upgrade tesserae==0.37.0`

Esta versión añade un ajuste y corrige varias afirmaciones.

## El carril denso puede pedir un codificador entrenado

En un corpus de 148 artículos, el incrustador estático `model2vec` incluido era
toda la diferencia entre el grafo y un almacén vectorial plano. Recall por
documentos distintos, con la misma fusión, el mismo grafo y la misma deduplicación:

| variante | @10 docs | @50 docs |
| --- | --- | --- |
| Almacén de fragmentos en bruto de Mem0 OSS, su propio codificador | 0.784 | 0.942 |
| Almacén de fragmentos en bruto de Mem0 OSS, el mismo bge-base | 0.775 | 0.944 |
| Tesserae, model2vec estático incluido | 0.754 | 0.914 |
| **Tesserae, bge-base en el carril denso** | **0.791** | **0.962** |

`TESSERAE_EMBEDDING_PREFER` elige el backend cuando quien llama pide `auto`
(`model2vec`, `st`, `openai`, `hash`); un valor que no nombra ningún backend se
informa y se ignora en lugar de caer en silencio al sustituto por hash.
`TESSERAE_ST_MODEL` nombra el modelo de sentence-transformers: el valor por
defecto pasa del no medido `all-MiniLM-L6-v2` al medido `BAAI/bge-base-en-v1.5`.

```bash
uv pip install sentence-transformers
export TESSERAE_EMBEDDING_PREFER=st
export TESSERAE_ST_MODEL=BAAI/bge-base-en-v1.5   # the default; any Hugging Face name
```

La escalera auto no cambia: `model2vec` primero, así que `pip install tesserae`
sigue sin torch y una instalación que nunca define la variable se comporta
exactamente como antes.

## Lo que la medición mostró realmente

Con el mismo codificador, el grafo y un almacén de fragmentos en bruto encuentran
los mismos documentos: emparejados sobre 57 preguntas son 8 victorias, 8 derrotas
y 41 empates a diez documentos (prueba de signos p=1.0). Eso es paridad, y la
documentación ahora dice paridad; la redacción anterior afirmaba que el grafo iba
por delante, y comparaba dos codificadores distintos.

El recuperador tampoco ve ya la marca de fecha ni el texto de instrucciones del
propio LongMemEval, que formaban parte de la consulta en todos los brazos.

## Dónde sí difiere el diseño

Empaquetar los documentos elegidos por el grafo como prosa original en lugar de
como afirmaciones extraídas puntuó +28.9% frente a un control de pasajes con un
juez `gpt-4o-mini`. Repetido con un juez local de 7B es +7%, no significativo, y
en un segundo corpus pierde. El README lleva los tres números, no el mejor.

## Actualización

No hay nada que migrar. Los grafos existentes no se ven afectados; el ajuste es
opcional y el backend por defecto no cambia.
