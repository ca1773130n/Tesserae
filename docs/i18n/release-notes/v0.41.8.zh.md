发布于 **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.8/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.8) · `pip install --upgrade tesserae==0.41.8`

`tesserae init` 和 `tesserae compile` 会把所在项目加入全机注册表 `~/.tesserae/registry.json`，
而不指定项目范围的查询会搜索其中的每个项目。在发现这个问题的机器上，注册表里有分布在 204 个目录上的
286 个条目，其中真正的项目只有 6 个。其余是基准测试运行、代理的临时目录和一个测试留下的一次性项目，
外加每个在 `init` 时起过名字的项目的第二个别名。

## 改了什么

- **不再产生第二个别名。** `init --name` 用给定的名字注册，而之后的编译没有 `--name`，
  于是又用目录名注册了一次。HypePaper 给它构建的每个专家都起名为 `hp-topic-<topic>`，结果每个专家都被列了两次。
  现在，已经以任何别名在注册表里的目录会保持原样。
- **基准测试运行把项目留在自己那里。** DeepScholar、growth、LongMemEval 和 LoCoMo 测试框架
  会为每个查询或对话各建一个项目。它们的 `init` 和 `compile` 现在使用工作目录里的注册表。
  曾有一次 DeepScholar 运行留下了 63 个名为 `0` 到 `62` 的项目。
- **测试套件不再写入你的注册表。** 有一个测试在子进程里运行 `init`，而套件的注册表隔离够不到那个子进程，
  于是它把临时目录下的 `cwd_wiki` 注册了进去。

## 升级

无需迁移。注册表里已有的条目会一直保留，直到你删除它们：`tesserae projects list` 可以查看，
`tesserae projects unregister <name>` 可以删除其中一个，项目本身不受影响。
