Выпущено **2026-08-30** · [PyPI](https://pypi.org/project/tesserae/0.36.0/) · [Релиз на GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.36.0) · `pip install --upgrade tesserae==0.36.0`

Этот выпуск — два дня измерений на скомпилированном графе. Все числа здесь, а стенды, которые их дали, — в репозитории.

## Один якорь на документ

Фрагментное извлечение создавало по якорю документа на каждый фрагмент — 9.4 на статью, — а ретривер отдаёт каждому якорю полный исходный текст, так что одна статья могла занять все десять мест в top-k. Теперь якорь каждого фрагмента перенаправляется на якорь первого фрагмента до слияния, а цитируемый документ, упомянутый раньше, не принимается за сам документ. Перекомпиляция тех же 148 статей на тех же попаданиях в кэш подняла recall@10 по документам с **0.550 → 0.652**.

Второй дефект того же корня: граф держал по два узла-якоря на сессию, и десять мест поиска «сначала документы» вмещали четыре сессии. Теперь на документ выводится один якорь, а оставшиеся места заполняются — LongMemEval recall@10 **0.867 → 0.891**.

## Одно имя — одна сущность, а факты читаются и через узлы

`PDB` был Benchmark в одной статье и Dataset в другой, и каждый потребитель, разрешающий по имени, отказывался из-за неоднозначности. Все три прохода слияния это пропускали. Теперь одинаковые имена сливаются между документами по типам исследовательских сущностей. А `verify_claim` читает факты, которые экстрактор записал через узел Result — `S reports_result R, R evaluated_on D`. Из 426 заявленных отношений верных **117 → 167**, сфабрикованных SUPPORTED на 426 негативах — **0**.

## Пометки проверки точны по умолчанию

Бесплатная проверка сама по себе менее точна, чем модель (0.872 против 0.928), и ни один вариант без модели не закрыл разрыв — каждый измерен. Каскад закрывает: отдав модели только неуверенную полосу, он даёт **0.935** на 40% вызовов. В `ask` он теперь включён по умолчанию; `TESSERAE_VERIFY_BAND=off` возвращает бесплатные пометки.

| Поиск в разговорной памяти | до | после |
|---|---|---|
| LoCoMo, 9 разговоров, recall@10 | 0.878 | **0.930** |
| LongMemEval, группа 0, recall@10 | 0.867 | **0.891** |

## Также

- `tesserae graph-repair` применяет проходы постобработки к графу, уже лежащему на диске — без модели, без сети, за секунды — и починенный граф совпадает с перекомпилированным
- ранжирование «сначала документы» (`document_first`) для разговорной памяти включают рычаги LoCoMo и LongMemEval; на корпусе статей оно хуже, поэтому не по умолчанию

## Обновление

Для существующих графов запустите `tesserae graph-repair` вместо перекомпиляции. `ask` теперь по умолчанию тратит токены на каскад проверки; прежнее поведение — `TESSERAE_VERIFY_BAND=off`.
