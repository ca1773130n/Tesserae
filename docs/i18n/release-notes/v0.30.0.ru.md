Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

Здесь три вещи. Исходный код перестаёт индексироваться, пока вы об этом не
попросите. Поверхность извлечения, которая была написана, покрыта тестами и
недостижима, становится доступной. А граф получает организационную структуру,
чтобы обычного агента можно было направить на один домен и получить эксперта.

## Исходный код теперь нужно запросить

Раньше Tesserae строил слой кода всякий раз, когда проект *выглядел* как
репозиторий — `kind` равнялся `CodeProject`, `Repository` или `Project`. Это
описание того, чем проект является, а не заявление владельца о том, что он хочет
разбора своих исходников. Единственным выходом было солгать о типе.

Цена накапливалась там, куда никто не смотрит. `graph.json` несёт
исследовательскую партицию, поэтому в нём было **ноль** узлов кода, тогда как
SQLite-проекция и сгенерированные страницы несли примерно 220 тысяч строк и 220
тысяч страниц. Никто не свяжет эти расходы с настройкой, которую никогда не
включал. На машине самого сопровождающего это было 327 МБ артефактов для
функции, которую проект отключил.

Теперь проект просит сам:

```json
"external_tools": [{"id": "codegraph"}]
```

Отсутствие записи — это «выключено». Тип проекта не учитывается вовсе. Здесь
переиспользована та же форма, которую уже читает интеграция с RAG-Anything, а не
создан второй переключатель.

**Сопровождение подчиняется тому же затвору** — и именно эта половина иначе бы
протекала. Оба хука sync-code проверяют согласие *до* собственной настройки
`sync_code_on_*`, поэтому те могут лишь сузить уже выданное разрешение, но
никогда не превратить его в выданное. Наличие базы CodeGraph на диске не является
согласием: агент мог запустить `codegraph init` для своих целей, не имея мнения о
том, должен ли Tesserae отслеживать её каждые 30 секунд.

`code-graph.json` следует переключателю в обе стороны: пишется при включении,
удаляется при выключении. Оставшийся файл не несёт отметки времени и продолжает
отвечать снимком репозитория, который с тех пор изменился.

Ничего не удалено. Адаптер CodeGraph, экстрактор, кэш и `tesserae code
ingest|sync` — всё на месте, за переключателем.

## Ручки извлечения, которые были там всегда

`facts_as_of` — битемпоральный запрос «во что граф верил на эту дату» — был
написан, побайтово идемпотентен и покрыт семью тестами при **нуле** вызывающих.
`personalized_pagerank` уже учитывал `edge_type_weights`. `compile_context`
принимал шестнадцать параметров, а MCP-сервер передавал семь. У Tesserae была
битемпоральность и обход с выбором представления — и он не мог запросить ни того,
ни другого.

Теперь может. `as_of` у `search_facts` и `timeline`, а `undated_included`
сообщает, сколько из полученных строк вовсе не имеют даты. `strategy`, `scope`,
`edge_type_weights`, `tame_hubs` и `recency_weight` у `compile_context`.

`as_of` и `current_only` вместе отклоняются намеренно: они выражают разные часы,
и вопрос «что было верно на прошлую дату» не должен молча возвращать пустоту
из-за того, что ответ позже был заменён.

## Организационная структура над графом

`tesserae domains status` показывает структуру, построенную над вашим графом
знаний: подразделения, выведенные из его сообществ; рекурсивное деление, когда
бриф домена перерастает то, что агент способен прочитать за один раз; и
идентичности, переживающие реорганизацию — закреплённый за агентом slug
продолжает разрешаться после того, как граф сдвинулся.

Это основание. Маршрутизация, которая им пользуется, придёт следующей.

## Приём перестаёт отчитываться об успехе там, где ничего не сделал

Раньше `tesserae ingest paper.pdf` копировал файл, запускал компиляцию с обходчиком,
читающим только `.md`, и печатал число узлов из остального корпуса. Ничто на этом пути
не могло отличить «принял ваш PDF» от «не принял ничего». Каталог PDF вёл себя так же,
а напечатанное `processed=1` считало сам каталог.

Теперь он отказывает — по файлу, с выполнимым средством:

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

Загрузка по URL тоже строже. Раньше PDF по ссылке декодировался как текст, писался с
суффиксом `.md` и хэшировался по мусору — после чего обходчик отдавал его экстрактору
как прозу. Тело, которое по байтам является бинарным, тело с бинарным заявленным типом
и ответ 200 без читаемого текста теперь отклоняются.

Новая проверка `INTERVAL_COVERAGE` сообщает, какую часть графа можно разместить во
времени. На графе самого проекта: **76 095 из 103 705 фактов (73,4%) не имеют
`valid_from`**, поэтому в `timeline()` они сортируются под строкой «undated». Она
сообщает на уровне `info` и не валит `--strict`: чтобы задать порог, нужно число из
актуального корпуса, а он пока не таков.

Импорт сессий считает блоки содержимого, которые не может прочитать, вместо того чтобы
молча их отбрасывать. На 150 реальных стенограммах это выявило **9 блоков изображений,
невидимых прежде** — они вложены внутрь `tool_result`, куда старый счётчик не заглядывал.

## Обновление

```bash
pip install --upgrade tesserae==0.30.0
```

Если вы запускали Tesserae как плагин Claude Code, **затвор в хуках начнёт
действовать только после установки плагина этой версии** — более ранние копии
плагина смотрят лишь на наличие базы CodeGraph и не видят согласия. До тех пор
`sync_code_on_edit: false` и `sync_code_on_start: false` в
`.claude/tesserae.local.md` — тот переключатель, который эти хуки понимают.

Существующие проекты продолжают работать. Проект, которому нужен слой кода,
добавляет запись `external_tools` выше; проект, которому он не нужен, ничего не
меняет и получает меньший граф, меньшую базу и никаких страниц кода.
