无法核查的回答，只能选择相信。这个版本让每个回答都能逐句核查，不花 token，也不走网络。

## 该复核哪些句子，以及为什么

`ask` 本就返回一个 `grounding` 分数。一个数字只能告诉读者哪里出了问题这件事本身，却永远说不出问题在哪里。现在这个信封还会带上 `unsupported`——那些内容在模型实际拿到的证据中基本不存在的句子，每一句都会列出缺失的词——旁边还有 `supported_rate`。

阈值来自阴性对照，而不是凭感觉。442 个真实回答的每个句子都被评分两次：对着它自己的证据，以及对着另一个问题的证据。

| 评分所对的证据 | 平均覆盖率 |
|---|---|
| 它自己的证据 | **0.682** |
| 另一个问题的证据 | **0.365** |

两者以 **AUC 0.908** 分开。在发布的阈值下，这项检查抓住了 **78.5%** 依据外部证据写出的句子，同时对 **11.3%** 的真实句子打上标记。它最初跑在一个凭眼力选定的阈值上，那会给一半正确输出打上标记——没人信得过的标记还不如没有标记，所以这个数字必须来自对照。

`UNSUPPORTED` 的意思是请复核这一句，绝不是“这句是假的”：用不同词汇正确改写的句子也会落在这里。`None` 表示检查无法执行，调用方必须把它读作未知，而不是干净。

## 图谱不再因拼写而丢失实体

`ResNet-50` 和 `ResNet 50` 曾是两个节点，于是每个按名称解析的使用者看到的要么是歧义要么是落空——在一个已编译语料库中这样的名称有 2,317 个。现在实体解析会在已有节点足够接近时复用它，阈值是在六个取值上实测得到而非选定的，而被合并掉的名称保留为别名，因此两种拼写仍都能解析。

分块抽取还会在两个分块对类型有分歧时，把一个实体留成两个节点——一个是 `Model`，另一个是 `Algorithm`，在 148 篇语料库中有 1,584 个这样的名称，且没有一个是同类型的。两者都已修复，并且**在测试过的每个阈值上特异度都保持在 1.000**：没有任何一次合并制造出语料库并未给出的支持。

## 其他

- 已发布的 npm 版本现在是空操作，而不是一次红色的 CI 运行，因为标签会因平常的原因被重新推送
- 实体解析在 `compile()` 内部运行；它曾有一个版本只是一个没人调用的模块

## 升级

在你重新编译之前什么都不会变。复核标记不需要重新编译——它读取回答所拿到的证据，因此在你现有的图谱上就能工作。
