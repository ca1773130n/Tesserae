Veröffentlicht **2026-07-21** · [PyPI](https://pypi.org/project/tesserae/0.22.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.22.0) · `pip install --upgrade tesserae==0.22.0`

v0.21.0 führte geschichtetes Agent-spezifisches Memory ein, aber die Hälfte davon war nur über MCP erreichbar und `tesserae agents init` platzierte jeden Agenten unter `org:root`. Dieses Release macht das ganze Feature vom Terminal aus nutzbar.

## `init` erstellt eine echte Organisation

`tesserae agents init` leitet nun die Hierarchie aus einem bereits vorhandenen Signal ab: eine Subagenten-Rolle (`claude-code:me:reviewer`) wird übergeordnet dem Hauptagenten, der sie spawnte (`claude-code:me:default`), statt dass alle flach unter `org:root` landen. Du erhältst eine funktionierende mehrstufige Organisation aus einem Befehl — kein `set-parent` notwendig. Übergib `--flat` für das alte Verhalten, und `init` gibt dir nun den vorgeschlagenen Baum aus, damit du sehen kannst, was es entschieden hat.

```
org:root
  claude-code:me:default   Main    sessions=42
    claude-code:me:reviewer   Reviewer   sessions=8   distilled_through=2026-07-20T…
    claude-code:me:planner    Planner    sessions=5   (not distilled)
```

## Scoped reads vom CLI

`--agent KEY` funktioniert jetzt auf `tesserae query`, `ask` und `context` — Abruf und Synthese laufen über die aufgelöste Sicht des Agenten (ein **Worker**-Schlüssel sieht sein eigenes Rohmemory plus destillierte Notizen, ein **Manager**-Schlüssel sieht nur die destillierten Schichten seiner Berichte, `org` sieht das ganze Team). Zuvor existierte dieses Scoping nur als MCP-Argument.

```bash
tesserae query "release checklist" --agent claude-code:me:reviewer
tesserae ask "what does my team know about deploys?" --agent org
```

Unbekannte Schlüssel und nicht-destillierte Agenten schlagen laut fehl mit dem genauen Remedial-Befehl, nie mit einer stillschweigend leeren Antwort.

## Die Organisation inspizieren

- **`tesserae agents tree`** — das Organisationsdiagramm als Baum mit Einzug, jeder Agent mit Sitzungsanzahl und wie veraltet sein destilliertes Memory ist.
- **`tesserae agents show KEY`** — Sicht auflösen und Modus, Member-Agenten, Artefaktpfade, Knotenzählungen und Veraltungsmarken ausgeben.
- **`tesserae agents drill NODE_ID [--agent KEY]`** — die überprüfte Eskalation von einer destillierten Notiz zurück zur rohen L0-Evidenz, jetzt ein First-Class-CLI-Befehl (alive / changed / absorbed / gone). Die `drill_down`-Logik wird mit dem MCP-Tool geteilt, daher verhalten sich beide Oberflächen identisch.

## Unter der Haube

Die Rollenhierarchie-Inferenz ist eine reine, deterministische Funktion; der `drill_down`-Kern wurde extrahiert, sodass CLI und MCP-Server einen überprüften Code-Pfad teilen. Keine Änderungen an den destillierten Artefakten oder ihren Determinismus-Garantien. Rein additiv — jeder existierende Befehl verhält sich exakt wie zuvor, wenn `--agent` fehlt.
