Tesserae — это вики на основе LLM — поэтому `compile` теперь создаёт **слой концепций/утверждений по умолчанию**, а не только структурный скелет.

## `compile` создаёт слой концепций по умолчанию

Раньше `tesserae compile` запускал **детерминированный** экстрактор по умолчанию: быстрый и байт-стабильный, но структурный только — источники, разделы и явные ссылки с разреженным слоем концепций. Более богатый слой (концепции, утверждения, возможности, технические термины, диапазоны свидетельств и типизированные рёбра между ними) был скрыт за дополнительным флагом только для Claude `--extractor claude-cli`. Для вики на основе LLM это было наоборот.

Теперь:

- **`--extractor llm` — это умолчание.** `tesserae compile` читает каждый документ через ваш **настроенный поставщик** — codex / claude / Anthropic API, согласно `llm_provider` — используя тот же сеанс `LLMJsonClient`, который использует извлечение сессий. Больше не путь только для Claude.
- **`deterministic` — это явное отключение** — `tesserae compile --extractor deterministic` для быстрого, не требующего ключей, байт-стабильного режима (CI / воспроизводимые сборки). Байт-идемпотентность не изменилась; это всегда было свойством этого режима.
- **Без тайм-аута по умолчанию.** Старый `--claude-timeout=180` молча усекал большие документы дизайна в деградированный fallback. Извлечение теперь работает до завершения; тайм-аут только для явного выбора.
- **Флаги, независимые от поставщика:** `--llm-provider`, `--llm-model`, `--llm-include`, `--llm-limit`. (Флаги `claude-cli` / `selective-claude` и `--claude-*` по-прежнему работают как устаревшие псевдонимы.)
- **Надёжно и грациозно.** Нет настроенного бэкенда? Деградирует до детерминированного с предупреждением, а не отказывает. Ошибка бэкенда в одном документе переключается на детерминированный для этого документа вместо отмены всей компиляции, и кэширование по содержимому означает, что повторная компиляция неизменённых документов переиспользует предыдущее извлечение.

```bash
tesserae compile                        # LLM concept layer, your configured provider
tesserae compile --extractor deterministic   # structural / byte-stable / key-free
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # cost-aware
```

## Более быстрый федеративный `ask`

Федеративный `ask` переассемблировал кросс-проектный граф (чтение + парсинг + пространство имён + слияние идентичности каждого проекта-участника) на *каждый* запрос — примерно четверть задержки, переделанной для каждого follow-up в беседе с одним и тем же набором проектов. Собранный граф теперь мемоизирован в процессе, ключевой по сигнатуре изменения файла графа каждого участника: повторный запрос — это мгновенное попадание в кэш, и запись **самоинвалидируется в момент повторной компиляции любого проекта-участника** (нет дискового кэша, нет устаревания). На реальной федерации из 6 проектов / 22,6k узлов это примерно ~0,6 с сборки пропущено за повторный запрос.

## Обновление с v0.12.x

Единственное изменение поведения: `tesserae compile` теперь выполняет извлечение LLM по умолчанию. Если вы хотите старое поведение только структурного (например, в CI или без настроенного бэкенда LLM), передайте `--extractor deterministic` — и на машине без настроенного поставщика compile уже переключается на неё автоматически.
