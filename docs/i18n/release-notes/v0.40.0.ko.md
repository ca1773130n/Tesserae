공개일 **2026-09-11** · [PyPI](https://pypi.org/project/tesserae/0.40.0/) · [GitHub 릴리스](https://github.com/ca1773130n/Tesserae/releases/tag/v0.40.0) · `pip install --upgrade tesserae==0.40.0`

v0.5.0 이후로 증분 컴파일러는 꺼진 플래그 뒤에 배송되었고,
실험적으로 표시되었으며, 일곱 가지 편집 형태에 대해 증명되었다고 말한 바이트 일관성 게이트가 있었다.
이 릴리스는 플래그를 켠다. 그렇게 하기 전에 게이트를 정직하게 만들어야 했다.

## 무슨 일이 있었나

일관성 게이트는 증분 컴파일을 전체 컴파일과 비교하고 바이트 동일함을 찾았다.
전체 컴파일을 전체 컴파일과 비교하고 있었다.
엣지 출처는 정규화 이전의 ID에 대해 기록되었으므로, 4개 논문 픽스처에서 8개의 올바른 엣지가 4개의 출처 행을 가졌고,
준비 검사는 아니오라고 대답했으며, 모든 증분 분기는 자동으로 전체 재컴파일로 저하되었다.
게이트는 이제 빌드 원장에서 `mode == "incremental"`를 주장한다. 재매핑이 수정되고 증분이 실제로 실행되면서, 일곱 개의 테스트가 실패했다. 모두 일곱 개가 닫혔다: 다중 소유자 페이로드는 소유자 합집합을 재추출하고, 생산자 소유 레이어는 제거되고 재생성되며, 이름 변경된 파일은 전체 컴파일이 폴딩하는 별칭을 유지하고, 전체 컴파일이 드롭하는 것을 유지한 세 개의 뺄셈 누수가 닫혔다.

실제 1,422개 파일 코퍼스에서 측정하면, 올바른 소유자 합집합은 편집당 중앙값 24개 파일을 만진다.
이것이 이제 "증분"의 비용이다.

## 무엇이 바뀌었나

- **`incremental_compile`이 기본적으로 켜진다.** 기본 프로젝트의 변경-만-컴파일이 증분적으로 실행되고, 원장 행은 그렇게 말한다.
  `incremental_compile: false`는 전체 재컴파일로 다시 옵트아웃한다.
- **빌드 원장이 컴파일의 비용을 기록한다.** 각 `.build-history.jsonl` 행은 모드, 기간, 추출된 소스 수, 그리고 전체 컴파일로 다운그레이드하는 이유를 전달한다.
- **사이드카가 정리된다.** `node_memory`와 `fact_observed`는 절대로 조정되지 않았다; 1.19GB 저장소에서 `node_memory` 행의 95%는 더 이상 존재하지 않는 노드에 속했다. 전체 컴파일은 이제 그들을 정리하고, `doctor`는 팽창을 보고한다. 측정: 이후 0.42GB, 65% 회수됨.
- **`tesserae engine --serve`는 데몬에서 사이트를 제공한다.** `tesserae serve`와 동일한 핸들러로, `/api/ask`를 포함하여, 자체 스레드에서, 종료 시 명시적 클로저로 중지됨. 바인드 실패는 로그하고 엔진은 계속 컴파일한다. 플릿 모드는 절대 제공하지 않으며; `--serve`는 `--once`, `--harvest-only`와 `--all`을 거부한다.
- **사이트 빌드는 원자적 교환이다.** 컴파일은 이전에 `.tesserae/site`를 삭제하고 다시 작성했으므로, 제공된 페이지는 컴파일 길이 동안 404했다. 빌드는 이제 스테이징 디렉토리에 들어가 한 번의 syscall에서 라이브 사이트와 교환된다. 세 개의 재빌드 동안 제공된 인덱스를 망치는 독자는 0개의 미스를 본다; 이전 경로에 대해 33,202개를 보았다.
- **`tesserae serve`는 스레드된다.** 하나의 LLM `/api/ask`는 더 이상 모든 정적 자산을 뒤에 막지 않는다.
- **실패한 페이지 푸시는 더 이상 저장소를 웨지하지 않는다.** `deploy.py`는 생성한 worktree를 모든 종료 경로에서 제거하고 먼저 오래된 등록을 정리한다.
- **`tesserae/frontend.py`가 삭제된다.** 한 줄 리바인드 뒤에 648줄의 죽은 코드; 테스트는 그것을 사라진 상태로 유지한다.

## 업그레이드

업그레이드 후 첫 번째 변경-만-컴파일이 증분적으로 실행된다. 그래프가 그 후 잘못되어 보인다면, `tesserae compile`은 여전히 전체 컴파일이고
`incremental_compile: false` in `.tesserae/config.json`은 이전 기본값을 복원한다. 게시는 의도적으로 수동으로 유지된다: `deploy`는 클린 트리가 필요하고
`gh-pages`는 세계적으로 읽을 수 있으므로, 데몬의 아무것도 푸시하지 않는다.
