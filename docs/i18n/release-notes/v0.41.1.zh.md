发布于 **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.1/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.1) · `pip install --upgrade tesserae==0.41.1`

CLI 中的每个命令都通过运行它而非阅读它进行了审计。六个缺陷在复现和一次对抗性第二意见中幸存下来。其中三个删除了文件。

## 发生了什么

- **三个导出程序不再删除 `--output` 指定的任何内容。** `export site`、`export kuzu` 和 `export okf` 各自通过删除其目的地而打开，而该目的地是你输入的路径。保存两个文件的目录在一次 `export site --output` 后包含了 54 个文件，原始文件已消失。OKF 清理是递归的，所以它到达了任何捆绑都不写入的子目录中的文档。
- **不是以前的导出的目的地被拒绝。** 测试不是"它是否为空"，因为在你自己的输出上重新导出必须保持静默。每个导出程序识别自己的工作：站点通过其文件，Kuzu 通过文件本身中的 `KUZU` 魔法而不是名称，捆绑通过 `index.md` 和 `log.md`。其他任何东西都需要 `--overwrite`。
- **`--overwrite`，故意不是 `--force`。** `export site --force` 已经意味着"部署一个脏树"。给一个标志两个含义是有人在尝试发布一个文件夹时删除一个文件夹的方式。
- **`export site` 报告站点实际所在的位置。** 自 v0.40.0 以来，它打印了暂存目录，原子交换在其出口处删除，所以你面前的路径已经消失了。
- **`graph-map --scope org:root` 返回代理树而不是崩溃。** 这是进入代理内存层次结构的唯一入口点，在任何真实项目上，它引发了 `RecursionError`：组织根是一个代理节点，任何未声明的都报告给根，所以根报告给自己，遍历永远不会结束。遍历现在是迭代的，父循环退化而不是使服务器宕机。
- **`distill` 可以服务它存在的目的的代理。** 它对每个有真实历史的代理都失败了：最繁忙的针对 48,000 字符的一次读取限制呈现了 79,445 个字符，截断只能删除索引条目，所以唯一可用的杠杆无法移动重要的数字。限制保持为默认值，因为它保护真实的东西。`--artifact-chars N` 现在是通过它的声明方式，拒绝告诉你要运行的命令。

## 升级

没有什么需要迁移。如果你针对保存不是以前导出的任何东西的目录脚本 `export site`、`export kuzu` 或 `export okf`，该调用现在退出 2 而不是删除它；如果删除是目标，添加 `--overwrite`。
