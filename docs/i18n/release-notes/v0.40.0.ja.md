公開日 **2026-09-11** · [PyPI](https://pypi.org/project/tesserae/0.40.0/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.40.0) · `pip install --upgrade tesserae==0.40.0`

v0.5.0 以降、インクリメンタルコンパイラはオフのフラグの背後で実装されており、実験的なものとしてラベル付けされ、7 つの編集形状に対して証明されたことを示すバイトパリティゲートがありました。このリリースではそのフラグがオンになります。その前に、そのゲートは誠実にする必要がありました。

## 何が起きたか

パリティゲートはインクリメンタルコンパイルをフルコンパイルと比較し、バイト同一であることを確認しました。フルコンパイルをフルコンパイルと比較していました。エッジプロビナンスは正規化前の ID に対して記録されたため、4 ペーパーのフィクスチャでは 8 つの正しいエッジは 4 つのプロビナンス行を持ち、準備チェックは no と答え、すべてのインクリメンタルアームは無言でフルリコンパイルに低下しました。ゲートはビルドレッジャーから `mode == "incremental"` をアサートするようになりました。リマップが修正されてインクリメンタルが実際に実行されると、7 つのテストが失敗しました。すべての 7 つは解決されました。マルチオーナーペイロードは所有者ユニオンを再抽出し、プロデューサー所有のレイヤーは削除および再生成され、名前を変更したファイルはフルコンパイルが折り込むエイリアスを保持し、3 つの減算リークはフルコンパイルが削除するものを保持しました。

実際の 1,422 ファイルコーパスで測定されたとき、正しい所有者ユニオンは編集あたりメディアンで 24 ファイルに接触します。これが「インクリメンタル」が現在コストするものです。

## 何が変わったか

- **`incremental_compile` がデフォルトでオンになった。** デフォルトプロジェクトでの変更のみのコンパイルはインクリメンタルに実行され、レッジャー行はそう述べています。`incremental_compile: false` はフルリコンパイルへのオプトアウトです。
- **ビルドレッジャーはコンパイルのコストを記録するようになった。** 各 `.build-history.jsonl` 行はモード、期間、抽出されたソースの数、フルコンパイルへのダウングレードの理由を含みます。
- **サイドカーが削除される。** `node_memory` と `fact_observed` は調整されることがありませんでした。1 つの 1.19 GB ストアでは、`node_memory` 行の 95% はもう存在しないノードに属していました。フルコンパイルは現在それらを削除し、`doctor` がブロートを報告します。測定：その後 0.42 GB、65% 回収。
- **`tesserae engine --serve` はデーモンからサイトをサーブするようになった。** `tesserae serve` と同じハンドラー（`/api/ask` を含む）が独自のスレッドで実行され、シャットダウン時に明示的なクローザーで停止します。バインド失敗はログに記録され、エンジンはコンパイル継続します。フリートモードはサーブしません。`--serve` は `--once`、`--harvest-only`、`--all` を拒否します。
- **サイトビルドはアトミックスワップです。** コンパイルは `.tesserae/site` を削除して書き直すので、サーブされたページはコンパイルの長さの間 404'd でした。ビルドは今、ステージングディレクトリに着地し、1 つの syscall でライブサイトと交換されます。3 つの再構築中にサーブされたインデックスをハンマーしているリーダーはゼロミスを見ます。古いパスに対してそれは 33,202 を見ました。
- **`tesserae serve` はスレッド化されている。** 1 つの LLM `/api/ask` はもはや背後のすべての静的アセットをブロックしません。
- **失敗した Pages プッシュはもう repo をウェッジしません。** `deploy.py` は作成したワークツリーをすべての終了パスで削除し、最初に古い登録を削除します。
- **`tesserae/frontend.py` は削除されています。** 1 行のリバインドの背後にある 648 行のデッドコード。テストはそれが消えたままであることを保持します。

## アップグレード

アップグレード後の最初の変更のみのコンパイルはインクリメンタルに実行されます。グラフがその後間違っているように見える場合、`tesserae compile` はまだフルコンパイルであり、`.tesserae/config.json` の `incremental_compile: false` は古いデフォルトを復元します。公開は意図的に手動のままです。`deploy` はクリーンなツリーが必要で、`gh-pages` は誰でも読み取り可能なので、デーモンは何もプッシュしません。
