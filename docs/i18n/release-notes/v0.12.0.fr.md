Publié **2026-06-29** · [PyPI](https://pypi.org/project/tesserae/0.12.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.12.0) · `pip install --upgrade tesserae==0.12.0`

Il n'y a plus de « projet actif ». Chaque projet enregistré est en direct en même temps — `ask` s'achemine automatiquement à travers eux, `serve` les sert tous sous un seul site, et `compile` peut maintenant construire la couche de concept LLM que l'extracteur déterministe omet.

## Pas de projet actif — un routeur `ask` intelligent

Le concept de « projet actif » est supprimé : `tesserae projects activate` et l'outil MCP `activate_project` sont supprimés, et chaque commande par projet résout le projet à partir du répertoire dans lequel vous vous trouvez. Tous les projets enregistrés sont égaux.

Un simple `tesserae ask` s'achemine maintenant **automatiquement** :

- nomme un projet → ce projet ;
- comparatif ou général → **fédéré** (une réponse fusionnée et renvoyée croisée sur l'union) ;
- une suite (« et pourquoi ? ») conserve l'acheminement précédent ; un changement de sujet (« qu'en est-il de *autre* ? ») réachemine.

Les cas clairs se résolvent gratuitement ; un arbitre LLM facultatif gère le cas ambigü au milieu, et un court historique par conversation maintient un fil de questions multiples cohérent. `--scope current|all-registered|federated` fonctionne toujours.

## Un serveur pour chaque projet — `tesserae serve`

Un simple `tesserae serve` sert maintenant **chaque projet enregistré** sous un serveur unique : une landing page des projets à `/`, chaque projet à `/<alias>/`, un sélecteur de projets dans l'en-tête, et des vues de session par projet. Le widget ask dans la page fonctionne en direct, acheminé vers le projet de la page qui a demandé. `tesserae serve --project X` sert toujours un seul projet. Les requêtes sont contenues par chemin (aucune évasion du répertoire du site d'un projet) et le point de terminaison ask est une porte même-origine avec un plafond de taille de requête.

## Construire la couche de concept dans `compile` — `--extractor`

`tesserae compile --extractor claude-cli` (ou `--extractor selective-claude --claude-include "<glob>" --claude-limit N`) construit la couche concept/revendication que le défaut déterministe laisse clairsemée — concepts, revendications, capacités, portées de preuves, et bords typés. Il est renforcé pour les corpus réels, où un document bruyant ou lent aurait auparavant annulé une compilation complète :

- un type de bord en dehors du vocabulaire contrôlé est **supprimé**, non fatal ;
- un document qui dépasse le délai d'attente par document **bascule** vers l'extraction déterministe pour ce fichier ;
- une génération invalide transitoire est **réessayée** (le modèle est non-déterministe, donc un rappel valide presque toujours).

## Également dans cette version

- **Compatibilité Cognee 1.0** — Cognee 1.0 a supprimé le type de recherche `INSIGHTS` par défaut de Tesserae, qui a silencieusement brisé le backend ask de Cognee. Il mappe maintenant à `GRAPH_COMPLETION` (répondre sur le graphe de connaissances), donc Cognee fonctionne à nouveau ; passez `--cognee-search-type CHUNKS` pour la récupération brute.
- **`tesserae setup`** — une installation interactive au niveau supérieur à l'échelle machine (fournisseur LLM/effort + dépendances optionnelles à installer) ; les drapeaux ignorent les invites, et les installations fonctionnent dans les environnements `uv tool` sans pip.
- **Docs** — README, démarrage rapide, installation, le guide MCP, carte des fonctionnalités, et les guides d'intégration mis à jour pour ce qui précède (plus de « projet actif »).

## Mise à niveau à partir de v0.11.x

Principalement interchangeable. **Modification majeure :** `tesserae projects activate` et l'outil MCP `activate_project` sont supprimés — les commandes par projet se résolvent par répertoire courant, et `ask` s'achemine automatiquement à travers vos projets. Si vous avez scriptisé `projects activate`, supprimez-le simplement. L'utilisation d'un seul projet est inchangée.
