发布日期 **2026-06-08** · [PyPI](https://pypi.org/project/tesserae/0.6.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.6.0) · `pip install --upgrade tesserae==0.6.0`

Tesserae 0.6.0 是一次 **CLI 重新设计**。引擎所做的一切此前都埋藏在 `tesserae project <26 个隐藏子命令>` 之下，`setup` 多达 29 个标志，`compile` 多达 26 个；直接运行 `tesserae` 会倾倒出一个原始的抽取解析器。0.6.0 用一棵 **扁平动词命令树** 取而代之 —— 日常动词置于顶层，外加少量小型名词分组、分组帮助，以及每条命令都附带 `EXAMPLES`。这是一项 **破坏性变更**，在 1.0 之前刻意为之：旧命令不会悄悄变成别名，而是打印一行 `… has moved → …` 重定向并以退出码 2 结束，因此迁移一目了然，而非令人摸不着头脑。引擎、图、MCP 工具以及 `tesserae_mcp` 服务器均未改动 —— 本次发布完全只关乎人类所键入的那层表面。

## 1. 全新的命令树

```
tesserae <command>

EVERYDAY    init compile context ask serve status
AUTOMATION  engine refresh research
ANALYSIS    query lint
GROUPS      sessions vault export code config projects integrations extract
LAB         lab
```

- **日常动词位于顶层。** `tesserae compile`、`tesserae serve`、`tesserae ask`、`tesserae context "…"` —— 不再有 `project` 前缀。
- **`status`** 是一项新增的只读摘要（节点/边数量、上次编译、vault、站点）。
- **`serve`** 在站点缺失或过期时会自动构建（用 `--no-build` 跳过）。
- **专用命令归入小型名词分组：** `sessions import|discover|list`、`vault sync|export|prune|set-root|sync-all`、`export harness|graphiti|site`、`code ingest|sync`、`config llm|show`、`projects register|list|activate|unregister|mcp-config`、`integrations refresh <name>`、`extract`、`lab evolve|schema-drift`。
- **`export site`** 收纳了旧的 `build-site`、`deploy`（`--deploy`）和 `watch`（`--watch`）等动词。
- **分组的根帮助 + `EXAMPLES`** —— 不带参数运行 `tesserae` 会显示分组树；每条命令的 `--help` 都以真实、可运行的示例结尾。

## 2. 瘦身后的 `init` 与 `compile`

- **`init`：29 → 8 个标志。** 默认采用向导方式；`--yes` 以非交互方式运行（可选集成 —— Cognee、RAG-Anything、Understand-Anything —— 默认 **关闭**，并且在非 TTY 环境下颜色会自动禁用，从而涵盖了旧的 `--no-color`/`--no-cognee`/`--skip-*` 标志）。`--bare` 不经向导直接写入工作区。LLM 后端标志（`--llm-provider`、`--claude-config-dir`、`--codex-home`）保留。
- **`compile`：26 → 8 个标志。** 日常标志保留（`--changed-only`、`--no-sessions`、`--limit`、`--refresh-integrations`、三个 LLM 标志，以及临时的 `compile <paths>`）。每一个被移除的集成开关（kuzu/cognee/trends/vault-pull/…）都迁移到了 `.tesserae/config.json` 中的 **`compile_options`** 块，名称不变，且其旧默认值得以保留 —— 因此行为完全一致，只是表面变得安静了。完整的 `compile_options` 表请参见[快速上手](../quickstart.md)。

## 3. 干净利落的迁移 —— 没有悄悄的别名

每一次旧式调用都会精确打印一行并以退出码 2 结束：

```
$ tesserae project compile
tesserae project compile has moved → tesserae compile
```

该重定向表覆盖了所有旧命令（包括像 `project sessions import` 这样的三段式形式，以及旧的 `wiki`/`llm-defaults` 顶层命令），而一个裸的 markdown 路径（`tesserae notes/x.md`）会把你指向 `tesserae extract`。钩子、CI 冒烟测试、发布流程，以及仓库内所有运行时字符串都同步完成了迁移；文档与全部八个 README（外加每一份本地化副本）如今都讲着这棵新树的语言。

## 从 v0.5.0 升级

- **重新熟悉你用于脚本的那些动词。** 最常见的替换：`project setup --yes …` → `tesserae init --yes`，`project compile` → `tesserae compile`，`project build-site` → `tesserae export site`，`project serve` → `tesserae serve`，`project obsidian-sync` → `tesserae vault sync`，`project sync-code` → `tesserae code sync`，`tesserae llm-defaults …` → `tesserae config llm …`，`tesserae wiki …` → `tesserae projects …`。把某条命令的旧形式运行一次 —— `… has moved → …` 消息会告诉你新的写法。
- **挪动了某个 `compile` 标志？** 如果你在脚本里写了 `compile --trends`、`--no-vault-pull`、`--cognee-*` 等，请改为在 `.tesserae/config.json` 中设置对应的 `compile_options.<key>`（表格见快速上手）。
- **`init` 的集成标志已从 CLI 中移除。** 要启用 Cognee / RAG-Anything / Understand-Anything，请回答 `tesserae init` 向导的提示，或者编辑 `.tesserae/config.json` 后运行 `tesserae integrations refresh <name>`。
- 关于**图、vault、站点、MCP 工具或 `tesserae_mcp` 服务器**，没有任何改动 —— 改变的只有面向人类的 CLI。
