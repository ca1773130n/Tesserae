Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

このリリースには三つの変更が入ります。求めない限りソースコードは索引されなく
なります。書かれ、テストもされていながら到達できなかった検索面が開きます。
そしてグラフに組織図が加わり、汎用エージェントを一つの領域に向けて専門家として
働かせられるようになります。

## ソースコードは「頼むもの」になりました

これまでは、プロジェクトがリポジトリのように*見える*だけでコードレイヤーを
構築していました（`kind` が `CodeProject` / `Repository` / `Project`）。それは
プロジェクトが何であるかの説明であって、所有者がソースを解析してほしいと言った
わけではありません。抜け道は種別を偽ることだけでした。

コストは誰も見ない場所に溜まりました。`graph.json` はリサーチ分割だけを持つため
コードノードは**ゼロ**に見える一方、SQLite 射影と生成ページにはおよそ 22 万行と
22 万ページがありました。設定した覚えのない項目にその費用を結びつける人はいま
せん。メンテナ自身のマシンでは、その機能を切ってあるプロジェクトに 327MB の
成果物が残っていました。

いまはプロジェクトが自ら求めます:

```json
"external_tools": [{"id": "codegraph"}]
```

エントリがなければオフです。プロジェクト種別は一切参照しません。二つ目の
スイッチを作るのではなく、RAG-Anything 連携がすでに読んでいる形を再利用します。

**メンテナンスも同じゲートに従います。** 放っておけば漏れるのはこちら側です。
二つの sync-code フックは、自分自身の `sync_code_on_*` 設定より*先に*オプトイン
を確認します。したがってそれらの設定は、すでに与えられた許可を狭めることしか
できず、許可を生み出すことはできません。ディスク上に CodeGraph データベースが
あることは同意ではありません — エージェントが自分の用途で `codegraph init` を
実行しただけで、Tesserae が 30 秒ごとに追跡すべきかについての意思表示では
ありません。

`code-graph.json` はスイッチに両方向で従います。有効なら書き、無効なら削除
します。残されたファイルにはタイムスタンプがなく、すでに動いたリポジトリの
スナップショットで応答し続けます。

削除されたものはありません。CodeGraph アダプタ、抽出器、キャッシュ、`tesserae
code ingest|sync` はすべてスイッチの背後に残っています。

## ずっとあった検索ノブ

`facts_as_of` — 「その日グラフは何を信じていたか」を問うバイテンポラルクエリ —
は書かれており、バイト単位で冪等で、七つのテストに覆われていながら、呼び出し元が
**ゼロ**でした。`personalized_pagerank` はすでに `edge_type_weights` を尊重して
いました。`compile_context` は 16 個の引数を取り、MCP サーバーは 7 個しか渡して
いませんでした。Tesserae はバイテンポラリティとビュー選択的走査を持ちながら、
そのどちらも要求できませんでした。

いまは要求できます。`search_facts` と `timeline` の `as_of`、そして返された行の
うち日付を持たないものが何件かを伝える `undated_included`。`compile_context` の
`strategy`、`scope`、`edge_type_weights`、`tame_hubs`、`recency_weight`。

`as_of` と `current_only` の併用は意図的に拒否されます。両者は異なる時計を表し、
過去のある時点で何が真だったかを尋ねたとき、後に置き換えられたという理由で黙って
空を返してはならないからです。

## グラフの上の組織図

`tesserae domains status` は、知識グラフの上に築かれた構造を示します。コミュニ
ティから導かれた部門、ある領域のブリーフがエージェントの一度に読める量を超えた
ときの再帰的な分割、そして再編を越えて生き残る同一性 — エージェントに固定した
スラッグは、グラフが動いたあとでも解決します。

これは土台です。これを使うルーティングは次に入ります。

## インジェストは、やっていない仕事を成功と報告しなくなります

これまでの `tesserae ingest paper.pdf` は、ファイルをコピーし、`.md` しか読まない
ウォーカーでコンパイルを回し、コーパスの残りから得たノード数を表示していました。
この経路には「PDF を取り込んだ」と「何も取り込まなかった」を区別できるものが一つも
ありませんでした。PDF の入ったディレクトリも同じで、表示される `processed=1` は
ディレクトリを数えたものでした。

いまはファイル単位で拒否し、実行できる対処法を添えます:

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

URL の取得も厳しくなりました。以前は PDF の URL をテキストとしてデコードし、`.md`
拡張子で書き込み、文字化けに対してハッシュを取っていました。その結果ウォーカーが
それを散文として抽出器に渡していました。バイトがバイナリだと示す本文、宣言型が
バイナリの本文、そして読めるテキストのない 200 応答は、すべて拒否されます。

新しい `INTERVAL_COVERAGE` リントは、グラフのどれだけを時間上に置けるかを報告します。
このプロジェクト自身のグラフでは **103,705 件のファクトのうち 76,095 件 (73.4%) に
`valid_from` がなく**、`timeline()` では文字列 "undated" の下に並びます。`info`
レベルで報告し、`--strict` を失敗させません。下限を決めるには現在のコーパスから得た
数字が要りますが、まだそうではないからです。

セッション取り込みは、読めないコンテンツブロックを黙って捨てるのではなく数えます。
実際のトランスクリプト 150 件で **これまで見えていなかった画像ブロック 9 件** が
現れました。それらは `tool_result` の中に入れ子になっており、以前のカウンターは
そこを見たことがありませんでした。

## アップグレード

```bash
pip install --upgrade tesserae==0.30.0
```

Claude Code プラグインとして Tesserae を動かしている場合、**フックのゲートは
このバージョンのプラグインを入れて初めて効きます** — 以前のプラグインの複製は
CodeGraph データベースの有無しか見ておらず、オプトインを認識できません。それ
までは `.claude/tesserae.local.md` の `sync_code_on_edit: false` と
`sync_code_on_start: false` が、それらのフックが理解するスイッチです。

既存プロジェクトはそのまま動きます。コードレイヤーを戻したいプロジェクトは上の
`external_tools` エントリを足すだけで、不要なプロジェクトは何も変えずに、より
小さなグラフと小さなデータベースを得て、コードページは生成されなくなります。
