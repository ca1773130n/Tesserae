Выпущено **2026-07-09** · [PyPI](https://pypi.org/project/tesserae/0.17.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.17.0) · `pip install --upgrade tesserae==0.17.0`

Этот релиз воплощает лучшие идеи из глубокого сравнения с двумя родственными LLM-wiki проектами — [alfadur7/llm-wiki-newsroom](https://github.com/alfadur7/llm-wiki-newsroom) и [langchain-ai/openwiki](https://github.com/langchain-ai/openwiki) — каждая идея проверена на соответствие тому, что уже было в Tesserae перед внедрением. Лейтмотив: **то, что потребляют агенты, теперь корректно, свежо и обнаружимо по построению.**

## Скомпилированный контекст перестаёт цитировать проигравшие

`compile_context` теперь исключает устаревшие узлы и проигравшие в арбитраже по умолчанию (`include_superseded=True` восстанавливает их). Утверждение, которое проиграло LLM-арбитражу, ранее цитировалось так же, как победитель; общий вспомогательный метод `superseded_ids()` теперь подавляет или отмечает эти случаи согласованно в `search_nodes`, `fresh_insights` и `node_context`. Страницы синтеза дополнительно проверяют каждую ссылку на соответствие фактическим ID входных узлов — поддельный ID теперь не проходит валидацию и возвращается к детерминированному телу.

## Двусторонний шлюз публикации

Lint выполняется безопасно для сбоев в конце **каждой компиляции**, поэтому `lint-report.md` всегда свежий. `tesserae compile --strict` преобразует результаты в ненулевой код выхода для CI — и **закрывается** ошибкой, если сам lint падает. Дополнительный флаг `lint --verify-claims` идёт дальше: он проверяет с помощью LLM, действительно ли цитируемые узлы *поддерживают* цитирующее предложение (ограничено, детерминировано семплируется, никогда не блокирует компиляцию).

## Шлюз снимка вывода

После каждой компиляции Tesserae хеширует скомпилированные артефакты и сообщает `Output: changed/unchanged`. В режиме `--strict` *подозрительное* состояние — входные данные не изменились, но вывод изменился — отказывает сборку: постоянное срабатывание для класса ошибок байтовой идемпотентности. Готовый к копированию рабочий процесс обновления CI находится в `docs/integrations/ci-refresh.md`.

## Агенты находят базу знаний самостоятельно

`tesserae setup` теперь устанавливает разделённый маркерами **блок указателя Tesserae** в `AGENTS.md`/`CLAUDE.md` целевого репозитория (идемпотентен; оставляет без изменений при неправильных или дублирующихся маркерах; сосуществует с другими управляемыми блоками). Корневой `index.md` вики переписан как **точка входа для агентов**: ориентация, раздел «как запрашивать» с приоритетом MCP, таблица типов и топовые сообщества. Страницы сообществ получают детерминированный подвал `## Sources`, перечисляющий файлы исходников-членов.

## Компиляция становится дешевле, а устаревание становится видимым

Слой графа кода теперь хранит **кэш извлечения целого слоя** (`.tesserae/code-graph-cache.json`): когда манифест статистики исходного дерева не изменён, кэшированный граф регидратирует байт-идентично вместо полной прогулки переизвлечения (десятки секунд на больших репозиториях). CLI сообщает о переиспользованных данных или дельта-счётчиках `+added ~changed -removed`. История сборки записывает git HEAD на момент компиляции, и lint выдаёт информационные находки для узлов code-graph, чьи исходные файлы изменились с тех пор — плюс страница `contradictions.md` вики теперь отслеживает открытые/разрешённые/устаревшие конфликты утверждений, и `graph_ppr` получает `exclude_direct_neighbors` для поиска неожиданных соединений в стиле Memex.

Кэши сводки сообществ также инвалидируют по дайджестам *содержимого* членов (не только по членству), поэтому изменённое описание переконструирует резюме вместо того, чтобы вечно подавать устаревший нарратив.

## Рекомендации по обновлению

- Первая компиляция после обновления сообщает `Output: changed` один раз (страницы сообществ получают разделы Sources, `index.md` становится точкой входа); последующие компиляции байт-стабильны.
- `tesserae setup` (включая `--yes`) устанавливает указатель агента по умолчанию; установите `install_agent_pointer=false` в плане для отказа.
