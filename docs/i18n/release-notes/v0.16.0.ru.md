Страница sessions в `tesserae serve` больше не ожидает следующей компиляции. Теперь она читает вашу **активную** деятельность агента прямо из корней harness — так что сеанс, в котором вы находитесь *прямо сейчас*, отображается по мере вашей работы.

## Активные сеансы на странице serve

Когда вы запускаете `tesserae serve`, страница Sessions получает новую конечную точку **`/api/sessions`**, которая сканирует ваши корни Claude Code на лету (ограниченные недавними окнами) и выводит текущие активные сеансы над скомпилированной таблицей — ID сеанса, аккаунт, количество ходов, время последней активности и предпросмотр открывающегося хода. Если открыть статическую сборку (GitHub Pages), панель просто останется скрытой: скомпилированная таблица — это вся страница, как и прежде.

Поле **быстрого поиска по стенограммам** становится активным таким же образом: свежие результаты, отсканированные из корней, объединяются *перед* результатами индекса memex (дедублированы), поэтому фраза, которую вы напечатали несколько мгновений назад, можно найти до того, как она будет когда-либо проиндексирована.

Обе поверхности **защищены origin-сторожем** — они раскрывают локальную историю, поэтому кросс-сайтовый запрос браузера отклоняется, как и у конечной точки clip.

### Почему только Claude, и как codex остается покрытым

Стенограммы Claude Code привязаны к каталогу, поэтому сканирование в реальном времени на каждый проект выполняется за доли секунды. Сеансы Codex — нет — ограничение одним проектом означало бы синтаксический анализ каждого недавнего файла сеанса (100 тыс.+ на занятой машине, ~170 с на запрос), что намного медленнее для интерактивной страницы. Таким образом, сканирование в реальном времени **только Claude**; codex обслуживается из индекса memex и скомпилированной проекции, как и раньше. Офлайн-команды `tesserae summary` и `tesserae decisions` по-прежнему сканируют **все** аккаунты — Claude и codex — потому что они могут позволить себе полный проход.

## `--max-turns` в summary и decisions

`tesserae summary` и `tesserae decisions` получают флаг `--max-turns N`, который ограничивает количество ходов, читаемых на сеанс перед windowing. Удобно для ограничения стоимости большого сеанса, когда вам нужен только недавний фрагмент. По умолчанию остается фактически неограниченным.

```bash
tesserae summary --day 2026-07-06 --max-turns 200
tesserae decisions --week --max-turns 200
```

## Обновление

Можно заменить v0.15.x. Все является дополнительным — активные конечные точки существуют только под `tesserae serve`, страница корректно деградирует при статическом хостинге, и ничего не требует миграции или перекомпиляции. Она читает ваши существующие сеансы в реальном времени.
