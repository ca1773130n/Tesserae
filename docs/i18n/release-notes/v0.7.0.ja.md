リリース日 **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.0) · `pip install --upgrade tesserae==0.7.0`

`tesserae ask` は、**すでにログイン済みの CLI** の上で実際の回答を合成するようになりました — `ANTHROPIC_API_KEY` は不要です — そしてマシン上のすべてのアカウントを巡回するため、レート制限によって止まることがありません。さらに、*問い合わせる対象*のセッションを検索可能にする 2 つの修正と、もはや中断しないコンパイルが加わります。

## 1. `tesserae ask` が claude/codex CLI の上で合成します — API キー不要

これまで `tesserae ask` は、`ANTHROPIC_API_KEY` を必要とする Anthropic SDK 経由でしか回答を書けませんでした。一般的なセットアップ — `claude` または `codex` CLI に OAuth でログインした状態 — を使っている場合、`ask` は黙って `(no LLM answer: LLM disabled)` 付きの生の検索ヒットへと劣化していました。

いまや回答パスは、JSON 抽出器がすでに使っているのと同じ OAuth クライアントを再利用します。`tesserae ask --llm "<question>"`（または `TESSERAE_QUERY_LLM=1`）は **API キーゼロ**で出典付きの回答を合成します — エンジンの他の部分が掲げているのとまさに同じ、キー不要の約束どおりです。

## 2. マシン上の**すべての**アカウントを巡回します

CLI クライアントは、すべての `~/.claude*` 設定ディレクトリと、すべての `~/.codex*` ホームを、すでに自動検出しています。v0.7.0 は `ask` がこれを使うようにし — さらにそれを*プロバイダ*をまたいで連鎖させます。問い合わせが諦めるのは、**すべての**アカウントが尽きたときだけです。

実際には次のとおりです。あなたの Claude アカウントがすべて Sonnet／週次の上限に達している状態で、実際の `tesserae ask --llm` はそれらを巡回し、続いて **Codex へフォールスルー**して回答します（`model=cli-oauth`）— キーも、手動でのアカウント切り替えも不要です。レート制限中またはログアウト済みのアカウントはスキップされ、致命的にはなりません。

## 3. 修正: セッションタイトルがもはやハーネスの前置きに潰れません

Codex はすべてのトランスクリプトの先頭に `# AGENTS.md instructions for <path>` を付加するため、セッションタイトルのヒューリスティックが*それ*を**すべての**セッションのタイトルとして取り込んでしまい — キーワード検索は、まったく同じスコアの、見分けのつかない定型文の壁を返していました。タイトルはいまや、注入された AGENTS/CLAUDE/GEMINI.md の前置き（およびシステムのラッパー）をスキップし、あなたの実際の最初の指示から取られます。`ask` は再び、互いに区別でき、関連性のあるヒットを返します。

これに 2 つの小さめの `ask` 修正が相乗りしています。LLM ゲート（`--llm` / `TESSERAE_QUERY_LLM`）が wiki 検索パスでも尊重されるようになり（以前はハード無効化されていました）、`--backend auto` がより高機能なバックエンドのエラー（例: cognee の認証失敗）によりフォールバックする際には、wiki が試された唯一のバックエンドであるかのように黙って見せるのではなく、そのことを明示するようになりました。

## 4. 修正: 古いキャッシュ参照でコンパイルが中断しなくなりました

完全な `tesserae compile` / `refresh` が `KeyError: 'CodeFunction:…'` — もはや存在しないコードノード id — で失敗することがありました。セッション findings は*抽出*時にドキュメントグラフに対して参照をフィルタリングしますが、findings はチャンク単位でキャッシュされます。参照先ノードの id が後で変化したり（例: コードが編集されると content-hash の id がずれるコード関数）、消失したりすると、キャッシュされた finding が**古い**参照を再生し、下流の code-graph ステップを壊すダングリングノードを捏造していました。参照はいまやマージ時にライブグラフに対して再検証されます — ターゲットがまだ存在すればリンクし、存在しなければ破棄します。

## v0.6.1 からのアップグレード

ドロップインです。`ask` から API キーなしで回答を得るには、`claude` または `codex` CLI にログインした状態で `--llm` を渡すだけです。コンパイルの `KeyError` に遭遇していたなら、`tesserae compile`（または `refresh`）を再実行してください — いまや中断する代わりに古い参照をスキップします。
