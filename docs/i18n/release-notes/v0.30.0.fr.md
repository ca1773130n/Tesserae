Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

Trois choses arrivent ici. Le code source cesse d'être indexé sauf demande
explicite. Une surface de récupération écrite, testée et inatteignable devient
atteignable. Et le graphe gagne un organigramme, pour qu'un agent généraliste
puisse être pointé sur un domaine et y agir en expert.

## Le code source est désormais quelque chose que l'on demande

Tesserae construisait une couche de code dès qu'un projet *ressemblait* à un
dépôt — `kind` valant `CodeProject`, `Repository` ou `Project`. C'est une
description de ce qu'un projet est, pas une déclaration que son propriétaire
voulait voir ses sources analysées. La seule sortie était de mentir sur le type.

Le coût s'accumulait là où personne ne regarde. `graph.json` porte la partition
recherche, il affichait donc **zéro** nœud de code pendant que la projection
SQLite et les pages générées en portaient environ 220 000 lignes et 220 000
pages. Personne n'impute cela à un réglage qu'il n'a jamais activé. Sur la
machine du mainteneur, cela représentait 327 Mo d'artefacts pour une
fonctionnalité que ce projet avait désactivée.

Désormais le projet le demande :

```json
"external_tools": [{"id": "codegraph"}]
```

L'absence vaut désactivation. Le type de projet n'est pas consulté du tout. On
réutilise ici la forme que l'intégration RAG-Anything lit déjà, plutôt que
d'inventer un second interrupteur.

**La maintenance suit la même barrière**, et c'est la moitié qui fuirait sinon.
Les deux hooks sync-code vérifient l'activation *avant* leur propre réglage
`sync_code_on_*` ; ceux-ci ne peuvent donc que restreindre une permission déjà
accordée, jamais la créer. Une base CodeGraph sur le disque n'est pas un
consentement : un agent a pu lancer `codegraph init` pour ses propres besoins
sans avoir d'avis sur la question de savoir si Tesserae doit la suivre toutes les
30 secondes.

`code-graph.json` suit l'interrupteur dans les deux sens : écrit quand c'est
activé, supprimé sinon. Un fichier résiduel ne porte aucun horodatage et continue
de répondre avec l'instantané d'un dépôt qui a depuis changé.

Rien n'a été supprimé. L'adaptateur CodeGraph, l'extracteur, le cache et
`tesserae code ingest|sync` sont toujours là, derrière l'interrupteur.

## Les molettes de récupération qui étaient là depuis toujours

`facts_as_of` — requête bitemporelle, « que croyait le graphe à cette date » —
était écrite, idempotente à l'octet près et couverte par sept tests, avec
**zéro** appelant. `personalized_pagerank` honorait déjà `edge_type_weights`.
`compile_context` prenait seize paramètres et le serveur MCP en transmettait
sept. Tesserae disposait de la bitemporalité et du parcours sélectif par vue, et
ne pouvait demander ni l'un ni l'autre.

Maintenant si. `as_of` sur `search_facts` et `timeline`, avec `undated_included`
indiquant combien des lignes reçues ne portent aucune date. `strategy`, `scope`,
`edge_type_weights`, `tame_hubs` et `recency_weight` sur `compile_context`.

`as_of` et `current_only` sont refusés ensemble, délibérément : ils expriment des
horloges différentes, et demander ce qui était vrai à une date passée ne doit pas
renvoyer le silence parce que la réponse a été remplacée depuis.

## Un organigramme au-dessus du graphe

`tesserae domains status` présente une structure bâtie sur votre graphe de
connaissances : des divisions dérivées de ses communautés, une division récursive
quand le résumé d'un domaine dépasse ce qu'un agent peut lire d'un coup, et des
identités qui survivent à une réorganisation — le slug que vous avez épinglé à un
agent se résout encore après que le graphe a bougé.

C'est le substrat. Le routage qui s'en sert arrive ensuite.

## L'ingestion cesse d'annoncer un succès pour un travail non fait

Auparavant, `tesserae ingest paper.pdf` copiait le fichier, lançait une compilation dont
le parcours ne lit que le `.md`, et affichait des comptes de nœuds venant du reste du
corpus. Rien sur ce chemin ne distinguait « j'ai ingéré votre PDF » de « je n'ai rien
ingéré ». Un répertoire de PDF se comportait pareil, et le `processed=1` affiché comptait
le répertoire.

Il refuse désormais, fichier par fichier, avec un remède exécutable :

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

La récupération d'une URL est plus stricte aussi. Une URL de PDF était décodée comme du
texte, écrite sous un suffixe `.md` et hachée sur le mojibake — le parcours la passait
ensuite à l'extracteur comme de la prose. Un corps que les octets disent binaire, un
corps dont le type déclaré est binaire, et un 200 sans texte lisible sont maintenant
refusés.

Un nouveau lint `INTERVAL_COVERAGE` indique quelle part du graphe peut être située dans
le temps. Sur le graphe de ce projet : **76 095 faits sur 103 705 (73,4 %) ne portent pas
de `valid_from`**, et se rangent donc sous la chaîne littérale « undated » dans
`timeline()`. Il rapporte au niveau `info` et ne fait pas échouer `--strict` ; fixer un
seuil demande un chiffre issu d'un corpus à jour, ce qui n'est pas encore le cas.

L'import de sessions compte les blocs de contenu qu'il ne sait pas lire au lieu de les
jeter en silence. Sur 150 transcriptions réelles, cela a révélé **9 blocs image
auparavant invisibles** : ils sont imbriqués dans `tool_result`, là où l'ancien compteur
n'a jamais regardé.

## Mise à niveau

```bash
pip install --upgrade tesserae==0.30.0
```

Si vous utilisiez Tesserae comme plugin Claude Code, **la barrière des hooks ne
prend effet qu'une fois le plugin de cette version installé** : les copies
antérieures ne regardent que l'existence d'une base CodeGraph et ne voient pas
l'activation. D'ici là, `sync_code_on_edit: false` et `sync_code_on_start: false`
dans `.claude/tesserae.local.md` sont l'interrupteur que ces hooks comprennent.

Les projets existants continuent de fonctionner. Celui qui veut retrouver sa
couche de code ajoute l'entrée `external_tools` ci-dessus ; celui qui n'en veut
pas obtient un graphe plus petit, une base plus petite et aucune page de code,
sans rien changer.
