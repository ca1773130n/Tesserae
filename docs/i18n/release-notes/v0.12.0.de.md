Freigegeben **2026-06-29** · [PyPI](https://pypi.org/project/tesserae/0.12.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.12.0) · `pip install --upgrade tesserae==0.12.0`

Es gibt kein „aktives Projekt" mehr. Jedes registrierte Projekt ist sofort aktiv — `ask` leitet sich selbst über sie weiter, `serve` serviert sie alle unter einer Site, und `compile` kann nun die LLM-Konzeptschicht erstellen, die der deterministische Extractor auslässt.

## Kein aktives Projekt — ein intelligenter `ask`-Router

Das Konzept des „aktiven Projekts" ist weg: `tesserae projects activate` und das `activate_project` MCP-Tool sind entfernt, und jeder projektbezogene Befehl löst das Projekt vom Verzeichnis auf, in dem Sie sich befinden. Alle registrierten Projekte sind gleich.

Ein einfaches `tesserae ask` leitet sich nun selbst weiter:

- benennt ein Projekt → das Projekt;
- vergleichend oder allgemein → **Verbundform** (eine zusammengefasste, Cross-referenzierte Antwort über die Vereinigung);
- eine Nachfrage („und warum?") behält die vorherige Route bei; eine Themenverschiebung („was ist mit *anderem*?") leitet neu weiter.

Die klaren Fälle werden kostenlos gelöst; ein optionaler LLM-Tiebreaker handhabt die echte mehrdeutige Mitte, und eine kurze Gesprächshistorie pro Konversation hält einen Thread mit mehreren Fragen kohärent. Explizit `--scope current|all-registered|federated` funktioniert weiterhin.

## Ein Server für jedes Projekt — `tesserae serve`

Ein einfaches `tesserae serve` serviert nun **jedes registrierte Projekt** unter einem einzelnen Server: ein Projekte-Landing auf `/`, jedes Projekt auf `/<alias>/`, ein Projekte-Umschalter in der Kopfzeile und projektbezogene Sitzungsansichten. Das Frage-Widget auf der Seite funktioniert live und wird an das Projekt der anfragenden Seite weitergeleitet. `tesserae serve --project X` serviert weiterhin ein einzelnes Projekt. Anfragen sind pfadgebunden (kein Escape aus dem Site-Verzeichnis eines Projekts) und der Ask-Endpunkt ist gleichursprungsgesperrt mit einer Anfragegrößenbegrenzung.

## Erstelle die Konzeptschicht in `compile` — `--extractor`

`tesserae compile --extractor claude-cli` (oder `--extractor selective-claude --claude-include "<glob>" --claude-limit N`) erstellt die Konzept-/Anspruchsschicht, die der deterministische Standard spärlich hinterlässt — Konzepte, Ansprüche, Fähigkeiten, Beweisumfang und typisierte Kanten. Es ist für echte Korpora gehärtet, wo ein lautes oder langsames Dokument früher eine ganze Kompilierung abgebrochen hätte:

- ein Kantentyp außerhalb des kontrollierten Vokabulars wird **gelöscht**, nicht tödlich;
- ein Dokument, das das pro-Dokument-Timeout überschreitet, **fällt zurück** auf deterministische Extraktion für diese Datei;
- eine vorübergehende ungültige Generierung wird **erneut versucht** (das Modell ist nicht-deterministisch, daher validiert ein erneuter Aufruf fast immer).

## Auch in dieser Version

- **Cognee 1.0-Kompatibilität** — Cognee 1.0 hat den `INSIGHTS`-Suchtyp entfernt, auf den Tesserae standardmäßig zurückfiel, was das Cognee `ask`-Backend stillschweigend unterbrach. Es wird nun auf `GRAPH_COMPLETION` abgebildet (Antwort über den Wissensgraph), sodass Cognee erneut funktioniert; übergeben Sie `--cognee-search-type CHUNKS` für unverarbeitete Abfrage.
- **`tesserae setup`** — eine Top-Level-Einrichtung auf Maschinenebene (LLM-Provider/Aufwand + welche optionalen Abhängigkeiten installiert werden); Flags überspringen die Eingabeaufforderungen, und Installationen funktionieren in pip-losen `uv tool`-Umgebungen.
- **Docs** — README, Schnellstart, Installation, der MCP-Leitfaden, Feature-Map und die Integrationsleitfäden sind oben aktualisiert worden (kein „aktives Projekt" mehr).

## Upgrade von v0.11.x

Überwiegend ausfallsicher. **Bruchänderung:** `tesserae projects activate` und das `activate_project` MCP-Tool sind entfernt — projektbezogene Befehle werden nach dem aktuellen Verzeichnis aufgelöst, und `ask` leitet sich automatisch über Ihre Projekte weiter. Wenn Sie `projects activate` skriptiert haben, löschen Sie es einfach. Die Verwendung eines einzelnen Projekts bleibt unverändert.
