Released **2026-07-06** · [PyPI](https://pypi.org/project/tesserae/0.16.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.16.0) · `pip install --upgrade tesserae==0.16.0`

`tesserae serve` 세션 페이지는 더 이상 다음 컴파일을 기다리지 않습니다. 이제 harness roots에서 직접 **실시간** 에이전트 활동을 읽으므로, 지금 진행 중인 세션이 작업하면서 즉시 표시됩니다.

## serve 페이지의 실시간 세션

`tesserae serve`를 실행하면 세션 페이지가 새로운 **`/api/sessions`** 엔드포인트를 가져와서 Claude Code roots를 즉시 스캔하고(최근 윈도우 범위 내에서) 현재 활성 세션을 컴파일된 테이블 위에 렌더링합니다 — 세션 ID, 계정, 턴 수, 마지막 활성 시간 및 시작 턴의 미리보기. 대신 정적 빌드(GitHub Pages)를 열면 패널은 간단히 숨겨집니다: 컴파일된 테이블이 전체 페이지이고, 이전과 정확히 같습니다.

**빠른 기록 검색** 상자도 같은 방식으로 실시간으로 작동합니다: roots에서 스캔한 새로운 히트가 memex 인덱스 결과보다 *먼저* 병합되므로(중복 제거), 몇 순간 전에 입력한 구문이 인덱싱되기 전에도 찾을 수 있습니다.

두 서피스 모두 **origin-gated**입니다 — 로컬 히스토리를 노출하므로 크로스 사이트 브라우저 요청은 클립 엔드포인트와 동일하게 거부됩니다.

### Claude 전용인 이유 및 codex가 지원되는 방식

Claude Code 기록은 디렉터리 범위이므로 실시간 프로젝트별 스캔은 1초 미만입니다. Codex 세션은 그렇지 않습니다 — 한 프로젝트로 범위를 지정하면 모든 최근 세션 파일을 구문 분석해야 하므로(바쁜 컴퓨터에서 100k 이상, 요청당 약 170초), 대화형 페이지에는 너무 느립니다. 따라서 실시간 스캔은 **Claude 전용**입니다; codex는 memex 인덱스와 컴파일된 프로젝션에서 제공됩니다. 오프라인 `tesserae summary` 및 `tesserae decisions` 명령은 여전히 **모든** 계정(Claude 및 codex)을 스캔합니다. 왜냐하면 전체 스캔을 감당할 수 있기 때문입니다.

## summary 및 decisions의 `--max-turns`

`tesserae summary` 및 `tesserae decisions`는 윈도우 전에 세션당 읽는 턴 수를 제한하는 `--max-turns N` 플래그를 얻습니다. 큰 세션의 비용을 제한하되 최근 슬라이스만 필요할 때 유용합니다. 기본값은 실질적으로 무제한입니다.

```bash
tesserae summary --day 2026-07-06 --max-turns 200
tesserae decisions --week --max-turns 200
```

## 업그레이드

v0.15.x에 그대로 업그레이드하세요. 모든 것이 추가적입니다 — 실시간 엔드포인트는 `tesserae serve` 아래에만 존재하고, 페이지는 정적 호스팅에서 깔끔하게 저하되며, 마이그레이션이나 재컴파일이 필요하지 않습니다. 기존 세션을 즉시 읽습니다.
