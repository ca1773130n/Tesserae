リリース **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1はクライアントビルダーを修正した。3つの呼び出しサイトはそれ自体のAnthropicSDK
クライアントを構築し、その修正の影響を受けなかったため、依然として`api.anthropic.com`に
ハードコードされたモデルで呼び出していた一方で、他のすべてのパスはプロジェクトに
設定されたエンドポイントを尊重していた。このリリースがそれらを閉じる。

## 3つのパス

- **`query --llm`** はAPIキーのみでクライアントを構築し — `base_url`なしで —
  メソッドのデフォルト`claude-sonnet-4-6`を送信していた。
- **散文合成**(`TESSERAE_SYNTHESIS_LLM=1`)も同じことをしたため、カスタムエンドポイントを
  設定したプロジェクトの要約はAnthropicに書かれていた。
- **`synthesis`** は`TESSERAE_SYNTHESIS_MODEL`またはリテラルからモデルを選び、
  `llm_model`からは選ばなかった。ウィキストアではなくプロジェクトルートを持つため、
  ルートは今`ProjectPaths`が既に定義している方法で導出されている。

## 配布されたパッケージを実際のエンドポイントに対して実行して見つかった3つ以上

0.37.1をPyPIからクリーンな環境にインストールし、ライブのOpenAI互換サーバを指していた。
動作した — そしてコードを読むだけでは明かされない3つのことを明かした:

- **可用性の障害が曖昧だった。** クライアントが既にどちらなのかを分類していたのに、
  「rate-limited / auth / unsupported model」と言っていた。今は
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`と読む。
- **`tesserae config status`がプロバイダのソースを`default`として報告していた。**
  プロジェクト設定から来ていたとしても。プロバイダはソース記録ヘルパーよりも前に
  解決されるため、そのレイヤーは記録されたことがなかった。
- **`tesserae setup`が`llm_claude_model`と`llm_claude_config_dir`を読んでいた** —
  誰も書かない単数キー。すべてのライターが`llm_model`と複数形`llm_claude_config_dirs`を
  使うため、ウィザードは設定をまったく見なかった。

## テスト

カスタムプロバイダテストは`importorskip("anthropic")`でゲートされていた —
プロバイダが壊れていたまさにそのベースインストールでスキップされていた。`openai`ワイヤには
SDKが不要なため、新しいカバレッジはスキップできず、1つのテストが`anthropic`インポートを
完全にブロックしてそれを証明する。

## アップグレード

移行するものはない。カスタムエンドポイントを設定し、`ask`と`compile`はそれを尊重しているのに
`query --llm`または合成は尊重していなかった場合、これがそれである。
