公開日 **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.2/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.2) · `pip install --upgrade tesserae==0.41.2`

すべてのコマンドは実行することで監査されました。42 個の候補欠陥のうち、31 個は再現と敵対的な第 2 意見を乗り越えました。このリリースは最も深刻な 12 個を閉じます。5 つは行わなかった作業の成功を報告し、5 つはデータを破壊し、1 つはフラグが無視されました。そして 1 つは意図的に放置されました。

## やったと嘘をついたコマンド

- **マークダウンを保持しないパスを超えるコンパイルは拒否されます。** `tesserae compile
  README.txt` — 正しいサフィックスを持つ実ファイル — グラフを何もないところから再構築し、空のもので置き換え、終了 0 になりました。拒否は書き込みの前に行われるため、グラフはまだ読むときに存在します。パスは現在のディレクトリではなく `--project` に対して解決されます。
- **`code ingest` は存在しないパスを拒否します**。実ファイルを空のコードグラフで置き換えて成功を報告する代わりに。
- **`query` はプロジェクトではないもに対するエラーです。** これは終了 0 で「一致が見つかりません」と答えました。これは実検索が何も見つけたように見えるものなので、`--project` の入力ミスは空のコーパスのように読まれました。
- **`lint` はグラフを読めないときに言います。** パース エラーを飲み込んで、空のグラフを超えるすべてのチェックを実行し、`graph.json` をまったく解析できない終了 0 で「検出事項はありません。ウィキはクリーンです。」と報告しました。
- **`engine --once` はコンパイルが失敗したときにゼロ以外で終了します。** 何が起こったかに関わらず、0 を返しました。継続的な統合は、発生したパイプラインの緑色を見ました。同じバグが、ユニットで各ユニットの終了コードを読むため、失敗したプロジェクトのバッチに対して`2/2 units ok`を出力しなかった理由です。

## 破壊されたデータ

- **解析できないマシン全体の設定は置き換えられなくなりました。** すべてのライターはファイルが読めないときに空の辞書にマージし、結果を書きました。1 つの迷ったコンマはクリップトークンと保存されたすべてのキーを費やしました。破損したファイルの過去読み取りは問題ありません。1 つの上に書き込みは。
- **`projects register` はコンパイルされたことのないプロジェクトを再初期化しなくなりました。**
  これはその構成を置き換え、ソース、名前、およびプロバイダを失いました。ガードのコメント自体はこれを約束しました。間違ったファイルでテストされました。
- **`sessions discover --import` は読めなかったルートからのレコードを保持します。** ディスク上にない `--root` はまだ削除範囲に渡され、そのインポートはそれから学んだものを持たないながらそれから収穫されたすべてを削除しました。マウントされていないディスクで十分でした。
- **`vault sync` は適用したと言うオーバーライドを保存します。** これは編集を報告し、ボルトのみを書き、次の実行はあなたの変更をそれが以前にあった方法に戻しました。
- **`vault export` はメモを保持する孤立ページを保持します** — `vault prune` がすでに削除を拒否したものと同じです。2 つは同意せず、静かなものはすべてのエクスポートで実行されました。

## 無視されました

- **`engine --all --harvest-only` はもはやコンパイルしません。** フラグは 1 つのプロジェクトに到達し、それが書き込まれた形状であるフリート モードで削除されました。複数のマシンが共有ディレクトリを共有し、それぞれ見えるもののみを読み取り、その中の 1 つがコンパイルされます。

## 意図的に放置されました

`lint --fix-trivial` は修復したばかりの検出事項をリストします。これは「これは私が修正したものです」と読まれ、テストはそれをピン留めします。欠陥ではありません。監査がそれを引き起こし、答えが「いいえ」であるため、ここで指定されています。

## アップグレード

移行するものはありません。何もできずに終了 0 だったコマンドは、なぜかを言うために終了 2 で終了するようになりました。沈黙に依存していたスクリプトは、それが既にしていた失敗を報告し始めます。
