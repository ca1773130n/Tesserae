Date de publication **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.1) · `pip install --upgrade tesserae==0.7.1`

`tesserae ingest <file|url>` est une nouvelle commande de premier niveau qui fusionne un **seul** document ou URL dans votre base de connaissances — sans réextraire tout le corpus — tout en restant **identique octet pour octet** à une compilation complète. Déposez un fichier, ou pointez-la vers une page web, et votre graphe se met à jour de façon incrémentale au lieu de payer le coût d'une recompilation complète à chaque fois.

## 1. `tesserae ingest <input>...` — ingestion incrémentale d'une seule source

La nouvelle commande prend une ou plusieurs entrées — des chemins de fichiers locaux ou des URLs `http(s)` — et intègre chacune individuellement dans la base de connaissances existante. Elle est distincte de `tesserae code ingest` : il s'agit ici d'ingestion de document/source dans le graphe principal, et non d'indexation de code.

Par défaut, `ingest` exécute un **chemin rapide incrémental** qui ne touche que la nouvelle source. Ce chemin rapide est *contrôlé par parité* : il est vérifié comme identique octet pour octet à une compilation complète, et si la parité ne peut être garantie, il bascule automatiquement vers une recompilation complète, de sorte que la justesse n'est jamais menacée. Passez `--exact` pour forcer vous-même la recompilation complète.

Options : `--exact`, `--dry-run`, `--title`, `--source-kind`.

## 2. Les URLs sont récupérées, converties et suivies avec leur provenance

Donnez une URL `http(s)` à `ingest` et elle récupère la page, la convertit en markdown et la persiste en tant que source suivie sous `data/ingested/<slug>.md` avec un front-matter de provenance : `source_url`, `fetched_at`, `content_sha256`, et `arxiv_id` lorsque la source est détectée comme un article arXiv.

L'ingestion d'URL est fournie derrière un nouvel extra optionnel afin que l'installation de base reste légère :

```
pip install tesserae[ingest-url]
```

## 3. Les fichiers locaux hors corpus deviennent partie intégrante du corpus

Lorsque vous ingérez un fichier local situé en dehors du corpus suivi, `ingest` le copie dans le corpus. Ainsi, une `tesserae compile` complète ultérieure reproduit exactement le même résultat — l'ingestion incrémentale et une compilation à partir de zéro convergent vers des octets identiques.

## 4. Sous le capot : une jointure (seam) incrémentale qui préserve la parité

Le chemin rapide incrémental repose sur une jointure `incremental_override` par invocation dans le pipeline de compilation. Elle est **inerte par défaut** — quand rien ne la remplace, le moteur se comporte exactement comme avant et la parité de la compilation complète est préservée. Un test de parité de référence contrôle la fonctionnalité, en affirmant qu'une ingestion incrémentale et une compilation complète produisent une sortie identique octet pour octet.

## Durcissement

Le front-matter de provenance est désormais écrit via un chemin sûr pour YAML, fermant l'injection de valeurs dans le front-matter (un titre ou une URL forgé ne peut plus s'échapper du bloc de front-matter).

## Mise à niveau depuis v0.7.0

Remplacement direct. `tesserae ingest <file>` fonctionne immédiatement pour les fichiers locaux. Pour ingérer des URLs, installez l'extra avec `pip install tesserae[ingest-url]`. Le comportement existant de `tesserae compile` / `refresh` est inchangé — la jointure incrémentale reste inerte tant que `ingest` ne la pilote pas.
