Released **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

エージェントは Tesserae の第一級のコンシューマーですが、0.18 のコマンド分割以降、2 つの機能が CLI にしか存在しませんでした。このリリースは新しい MCP ツールで両方のギャップを埋めます。

## `query` — MCP 経由の生のリトリーバル

`tesserae query` をミラーします：コンパイル済み wiki に対する決定的な BM25／セマンティック検索で、`top_k` と `kind` フィルタを備え、LLM 呼び出しを一切行わないことが保証されています（`force_no_llm` がエンドツーエンドで適用）。`backend: "raganything"` はオプションのマルチモーダル RAG インデックスに到達します — これは 0.18 の分割で `ask` が backend パラメータを失って以来、**MCP からの経路がまったく存在しませんでした**。合成された引用付きの回答が欲しいときは `ask` を、ランク付けされたエビデンスそのものが欲しいときは `query` を使ってください。

## `doctor_run` — MCP 経由の新鮮なヘルスチェック

`doctor_report`（0.18）は最後に永続化されたレポートを返すだけでした — doctor を一度も実行していないプロジェクトに当たったエージェントは何も得られませんでした。`doctor_run` は 20 項目のチェックレジストリ全体をオンデマンドで実行し、0/1/2 の終了コードとともに結果を JSON で返します。これは**常に読み取り専用**です：MCP 経由で修復が実行されることはなく、レポートアーティファクトも書き込まれません；修復は `tesserae doctor --fix` による明示的な人間のアクションのままです。

## その他はすでに流れていた

0.18–0.19 の残りの機能には変更は不要でした：`ask` は `llm` をデフォルト true として LLM プランニング済みの回答を返し、`activity_summary` / `query_decisions` / `timeline` は日次セッションチャンクのファストパスを透過的に継承し、セットアップツールはカスタムプロバイダーのキーを受け付けます（`llm_api_key` は意図的に設定不可・レダクト済み）。
