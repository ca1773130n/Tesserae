[v0.6.0 CLI 재설계](v0.6.0.md)에 대한 작은 후속 릴리스입니다. 새로운 플랫 동사 CLI에 대한 두 가지 편의 기능 개선과, 멀티 계정 codex 사용자를 위한 실제 버그 수정 하나가 포함되어 있습니다.

## 1. `tesserae compile`이 이제 실시간 진행 상황을 표시합니다

긴 컴파일은 예전에는 아무 출력 없이 조용히 진행되었습니다. 이제 인터랙티브 터미널에서 여러 단계로 구성된 `codegraph index` 스타일의 진행 표시를 렌더링합니다:

```
◆ Scanning sources — 2036 found
  Extracting ████████████████░░░░░░░░  64%  1302/2036  0:12
◆ Extracted 2036 files
⠙ Finalizing — community summaries, vault, site…
◆ Compiled  ·  220243 nodes · 679073 edges  ·  41s
```

이 기능은 `rich`(이미 의존성에 포함됨)로 구동되며 TTY에서만 렌더링됩니다. 파이프, CI, MCP 서버, 데몬 실행은 바이트 단위까지 동일하게 유지되므로(일반 `Compiled project wiki: …` 요약 줄은 그대로 보존됩니다), 스크립트에는 아무런 변화가 없습니다.

## 2. `tesserae projects register`가 자동으로 초기화합니다

아직 Tesserae 프로젝트가 아닌 디렉터리를 등록하면 `No .tesserae/graph.json found` 오류와 함께 실패했습니다. 이제 해당 경로가 `.tesserae/` 워크스페이스가 없는 기존 디렉터리라면, register가 먼저 비어 있는 워크스페이스를 생성합니다(그런 다음 `tesserae compile`을 실행하라는 힌트를 출력합니다). 존재하지 않거나 잘못 입력된 경로는 여전히 오류이며 — 절대 자동으로 생성되지 않습니다 — 이미 초기화된 프로젝트는 그대로 유지됩니다.

## 3. 수정: `llm_provider: codex`가 이제 모든 LLM 패스에서 존중됩니다

codex를 선택한 경우(`tesserae config llm --llm-provider codex` 또는 프로젝트의 `config.json`을 통해), 여러 컴파일 시점 LLM 패스가 여전히 Claude CLI를 사용했고 — codex를 선택했음에도 `ClaudeCLIJsonClient … You've hit your Sonnet limit`를 발생시켰습니다. 원인은 다음과 같습니다: 커뮤니티 요약 패스, Phase-5 메모리 패스, 그리고 `lab schema-drift` / `lab evolve` / `query --llm` 명령이 프로바이더 설정을 참조하지 않고 LLM 클라이언트를 구성하여 항상 기본값인 Claude를 사용했습니다. 이제 이들 모두 엔진의 나머지 부분과 동일한 방식으로 백엔드를 결정합니다 — **환경 변수 > 프로젝트 `config.json` > 전역 `~/.tesserae/config.json` > 기본값** — 따라서 `llm_provider: codex`가 모든 곳에서 존중됩니다.

## v0.6.0에서 업그레이드하기

변경할 것이 없습니다 — 세 가지 모두 드롭인입니다. 이전에 `llm_provider: codex`를 설정했는데도 컴파일 중에 Claude가 호출되는 것을 보았다면, 이번 릴리스가 이를 수정합니다. 그냥 다시 `tesserae compile`을 실행하세요.
