发布于 **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.6/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.6) · `pip install --upgrade tesserae==0.41.6`

编译运行在引擎的事件循环线程上，而停止信号要经由该循环传递，所以 Ctrl-C 或 SIGTERM 会一直无人应答，
直到编译结束。随后关闭流程又为积压的触发跑了一次编译。本项目自己的引擎日志里就有：两次信号之后，
又开始了一次覆盖 4,740 条路径的最终编译。

## 改了什么

- **第二个信号会停下引擎。** 第一个信号仍然把手头的工作做完，并且现在会说明这一点：
  `signal again to stop now`。第二个信号会在主线程正在做的任何事情处抛出，因此引擎即使在编译中途
  也会退出，删除自己的 pidfile 并返回惯用的退出状态。什么都不会丢：下次启动的编译会通过清单差异
  找到改动过的来源。
- **停止不再把 LLM 留下。** CLI 代理运行在自己的会话里，终端的 Ctrl-C 根本到不了它，而此前只有超时
  才会杀掉它。以其他方式结束等待时，`claude -p` 会在发起它的进程消失之后继续运行并继续计费。
  现在无论等待以何种方式结束，都会杀掉它的进程组。普通 `tesserae compile` 期间的 Ctrl-C 同样适用。

## 升级

无需迁移。正在运行的引擎需要重启才能生效。舰队模式（`engine --all`）仍是一次信号的行为。
