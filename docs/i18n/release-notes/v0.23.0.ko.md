Released **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.23.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.23.0) · `pip install --upgrade tesserae==0.23.0`

계층화된 에이전트 메모리(v0.21)는 축약할 수 있지만, 오직 당신이 요청할 때만 가능했습니다. `tesserae refresh`를 실행할 때, 메모리 부족 상황에서만 축약이 일어났습니다. 이번 릴리스에서는 항상 실행되는 엔진에 **휴면 사이클**을 더합니다. 마치 뇌가 휴식 중에 기억을 정리하듯이, 에이전트 메모리를 자동으로 통합합니다.

## 휴면 중에 통합하기

`tesserae engine`을 실행 중인 상태로 두면, 이제 활동 시계를 감시합니다. 프로젝트가 **유휴 상태**가 되면 — 몇 분 동안 편집이나 새 세션이 없으면 — 해당 프로젝트의 에이전트들에 대해 축약 처리를 실행하고, 당신이 없는 동안 그들의 누적된 경험을 재조직하고 압축합니다. 주기적인 **상한선**(기본값 6시간)은 지속적으로 바쁜 프로젝트도 여전히 통합하도록 보장합니다.

```bash
tesserae engine                      # idle consolidation on by default
tesserae engine --consolidate-idle 600 --consolidate-every 43200
tesserae engine --all                # every registered project, on idle
tesserae engine --no-consolidate     # opt out
```

유휴 상태는 뇌 메커니즘과 일치하는 트리거입니다. 통합은 임의의 벽시계 시간이 아니라 시스템이 쉬고 있을 때 발생합니다.

## 구조적으로 안전함

휴면 사이클은 기존의 `maybe_distill_on_refresh` 처리를 정확히 래핑하므로, 그 모든 보장이 유지됩니다:

- **선택하지 않는 한 작동하지 않습니다.** `TESSERAE_AGENT_DISTILL=1`에 옵트인할 때까지 아무것도 실행되지 않습니다. — 축약이 항상 사용해 온 같은 게이트이며, 에이전트별 워터마크와 메모리 부족 검사가 추가됩니다. 플래그는 기본적으로 켜져 있습니다. 왜냐하면 처리 자체가 옵트인 없이는 아무것도 하기를 거부하기 때문입니다.
- **재컴파일과 겹치지 않습니다.** 통합은 컴파일 게이트 아래에서 실행되므로, 그것과 파이프라인은 상호 배타적입니다. 단일 데몬 모드에서 이를 유지하기 위해, 설정되지 않은 게이트는 이제 비공개 세마포로 기본값이 지정됩니다.
- **데몬을 방해하지 않습니다.** 자신의 스레드에서 실행되며(데몬의 기존 폴러 관용구), 이벤트 루프로 상승하지 않고, 종료 시 빠르게 종료되며, 일회성 `engine` 실행에서는 완전히 건너뜁니다.
- **결정론적 아티팩트는 건드리지 않습니다.** 축약된 그래프는 바이트 동등성을 유지합니다. 단조로운 활동 시계는 절대 지속되지 않습니다.

## 플래그

| Flag | Default | Meaning |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | enable the sleep cycle |
| `--consolidate-idle` | `300` | seconds of quiet before consolidating |
| `--consolidate-every` | `21600` | ceiling — consolidate at least this often (`0` = off) |
| `--consolidate-check` | `30` | how often the thread checks the clock |

전체 동작 및 플릿 참고: [`docs/engine-consolidation.md`](../../engine-consolidation.md).
