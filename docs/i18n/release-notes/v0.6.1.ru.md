Небольшое продолжение [переработки CLI в v0.6.0](v0.6.0.ru.md): два улучшения удобства нового CLI с плоскими глаголами и одно реальное исправление ошибки для пользователей codex с несколькими аккаунтами.

## 1. `tesserae compile` теперь показывает ход выполнения в реальном времени

Раньше длительная компиляция проходила в тишине. Теперь она отображает многофазный индикатор прогресса в стиле `codegraph index` в интерактивном терминале:

```
◆ Scanning sources — 2036 found
  Extracting ████████████████░░░░░░░░  64%  1302/2036  0:12
◆ Extracted 2036 files
⠙ Finalizing — community summaries, vault, site…
◆ Compiled  ·  220243 nodes · 679073 edges  ·  41s
```

Он работает на основе `rich` (уже является зависимостью) и отображается только в TTY — запуски через конвейер, в CI, на MCP-сервере и в демоне остаются побайтово идентичными (обычная итоговая строка `Compiled project wiki: …` сохраняется), поэтому для скриптов ничего не меняется.

## 2. `tesserae projects register` автоматически инициализирует

Регистрация каталога, который ещё не был проектом Tesserae, завершалась ошибкой `No .tesserae/graph.json found`. Теперь, если путь — это существующий каталог без рабочего пространства `.tesserae/`, register сначала создаёт пустое (затем выводит подсказку запустить `tesserae compile`). Отсутствующий или ошибочно введённый путь по-прежнему является ошибкой — он никогда не создаётся автоматически — а уже инициализированный проект остаётся нетронутым.

## 3. Исправление: `llm_provider: codex` теперь учитывается в каждом проходе LLM

Если вы выбрали codex (через `tesserae config llm --llm-provider codex` или `config.json` проекта), несколько проходов LLM во время компиляции всё равно использовали Claude CLI — выдавая `ClaudeCLIJsonClient … You've hit your Sonnet limit`, хотя вы выбрали codex. Причина: проход формирования сводок сообществ, проходы памяти Phase-5 и команды `lab schema-drift` / `lab evolve` / `query --llm` создавали свой LLM-клиент, не сверяясь с настройкой провайдера, поэтому всегда по умолчанию использовали Claude. Теперь все они определяют бэкенд так же, как и остальной движок — **переменная окружения > `config.json` проекта > глобальный `~/.tesserae/config.json` > значение по умолчанию** — поэтому `llm_provider: codex` учитывается везде.

## Обновление с v0.6.0

Менять ничего не нужно — все три изменения работают «из коробки». Если ранее вы устанавливали `llm_provider: codex`, но во время компиляции всё равно видели вызовы Claude, этот выпуск это исправляет; просто запустите `tesserae compile` снова.
