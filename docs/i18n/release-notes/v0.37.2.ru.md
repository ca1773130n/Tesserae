Выпущено **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [Релиз на GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1 исправила построители клиентов. Три места вызова строят собственного клиента Anthropic SDK и не были затронуты этим исправлением, поэтому они все ещё переходили к `api.anthropic.com` с жесткокодированной моделью, в то время как каждый другой путь соблюдал настроенную конечную точку проекта. Этот выпуск их закрывает.

## Три пути

- **`query --llm`** построила клиента только с помощью ключа API — без `base_url` —
  и отправила модель по умолчанию метода `claude-sonnet-4-6`.
- **Синтез прозы** (`TESSERAE_SYNTHESIS_LLM=1`) делала то же самое, поэтому проект
  с пользовательской конечной точкой имел свои краткие изложения, написанные Anthropic.
- **`synthesis`** выбирала модель из `TESSERAE_SYNTHESIS_MODEL` или литерала,
  никогда из `llm_model`. Она содержит хранилище вики, а не корень проекта, поэтому
  корень теперь выводится так, как это уже определяет `ProjectPaths`.

## Три ещё, найденные путём запуска выпущенного пакета против реальной конечной точки

0.37.1 была установлена из PyPI в чистую среду и направлена на работающий
совместимый с OpenAI сервер. Это работало — и раскрыло три вещи, которые чтение
кода не раскрыло:

- **Сообщение об ошибке доступности было расплывчато.** Оно говорило «rate-limited / auth / unsupported
  model», когда клиент уже классифицировал, какой это был. Теперь оно гласит:
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`.
- **`tesserae config status` сообщала об источнике провайдера как `default`**
  даже когда это пришло из конфигурации проекта. Провайдер разрешается до того,
  как запустится помощник записи источника, поэтому его уровень никогда не
  записывался.
- **`tesserae setup` читала `llm_claude_model` и `llm_claude_config_dir`** —
  ключи в единственном числе, которые ничто не пишет. Каждый писатель использует
  `llm_model` и множественное число `llm_claude_config_dirs`, поэтому мастер
  молча не видел конфигурации вообще.

## Тесты

Тесты пользовательского провайдера были заблокированы на `importorskip("anthropic")` —
пропускались ровно при базовой установке, где провайдер был неработающий. Провод
`openai` не требует SDK, поэтому новое покрытие не может быть пропущено, и один
тест полностью блокирует импорт `anthropic`, чтобы это доказать.

## Обновление

Нечего переносить. Если вы настроили пользовательскую конечную точку и обнаружили,
что `ask` и `compile` её соблюдали, а `query --llm` или synthesis нет, то это она.
