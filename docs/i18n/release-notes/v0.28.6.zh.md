已发布 **2026-08-04** · [PyPI](https://pypi.org/project/tesserae/0.28.6/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.6) · `pip install --upgrade tesserae==0.28.6`

如果有东西从本地运行框架约定之外写会话进 Tesserae，就应该升级。到 0.28.5 为止，`tesserae sessions discover --import` 一直在悄悄删除这些记录。插件的 `SessionEnd` 钩子在每次会话结束时都会执行一个发现。

## 存储在只报告增长的行里缩小了

[#104](https://github.com/ca1773130n/Tesserae/issues/104)，在 0.28.2 报告，仍然存在于 0.28.5。一个项目有一个由外部生产者导入的会话——一个将其自己的代理会话规范化为 `HarnessSession` JSON 的应用，并调用 `tesserae sessions import <file>`。运行 `sessions discover --import` 来添加本地 Claude Code 和 Codex 历史记录把清单从 1 个会话变成了 377 个，之前存在的记录消失了。不仅从清单中：从存储中被删除了。唯一打印的行是 `Imported harness sessions: 377`。

空扫描保护早已正确——一个没找到任何东西的扫描是合并而不是擦除。错误的是"权威"的范围有多远。发现扫描的是本地 Claude Code 和 Codex 成绩单；来自任何其他生产者的记录在结构上对它是不可见的。不是陈旧的。超出范围。它仍然被删除了。

## 修复，以及越过第一次尝试的三种方法

第一个修复把删除的范围缩小到了扫描实际走过的运行框架根目录。对它的审查发现了越过该范围的三种方式，每一种都删除了该运行没有权限处理的记录：

- **`--harness` 缩小了扫描但没有缩小范围。** 根目录是在筛选器应用之前发现的，所以 `sessions discover --harness codex --import` 仍然在其删除范围内携带着 `~/.claude`，同时不从它重写任何东西，并删除了每一个存储的 claude-code 记录。这是 CLI 自己的 `--help` 文本中的例子。
- **无法解析的记录被视为属于没有人的**，并被删除。但那是一个生产者在写，或者一个损坏的文件——无论哪种方式所有者都是*未知的*，而在未知上删除正是最初的错误发生的方式。
- **`Path.resolve()` 在没有保护的情况下运行。** 一个符号链接循环会引发 `RuntimeError`，一个嵌入的 NUL 会引发 `ValueError`，都没有被捕捉——在新文件着陆之后但在清单被重建之前中止写，使存储和其清单不一致。

这三个都来自以相同的错误方式回答相同的问题。现在写进代码的规则：**每一个不确定的情况都回答"这不是我的东西要删除"。** 删除是破坏性的，扫描的权限是狭窄的，所以"我无法证明这条记录是我的"必须意味着"不管它"。

具体来说，一条存储的记录只有在其成绩单位于这次运行扫描过的根目录**下**，**且**其运行框架是这次运行扫描过的**之一**时才会被删除。两个部分独立地缩小范围。一个没有记录在其后的 `.md` 页面仍然会被清扫——那是真正的孤儿，清扫这些正是删除的用途。

两件小事随之而生：删除记录的删除现在在导入计数旁边打印计数，所以缩小永远无法再隐藏在报告增长的行内；`write_sessions` 现在文档说明了用 `replace=True` 省略范围仍然会擦除整个存储，这是旧行为，仍然可达，而 Tesserae 中没有调用者想要它。

## 合同现在被写下来了

这个错误之所以可能，部分原因是没有任何东西说明两个入口点的不同之处。生产规范化 `HarnessSession` JSON 的工具可以调用 `sessions import`，而无法学习到后来的发现会删除它写的东西。[`docs/session-history.md`](../session-history.md) 现在有一个**存储如何被写入**的部分说明它：导入合并，发现只在它扫描过的范围内替换，其他所有东西都保留。

## 这个发布中的其他部分

关于图形增长评估的工作，这是面向开发者的，不改变任何运行时行为。它现在切分整个演示语料库——73 份文档而不是 50 篇论文，包括仓库、摘要、合成和开放问题，从它们已经声明的内容而不是写入语料库的日期进行日期标记。锚定解析匹配标签令牌而不是字面短语。

运行它的诚实结果：15/15 个问题可回答，这个数字意味着比它替换的 14/15 更少。在更大的图形上，15 个问题中的 14 个已经在*单个*跳跃中回答，87% 的任意锚点对在三以内连接。可回答性随语料库大小而膨胀，因为锚定解析是基于集合的。`evals/growth/probe_anchors.py` 精确测量这一点，其发现被记录而不是平滑——评估的判别力，而不是其分数，是开放的问题。
