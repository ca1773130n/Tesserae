发布于 **2026-06-20** · [PyPI](https://pypi.org/project/tesserae/0.10.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.10.0) · `pip install --upgrade tesserae==0.10.0`

一个功能版本：知识交互、更快的会话搜索和一键机器级设置。所有内容都是附加的 — 普通 `tesserae compile` 保持不变，按项目配置仍然覆盖新的全局默认值。

## 1. Google OKF v0.1 导入/导出

`tesserae export okf` 将图导出为 [Google **Open Knowledge Format** v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog) 包 — 一棵包含 YAML 前置信息和相对链接关系的 Markdown 文件树。`--import DIR` 可以读取一个包。Tesserae 自己的包通过 `x_tesserae` 前置信息命名空间 **无损** 往返（真实节点 id + 类型化边 + 边元数据）；外部包采用尽力而为的方式导入（未知 `type` → `Concept`，无类型链接 → `references`），容忍缺失的类型和破损/符号链接文件（遵循规范）。

## 2. 会话仪表板上的快速文本搜索

`tesserae serve` 的会话仪表板增加了一个全文搜索框，覆盖所有已索引的 Claude/Codex 文本，由 [`nicosuave/memex`](https://github.com/nicosuave/memex)（BM25）驱动。这是可选的且优雅降级的：如果没有 `memex` 二进制文件，搜索框会显示一条可操作的消息，仪表板的其余部分不受影响。`GET /api/transcript-search` 端点仅限同源/回环调用者，因此访问的网页无法探测本地历史，结果通过 `textContent` 呈现（无标记注入）。

## 3. MCP 的 memex 风格读取规范

受 Databricks 的"可编程草稿板"启发，`compile_context` 现在接受 `preview=N`：与其转储巨大的正文内容到代理的上下文，它返回一个有界的预览加上内容密钥 **handle**，新的 **`get_handle`** 工具按需对其余部分进行分页。默认 `preview=0` 保持完整正文行为。

## 4. 提取质量信号

会话发现现在携带从提取器蒸馏的 `confidence` + `confidence_rationale` + `revisit_signals`（思想来自 Jonasb8/memex；未复制代码）。它们遵循内容密钥提取缓存，因此保持字节幂等，并在 `fresh_insights` MCP 工具中显示为标志（绝不是真理保证）。

## 5. 机器级设置 + 依赖项安装

`tesserae config setup` 为 **所有** 项目设置 LLM 默认值（`--llm-provider`、`--reasoning-effort`、`--codex-home`、`--claude-config-dir`），**并且** 在一次调用中安装可选依赖项（`--install all`）。`tesserae config deps` 列出/安装 **memex**、**cognee**、**raganything** 和 **understand-anything**；`tesserae config llm` 获得了 `--reasoning-effort`；`tesserae init` 在交互式设置期间提议安装 memex。解析顺序：env → 项目配置 → 机器级配置 → 内置。

## 从 v0.9.x 升级

即插即用。运行 `tesserae config setup` 一次配置机器级默认值，或保持你的按项目 `.tesserae/config.json` — 它仍然获胜。
