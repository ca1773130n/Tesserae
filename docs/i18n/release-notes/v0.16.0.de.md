Die `tesserae serve` Sessions-Seite wartet nicht mehr auf die nächste Kompilierung. Sie liest Ihre **Live**-Agent-Aktivität jetzt direkt aus den Harness-Roots – sodass eine Sitzung, in der Sie *gerade eben* arbeiten, live angezeigt wird.

## Live Sessions auf der Serve-Seite

Wenn Sie `tesserae serve` ausführen, ruft die Sessions-Seite einen neuen **`/api/sessions`**-Endpunkt ab, der Ihre Claude Code-Roots dynamisch durchsucht (recent-window bounded) und die aktuell aktiven Sitzungen über der kompilierten Tabelle anzeigt – Sitzungs-ID, Konto, Anzahl der Turns, letzte Aktivitätszeit und eine Vorschau des ersten Turns. Öffnen Sie stattdessen einen statischen Build (GitHub Pages), bleibt das Panel einfach verborgen: die kompilierte Tabelle ist die gesamte Seite, genau wie vorher.

Das **Schnelltranskript-Suchfeld** wird auf die gleiche Weise live geschaltet: frische Ergebnisse aus den Roots werden *vor* den memex-Indexergebnissen zusammengeführt (dedupliziert), sodass eine Phrase, die Sie vor Momenten eingegeben haben, gefunden werden kann, bevor sie jemals indiziert wird.

Beide Oberflächen sind **origin-gated** – sie zeigen lokalen Verlauf, daher wird eine browserübergreifende Anfrage abgelehnt, genauso wie der Clip-Endpunkt.

### Warum nur Claude und wie Codex abgedeckt bleibt

Claude Code-Transkripte sind verzeichnis-scoped, daher ist ein Live-Scan pro Projekt im Subsekunden-Bereich. Codex-Sitzungen sind das nicht – Einschränkung auf ein Projekt würde bedeuten, jede aktuelle Sitzungsdatei zu parsen (100k+ auf einem beschäftigten Computer, ~170s pro Anfrage), viel zu langsam für eine interaktive Seite. Daher ist der Live-Scan **nur Claude**; Codex wird wie zuvor aus dem memex-Index und der kompilierten Projektion bedient. Die Offline-Befehle `tesserae summary` und `tesserae decisions` scannen immer noch **jedes** Konto – Claude und Codex – weil sie sich den vollständigen Durchlauf leisten können.

## `--max-turns` auf Summary und Decisions

`tesserae summary` und `tesserae decisions` erhalten ein `--max-turns N` Flag, das begrenzt, wie viele Turns pro Sitzung vor dem Windowing gelesen werden. Praktisch, um die Kosten einer großen Sitzung zu begrenzen, wenn Sie nur einen neueren Abschnitt benötigen. Der Standard bleibt effektiv unbegrenzt.

```bash
tesserae summary --day 2026-07-06 --max-turns 200
tesserae decisions --week --max-turns 200
```

## Aktualisierung

Drop-in über v0.15.x. Alles ist additiv – die Live-Endpunkte existieren nur unter `tesserae serve`, die Seite wird auf statischem Hosting sauber abgebaut, und nichts benötigt eine Migration oder Neukompilierung. Es liest Ihre bestehenden Sitzungen dynamisch.
