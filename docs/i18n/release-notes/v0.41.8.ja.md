リリース **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.8/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.8) · `pip install --upgrade tesserae==0.41.8`

`tesserae init` と `tesserae compile` は自分のプロジェクトをマシン全体のレジストリ
`~/.tesserae/registry.json` に追加し、プロジェクトの範囲を指定しないクエリはその中のすべてのプロジェクトを
検索します。問題が見つかったマシンでは、レジストリに 204 のディレクトリにわたる 286 件のエントリがあり、
本物のプロジェクトはそのうち 6 件でした。残りはベンチマークの実行、エージェントの作業用ディレクトリ、
1 つのテストが残した使い捨てのプロジェクトと、`init` で名前を付けたすべてのプロジェクトの 2 つ目の別名でした。

## 何が変わったか

- **2 つ目の別名はできなくなりました。** `init --name` は渡された名前で登録しますが、その後の
  コンパイルは `--name` を持たないため、ディレクトリ名でも登録していました。HypePaper は構築する
  エキスパートごとに `hp-topic-<topic>` という名前を付けるので、どのエキスパートも 2 回ずつ並んでいました。
  どの別名であれ、すでにレジストリにあるディレクトリはそのままにするようになりました。
- **ベンチマークの実行は自分のプロジェクトを自分の中に留めます。** DeepScholar、growth、LongMemEval、
  LoCoMo のハーネスは、クエリや会話ごとにプロジェクトを 1 つずつ作ります。それらの `init` と
  `compile` は作業ディレクトリ内のレジストリを使うようになりました。DeepScholar の 1 回の実行が
  `0` から `62` という名前のプロジェクトを 63 件残したことがあります。
- **テストスイートがあなたのレジストリに書き込まなくなりました。** あるテストが、スイートのレジストリ
  分離の届かないサブプロセスで `init` を実行し、一時ディレクトリ配下の `cwd_wiki` を登録していました。

## アップグレード

移行作業はありません。すでにレジストリにあるエントリは削除するまで残ります。
`tesserae projects list` で確認でき、`tesserae projects unregister <name>` で 1 件ずつ削除できます。
プロジェクト自体には触れません。
