릴리스 일자 **2026-06-13** · [PyPI](https://pypi.org/project/tesserae/0.8.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.8.1) · `pip install --upgrade tesserae==0.8.1`

첫 번째 실제 `tesserae engine --all` 실행(프로젝트 5개)에서 발견된 문제를 수정한 패치 릴리스입니다. 업그레이드 후 엔진을 재시작하세요.

## 1. sqlite "unable to open database file" 폭풍 종식

인프로세스 컴파일과 여러 개의 틱킹 세션 테일러가 macOS 기본 **열린 파일 소프트 제한 256**을 초과합니다; 한도가 소진되면 프로세스 내의 모든 sqlite open이 실패하고, 테일러는 추적 중인 파일마다 트레이스백을 출력했습니다. `tesserae engine`은 이제 시작 시 `RLIMIT_NOFILE`을 8192로 올리며, 시스템 틱 실패는 트레이스백 **하나**와 억제된 건수 요약만 로깅합니다.

## 2. 재시작 시 콜드 스윕 생략

세션 테일러의 첫 실행은 프로젝트 세션을 찾기 위해 Codex 전체 출시 히스토리를 한 번 스윕합니다 — 대규모 히스토리에서는 수십 분이 걸리며, 이전에는 **매번** 재시작할 때마다 다시 수행했습니다. 이제 스윕 하한선이 세션 DB에 영속적으로 저장됩니다; 재시작은 해당 지점부터 재개하며(최근에 재개된 세션을 위한 7일 룩백 포함), 콜드 또는 웜 여부, 소요 시간, 건수를 알립니다.

## 3. 조용하고 유익한 로그

- 여섯 가지 새로운 Claude Code 트랜스크립트 행 유형(`last-prompt`, `queue-operation`, `mode`, `ai-title`, `file-history-snapshot`, `pr-link`)이 양성 메타데이터로 인식됩니다 — 라이브 테일링 시 경고 스팸이 사라지며, 진정으로 알 수 없는 유형은 **프로세스당 한 번**만 경고합니다.
- 각 파이프라인 실행은 `pipeline starting for <project>`를 로깅합니다 — 긴 컴파일이 완료된 *후*에만 다른 출력이 있던 기존 방식과 달리, 더 이상 중단된 것처럼 보이지 않습니다.

## 4. README 개선

README(및 7개 언어 미러 전체)가 재작성되었습니다: 현재 기능 세트(`ingest`, `engine --all`, sessions), 올바른 Python 요구 사항(3.10+), 비교 매트릭스와 워크스루 GIF를 접힌 섹션으로 정리한 깔끔한 구조.

## v0.8.0에서 업그레이드

그대로 교체하면 됩니다. 실행 중인 `tesserae engine` / `tesserae engine --all`을 재시작하여 수정 사항을 적용하세요 — 첫 번째 재시작에서는 영속적 하한선을 초기화하기 위한 최종 콜드 스윕이 한 번 수행되며, 이후 모든 재시작은 빠릅니다.
