Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

本次发布包含三件事。除非你主动要求，否则不再索引源码。一个已写好、已测试却无法
触及的检索面向外开放。图谱获得一张组织结构图，让通用智能体可以被指向某个领域并
以该领域专家的身份工作。

## 源码现在需要你主动要求

过去只要项目*看起来*像一个仓库（`kind` 为 `CodeProject`、`Repository` 或
`Project`），Tesserae 就会构建代码层。那只是对项目"是什么"的描述，并不代表其
拥有者希望自己的源码被解析。唯一的退出方式是谎报项目类型。

代价藏在没人会看的地方。`graph.json` 只承载研究分区，所以它显示的代码节点是
**零**，而 SQLite 投影和生成页面里却有大约 22 万行与 22 万个页面。没有人会把这
笔开销归因于一个自己从未设置过的选项。在维护者本人的机器上，一个已经关闭该功能
的项目仍留有 327MB 的产物。

现在由项目主动提出：

```json
"external_tools": [{"id": "codegraph"}]
```

没有该条目即为关闭。项目类型完全不参与判断。这里复用了 RAG-Anything 集成已经
读取的结构，而不是另造一个开关。

**维护也遵循同一道闸门**，这正是否则会泄漏的那一半。两个 sync-code 钩子都会在
自己的 `sync_code_on_*` 设置*之前*先检查启用状态，因此那些设置只能收窄你已经
授予的权限，绝不能凭空创造权限。磁盘上存在 CodeGraph 数据库并不等于同意——智能体
可能只是为自己的用途运行了 `codegraph init`，对 Tesserae 是否该每 30 秒跟踪一次
并无立场。

`code-graph.json` 在两个方向上都跟随开关：启用时写入，禁用时删除。残留的文件不
带时间戳，会继续用一个早已变化的仓库快照来回答查询。

没有任何东西被删除。CodeGraph 适配器、提取器、缓存以及 `tesserae code
ingest|sync` 都还在，只是位于开关之后。

## 一直都在的检索旋钮

`facts_as_of`——双时态查询，"图谱在这一天相信什么"——早已写好、字节幂等、有七个
测试覆盖，却有**零**个调用者。`personalized_pagerank` 本就尊重
`edge_type_weights`。`compile_context` 接受十六个参数，而 MCP 服务器只转发七个。
Tesserae 拥有双时态与视图选择性遍历，却无法请求其中任何一个。

现在可以了。`search_facts` 与 `timeline` 上的 `as_of`，以及报告返回行中有多少条
没有日期的 `undated_included`。`compile_context` 上的 `strategy`、`scope`、
`edge_type_weights`、`tame_hubs` 和 `recency_weight`。

`as_of` 与 `current_only` 不可同时使用，这是刻意的：它们表达不同的时钟，而当你
询问过去某一时刻什么为真时，不该因为答案后来被取代就静默地返回空。

## 图谱之上的组织结构

`tesserae domains status` 会展示建立在你的知识图谱之上的组织结构：由社区推导出的
部门；当某个领域的简报超出智能体一次可读的容量时进行的递归拆分；以及能在重组后
存活的身份标识——你为智能体固定的 slug，在图谱变动之后依然有效。

这是底座。使用它的路由将在下一步落地。

## 摄取不再为没做的事报告成功

过去 `tesserae ingest paper.pdf` 会把文件复制进来，运行一次只读 `.md` 的编译，
然后打印来自语料库其余部分的节点数。该路径中没有任何东西能区分"摄取了你的 PDF"
与"什么都没摄取"。装满 PDF 的目录同样如此，而它打印的 `processed=1` 数的是那个目录。

现在它会逐个文件拒绝，并给出可执行的补救办法：

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

抓取 URL 也更严格了。过去 PDF URL 会被当作文本解码、以 `.md` 后缀写入，并对乱码
计算哈希——于是遍历器把它当成散文喂给了提取器。现在，字节表明是二进制的正文、
声明类型为二进制的正文，以及没有可读文本的 200 响应，都会被拒绝。

新的 `INTERVAL_COVERAGE` 检查会报告图谱中有多少可以被放置在时间轴上。在本项目自己
的图谱上：**103,705 条事实中有 76,095 条（73.4%）没有 `valid_from`**，因此在
`timeline()` 中排在字面量 "undated" 之下。它以 `info` 级别报告，不会让 `--strict`
失败；设定下限需要一个来自当前语料库的数字，而目前还不是。

会话导入会统计它读不了的内容块，而不是静默丢弃。在 150 份真实记录上，这让
**9 个此前不可见的图像块**浮出水面——它们嵌套在 `tool_result` 里，旧的计数器
从未看过那里。

## 升级

```bash
pip install --upgrade tesserae==0.30.0
```

如果你以 Claude Code 插件方式运行 Tesserae，**钩子闸门要等这个版本的插件安装后
才会生效**——更早的插件副本只检查 CodeGraph 数据库是否存在，看不到这项启用设置。
在此之前，`.claude/tesserae.local.md` 中的 `sync_code_on_edit: false` 与
`sync_code_on_start: false` 是那些钩子确实理解的开关。

现有项目照常工作。想要代码层的项目添加上面的 `external_tools` 条目；不需要的
项目什么都不用改，就能得到更小的图谱、更小的数据库，并且不再生成代码页面。
