Publié le **2026-09-06** · [PyPI](https://pypi.org/project/tesserae/0.39.0/) · [Version GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.0) · `pip install --upgrade tesserae==0.39.0`

`tesserae compile` a toujours construit la couche concept et assertion via votre LLM configuré. Aucun autre point d'accès à la compilation ne l'a fait : `refresh`, le daemon du moteur, le chemin MCP `materialize` et `deploy --build` demandaient tous une compilation sans nommer d'extracteur, et « aucun » voulait dire le déterministe.

## Ce qui s'est passé

Un `tesserae refresh` sur un vrai projet a reconstruit la couche document entière sans le LLM. Chaque fichier est resté marqué comme graphé, aucun document n'a été marqué en recours, et le graphe est revenu sans ses concepts, capacités, modèles et sujets — 466 concepts sont devenus 0. Un daemon en boucle de rafraîchissement aurait fait la même chose à sa première recompilation. La correction a d'abord été épinglée par un fixture : le différenceur incrément préserve les nœuds typés LLM des fichiers non modifiés ; les points d'entrée étaient la faille.

## Ce qui a changé

- **Une compilation sans extracteur nommé construit maintenant le LLM configuré**, de la même forme que `tesserae compile` construit, avec l'extracteur déterministe comme recours par document. Tout backend inutilisable se dégrada vers le graphe structurel avec avertissement, jamais en silence. `compile --extractor deterministic` reste l'opt-out explicite.
- **Les bundles de contexte citent et intègrent le document qui développe une entité.** v0.38.0 stockait la densité de mention par document ; rien ne la lisait. La section du bundle pour une entité intègre maintenant la prose de ce document et la cite par son nom, se repliant sur le chemin premier-vu quand aucun miroir SQLite frais n'existe. `node_context` gagne une liste additive `documents`, classée. Mesuré sur deux corpus, premier-vu identifie le papier propriétaire environ la moitié du temps ; le document le plus riche en mentions, neuf fois sur dix.
- **`verify_attribution`**, comme outil MCP et verbe CLI `verify-attribution`. Une vérification de couverture valide un nombre réel copié d'une ligne voisine, car tous les jetons sont dans la preuve. Celle-ci vérifie l'auteur à la place : dans quel enregistrement le chiffre se trouve, et si ce document nomme le benchmark. Déterministe, sans graphe, sans LLM ; audité à 14 sur 15 attributions incorrectes détectées avec 4 fausses alarmes parmi 33 vraies réponses.
- **Un compte codex sans crédit est l'épuisement, pas une panne transitoire.** Un spawn, verdict `exhausted`, mémorisé pour la session — et la chaîne de fournisseur se replie sur Claude CLI authentifiée au moment de l'appel, comme sa docstring l'a toujours promis. Avant cela, chaque appel dépensait environ 55 secondes à réessayer quatre emplacements et ne retournait rien.

## Mise à niveau

Si vous exécutez un daemon ou une boucle `refresh`, attendez-vous à ce qu'elle dépense des appels LLM sur les documents modifiés dorénavant ; les documents inchangés atteignent le cache adressé par prompt. Un graphe compilé par `refresh` sous une version antérieure est purement structurel — une `tesserae compile` complète restaure la couche LLM. Rien d'autre à migrer.
