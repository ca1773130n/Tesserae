Veröffentlichungsdatum **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.0) · `pip install --upgrade tesserae==0.7.0`

`tesserae ask` synthetisiert nun echte Antworten über die **CLI, in der du bereits angemeldet bist** — ganz ohne `ANTHROPIC_API_KEY` — und rotiert über jedes Konto auf deiner Maschine, sodass ein Rate-Limit es niemals aufhält. Hinzu kommen zwei Fixes, die die Sessions, *über die* du fragst, durchsuchbar machen, sowie eine Kompilierung, die nicht mehr abbricht.

## 1. `tesserae ask` synthetisiert über die claude/codex-CLI — kein API-Schlüssel

Bisher konnte `tesserae ask` eine Antwort nur über das Anthropic-SDK verfassen, das `ANTHROPIC_API_KEY` benötigt. Wenn du das gängige Setup verwendest — über OAuth in der `claude`- oder `codex`-CLI angemeldet — degradierte `ask` stillschweigend zu rohen Suchtreffern mit `(no LLM answer: LLM disabled)`.

Jetzt nutzt der Antwortpfad dieselben OAuth-Clients wieder, die die JSON-Extraktoren bereits verwenden. `tesserae ask --llm "<question>"` (oder `TESSERAE_QUERY_LLM=1`) synthetisiert eine belegte Antwort mit **null API-Schlüsseln** — genau das schlüssellose Versprechen, das der Rest der Engine gibt.

## 2. Es rotiert über **jedes** Konto auf der Maschine

Die CLI-Clients erkennen bereits automatisch jedes `~/.claude*`-Konfigurationsverzeichnis und jedes `~/.codex*`-Home. v0.7.0 sorgt dafür, dass `ask` das nutzt — und verkettet es über *Provider* hinweg: Eine Anfrage gibt erst dann auf, wenn **jedes** Konto erschöpft ist.

In der Praxis: Wenn alle deine Claude-Konten an ihrem Sonnet-/Wochenlimit sind, rotiert ein echtes `tesserae ask --llm` durch sie hindurch, **fällt dann zu Codex durch** und antwortet (`model=cli-oauth`) — kein Schlüssel, kein manuelles Kontowechseln. Ein ratenbegrenztes oder abgemeldetes Konto wird übersprungen, nicht fatal.

## 3. Fix: Session-Titel kollabieren nicht mehr zur Harness-Präambel

Codex stellt jedem Transkript `# AGENTS.md instructions for <path>` voran, sodass die Heuristik für den Session-Titel *das* als Titel **jeder** Session nahm — und die Stichwortsuche eine Wand aus nicht unterscheidbarem Boilerplate bei identischen Scores zurückgab. Titel überspringen jetzt die eingefügte AGENTS/CLAUDE/GEMINI.md-Präambel (und System-Wrapper) und stammen aus deiner tatsächlichen ersten Anweisung; `ask` liefert wieder eindeutige, relevante Treffer.

Zwei kleinere `ask`-Fixes fahren mit: Das LLM-Gate (`--llm` / `TESSERAE_QUERY_LLM`) wird auf dem Wiki-Suchpfad berücksichtigt (es war zuvor hart deaktiviert), und wenn `--backend auto` zurückfällt, weil ein reichhaltigeres Backend einen Fehler hatte (z. B. ein cognee-Authentifizierungsfehler), sagt es das jetzt, statt stillschweigend so auszusehen, als wäre das Wiki das einzige versuchte Backend gewesen.

## 4. Fix: Kompilierung bricht nicht mehr bei einer veralteten zwischengespeicherten Referenz ab

Ein vollständiger `tesserae compile` / `refresh` konnte mit `KeyError: 'CodeFunction:…'` fehlschlagen — einer Code-Node-id, die nicht mehr existiert. Session-Findings filtern ihre Referenzen zum *Extraktions*zeitpunkt gegen den Doc-Graphen, aber Findings werden pro Chunk zwischengespeichert; wenn sich die id eines referenzierten Knotens später ändert (z. B. bei einer Code-Funktion, deren content-hash-basierte id sich verschiebt, wenn der Code bearbeitet wird) oder verschwindet, spielte das zwischengespeicherte Finding eine **veraltete** Referenz erneut ab und fabrizierte einen baumelnden Knoten, der einen nachgelagerten Code-Graph-Schritt zerstörte. Referenzen werden nun zum Merge-Zeitpunkt gegen den Live-Graphen erneut validiert — verlinkt, wenn das Ziel noch existiert, verworfen, wenn nicht.

## Upgrade von v0.6.1

Drop-in. Um ohne API-Schlüssel Antworten von `ask` zu erhalten, sei einfach in der `claude`- oder `codex`-CLI angemeldet und übergib `--llm`. Falls du auf den Kompilierungs-`KeyError` gestoßen bist, führe `tesserae compile` (oder `refresh`) erneut aus — es überspringt jetzt veraltete Referenzen, statt abzubrechen.
