Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

В этом релизе нет изменений поведения во время выполнения. Он чинит механизм,
который должен такие изменения ловить — механизм, которого до сих пор не
существовало.

## Тесты не запускал никто

В репозитории было два воркфлоу. Один компилировал демо-вики, другой публиковал
npm-обёртку по тегу. Ни один не выполнял ни единого теста. «`main` зелёный» был
утверждением, которое никто не проверял — 2 993 теста могли покраснеть во
вторник, а цвет бейджа остался бы прежним.

Теперь `tests.yml` гоняет весь набор на каждый push и каждый pull request, на
Python 3.10, 3.11 и 3.12 — тех самых трёх версиях, поддержку которых заявляет
`pyproject.toml`. Эти заявления тоже никогда не проверялись.

## Две зависимости существовали только на одной машине

Чтобы добавить CI, сначала пришлось признать: свежий клон вообще не может
запустить тесты:

- **`pytest` не был объявлен нигде** — ни в `pyproject.toml`, ни в `uv.lock`.
  Набор работал потому, что когда-то давно pytest поставили руками в локальный
  `.venv`. Любая команда `uv`, пересобирающая окружение из локфайла, тихо
  создавала окружение без тест-раннера.
- **С `kuzu` та же проблема, но злее.** Два теста обращаются к Kuzu-store без
  защиты `importorskip`, поэтому при его отсутствии они *падают*, а не
  пропускаются.

Оба теперь в группе зависимостей `dev`. Важно вот что: тестируемое окружение и
окружение, которое получает контрибьютор, теперь одно и то же. Это единственное
условие, при котором зелёный набор что-то значит.

## Локфайл разошёлся

`uv lock --check` падал на закоммиченном `uv.lock`: он рассинхронизировался с
`pyproject.toml`, в нём не хватало `markdownify` и `model2vec`. Любой, кто
запускает `uv sync --locked`, и любой CI, фиксирующий лок, натыкался на это сразу.

Лок перегенерирован, а воркфлоу использует `uv sync --locked` — при устаревшем
локе сборка краснеет, а не обновляется молча, так что тихо разойтись снова
не получится.

## Что CI нашёл за первые четыре минуты

Он покраснел на всех трёх версиях Python с одинаковыми падениями. Одинаково на
всех версиях — значит дело в платформе, а не в версии: два теста кодировали
свойства одной macOS-машины.

Пять из них запускали `hooks/_lib.sh` через `zsh`. На CI-раннерах zsh нет — а сама
библиотека документирует себя как POSIX-дружественную именно затем, чтобы не
зависеть ни от чьего логин-шелла.

Шестой стоит прочитать дважды. Он подменял `subprocess.run`, но тестируемый код
давно перешёл на `subprocess.Popen`, чтобы по таймауту убивать всю группу
процессов. Патч тихо стал пустышкой, и с тех пор тест дёргал **настоящий бинарник
`claude`** — проходя на машинах, где тот установлен и залогинен, и не утверждая
ровным счётом ничего о коде, чьё имя носит.

Ни то, ни другое не баг продукта. И то, и другое — тесты, которые не могли упасть
по правильной причине, и найти их, не запустив в другом месте, было невозможно.

## Демо-сайт заморожен

`build-demo.yml` удалён. Он компилировал Tesserae по её собственным исходникам на
каждый push в `main` и деплоил результат на GitHub Pages.

Последствие — говорим прямо, потому что его легко упустить:
[живое демо](https://ca1773130n.github.io/Tesserae) по-прежнему отвечает, README
по-прежнему на него ссылается, но переразвёртывать его больше нечему. Эта
страница теперь снимок на момент последнего запуска воркфлоу, и она будет тихо
расходиться с `main`. Переопубликовать — это ручной `tesserae export site` либо
новый воркфлоу.

Вместе с ним исчезло и единственное автоматическое покрытие пути
`init` → `compile` → `export site`. `tests.yml` гоняет юнит-набор и не проходит
этот путь целиком; теперь там стоит только ручной smoke из чек-листа публикации —
и в чек-листе это написано.

## Обновление с v0.28.4

Drop-in. Ни изменений API, ни изменений схемы, ни изменений поведения — каждый
коммит этого релиза трогает только конфигурацию CI, тестовые файлы, объявления
зависимостей или документацию. Перекомпилировать незачем.

Если вы ставите из исходников с зафиксированным локфайлом, это тот релиз, который
снова делает `uv sync --locked` рабочим.
