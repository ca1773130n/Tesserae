v0.12.0의 다중 프로젝트 `serve` 스토리를 완성하는 패치 릴리스입니다. v0.12.0 위의 드롭인 대체입니다.

## 모든 `/api/*`이 베어 서버에서 올바른 프로젝트로 라우팅됨

v0.12.0에서는 베어 `tesserae serve` (모든 등록된 프로젝트 서빙)가 `/api/ask`만 라우팅했으므로 — `/api/clip`과 `/api/transcript-search`는 404를 반환했고, **Chrome 클리퍼가 다중 프로젝트 서버에 클립할 수 없었으며** 프로젝트별 세션 검색이 작동하지 않았습니다. 이제 모든 엔드포인트가 라우팅됩니다:

- **`/api/ask`, `/api/ask/health`, `/api/transcript-search`** — 페이지의 `/<alias>/` Referer로 해당 프로젝트로 라우팅됩니다.
- **`/api/clip`** — 클립은 *외부* 웹 페이지에서 오므로 라우팅할 Tesserae Referer가 없습니다. 서버는 대상 프로젝트를 (1) 클립 본문의 `project` 별칭에서, (2) 등록된 프로젝트가 하나뿐인 경우 그 프로젝트에서, 또는 (3) 사용 가능한 별칭을 나열하는 `400`에서 해결합니다. **Chrome 확장 프로그램**은 `project`를 채우는 *Target project* 설정을 얻었습니다.

단일 프로젝트 `tesserae serve --project X`는 변경되지 않았습니다 — 그 보안성(확장 프로그램/루프백 CORS 게이트, 클립 토큰, 5 MB 본문 상한)은 바이트 동일합니다. 두 모드가 이제 하나의 구현을 공유하기 때문입니다.

트랜스크립트 검색은 두 개의 등록된 프로젝트가 디렉토리 이름을 공유할 때 `409`로 실패 폐쇄됩니다 (memex가 트랜스크립트를 기본이름으로 네임스페이스하므로 구별할 수 없음) — 한 프로젝트의 세션 기록을 다른 프로젝트로 혼합하는 것 대신에.

## 또한

- **문서** — `docs/ingest.md`는 v0.12.0 LLM 추출기를 위한 "개념 계층 구축(`--extractor`)" 가이드를 얻었습니다. cognee 백엔드의 `GRAPH_COMPLETION` 기본값과 fleet live-ask는 이제 문서화됩니다.

## v0.12.0에서 업그레이드

드롭인입니다. 베어 `tesserae serve`에서 특정 프로젝트로 클립하려면 확장 프로그램 옵션에서 **Target project**를 해당 프로젝트의 별칭으로 설정합니다.
