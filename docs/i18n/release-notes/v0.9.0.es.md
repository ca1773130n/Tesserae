Released **2026-06-14** · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

Una versión de características: una capa de memoria multi-granularidad portada desde AgentRunbook de LongMemEval-V2, y un conjunto de correcciones que hacen el backend LLM visible y honesto en lugar de fallar silenciosamente.

## 1. Memoria multi-granularidad estilo AgentRunbook

Una nueva capa de destilación opcional por encima de los hallazgos brutos de sesión — tres granularidades, todas byte-idempotentes (ids derivados del contenido, sin reloj de pared/RNG, fallback determinista) y opcionales de LLM:

- **`Event`** — registros por transición extraídos de los turnos de una sesión (seguimiento de estado dinámico), integrados en la extracción de hallazgos de sesión.
- **`Runbook`** — procedimientos reutilizables destilados para flujos de trabajo recurrentes (entre sesiones, ≥2 sesiones por defecto).
- **`Gotcha`** — modos de fallo recurrentes destilados / suposiciones equivocadas-aquí.

Además **recuperación multi-pool**: `compile_context(multi_pool=True)` descompone la consulta y reserva espacios de presupuesto para los nodos de memoria destilada más relevantes. Configurable a través de `tesserae compile --distill`, `tesserae context --multi-pool`, `distillation.enabled` en config, y el argumento MCP `compile_context` `multi_pool`. Todos desactivados por defecto, por lo que una compilación simple no cambia.

## 2. Un backend LLM visible y honesto

- **`tesserae config status`** — imprime el proveedor *resuelto* + codex-home / claude-dirs con la **fuente** de cada configuración (env > config de proyecto > `~/.tesserae/config.json` > por defecto), y un **ping en vivo**. Un backend limitado en tasa o mal autenticado ahora es obvio en lugar de invisible.
- **Fallos de extracción de sesión ruidosos** — la extracción ahora distingue "el modelo no devolvió nada" de "el modelo nunca respondió". Un fragmento fallido **ya no se almacena en caché como vacío** (se re-extrae una vez que el backend funciona), y la compilación imprime una advertencia inconfundible. Anteriormente, un backend limitado producía silenciosamente un gráfico con sesiones pero **cero hallazgos**.
- **El esfuerzo de razonamiento Codex** se fija a `medium` para las propias llamadas de Tesserae (configurable a través de `llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT`), por lo que un global `xhigh` establecido para codex interactivo ya no hace cada compilación muchas veces más lenta.

## 3. Endurecimiento de determinismo

- Los guardias de byte-idempotencia ahora ejercen la compilación determinista (sin LLM) que realmente garantizan — un LLM ambiental ya no los hace inestables.
- Una compilación sin LLM **re-emite resúmenes de comunidad en caché** en lugar de descartarlos, por lo que las recompilaciones permanecen estables en fluctuaciones de disponibilidad de LLM.

## Actualización desde v0.8.x

Drop-in. Todo lo nuevo es opcional o aditivo; un simple `tesserae compile` se comporta como antes. Ejecuta `tesserae config status` para confirmar en qué backend LLM estás.
