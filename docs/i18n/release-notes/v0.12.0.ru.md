Выпущено **2026-06-29** · [PyPI](https://pypi.org/project/tesserae/0.12.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.12.0) · `pip install --upgrade tesserae==0.12.0`

Концепция «активного проекта» больше не существует. Каждый зарегистрированный проект работает одновременно — `ask` маршрутизирует себя между ними, `serve` обслуживает все на одном сайте, а `compile` теперь может создавать слой LLM концепций, который опускает детерминированный экстрактор.

## Нет активного проекта — умный маршрутизатор `ask`

Концепция «активного проекта» исчезла: `tesserae projects activate` и инструмент MCP `activate_project` удалены, и каждая команда для конкретного проекта разрешает проект из директории, в которой вы находитесь. Все зарегистрированные проекты равны.

Простой `tesserae ask` теперь **маршрутизирует себя**:

- названием проекта → этот проект;
- сравнительное или общее → **объединённое** (один объединённый, перекрёстно ссылаемый ответ по объединению);
- продолжение («а почему?») сохраняет предыдущий маршрут; переход на новую тему («а что насчет *другого*?») перемаршрутизирует.

Ясные случаи разрешаются автоматически; необязательный разрыватель связей на базе LLM обрабатывает действительно неоднозначные ситуации, а краткая история разговора сохраняет согласованность в многовопросной цепочке. Явный флаг `--scope current|all-registered|federated` по-прежнему работает.

## Один сервер для каждого проекта — `tesserae serve`

Простой `tesserae serve` теперь обслуживает **каждый зарегистрированный проект** под одним сервером: целевая страница проектов в `/`, каждый проект в `/<alias>/`, переключатель проектов в заголовке и представления сессий для каждого проекта. Встроенный виджет запроса работает в реальном времени, перенаправленный на проект страницы, которая его запросила. `tesserae serve --project X` по-прежнему обслуживает отдельный проект. Запросы содержатся в пути (без выхода за пределы директории сайта проекта) и конечная точка запроса защищена одинаковым источником с ограничением размера запроса.

## Создание слоя концепций в `compile` — `--extractor`

`tesserae compile --extractor claude-cli` (или `--extractor selective-claude --claude-include "<glob>" --claude-limit N`) создаёт слой концепций/утверждений, который детерминированный стандарт оставляет разреженным — концепции, утверждения, возможности, диапазоны доказательств и типизированные рёбра. Он укреплён для реальных корпусов, где один шумный или медленный документ обычно прерывал всю компиляцию:

- тип рёбра вне контролируемого словаря **отбрасывается**, не смертельно;
- документ, превышающий временное ограничение на один документ, **переходит** на детерминированное извлечение для этого файла;
- мимолётное неверное поколение **повторяется** (модель недетерминирована, поэтому повторный вызов почти всегда подтверждает).

## Также в этом выпуске

- **Совместимость с Cognee 1.0** — Cognee 1.0 удалил тип поиска `INSIGHTS`, на который Tesserae по умолчанию полагалась, что молча нарушило бэкэнд cognee `ask`. Теперь он отображается на `GRAPH_COMPLETION` (ответ над графом знаний), поэтому cognee работает снова; передайте `--cognee-search-type CHUNKS` для сырого извлечения.
- **`tesserae setup`** — настройка верхнего уровня, интерактивная установка на уровне машины (провайдер LLM/усилие + какие дополнительные зависимости установить); флаги пропускают подсказки, и установки работают в окружениях без pip `uv tool`.
- **Документы** — README, быстрый старт, установка, руководство MCP, карта функций и руководства по интеграции обновлены для указанного выше (больше никакого «активного проекта»).

## Обновление с v0.11.x

В основном совместимо. **Критическое изменение:** `tesserae projects activate` и инструмент MCP `activate_project` удалены — команды для конкретного проекта разрешаются по текущей директории, и `ask` маршрутизирует между вашими проектами автоматически. Если вы использовали скрипт `projects activate`, просто удалите его. Использование одного проекта не изменилось.
