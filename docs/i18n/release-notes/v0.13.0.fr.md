Tesserae est un wiki LLM — ainsi `compile` construit maintenant la **couche de concepts/affirmations par défaut**, et non simplement un squelette structural.

## `compile` construit la couche conceptuelle par défaut

Auparavant, `tesserae compile` exécutait l'extracteur **déterministe** par défaut : rapide et byte-stable, mais structural uniquement — sources, sections et liens explicites, avec une couche conceptuelle clairsemée. La couche plus riche (concepts, affirmations, capacités, termes techniques, spans de preuve, et les liens typés entre eux) était cachée derrière un drapeau opt-in réservé à Claude, `--extractor claude-cli`. Pour un wiki LLM, c'était à l'envers.

Maintenant :

- **`--extractor llm` est le comportement par défaut.** `tesserae compile` lit chaque document via votre **fournisseur configuré** — codex / claude / Anthropic API, selon `llm_provider` — en utilisant la même session `LLMJsonClient` que l'extraction de session utilise déjà. Plus de chemin exclusif à Claude.
- **`deterministic` est l'opt-out explicite** — `tesserae compile --extractor deterministic` pour le mode rapide, sans clé, byte-stable (CI / builds reproductibles). L'idempotence des bytes est inchangée ; c'était toujours une propriété de ce mode.
- **Pas de timeout par défaut.** L'ancien `--claude-timeout=180` tronquait silencieusement les gros documents de conception en repli dégradé. L'extraction s'exécute maintenant jusqu'au bout ; un timeout est opt-in uniquement.
- **Drapeaux indépendants du fournisseur :** `--llm-provider`, `--llm-model`, `--llm-include`, `--llm-limit`. (`claude-cli` / `selective-claude` et les drapeaux `--claude-*` fonctionnent toujours en tant qu'alias dépréciés.)
- **Robuste et gracieux.** Pas de backend configuré ? Il bascule vers déterministe avec un avertissement plutôt que d'échouer. Une erreur de backend sur un document bascule vers déterministe pour ce document au lieu d'abandonner l'intégralité de la compilation, et la mise en cache basée sur le contenu signifie qu'une recompilation des documents inchangés réutilise l'extraction antérieure.

```bash
tesserae compile                        # LLM concept layer, your configured provider
tesserae compile --extractor deterministic   # structural / byte-stable / key-free
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # cost-aware
```

## `ask` fédéré plus rapide

L'`ask` fédéré réassemblait le graphe multi-projets (lire + analyser + créer l'espace de noms + fusionner les identités de chaque projet membre) à *chaque* requête — environ un quart de la latence, refait pour chaque réponse en suivi dans une conversation contre le même ensemble de projets. Le graphe assemblé est maintenant mis en cache en processus, indexé sur la signature de changement du fichier graphe de chaque membre : une requête répétée est un cache hit instantané, et l'entrée **s'invalide automatiquement dès qu'un projet membre recompile** (pas de cache disque, pas d'obsolescence). Sur une fédération réelle de 6 projets / 22,6k nœuds, c'est environ 0,6 s d'assemblage ignorées par requête répétée.

## Mise à jour depuis v0.12.x

L'unique changement de comportement : `tesserae compile` effectue maintenant l'extraction LLM par défaut. Si vous voulez l'ancien comportement structural uniquement (par exemple en CI, ou sans backend LLM), passez `--extractor deterministic` — et sur une machine sans fournisseur configuré, la compilation bascule déjà automatiquement vers lui.
