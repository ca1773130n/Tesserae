## 密ベクトルレーンが学習済みエンコーダを要求できる

論文 148 本のコーパスでは、同梱の静的 `model2vec` 埋め込み器がグラフと素のベクトル
ストアの差のすべてだった。同じ融合、同じグラフ、同じ文書重複排除での、文書単位の
再現率:

| 方式 | @10 文書 | @50 文書 |
| --- | --- | --- |
| Mem0 OSS の生チャンクストア、自前のエンコーダ | 0.784 | 0.942 |
| Mem0 OSS の生チャンクストア、同じ bge-base | 0.775 | 0.944 |
| Tesserae、同梱の静的 model2vec | 0.754 | 0.914 |
| **Tesserae、密ベクトルレーンに bge-base** | **0.791** | **0.962** |

呼び出し側が `auto` を要求したとき、`TESSERAE_EMBEDDING_PREFER` がバックエンドを
選ぶ(`model2vec`、`st`、`openai`、`hash`)。どのバックエンドも指さない値は、黙って
ハッシュのスタブに落ちるのではなく、報告されたうえで無視される。
`TESSERAE_ST_MODEL` は sentence-transformers モデルを指定し、既定値は未測定の
`all-MiniLM-L6-v2` から測定済みの `BAAI/bge-base-en-v1.5` に変わる。

```bash
uv pip install sentence-transformers
export TESSERAE_EMBEDDING_PREFER=st
export TESSERAE_ST_MODEL=BAAI/bge-base-en-v1.5   # the default; any Hugging Face name
```

auto のはしごは変わらない: `model2vec` が最初なので `pip install tesserae` は torch
なしのままで、この変数を一度も設定していないインストールは以前とまったく同じに
振る舞う。

## 測定が実際に示したこと

同じエンコーダを与えれば、グラフと生チャンクストアは同じ文書を見つける: 57 問で
対応をとると、文書 10 件では 8 勝 8 敗 41 分けである(符号検定 p=1.0)。これは同等で
あり、ドキュメントも同等と述べるようになった — 以前の文言はグラフが前に出ていると
書いていたが、それは異なる二つのエンコーダを比べていた。

リトリーバはまた、LongMemEval 自身の日付スタンプと指示文を見なくなった。これまでは
どの腕でもクエリの一部だった。

## 設計が実際に異なるところ

グラフが選んだ文書を、抽出された主張ではなく原文の散文として詰めると、
`gpt-4o-mini` のジャッジではパッセージ対照に対して +28.9% だった。ローカルの 7B
ジャッジで再実行すると +7% で有意ではなく、二つ目のコーパスでは負ける。README は
最良の数字ではなく三つすべてを載せている。

## アップグレード

移行作業はない。既存のグラフは影響を受けず、ノブはオプトインで既定のバックエンドは
変わらない。
