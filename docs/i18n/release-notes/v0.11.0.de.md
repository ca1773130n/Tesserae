Veröffentlicht **2026-06-27** · [PyPI](https://pypi.org/project/tesserae/0.11.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.11.0) · `pip install --upgrade tesserae==0.11.0`

Ein Feature-Release: **Fragen Sie gleichzeitig alle Ihre registrierten Projekte ab** und erhalten Sie eine einzelne, projektübergreifend referenzierte und zitierte Antwort. Direkt kompatibel mit v0.10.x.

## Projektübergreifende Föderierung

`tesserae ask --scope federated --scope-aliases research work "…"` (und das MCP `ask` Tool mit `scope: "federated"`) montiert **einen** Graph aus den benannten Projekten zusammen und gibt eine einzelne Antwort zurück, die sie projektübergreifend referenziert — anstelle der `all-registered` Fan-Out, die eine Antwort pro Projekt zurückgibt. Die projektspezifische `.tesserae/graph.json` wird nie verändert; die Föderierung wird zum Zeitpunkt der Abfrage im Speicher zusammengebaut.

Projekte verbinden sich auf zwei Wegen:

- **Identitätsführung (immer aktiviert).** Die gleiche *Entität* über Projekte hinweg — gleiche arXiv-ID, Repository, Content-Hash oder Code-Symbol — kollabiert zu einem Knoten. Hochpräzise, deterministisch, keine Embeddings. Ein Papier, das Sie in `research` geclippt und in `work` referenziert haben, wird also zu einem einzelnen zitierten Knoten.
- **Semantische Links (standardmäßig aktiviert, Abwahl möglich).** Die gleiche *Idee* in anderen Worten — z.B. eine Caching-Entscheidung in `work` und ein Cache-Papier in `research` — erhält einen durch Embeddings unterstützten projektübergreifenden Link, sodass der Abruf *verwandte*, nicht nur identische, Konzepte überbrücken kann. Gewichtet nach unten, so dass ein Identitätsmatch immer einen unscharfen Bridge-Match übertrumpft. Geben Sie `--no-semantic` für nur-Identität an. Benötigt ein echtes Embedding-Backend (`pip install tesserae[semantic]`); ohne eines degradiert es elegant und teilt dies mit.

Der Link-Schwellwert (`0.55`) und die Bridge-Gewichtung (`0.5`) sind keine Schätzungen — sie werden aus einer Präzisions-/Abruf- + Swamping-Evaluierung eingestellt (`evals/federation/`, geschützt in CI).

## Inspizieren Sie es

- `tesserae federation status [aliases] [--semantic]` — Knotenzählungen pro Projekt, Identitätsführungen, Semantische-Link-Zählungen.
- `tesserae federation explain <node> [aliases]` — warum ein Knoten Projekte überbrückt: welche Projekte er identitätsmäßig über zusammengebracht hat und seine semantischen Links (mit Ähnlichkeit und Zielprojekt). Akzeptiert eine Namespace-ID oder eine zusammengebrachte ID.

Föderierte semantische Links werden in `~/.tesserae/federation/` gepuffert, mit Projektinhalt als Schlüssel, so dass sich der Cache automatisch invalidiert, wenn ein Projekt neu kompiliert.

## Ebenfalls in diesem Release

- **Chrome-Erweiterung** — die README dokumentiert nun den korrekten Standard-Endpoint (`http://127.0.0.1:8765`, IPv4), um mit dem Standard der ausgelieferten Erweiterung übereinzustimmen.

## Upgrade von v0.10.x

Drop-in. Föderierung ist pro Abfrage opt-in (`--scope federated`); nichts ändert sich für Single-Project-Use. Für semantisches Brückenbau, `pip install tesserae[semantic]`.
