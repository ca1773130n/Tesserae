リリース **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.7/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.7) · `pip install --upgrade tesserae==0.41.7`

v0.41.6 では、2 回目の Ctrl-C や SIGTERM で `tesserae engine` がコンパイルの途中でも止まるようになりました。
コンパイルが走るメインスレッドで例外を発生させる方法です。フリートモード `tesserae engine --all` は
古い挙動のままでした。そこでは各プロジェクトが自分のスレッドでコンパイルするためこの方法が届かず、
フリートは最初より後のシグナルにはすべて、コンパイルが終わるのを待つことでしか応えませんでした。
抜け出す手段は SIGKILL しかなく、そうすると `claude -p` の子プロセスがどれも自分のセッションで動き続け、課金も続きました。

## 何が変わったか

- **2 回目のシグナルでフリートが止まります。** フリートの pidfile と自分が書いたプロジェクトの pidfile を削除し、
  実行中の CLI エージェントをすべて終了して新たな起動を拒み、慣例どおりの終了ステータスで終了します。
  失われるものはありません。各プロジェクトの次回のコンパイルがマニフェストの差分から変更されたソースを見つけます。
- **最初のシグナルがすべてのプロジェクトに同時に届きます。** 以前はプロジェクトを 1 つずつ止めていたため、
  最初のプロジェクトがコンパイルを終えるまでの間、残りは変更の監視を続け、停止の後に新しいコンパイルを
  始めることがありました。各プロジェクトは今も手元の作業を終えてから止まり、フリートは
  `signal again to stop now` と知らせるようになりました。

## アップグレード

移行作業はありません。実行中のフリートは再起動してください。`engine --all --once` や通常の
`tesserae compile` に送った SIGTERM は、今もプロセスを即座に終了させ、`claude -p` の子プロセスを
残すことがあります。Ctrl-C はどちらにも対応しています。
