发布于 **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.1/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.1) · `pip install --upgrade tesserae==0.37.1`

配置自定义 LLM 提供商之前无法工作，原因有三个相互独立，症状每次都是关于一个从未配置过的模型的错误。对提供商代码的审计确认了 23 个缺陷；本次发布修复了它们。

## 线路协议从未被建模

`llm_provider` 混淆了*哪个后端*和*哪个 HTTP 方言*，而 `custom` 总是构建 Anthropic 客户端，它发送到 `{base}/v1/messages`。每个 OpenAI 兼容的服务器——vLLM、LiteLLM、OpenRouter、Together、Ollama、LM Studio——都对此回复 404。唯一能说 `chat/completions` 的类是由任何代码路径都没有构建过的，并且硬编码了 `api.openai.com`，所以它也无法为您的端点提供服务。

现在 `llm_api_style` 命名了线路，是唯一选择客户端的东西。如果不设置，对于 `custom` 来说它保持 `anthropic`，因此现有的自定义配置的行为完全相同。

```bash
# 一个 OpenAI 兼容端点（vLLM、LiteLLM、OpenRouter、Ollama、LM Studio）
tesserae config llm --llm-provider custom --llm-api-style openai \
  --llm-base-url https://gw.example/v1 --llm-model qwen3-coder --llm-auth-token sk-…

# 一个 Anthropic 兼容端点——没有 /v1，SDK 会附加它
tesserae config llm --llm-provider custom --llm-api-style anthropic \
  --llm-base-url https://gw.example --llm-model my-model --llm-api-key sk-…

tesserae config status --project .
```

## 模型被丢弃了，其他东西给出了答复

配置的 `llm_model` 的范围被限定在提供了 `llm_provider` 的配置*层*——通过标志设置提供商，在配置文件中设置模型，您的模型会被丢弃而取代以硬编码的默认值。然后自定义端点降级到 Claude CLI，CLI 使用 `--model sonnet` 针对您自己的基础 URL 启动，并报告不支持的模型。没有东西会指出真正的原因。

显式配置的**端点**提供商（`anthropic`、`openai`、`custom`）现在是一个契约：它单独构建，失败时会抛出一个命名了提供商、线路、基础 URL、模型和使用的凭证类型的错误。`llm_allow_fallback: true` 恢复了旧的链式方式。两个 OAuth CLI 仍然彼此回退，因为都不携带您自己的端点。

## 没有承载者凭证

一个 `llm_api_key` 被 SDK 作为 `X-Api-Key` 发送，作为承载令牌由 CLI 发送，并且将其传递给 SDK 会抑制 SDK 自己的 auth-token 解析——所以要求 `Authorization: Bearer` 的网关是不可达的。`llm_auth_token` 是两条线路上的承载凭证。

## 可以看到的配置

每个键都有一个优先级：`TESSERAE_LLM_*` 环境变量 → 项目 `.tesserae/config.json` → `~/.tesserae/config.json` → 默认，其中遗留的 `ANTHROPIC_*` 变量低一级。解析器记录哪个层赢得了每个键，`tesserae config status` 会打印出来——它过去是猜测的，并归功于解析器刻意忽略的环境变量。Status 还显示线路、凭证类型和为其探针提供服务的客户端。

`ask`、`query`、lint、MCP 摘要和引擎守护程序只针对环境和全局配置进行解析，所以项目级端点由 `compile` 尊重，但在其他任何地方都被默认忽略。现在它们都读取项目。

## 还有

- 无效的 `llm_provider` 被报告而不是默认变成 `claude`。
- Anthropic 基础 URL 被规范化，修复了这个项目自己的快速开始文档中的重复 `/v1/v1/messages`。
- `401`/`403` 被分类为认证失败，`404`/模型未找到被分类为端点失败，而不是都报告为"不可用"。
- `init` 和 `setup` 保存了新的键；它们过去接受并丢弃它们。

## 升级

无需迁移。两个可见的变化：明确的端点提供商不再降级到不同的后端，`config status` 打印凭证*类型*而不是 `set`/`unset`。
