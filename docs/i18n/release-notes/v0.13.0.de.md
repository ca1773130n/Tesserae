Tesserae ist ein LLM-Wiki — daher erstellt `compile` nun standardmäßig die **Konzept-/Anspruchsebene**, nicht nur ein strukturelles Gerüst.

## `compile` erstellt standardmäßig die Konzeptschicht

Zuvor führte `tesserae compile` standardmäßig den **deterministischen** Extraktor aus: schnell und byte-stabil, aber nur strukturell — Quellen, Abschnitte und explizite Links, mit einer spärlichen Konzeptebene. Die reichere Ebene (Konzepte, Ansprüche, Fähigkeiten, technische Begriffe, Evidenzspannen und die typisierten Kanten zwischen ihnen) war hinter einem optionalen, nur für Claude `--extractor claude-cli` Flag verborgen. Für ein LLM-Wiki war das rückwärts.

Jetzt:

- **`--extractor llm` ist der Standard.** `tesserae compile` liest jedes Dokument durch Ihren **konfigurierten Provider** — codex / claude / Anthropic API, pro `llm_provider` — unter Verwendung derselben `LLMJsonClient` Sitzungsextraktion, die bereits vorhanden ist. Kein reiner Claude-Pfad mehr.
- **`deterministic` ist der explizite Opt-out** — `tesserae compile --extractor deterministic` für den schnellen, schlüssellosen, byte-stabilen Modus (CI / reproduzierbare Builds). Byte-Idempotenz ist unverändert; es war immer eine Eigenschaft dieses Modus.
- **Kein Standard-Timeout.** Das alte `--claude-timeout=180` hat große Design-Dokumente stillschweigend auf einen fehlerhaften Fallback gekürzt. Extraktion wird nun bis zur Fertigstellung ausgeführt; ein Timeout ist nur auf Opt-in Basis verfügbar.
- **Provider-neutrale Flags:** `--llm-provider`, `--llm-model`, `--llm-include`, `--llm-limit`. (`claude-cli` / `selective-claude` und die `--claude-*` Flags funktionieren weiterhin als veraltete Aliase.)
- **Robust + elegant.** Kein Backend konfiguriert? Es wird mit einer Warnung auf deterministisch herabgestuft, anstatt zu fehlschlagen. Ein Backend-Fehler bei einem Dokument fällt zurück auf deterministisch für dieses Dokument, anstatt die gesamte Kompilierung abzubrechen, und inhaltsgesteuerte Caching bedeutet, dass eine Neukompilierung von unveränderten Dokumenten die vorherige Extraktion wiederverwendet.

```bash
tesserae compile                        # LLM concept layer, your configured provider
tesserae compile --extractor deterministic   # structural / byte-stable / key-free
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # cost-aware
```

## Schnellerer föderierter `ask`

Föderierter `ask` montierte den projektübergreifenden Graphen (lesen + parsen + Namespace + Identitätsmerge für jedes Mitgliedsprojekt) bei *jeder* Abfrage wieder zusammen — etwa ein Viertel der Latenz, für jede Folgefrage in einem Gespräch gegen denselben Projektbestand wiederholt. Der montierte Graph wird nun in-process memoized, gekennzeichnet durch die Änderungssignatur jedes Mitglieds: eine wiederholte Abfrage ist ein sofortiger Cache-Hit, und der Eintrag **invalidiert sich selbst, sobald ein Mitgliedsprojekt neu kompiliert wird** (kein Disk-Cache, keine Veraltung). Bei einer realen 6-Projekt- / 22.6k-Knoten-Föderation sind das ~0,6 s Assembly, die pro wiederholter Abfrage übersprungen werden.

## Upgrade von v0.12.x

Die eine Verhaltensänderung: `tesserae compile` führt nun standardmäßig LLM-Extraktion durch. Wenn Sie das alte strukturelle Verhalten mögen (z. B. in CI oder ohne LLM-Backend), übergeben Sie `--extractor deterministic` — und auf einem Computer ohne konfigurierten Provider wird compile bereits automatisch darauf zurückgreifen.
