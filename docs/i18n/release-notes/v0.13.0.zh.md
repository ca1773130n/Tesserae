发布于 **2026-06-30** · [PyPI](https://pypi.org/project/tesserae/0.13.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.13.0) · `pip install --upgrade tesserae==0.13.0`

Tesserae 是一个 LLM wiki — 因此 `compile` 现在默认构建 **concept/claim 层**，而不仅仅是结构框架。

## `compile` 默认构建概念层

之前，`tesserae compile` 默认运行 **deterministic** 提取器：快速且字节稳定，但仅限结构 — 源文件、章节和显式链接，概念层稀疏。更丰富的层（概念、声明、功能、技术术语、证据跨度及其间的类型化边）隐藏在可选的、仅限 Claude 的 `--extractor claude-cli` 标志后面。对于 LLM wiki 来说，这是颠倒的。

现在：

- **`--extractor llm` 是默认值。** `tesserae compile` 通过你的 **配置的提供商** 读取每个文档 — codex / claude / Anthropic API，根据 `llm_provider` — 使用与会话提取已使用的相同 `LLMJsonClient`。不再是仅限 Claude 的路径。
- **`deterministic` 是显式的退出选项** — `tesserae compile --extractor deterministic` 用于快速、无密钥、字节稳定模式（CI / 可重现构建）。字节幂等性未变；它总是此模式的属性。
- **无默认超时。** 旧的 `--claude-timeout=180` 无声地将大型设计文档截断为降级后备。提取现在运行到完成；超时是可选的。
- **提供商中立标志：** `--llm-provider`、`--llm-model`、`--llm-include`、`--llm-limit`。（`claude-cli` / `selective-claude` 及 `--claude-*` 标志仍作为已弃用别名工作。）
- **强大 + 优雅。** 没有配置后端？它会优雅降级为 deterministic 并显示警告，而不是失败。一个文档的后端错误会为该文档回退到 deterministic，而不是中止整个编译，内容密钥缓存意味着重新编译未更改的文档会重用之前的提取。

```bash
tesserae compile                        # LLM concept layer, your configured provider
tesserae compile --extractor deterministic   # structural / byte-stable / key-free
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # cost-aware
```

## 更快的联合 `ask`

联合 `ask` 在 *每次* 查询时重新组装跨项目图（读取 + 解析 + 命名空间 + 标识合并每个成员项目）— 约四分之一的延迟，对于针对同一项目集的对话中的每次后续查询重做。组装的图现在在进程中被记忆化，以每个成员的图文件更改签名为键：重复查询是即时缓存命中，条目 **在任何成员项目重新编译的瞬间自动失效**（无磁盘缓存，无陈旧性）。在真实的 6 项目 / 22.6k 节点联合上，这是每次重复查询跳过的约 0.6 秒组装。

## 从 v0.12.x 升级

唯一的行为变化：`tesserae compile` 现在默认执行 LLM 提取。如果你想要旧的仅结构行为（例如在 CI 中，或没有 LLM 后端），传递 `--extractor deterministic` — 在没有配置提供商的机器上，编译已经自动回退到它。
