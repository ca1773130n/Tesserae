发布于 **2026-08-24** · [PyPI](https://pypi.org/project/tesserae/0.33.1/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.33.1) · `pip install --upgrade tesserae==0.33.1`

这是一个关于回答 prompt、以及本应盯着它的那些对照组的补丁版本。两者衡量的都不是它们自称衡量的东西。

## 每一份进入排名的文档都被粘贴了两次

`_build_synthesis_message` 在同一个语料库上跑两条通道。文档通道按索引文档的单元目录记录自己输出了什么——一篇论文是 `abstract.md` 加 `paper.md`，以容纳它们的目录为键。而命中通道问的却是某个*文件*路径是否在那个集合里。文件路径永远不等于它的父目录，所以这道防护什么也没拦住，融合通道已经粘贴过的每一份文档都被原样再粘贴了一遍。

在演示语料库上，这份重复占**每个无关系 prompt 的 15.6%**——每次规划器回答的输入 token 账单中有六分之一，花在向模型重复展示它已经看过的文本上。现在 `_unit_of` 让两条通道共用一个键空间，并且是实际输出、而非读取的决定，才把一个单元标记为已输出。

## 一个区块只有与问题共享稀有词才会被放行

合成 prompt 原本是混合基线的 prompt 再加上一条更弱的第二通道：中位数约 8 个额外区块，占证据字符的 30.7%。它换来的是标准答案覆盖率 0.388 对 0.303——以及弃答对照组上的编造率 **52.9% 对 38.2%**。更多擦身而过的材料会通过同一个机制把两者一起抬高。

排名无法把额外通道里有用的区块和擦身而过的区块分开；基于排名的判别力实测 AUC 0.474，即随机水平。稀缺性可以。一个在语料库中出现率不超过 5% 的问题词，会把区块锚定到*那个*问题上。融合前 10 名和 `kg:` 区块仍然无条件通过，因此产出持平 token F1 的那一路逐字节未变——在全部 352 个演示问题上验证，0 个文档区块和 0 个 kg 区块发生变化。

## 协议门拒绝了真相，接受了虚构

当被问及一次公开基准比较是否只差一个密钥时，这道本该拦下不可引用主张的门，靠敲几个标志就能被满足。一份手写的 `answers.json` 声称四项对照全部达标，返回了零条阻断；而针对真实 OpenAI 嵌入器的诚实运行却**失败了**，因为后端把自己命名为 `openai:text-embedding-3-small`，协议里握着的却是裸模型名。

现在声明是需要证据的主张，会记录 `answer_calls` 和 `judge_calls`，因为一次运行能记录自己做了什么，而手写文件不能。评判对照组现在被刻意且显眼地设成任何运行都无法满足：本仓库中没有任何评判实现，于是这道门直说这一点，而不是让一个标志的默认值冒充实物。

## 配对的系统要用配对的检验

在同一批问题上评分的两个系统是配对数据，比较它们的边际比率就是丢掉这层配对。在编造问题上这一点是决定性的：6/48 对 2/48 的 Fisher **p = 0.268**，而扩大探针集合并没有用，因为边际检验看不出两个系统是在同一批问题上失败，还是在不同问题上失败。

`mcnemar` 以不一致对为条件，采用精确双侧二项检验而非卡方，因为这个基准产生的是个位数计数。返回 `n_discordant` 是有意为之——样本量是它，而不是总数。

## 无语料库规则赢不了的对照组

原有的 48 个弃答对照组并没有衡量弃答。相对于实际集合的 57 词，它们只有 31 词，于是“凡不足 40 token 一律拒答”——一条完全不接触语料库的规则——拿到 2.1% 幻觉率和 4.6% 过度拒答率，胜过一切真正的知识信号。今天之前报告的每一个幻觉数字都出自那个集合。

取而代之的是 68 个对照组，按长度对齐撰写，然后不是照单全收而是加以攻击。在新集合上，旧的漏洞打法在相同过度拒答率下拿到 **100%** 幻觉率，而单靠词数的 AUC 从 0.988 跌到 0.456。
