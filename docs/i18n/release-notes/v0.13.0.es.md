Tesserae es un wiki de LLM — así que `compile` ahora construye la **capa de concepto/afirmación de forma predeterminada**, no solo un esqueleto estructural.

## `compile` construye la capa de concepto de forma predeterminada

Anteriormente, `tesserae compile` ejecutaba el extractor **determinístico** de forma predeterminada: rápido y estable en bytes, pero solo estructural — fuentes, secciones y enlaces explícitos, con una capa de concepto escasa. La capa más rica (conceptos, afirmaciones, capacidades, términos técnicos, tramos de evidencia y los bordes tipados entre ellos) estaba oculta detrás de una marca `--extractor claude-cli` opcional exclusiva de Claude. Para un wiki de LLM, eso era al revés.

Ahora:

- **`--extractor llm` es el predeterminado.** `tesserae compile` lee cada documento a través de tu **proveedor configurado** — codex / claude / API de Anthropic, según `llm_provider` — usando la misma sesión `LLMJsonClient` que ya usa la extracción. No más ruta exclusiva de Claude.
- **`deterministic` es la exclusión explícita** — `tesserae compile --extractor deterministic` para el modo rápido, sin clave, estable en bytes (CI / compilaciones reproducibles). La idempotencia de bytes no ha cambiado; siempre fue una propiedad de este modo.
- **Sin tiempo de espera predeterminado.** El antiguo `--claude-timeout=180` truncaba silenciosamente documentos de diseño grandes en un respaldo degradado. Ahora la extracción se ejecuta hasta completarse; un tiempo de espera es opcional solo.
- **Marcas neutrales del proveedor:** `--llm-provider`, `--llm-model`, `--llm-include`, `--llm-limit`. (`claude-cli` / `selective-claude` y las marcas `--claude-*` todavía funcionan como alias deprecados.)
- **Robusto + elegante.** ¿No hay ningún backend configurado? Se degrada a determinístico con una advertencia en lugar de fallar. Un error de backend en un documento se revierte al determinístico para ese documento en lugar de abortar toda la compilación, y el almacenamiento en caché con clave de contenido significa que una recompilación de documentos sin cambios reutiliza la extracción anterior.

```bash
tesserae compile                        # LLM concept layer, your configured provider
tesserae compile --extractor deterministic   # structural / byte-stable / key-free
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # cost-aware
```

## Preguntas federadas más rápidas `ask`

La consulta federada `ask` reensamblaba el gráfico entre proyectos (lectura + análisis + espacio de nombres + fusión de identidad de cada proyecto miembro) en *cada* consulta — aproximadamente una cuarta parte de la latencia, rehecha para cada seguimiento en una conversación contra el mismo conjunto de proyectos. El gráfico ensamblado ahora se memoriza en el proceso, codificado en la firma de cambio del archivo gráfico de cada miembro: una consulta repetida es un golpe de caché instantáneo, y la entrada **se auto-invalida en el momento en que cualquier proyecto miembro se recompila** (sin caché de disco, sin obsolescencia). En una federación real de 6 proyectos / 22,6k nodos, eso es un ensamblaje de ~0,6 s omitido por consulta repetida.

## Actualización desde v0.12.x

El único cambio de comportamiento: `tesserae compile` ahora realiza la extracción de LLM de forma predeterminada. Si quieres el antiguo comportamiento de solo estructura (por ejemplo, en CI, o sin backend de LLM), pasa `--extractor deterministic` — y en una máquina sin proveedor configurado, la compilación ya se revierte automáticamente.
