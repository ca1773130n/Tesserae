发布日期 **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.1) · `pip install --upgrade tesserae==0.7.1`

`tesserae ingest <file|url>` 是一个新的顶级命令，它将**单个**文档或 URL 合并到你的知识库中——无需重新提取整个语料库——同时与完整编译保持**逐字节一致**。放入一个文件，或将其指向一个网页，你的图谱便会增量更新，而不必每次都为完整重新编译付出代价。

## 1. `tesserae ingest <input>...` — 增量式单源摄取

这个新命令接受一个或多个输入——本地文件路径或 `http(s)` URL——并将每一个独立地折叠进现有的知识库。它有别于 `tesserae code ingest`：这是将文档/来源摄取到主图谱中，而非代码索引。

默认情况下，`ingest` 运行一条仅触及新来源的**增量快速路径**。该快速路径是*受奇偶校验门控的*：它经过验证与完整编译逐字节一致，并且如果无法保证一致性，它会自动回退到完整重新编译，因此正确性绝不会受到威胁。传入 `--exact` 可自行强制执行完整重新编译。

标志：`--exact`、`--dry-run`、`--title`、`--source-kind`。

## 2. URL 会被获取、转换，并带着溯源信息被跟踪

给 `ingest` 一个 `http(s)` URL，它便会获取该页面，将其转换为 markdown，并将其作为受跟踪的来源持久化到 `data/ingested/<slug>.md` 下，附带溯源 front-matter：`source_url`、`fetched_at`、`content_sha256`，以及当来源被检测为 arXiv 论文时的 `arxiv_id`。

URL 摄取由一个新的可选 extra 提供，以保持基础安装的精简：

```
pip install tesserae[ingest-url]
```

## 3. 语料库之外的本地文件会成为语料库的一部分

当你摄取一个位于受跟踪语料库之外的本地文件时，`ingest` 会将其复制进语料库。这样一来，之后的完整 `tesserae compile` 便能重现完全相同的结果——增量摄取与从头编译会收敛到相同的字节。

## 4. 底层机制：一条保持一致性的增量接缝（seam）

增量快速路径建立在编译流水线中一个按调用的 `incremental_override` 接缝之上。它**默认是惰性的（inert）**——当没有任何东西覆盖它时，引擎的行为与以往完全相同，完整编译的一致性得以保留。一个黄金一致性测试为该功能门控，断言增量摄取与完整编译产生逐字节一致的输出。

## 加固

溯源 front-matter 现在通过一条 YAML 安全的路径写入，从而堵住了 front-matter 值注入（精心构造的标题或 URL 不再能逃出 front-matter 块）。

## 从 v0.7.0 升级

可直接替换。`tesserae ingest <file>` 对本地文件开箱即用。要摄取 URL，请用 `pip install tesserae[ingest-url]` 安装该 extra。现有的 `tesserae compile` / `refresh` 行为不变——除非由 `ingest` 驱动，否则该增量接缝保持惰性。
