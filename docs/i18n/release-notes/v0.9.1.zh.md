发布于 **2026-06-19** · [PyPI](https://pypi.org/project/tesserae/0.9.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.1) · `pip install --upgrade tesserae==0.9.1`

一个 bugfix 版本。无 API 变化 — 可直接升级自 v0.9.0。

## Fixes

- **不再有自我捕获反馈循环。** 会话监视器曾把 Tesserae 自己的编译时 codex/claude 调用（提取、综合、蒸馏等）记录为你的工作会话，导致会话数据库泛滥，使下一次编译"提取发现"来自它自己的提取调用。现在在发现和实时追踪时将其排除，使用 `tesserae sessions prune-internal` 来清理修复前被污染的数据库。

- **引擎不再错误地报告"已在运行"。** 当引擎死亡而未清理其 pidfile，并且操作系统后来将该 PID 回收给无关进程时，简单的活动检查会通过且引擎拒绝启动。pidfile 现在记录每个化身的标识（进程启动时间），只有当 PID 存活且其标识仍然匹配时，才将锁视为已持有，所以陈旧的 pidfile 可以自我修复。

- **Chrome 扩展隐私政策。** 添加了"Clip to Tesserae"扩展的完整隐私政策（Chrome Web Store 所需）。

## 从 v0.9.0 升级

即插即用。如果项目的会话列表看起来被 Tesserae 自己的提示污染，请运行一次 `tesserae sessions prune-internal`。
