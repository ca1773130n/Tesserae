Выпущено **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

Агенты — первоклассные потребители Tesserae, но после разделения команд в 0.18 две возможности существовали только в CLI. Этот релиз закрывает оба пробела новыми MCP-инструментами.

## `query` — сырой поиск через MCP

Зеркалирует `tesserae query`: детерминированный BM25/семантический поиск по скомпилированной вики с `top_k` и фильтром `kind`, с гарантией никогда не обращаться к LLM (`force_no_llm` на всём пути). `backend: "raganything"` достигает опционального мультимодального RAG-индекса — у которого **вообще не было MCP-пути** с тех пор, как `ask` лишился параметра backend при разделении 0.18. Используйте `ask`, когда нужен синтезированный ответ с цитатами; используйте `query`, когда нужны сами ранжированные свидетельства.

## `doctor_run` — свежие проверки здоровья через MCP

`doctor_report` (0.18) отдавал только последний сохранённый отчёт — агент, попавший в проект, где doctor ни разу не запускался, не получал ничего. `doctor_run` выполняет полный реестр из 20 проверок по требованию и возвращает результаты в JSON с кодом выхода 0/1/2. Он **всегда только для чтения**: исправления никогда не выполняются через MCP и никакой артефакт отчёта не записывается; ремонт остаётся явным действием человека через `tesserae doctor --fix`.

## Всё остальное уже работало

Для остальных возможностей 0.18–0.19 изменений не потребовалось: `ask` отдаёт спланированный LLM ответ с `llm` по умолчанию true, `activity_summary` / `query_decisions` / `timeline` прозрачно наследуют быстрый путь по дневным чанкам сессий, а инструменты setup принимают ключи кастомных провайдеров, при этом `llm_api_key` намеренно нельзя задать и он редактируется при выводе.
