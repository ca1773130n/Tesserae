Lanzado **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

Los agentes son los consumidores de primera clase de Tesserae y, tras la división de comandos de 0.18, dos capacidades existían solo en la CLI. Esta versión cierra ambas brechas con nuevas herramientas MCP.

## `query` — recuperación en bruto vía MCP

Refleja `tesserae query`: búsqueda determinista BM25/semántica sobre la wiki compilada con `top_k` y un filtro `kind`, con la garantía de no hacer nunca una llamada LLM (`force_no_llm` de extremo a extremo). `backend: "raganything"` alcanza el índice RAG multimodal opcional — que **no tenía ninguna ruta MCP** desde que `ask` perdió su parámetro de backend en la división de 0.18. Usa `ask` cuando quieras una respuesta sintetizada y con citas; usa `query` cuando quieras la evidencia clasificada en sí.

## `doctor_run` — chequeos de salud frescos vía MCP

`doctor_report` (0.18) solo servía el último informe persistido — un agente que llegaba a un proyecto que nunca había ejecutado doctor no obtenía nada. `doctor_run` ejecuta bajo demanda el registro completo de 20 chequeos y devuelve los hallazgos como JSON con el código de salida 0/1/2. Es **siempre de solo lectura**: las correcciones nunca se ejecutan vía MCP y no se escribe ningún artefacto de informe; las reparaciones siguen siendo una acción humana explícita mediante `tesserae doctor --fix`.

## Todo lo demás ya fluía

No hicieron falta cambios para el resto de las funcionalidades de 0.18–0.19: `ask` entrega la respuesta planificada por LLM con `llm` en true por defecto, `activity_summary` / `query_decisions` / `timeline` heredan de forma transparente la vía rápida de chunks de sesión diarios, y las herramientas de setup aceptan las claves de proveedor personalizado con `llm_api_key` deliberadamente no configurable y redactada.
