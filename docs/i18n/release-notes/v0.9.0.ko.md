**2026-06-14** 릴리스됨 · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

피쳐 릴리스입니다: LongMemEval-V2의 AgentRunbook에서 포팅된 다중 그래뉼래리티 메모리 레이어와 LLM 백엔드를 눈에 보이고 정직하게 만들어주는 일련의 수정 사항들이 포함되어 있습니다. 이전에는 조용히 실패했던 것들입니다.

## 1. AgentRunbook 스타일 다중 그래뉼래리티 메모리

원본 세션 발견물 위의 새로운 선택적 증류 레이어입니다 — 세 가지 그래뉼래리티, 모두 바이트-멱등(콘텐츠 파생 ID, 벽시계/RNG 없음, 결정적 폴백)이고 LLM 선택사항:

- **`Event`** — 세션의 턴에서 채굴된 전이 당 레코드(동적 상태 추적), 세션 발견물 추출에 통합됩니다.
- **`Runbook`** — 반복되는 워크플로우를 위한 증류된 재사용 가능한 절차(교차 세션, 기본값은 ≥2개 세션).
- **`Gotcha`** — 증류된 반복되는 실패 모드 / 잘못된 가정.

또한 **다중 풀 검색**: `compile_context(multi_pool=True)`는 쿼리를 분해하고 가장 관련성 높은 증류된 메모리 노드를 위해 예산 슬롯을 예약합니다. `tesserae compile --distill`, `tesserae context --multi-pool`, `distillation.enabled`(config에서), 그리고 MCP `compile_context` `multi_pool` 인수를 통해 구성할 수 있습니다. 모두 기본값-꺼짐이므로 일반 컴파일은 변하지 않습니다.

## 2. 눈에 보이고 정직한 LLM 백엔드

- **`tesserae config status`** — 각 설정의 **소스**(env > 프로젝트 config > `~/.tesserae/config.json` > 기본값)와 **라이브 핑**을 포함하여 *해석된* 프로바이더 + codex-home / claude-dirs을 인쇄합니다. 속도 제한 또는 잘못된 인증의 백엔드가 이제 숨겨지지 않고 명확합니다.
- **큰 세션 추출 실패** — 추출은 이제 "모델이 아무것도 반환하지 않음"과 "모델이 절대 답하지 않음"을 구분합니다. 실패한 청크는 **더 이상 빈 상태로 캐시되지 않습니다**(백엔드가 작동하면 다시 추출됨), 그리고 컴파일은 놓칠 수 없는 경고를 인쇄합니다. 이전에는 속도 제한 백엔드가 조용히 세션이 있지만 **발견물은 0개**인 그래프를 생성했습니다.
- **Codex 추론 노력**은 Tesserae 자체 호출에 대해 `medium`으로 고정됩니다(`llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT`를 통해 구성 가능), 따라서 대화형 codex에 대해 전역으로 `xhigh`를 설정하면 모든 컴파일이 여러 배 더 느려지지 않습니다.

## 3. 결정성 강화

- 바이트-멱등 보호는 이제 그들이 실제로 보장하는 결정적 (LLM 없음) 컴파일을 실행합니다 — 주변 LLM이 더 이상 그들을 불안정하게 하지 않습니다.
- LLM 없는 컴파일은 캐시된 커뮤니티 요약을 **삭제하는 대신 다시 내보냅니다**, 따라서 재컴파일은 LLM 가용성 변동 전에 안정적으로 유지됩니다.

## v0.8.x에서 업그레이드

플러그인 앤 플레이입니다. 모든 새로운 기능은 선택적이거나 추가적이므로 일반 `tesserae compile`은 이전처럼 동작합니다. `tesserae config status`를 실행하여 어느 LLM 백엔드에 있는지 확인하세요.
