Released **2026-07-21** · [PyPI](https://pypi.org/project/tesserae/0.22.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.22.0) · `pip install --upgrade tesserae==0.22.0`

v0.21.0은 에이전트별 계층화된 메모리를 배포했지만, 그 기능의 절반은 MCP를 통해서만 접근 가능했고 `tesserae agents init`은 모든 에이전트를 `org:root` 아래에 덤프했습니다. 이 릴리스는 전체 기능을 터미널에서 사용 가능하게 만듭니다.

## `init`이 실제 조직을 구축합니다

`tesserae agents init`은 이제 이미 존재하는 신호로부터 계층 구조를 추론합니다: 서브에이전트 역할(`claude-code:me:reviewer`)은 그것을 생성한 메인 에이전트(`claude-code:me:default`)의 부모가 되며, `org:root` 아래에 모두 가지 않습니다. 하나의 명령어로 작동하는 다중 레벨 조직을 얻습니다 — `set-parent`가 필요 없습니다. 이전 동작을 위해 `--flat`을 전달하고, `init`은 이제 제안된 트리를 출력하므로 어떤 것을 결정했는지 볼 수 있습니다.

```
org:root
  claude-code:me:default   Main    sessions=42
    claude-code:me:reviewer   Reviewer   sessions=8   distilled_through=2026-07-20T…
    claude-code:me:planner    Planner    sessions=5   (not distilled)
```

## CLI에서 범위가 정해진 읽기

`--agent KEY`는 이제 `tesserae query`, `ask`, `context`에서 작동합니다 — 검색 및 합성이 에이전트의 해석된 뷰에 대해 실행됩니다(**워커** 키는 자신의 원시 + 증류된 메모리를 보고, **관리자** 키는 자신의 보고서의 증류된 계층만 보고, `org`는 전체 팀을 봅니다). 이전에는 이 범위지정이 MCP 인자로만 존재했습니다.

```bash
tesserae query "release checklist" --agent claude-code:me:reviewer
tesserae ask "what does my team know about deploys?" --agent org
```

알 수 없는 키와 증류되지 않은 에이전트는 정확한 해결책 명령어와 함께 크게 실패하며, 조용히 빈 답변이 되지 않습니다.

## 조직 검사

- **`tesserae agents tree`** — 조직도를 들여쓴 트리로, 각 에이전트에 세션 수와 증류된 메모리가 얼마나 오래되었는지 주석을 붙입니다.
- **`tesserae agents show KEY`** — 뷰를 해석하고 모드, 멤버 에이전트, 아티팩트 경로, 노드 수, 신선도 워터마크를 출력합니다.
- **`tesserae agents drill NODE_ID [--agent KEY]`** — 증류된 노트에서 원시 L0 증거로의 감사 에스컬레이션, 이제 1등급 CLI 명령어입니다(활성 / 변경 / 흡수 / 사라짐). `drill_down` 로직은 CLI 및 MCP 서버 간에 공유되므로, 두 표면이 동일하게 작동합니다.

## 내부 구조

역할 계층 추론은 순수하고 결정론적 함수입니다; `drill_down` 핵심은 CLI와 MCP 서버가 하나의 감사 코드 경로를 공유하도록 추출되었습니다. 증류된 아티팩트 또는 그들의 결정론성 보장에 변경사항 없음. 순전히 추가적입니다 — `--agent`가 없을 때 모든 기존 명령어는 정확히 전과 같이 작동합니다.
