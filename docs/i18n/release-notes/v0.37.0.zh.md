发布于 **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.0) · `pip install --upgrade tesserae==0.37.0`

本次发布新增一个开关，并纠正若干说法。

## 稠密通道可以要求使用训练过的编码器

在 148 篇论文的语料上，随包附带的静态 `model2vec` 嵌入器就是图与普通向量库之间
差距的全部。相同融合、相同图、相同文档去重下，按不同文档计的召回率：

| 方式 | @10 文档 | @50 文档 |
| --- | --- | --- |
| Mem0 OSS 原始分块存储，其自带编码器 | 0.784 | 0.942 |
| Mem0 OSS 原始分块存储，同一个 bge-base | 0.775 | 0.944 |
| Tesserae，随包附带的静态 model2vec | 0.754 | 0.914 |
| **Tesserae，稠密通道使用 bge-base** | **0.791** | **0.962** |

当调用方请求 `auto` 时，`TESSERAE_EMBEDDING_PREFER` 决定后端（`model2vec`、`st`、
`openai`、`hash`）；指不到任何后端的值会被报告并忽略，而不是悄悄落到哈希桩。
`TESSERAE_ST_MODEL` 指定 sentence-transformers 模型 —— 默认值从未经测量的
`all-MiniLM-L6-v2` 改为经过测量的 `BAAI/bge-base-en-v1.5`。

```bash
uv pip install sentence-transformers
export TESSERAE_EMBEDDING_PREFER=st
export TESSERAE_ST_MODEL=BAAI/bge-base-en-v1.5   # the default; any Hugging Face name
```

auto 阶梯没有变化：仍然优先选 `model2vec`，因此 `pip install tesserae` 保持不含
torch，而从未设置该变量的安装行为与以前完全一致。

## 测量真正说明了什么

给定同一个编码器，图和原始分块存储找到的是同样的文档：在 57 个问题上配对比较，
按 10 篇文档计是 8 胜 8 负 41 平（符号检验 p=1.0）。这就是持平，文档现在也这么写 ——
先前的措辞称图更领先，而那是在比较两个不同的编码器。

检索器也不再看到 LongMemEval 自带的日期戳和指令文本，此前它们对每一条臂都是查询的
一部分。

## 设计真正不同的地方

把图选出的文档以原文散文而非抽取出的主张打包，在 `gpt-4o-mini` 评判器下比段落对照
高 +28.9%。改用本地 7B 评判器重跑是 +7%，不显著，而在第二个语料上则落败。README
同时列出三个数字，而不是最好看的那个。

## 升级

无需迁移。既有的图不受影响；该开关需显式启用，默认后端未变。
