Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

这个版本没有任何运行时行为变化。它修的是本该捕捉运行时行为变化的那套机制 ——
而那套机制此前并不存在。

## 没有任何东西在跑测试

仓库里有两个工作流。一个编译演示 wiki，一个在打标签时发布 npm 包装器。两个都
没有执行过哪怕一个测试。"`main` 是绿的"是一句没人核实过的断言 —— 2,993 个测试
可以在某个周二全部变红，而徽章的颜色不会有任何变化。

现在 `tests.yml` 会在每次推送和每个 pull request 上运行整个测试套件，覆盖
Python 3.10、3.11 和 3.12 —— 也就是 `pyproject.toml` 一直声称支持的那三个版本。
那些声称同样从未被执行过。

## 有两个依赖只存在于一台机器上

要加 CI，first 必须承认一件事：一个全新的克隆根本跑不了测试：

- **`pytest` 没有在任何地方被声明** —— `pyproject.toml` 里没有，`uv.lock` 里也
  没有。测试能跑，是因为很久以前有人手工把 pytest 装进了本地 `.venv`。任何从
  锁文件重建环境的 `uv` 命令，都会悄悄产出一个没有测试运行器的环境。
- **`kuzu` 是同样的问题，但更尖锐。** 有两个测试直接调用 Kuzu store，没有
  `importorskip` 保护，所以它缺失时是*失败*而不是跳过。

两者现在都进了 `dev` 依赖组。真正重要的区别是：被测试的环境和贡献者拿到的环境
现在是同一个环境 —— 这是"套件是绿的"这句话能有意义的前提。

## 锁文件已经漂移

`uv lock --check` 对已提交的 `uv.lock` 失败：它与 `pyproject.toml` 不同步，缺少
`markdownify` 和 `model2vec`。任何执行 `uv sync --locked` 的人，或任何固定锁文件
的 CI，都会立刻撞上。

锁文件已重新生成，并且工作流使用 `uv sync --locked` —— 锁文件过期时它会让构建
变红，而不是悄悄更新，因此不会再次悄悄漂移。

## CI 在头四分钟里发现了什么

它在三个 Python 版本上都变红，而且失败完全相同。跨版本相同意味着这是平台问题
而非版本问题：有两个测试编码了某一台 macOS 机器的属性。

其中五个用 `zsh` 驱动 `hooks/_lib.sh`。CI runner 上没有 zsh —— 而那个库把自己
文档化为 POSIX 友好的，正是为了不依赖任何人的登录 shell。

第六个值得读两遍。它 monkeypatch 了 `subprocess.run`，但被测代码早已改用
`subprocess.Popen`，以便超时时能杀掉整个进程组。于是这个 patch 悄无声息地变成了
空操作，从那以后该测试一直在调用**真正的 `claude` 二进制** —— 在装了它并且已
登录的机器上通过，同时对它名义上要测的代码不作任何断言。

两者都不是产品缺陷。两者都是不可能因正确原因失败的测试，而且不换个地方运行就
找不出来。

## 演示站点已冻结

`build-demo.yml` 被移除了。它曾在每次推送到 `main` 时把 Tesserae 针对其自身源码
编译，并把结果部署到 GitHub Pages。

后果说明白，因为它很容易被忽略：
[在线演示](https://ca1773130n.github.io/Tesserae)仍然可以访问，README 也仍然
链接它，但已经没有任何东西重新部署它。那个页面现在是该工作流最后一次运行时的
快照，并将与 `main` 悄悄脱节。要重新发布，需要手动 `tesserae export site`，或者
新建工作流。

这同时移除了 `init` → `compile` → `export site` 这条路径上唯一的自动化覆盖。
`tests.yml` 只跑单元测试套件，并不端到端地执行那条路径；现在守在那里的只有发布
检查清单里的手动冒烟测试 —— 清单里已经写明了这一点。

## 从 v0.28.4 升级

直接替换即可。没有 API 变化、没有 schema 变化、没有行为变化 —— 本次发布的每个
提交都只触及 CI 配置、测试文件、依赖声明或文档。没有理由重新编译。

如果你使用固定锁文件从源码安装，这就是让 `uv sync --locked` 重新可用的那个版本。
