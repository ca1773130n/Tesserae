Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

이번 릴리스에 런타임 동작 변경은 없다. 런타임 동작 변경을 잡아내야 할 장치를
고쳤을 뿐이다 — 그 장치는 지금까지 존재하지 않았다.

## 아무것도 테스트를 실행하지 않고 있었다

저장소에는 워크플로가 둘 있었다. 하나는 데모 위키를 컴파일하고, 하나는 태그가
붙으면 npm 래퍼를 배포한다. 둘 다 테스트를 단 하나도 실행하지 않았다. "`main`은
그린이다"는 아무도 확인하지 않은 주장이었다 — 2,993개 테스트가 어느 화요일에
빨갛게 변했어도 배지 색은 그대로였을 것이다.

이제 `tests.yml`이 모든 푸시와 모든 풀 리퀘스트에서 Python 3.10, 3.11, 3.12
전체에 대해 스위트를 실행한다. `pyproject.toml`이 지원한다고 주장해 온 바로 그
세 버전이다. 그 주장 역시 한 번도 실행된 적이 없었다.

## 의존성 두 개가 machine 한 대에만 존재했다

CI를 붙이려면 먼저 인정해야 할 것이 있었다. 새로 클론한 저장소는 애초에 테스트를
실행할 수 없었다:

- **`pytest`가 어디에도 선언되어 있지 않았다** — `pyproject.toml`에도,
  `uv.lock`에도. 스위트가 돌았던 것은 오래전 누군가 로컬 `.venv`에 pytest를 손으로
  설치해 뒀기 때문이다. 락파일로부터 환경을 다시 만드는 `uv` 명령은 무엇이든
  테스트 러너가 없는 환경을 조용히 만들어 냈다.
- **`kuzu`는 같은 문제를 더 날카롭게 갖고 있었다.** 두 테스트가 `importorskip`
  가드 없이 Kuzu 스토어를 호출하기 때문에, 없으면 건너뛰는 게 아니라 *실패*한다.

둘 다 이제 `dev` 의존성 그룹에 들어갔다. 핵심은 이것이다: 테스트되는 환경과
기여자가 받는 환경이 이제 같은 환경이다. 그린 스위트가 무언가를 의미하려면
그 조건이 먼저 성립해야 한다.

## 락파일이 어긋나 있었다

커밋된 `uv.lock`에 대해 `uv lock --check`가 실패했다. `pyproject.toml`과 동기화가
깨져 있었고 `markdownify`와 `model2vec`이 빠져 있었다. `uv sync --locked`를
실행하는 사람이나 락을 고정하는 CI라면 곧바로 부딪혔을 문제다.

락파일을 재생성했고, 워크플로는 `uv sync --locked`를 쓴다 — 락이 낡았으면 조용히
갱신하는 대신 빌드를 실패시키므로, 다시 조용히 어긋날 수 없다.

## CI가 처음 4분 만에 찾아낸 것

세 Python 버전 모두에서 동일한 실패로 빨갛게 떴다. 버전에 무관하게 동일하다는
것은 버전 문제가 아니라 플랫폼 문제라는 뜻이다. 테스트 두 개가 macOS 기계 한
대의 속성을 인코딩하고 있었다.

다섯 개는 `hooks/_lib.sh`를 `zsh`로 구동했다. CI 러너에는 zsh가 없다 — 그리고
그 라이브러리는 누구의 로그인 셸에도 의존하지 않으려고 스스로를 POSIX 친화적이라
문서화해 두었다.

여섯 번째는 두 번 읽을 가치가 있다. 이 테스트는 `subprocess.run`을
몽키패치했지만, 대상 코드는 타임아웃 시 프로세스 그룹 전체를 죽일 수 있도록
`subprocess.Popen`으로 옮겨 간 뒤였다. 패치는 조용히 무의미해졌고, 그 이후로
테스트는 **진짜 `claude` 바이너리**를 실행하고 있었다 — 그 바이너리가 설치되어
있고 로그인된 기계에서만 통과하면서, 정작 이름이 가리키는 코드에 대해서는
아무것도 검증하지 않은 채로.

둘 다 제품 버그는 아니었다. 둘 다 옳은 이유로는 실패할 수 없는 테스트였고,
다른 곳에서 실행해 보지 않고서는 찾을 수 없었다.

## 데모 사이트는 얼어붙었다

`build-demo.yml`을 제거했다. 이 워크플로는 `main`에 푸시할 때마다 Tesserae를
자체 소스로 컴파일하고 결과를 GitHub Pages에 배포했다.

놓치기 쉬우니 분명히 적어 둔다:
[라이브 데모](https://ca1773130n.github.io/Tesserae)는 여전히 응답하고 README도
여전히 링크하지만, 아무것도 그것을 다시 배포하지 않는다. 그 페이지는 이제
워크플로가 마지막으로 돌던 시점의 스냅샷이며, `main`과 조용히 어긋나 갈 것이다.
다시 게시하려면 수동 `tesserae export site`나 새 워크플로가 필요하다.

이로써 `init` → `compile` → `export site` 경로의 유일한 자동 커버리지도 사라졌다.
`tests.yml`은 유닛 스위트를 실행할 뿐 그 경로를 끝까지 실행하지 않는다. 이제 그
자리를 지키는 것은 배포 체크리스트의 수동 스모크뿐이고, 체크리스트에 그렇게
적혀 있다.

## v0.28.4에서 업그레이드

드롭인이다. API 변경도, 스키마 변경도, 동작 변경도 없다 — 이번 릴리스의 모든
커밋은 CI 설정, 테스트 파일, 의존성 선언, 문서만 건드린다. 다시 컴파일할 이유는
없다.

락파일을 고정해 소스에서 설치한다면, `uv sync --locked`가 다시 동작하게 되는
릴리스가 바로 이것이다.
