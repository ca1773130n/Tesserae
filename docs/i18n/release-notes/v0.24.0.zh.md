发布于 **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.24.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.24.0) · `pip install --upgrade tesserae==0.24.0`

v0.23 给引擎赋予了睡眠周期，在空闲休息时压缩内存。但大脑中的记忆整合不仅仅是压缩——它也**删除你从不重新访问的记忆**并**链接那些关联的记忆**。此版本添加了这两个操作，所以守护程序的空闲周期现在运行这三个操作。

## 1 · 遗忘不再使用的记忆（LRU）

直到现在，一个发现的衰减是基于其**年龄**。这系统性地隐埋了旧的、很少看到的陷阱——正是那些当它们再次出现时你最需要的。现在**每次有意义的读取都记录访问**：搜索、`ask`、`query`、`context`、`node_context`、`drill_down`、会话发现查找以及代理作用域读取都会将 `last_accessed_at` 时间戳记录到内存副本中。

然后整合操作按照**检索最近性而不是创建年龄**来衰减。你持续使用的知识保持敏锐；你从未重新访问的知识缓慢衰退，并在睡眠周期中被吸收或降级——真正的 LRU 遗忘。（一个发现永远不会被**删除**；它会被折叠到引用它的蒸馏液中，可通过 `agents drill` 访问。）

## 2 · 发现新联系

睡眠还会重放记忆并链接距离遥远的记忆。新的**关联**操作在整合期间运行：它使用嵌入来找到**跨不同代理**内的相关——不是相同的——节点，并在它们之间添加 `shares_concept_with` 连接。发现的链接**跨周期累积**，可通过搜索、个性化 PageRank 和联合查询遍历，所以代理可以到达它从未明确链接的相关知识。

## 保持确定性

这两个操作仅写入**副本**——访问状态到 `node_memory` 存储，发现的链接到在读取时合并到内存中的累积 `.tesserae` 覆盖层。**`graph.json` 永远不会被触碰**，所以编译保持字节一致。发现的链接基于嵌入（因此机器相关），这正是为什么它们位于覆盖层中而永远不在确定性图中。关联由真实嵌入后端（`pip install "tesserae[semantic]"`）控制，没有后端时是无声的无操作。

## 周期现在完整

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine        # idle → compress · forget-by-disuse · associate
```

无需配置新内容——三个操作在现有空闲整合刻度内运行，在编译门下，永不阻断重新编译。完整详情：[`docs/engine-consolidation.md`](../engine-consolidation.md)。

`pip install --upgrade tesserae==0.24.0`（或 `npm i -g @jokerized/tesserae@0.24.0`）。
