リリース **2026-09-08** · [PyPI](https://pypi.org/project/tesserae/0.39.3/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.3) · `pip install --upgrade tesserae==0.39.3`

Claude アカウントに 2 つともログインしているのに `claude /login` を実行しろと言われた。一方のアカウントはクォータを使い切っており、実行が試すことを許されたアカウントはそれだけだった。

## 何が起きていたか

設定されたアカウントリストが壁として扱われていた。`llm_claude_config_dirs` に — あるいは古い `init` が書いた単数形の `extraction.claude_config_dir` に — ディレクトリを 1 つ指定すると、そのディレクトリが rotation のすべてだった。週次クォータが尽きると、使い切ったアカウントを生き延びるために存在するその仕組みには移る先がなく、同じマシン上で健全なアカウントが遊んでいる間にコンパイルは決定的抽出へ落ちた。

2 台目のマシンでは、これがログインプロンプトに変わる。アカウントリストは絶対パスを保持し、絶対パスは移動しない: CLI はディスク上にない設定ディレクトリを渡されて `Not logged in` と答え、表示される対処法は利用者がすでに済ませたログインになる。

どちらの診断もこれを捕まえられなかった。`doctor` はディレクトリが存在するという理由で `[ok] llm_login` を報告したが、それがこの検査の見ているすべてだ。`tesserae test` は「Backend is answering」と報告したが、それは provider チェーンが静かに codex へ落ちていたからで — 真実ではあるが、問われていた質問ではない。

## 何が変わったか

- **設定されたリストは排他的ではなく、最初に試される。** マシン上の他のすべての認証済み `~/.claude*` / `~/.codex*` がその後ろに追加される。指定したアカウントのどれかが動いている間は依然としてそれらだけが使われ — クライアントは最初の成功で戻る — 末尾に到達するのは、指定したすべてのアカウントが行き止まりだと証明された後だけだ。`llm_claude_config_dirs_exclusive` と `llm_codex_homes_exclusive` は、指定していないアカウントを使うことが救済ではなく請求上の問題である人のために、以前の挙動を戻す。
- **期限切れの OAuth セッションは認証の失敗である。** 判定用の部分文字列が `not logged in` だけだったため、MAX アカウントのリフレッシュトークンが死んだときに現れる形 — `Failed to authenticate: OAuth session expired and could not be refreshed` — が汎用エラー経路に落ち、それを直す唯一のコマンドではなく「エラーを読め」を得ていた。
- **`tesserae test` は試したすべてのアカウントを名指しする。** 2 つの CLI クライアントは rotation が起動したアカウントごとに 1 行を追加コストなしで記録するようになり、コマンドがそれを描画する: 設定ディレクトリ、何が起きたか、そして CLI 自身の言葉。さらに各結果にふさわしい対処法を添え、このマシンにない設定ディレクトリを指摘し、設定した provider が死んでフォールバックが代わりに答えたときは **degraded** の判定を報告する。
- **`doctor` はそれを緑で通さなくなる。** このマシンにない設定済みディレクトリは警告であり、`doctor --fix` がそれを `config.json` から削除する — そこにないディレクトリはログインできないので、削除してアカウントを失うことはない。rotation から除外された認証済みアカウントも名指しされる。doctor は依然として LLM 呼び出しを使わない。この 2 つは無料で判定できることだ。

## 使い方

```bash
tesserae test          # which account answered, and what the others said
tesserae doctor --fix  # drops account dirs that are not on this machine
```

## アップグレード

移行するものはなく、この修正を受け取るのに設定変更も要らない。設定リストが排他的であることに頼っていたなら — 他のアカウントに決して課金されないよう 1 つを固定していたなら — `"llm_claude_config_dirs_exclusive": true`（または `llm_codex_homes_exclusive`）を設定してそれを保つこと。
