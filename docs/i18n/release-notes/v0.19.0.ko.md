Released **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.19.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.19.0) · `pip install --upgrade tesserae==0.19.0`

백엔드 수명 종료(end-of-life) 릴리스입니다. v0.18.0 이후 기본 지식 그래프 업데이트 및 검색 루프는 완전히 자체 구현이었습니다 — 타입 지정 ResearchGraph 파이프라인이 그래프를 작성하고(네이티브 코드 그래프 추출 포함), `ask`가 LLM으로 그 위에서 검색을 계획합니다. 이번 릴리스는 더 이상 제 몫을 하지 못하는 덧붙여진 두 백엔드를 제거합니다.

## understand-anything: 제거됨

유일한 기여 — 외부에서 생성된 코드 구조 노드의 `knowledge-graph.json`을 ResearchGraph에 병합하는 것 — 은 네이티브 코드 그래프 추출기가 출시된 이후 중복이었습니다. 어댑터, refresh 모듈, 컴파일 타임 병합, deps 감지, setup 항목이 사라졌습니다. `tesserae integrations refresh understand-anything`는 네이티브 코드 수집을 가리키는 한 줄을 출력하고 2로 종료합니다. understand-anything `external_tools` 항목을 담고 있는 오래된 구성은 단 하나의 노트와 함께 로드되며, 기존 그래프의 UA가 생성한 노드는 여전히 유효합니다.

## cognee: 제거됨

cognee는 그래프를 자체 저장소로 *바깥으로* 복제할 뿐 아무것도 되돌려주지 않았습니다; 0.18 이전에는 기본 설치에서 `ask` 출력에 로그 스팸과 `OperationalError` 폴백까지 누출했습니다. 기본 비활성화 유예 릴리스 한 번을 거친 후 완전히 제거되었습니다: 어댑터/직접/쿼리 모듈, 컴파일 타임 cognify 패스와 번들 내보내기, `[cognee]` extra, 마법사 프롬프트, MCP 스키마 참조 (~1,100 LOC과 테스트 파일 6개). `query --backend cognee`와 모든 `--cognee-*` / `--enable-cognee` 플래그는 한 줄짜리 제거 스텁을 출력하고 2로 종료합니다. `memory_backends.cognee` 섹션을 담고 있는 구성은 여전히 로드되고 컴파일됩니다 — 프로세스당 정확히 하나의 노트와 함께.

## rag-anything: 의도적으로 유지

지식 그래프에 진짜로 없는 능력 — 멀티모달 문서 RAG (PDF, 이미지) — 을 가진 유일한 백엔드는 선택적 `tesserae[raganything]` extra로 남아 있으며, 기본적으로 꺼져 있고, `tesserae query --backend raganything`으로 접근할 수 있습니다.

## 파괴적 변경 사항

프로젝트 관례에 따라 아무것도 조용히 실패하지 않습니다 — 제거된 모든 표면은 대체물이나 설명을 출력하고 2로 종료합니다: `integrations refresh understand-anything`, `query --backend cognee`, `--cognee-search-type`, `--cognee-dataset`, `--enable-cognee` 및 나머지 `--cognee-*` setup/extract 플래그. 두 제거의 순 효과: +1,600 대비 **−5,500줄**, 전체 테스트 스위트 그린 (2,251 passed).
