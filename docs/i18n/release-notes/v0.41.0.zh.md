发布于 **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.0) · `pip install --upgrade tesserae==0.41.0`

Tesserae 将自己描述为一个引擎，它自主拉取知识，而不是等待被告知。直到这个版本，它从未拉取过任何东西。守护进程拥有的每个触发源都等待本地文件更改：文件系统监视器、保管库监视器、会话跟踪器和在 v0.40.0 中添加的站点服务器。它们重建你已经放在磁盘上的内容。

## 发生了什么

- **`tesserae engine --proactive` 获取文档。** 它轮询项目的 `proactive_sources` 中列出的源，拉取它从未见过的文档，并将它们传递给与任何其他新文件相同的防抖和编译路径。RSS 和 Atom 都有效，不是源的 URL 被当作文档本身处理，并被摄入一次。
- **它默认关闭，并且保持成本低廉。** 这是 Tesserae 中第一个在没有人在键盘前花钱的东西，所以 `--proactive` 是选择加入，与 `--once`、`--harvest-only` 和 `--all` 拒绝，并按每次轮询五个新文档的预算。轮询器在其第一个 tick 前等待，所以说明它将要做什么的日志行先到达。
- **没有任何东西被获取两次。** 图谱旁边的一个分类账记录每个 URL。一个 Tesserae 无法读取的 URL，比如仅限 PDF 的链接，被记录为拒绝而不是每小时重试。超时不是关于文档的判决，永远不被记录，所以传输失败会重试。
- **源被防御性解析。** 这是 Tesserae 唯一解析来自其他人控制的 URL 的 XML 的地方，所以声明 DTD 的源被直接拒绝。这一起消除了实体扩展和外部实体攻击，真实的源对此没有用处。
- **`tesserae sources add <url>`** 添加一个源，与添加目录的动词相同。图谱的知识来自哪里是一个问题，所以它是一个命令；`sources list` 标记每个条目。
- **`tesserae completion bash|zsh|fish`** 打印一个 shell 完成脚本，从真实命令树生成，所以它不能与 CLI 偏离。生成器立即捕获了帮助中的一条过时的行，它宣传了 `sessions` 五个子命令中的三个。
- **拼写错的命令建议正确的。** `tesserae complie` 指向 `compile`，而没有其组的子命令（如 `sync`）命名两个都有一个的组。像 `tesserae vault` 这样的裸组名现在打印该组的帮助，而不是关于缺少参数的 argparse 错误。
- **`write_sessions` 将不推断谁拥有一个存储。** 其 `producer` 参数默认为空，这意味着整个存储权限，所以破坏性读取是你通过不传递任何东西得到的。它现在是必需的。整个存储权限仍然可用，拼写为 `producer=""`，它读作一个决定而不是遗漏。

## 升级

没有什么需要迁移。主动摄入不会做任何事情，直到你添加一个源并传递 `--proactive`，而每个其他更改都是附加的。唯一的破坏性更改是对直接调用 `write_sessions` 的代码：传递 `producer=`。Tesserae 内部的每个调用者已经这样做了。
