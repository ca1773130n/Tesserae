Released **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.24.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.24.0) · `pip install --upgrade tesserae==0.24.0`

v0.23はエンジンに、アイドル状態の時にメモリを圧縮するスリープサイクルを与えました。しかし、脳の統合は単なる圧縮ではなく、二度と参照しないものを剪定し、関連することが分かった記憶を結びつけることも含まれます。このリリースではそれら二つの操作も追加されたため、デーモンのアイドルサイクルは現在、三つすべてを実行します。

## 1 · 使用されないことで忘れる（LRU）

これまでは、発見の陳腐化はその年齢に基づいていました。それは、めったに見られない古い問題点を体系的に埋もれさせてしまいます — 再発したときに最も必要なものです。現在、すべての有意義な読み取りはアクセスを記録します：検索、問い合わせ、クエリ、コンテキスト、ノードコンテキスト、ドリルダウン、セッション発見の参照、エージェントスコープの読み取りすべてが、memory sidecar に last_accessed_at を記録します。

統合プロセスは、その後、作成時の年齢ではなく、取得の新しさによって減衰します。繰り返しアクセスする知識は鮮明なままですが、決して再訪しない知識は徐々に薄れ、睡眠サイクル中に吸収されるかランクが下げられます—これは真のLRU忘却です。（発見は決して削除されず、それを引用する蒸留物に折り込まれ、エージェントのドリルを通じてアクセス可能です。）

## 2 · 新しいつながりを発見する

睡眠はまた記憶を再生し、遠く離れた記憶を結びつけます。新しいアソシエイトパスは統合中に実行されます：それは埋め込みを使用して、プロジェクト内の異なるエージェント間で関連する（同一ではない）ノードを見つけ、これらの間にshares_concept_withの接続を追加します。発見されたリンクはサイクルを通じて蓄積され、検索、パーソナライズされたPageRank、およびフェデレーテッドクエリによってたどることができるため、エージェントは明示的にリンクしていない関連知識に到達することができます。

## 決定論が主張された

両方の操作はサイドカーにのみ書き込みます — ノードメモリストアへの状態アクセス、読み取り時にメモリ内でマージされる累積的な .tesserae オーバーレイへの発見リンク。graph.json は決して触られないため、コンパイルはバイト単位で同一のままです。発見されたリンクは埋め込みベース（つまりマシン依存）であり、まさにそのためオーバーレイに存在し、決定的なグラフには存在しません。関連付けは実際の埋め込みバックエンド（pip install tesserae[semantic]）で制御されており、バックエンドがない場合は静かに何もしません。

## そのサイクルは、今、完了しました

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine        # idle → compress · forget-by-disuse · associate
```

設定する新しい項目はありません — これら3つの操作は既存のアイドル統合ティック内で、コンパイルゲートの下で実行され、再コンパイルをブロックすることはありません。詳細は docs/engine-consolidation.md をご覧ください。

`pip install --upgrade tesserae==0.24.0（または npm i -g @jokerized/tesserae@0.24.0）。`
