공개일 **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.2/) · [GitHub 릴리스](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.2) · `pip install --upgrade tesserae==0.41.2`

모든 명령을 실행하여 감시했다. 42개의 후보 결함 중 31개가 재현과 적대적 두 번째 의견을 견뎌냈다. 이 릴리스는 가장 심각한 12개를 종료한다: 자신이 하지 않은 작업에 대해 성공을 보고한 5개, 데이터를 파괴한 5개, 무시된 하나의 플래그, 그리고 의도적으로 남겨진 하나.

## 자신이 하지 않은 작업에 대해 성공을 보고

- **마크다운을 보유하지 않은 경로에 대한 컴파일이 거부된다.** `tesserae compile README.txt` — 올바른 접미사를 가진 실제 파일 — 그래프를 아무것도 아닌 것으로부터 다시 만들었고, 빈 것으로 교체했으며, 종료 0으로 나갔다. 거부는 쓰기 전에 나온다. 따라서 그래프는 당신이 읽을 때 여전히 있다. 경로는 이제 작업 디렉토리가 아닌 `--project`에 대해 해석된다.
- **`code ingest`가 실제 코드 그래프 위에 빈 것을 쓰고 성공을 보고하는 대신 실제로 없는 경로를 거부한다.**
- **프로젝트가 아닌 것에 대한 `query`는 오류다.** 종료 0으로 "일치 없음"을 답했는데, 이것은 실제 검색이 아무것도 찾지 못한 것처럼 보인다. 따라서 `--project`의 오타는 빈 말뭉치처럼 읽혔다.
- **`lint`가 그래프를 읽을 수 없을 때를 말한다.** 파싱 오류를 삼켰고, 빈 그래프 위에서 모든 검사를 실행했으며, "발견 사항 없음. Wiki가 깨끗하다"고 종료 0으로 보고했다. 이는 전혀 파싱할 수 없는 `graph.json`에 대한 것이었다.
- **`engine --once`가 컴파일에 실패했을 때 0이 아닌 것으로 나간다.** 무슨 일이 일어났든 0을 반환했고, 따라서 지속적 통합은 상승한 파이프라인에 대해 녹색을 봤다. 같은 버그가 함대에서 `2/2 units ok`을 출력하게 했다. 일괄에서 프로젝트가 실패했다: 각 단위의 종료 코드를 읽는다.

## 데이터 파괴

- **파싱할 수 없는 머신 전체 구성은 더 이상 교체되지 않는다.** 모든 라이터는 파일을 읽을 수 없을 때 빈 사전에 병합되고, 결과를 썼다. 따라서 하나의 방황하는 쉼표는 저장된 클립 토큰과 모든 저장된 키를 비용으로 책정했다. 손상된 파일을 읽은 후 읽는 것은 여전히 괜찮다; 쓰는 것은 아니다.
- **`projects register`가 컴파일되지 않은 프로젝트를 더 이상 다시 초기화하지 않는다.** 이것은 구성을 교체하고 소스, 이름 및 제공자를 잃었다. 가드의 자신의 주석은 이미 이것을 약속했다; 잘못된 파일을 테스트했다.
- **`sessions discover --import`가 읽을 수 없는 루트로부터 기록을 유지한다.** 디스크에 없는 `--root`는 여전히 정리 범위에 전달되었으므로, 가져오기는 그로부터 수확한 모든 것을 삭제했으면서 그것에 대해 아무것도 배우지 못했다. 마운트되지 않은 디스크로 충분했다.
- **`vault sync`가 적용했다고 말한 재정의를 저장한다.** 편집을 보고했고, 금고만 썼으며, 다음 실행은 변경을 예전 방식으로 다시 둔다.
- **`vault export`가 메모를 보유한 고아 페이지를 유지한다** — `vault prune`가 이미 삭제하기를 거부하는 것과 정확히 같다. 두 개가 동의하지 않았고, 조용한 것이 모든 내보내기에서 실행되었다.

## 무시됨

- **`engine --all --harvest-only`가 더 이상 컴파일되지 않는다.** 플래그는 단일 프로젝트에 도달했고 함대 모드에서 떨어졌는데, 이것은 작성된 모양이다: 여러 머신이 디렉토리를 공유하고, 각각이 자신이 볼 수 있는 것을 읽고, 그 중 하나가 컴파일한다.

## 의도적으로 남겨진

`lint --fix-trivial`는 방금 수리한 발견 사항을 나열한다. 이것은 "여기가 내가 수정한 것"으로 읽히고, 테스트가 이것을 고정하며, 이것은 결함이 아니다. 감시가 그것을 제기했기 때문에 여기에 이름이 있고 답은 아니다.

## 업그레이드

마이그레이션할 것이 없다. 아무것도 유용하지 않고 종료 0으로 나가는 명령은 이제 종료 2로 나가고 이유를 말한다. 따라서 침묵에 의존한 스크립트는 이미 가지고 있던 실패를 보고하기 시작할 것이다.
