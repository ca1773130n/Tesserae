发布于 **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

Agent 是 Tesserae 的一等消费者，而在 0.18 的命令拆分之后，有两项能力只存在于 CLI 上。本版本通过新的 MCP 工具补齐了这两个缺口。

## `query` — 通过 MCP 进行原始检索

对应 `tesserae query`：在已编译的 wiki 上进行确定性的 BM25/语义搜索，支持 `top_k` 和 `kind` 过滤，并保证绝不发起 LLM 调用（端到端 `force_no_llm`）。`backend: "raganything"` 可访问可选的多模态 RAG 索引——自从 `ask` 在 0.18 拆分中失去 backend 参数后，该索引**完全没有 MCP 通路**。想要一个经过合成、带引用的答案时用 `ask`；想要排序后的证据本身时用 `query`。

## `doctor_run` — 通过 MCP 进行实时健康检查

`doctor_report`（0.18）只提供最近一次持久化的报告——agent 访问一个从未运行过 doctor 的项目时什么也拿不到。`doctor_run` 按需执行完整的 20 项检查注册表，并以 JSON 形式返回检查结果及 0/1/2 退出码。它**始终是只读的**：修复操作绝不会通过 MCP 执行，也不会写入任何报告工件；修复仍是一个显式的人工操作，通过 `tesserae doctor --fix` 完成。

## 其余能力早已打通

0.18–0.19 的其余特性无需任何改动：`ask` 提供 LLM 规划的答案且 `llm` 默认为 true，`activity_summary` / `query_decisions` / `timeline` 透明地继承按日 session-chunk 快速路径，setup 工具接受自定义 provider 键，其中 `llm_api_key` 被刻意设为不可设置并做了脱敏处理。
