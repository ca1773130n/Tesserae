发布于 **2026-08-17** · [PyPI](https://pypi.org/project/tesserae/0.32.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.32.0) · `pip install --upgrade tesserae==0.32.0`

拥有六万个节点的图谱，面临的问题和拥有六万名员工的公司一样。你没法从正门走进去就开始
读。在此之前，入口把手头最大的那些节点按体积排好交给代理，剩下的——它们究竟是干什么
用的——留给代理自己去弄明白。在本项目自己的图谱上，那意味着 32.5 秒内出现 1,852 张
没有名字的卡片：一份把楼里每张办公桌都列出来、并按办公桌排序的名录。

这个版本给图谱配了一张组织架构图。

## 宪章

编译现在会从语料中推导出一个机构。分部、部门、团队，每一个都是一个领域，带着人能认出
来的名字和可以指向的锚点。入口走这棵树而不是走体积排名，在同一个图谱上，这是 1.6 秒
内的四张带标题的卡片。

`graph_map` 打开时是一份名字目录，没有名字的卡片不会因为体积大而被提拔。
`charter_route` 会把一项任务放进树的第三层，或者什么也不指认——总能给出答案的路由器，
就是有时会自信地给错答案的路由器，而这一个宁愿弃权。每个领域背后都有一份简报：以领域
的 slug 为键的社区摘要，生成一次后缓存下来，代理拿到的是这段可读的文字，而不是一堆节
点。

领域的日期取自它的来源，而当它根本无法定期时，它会这么说。这个区分比听上去更要紧。把
推导出来的日期当作事实呈现，正是一个图谱开始断言其语料从未说过的东西的方式。

`engine` 守护进程在空闲 tick 期间预热简报，读取方因此不再抵达背后什么都没写的领域；两
个新的 lint 探针检查磁盘上的宪章文件，而不是内存里的对象——因为这两者正是会彼此漂移的
东西。在 Tesserae 自己的语料上测得：1,411 个领域，其中 1,410 个已预热。保持冷的那一
个是普查领域，它按设计从不预热。

## 检索不再付两遍钱

这里有四处改动，四处都在删掉正在被重做的工作。向量现在会持久化，查询不再重新嵌入它上
次已经嵌入过的语料。BM25 通道不再在每次查询时重建语料。嵌入通道用一次矩阵乘法而不是一
个循环来给整个语料打分。而且查询会报告每条通道花了多少，这把一个慢回答从只能猜测的东
西变成可以归因的东西。

与此同时，检索获得了视图注册表——带视图范围遍历的命名边分区——以及带排名融合的多视图遍
历，结果可以说出自己出自哪个视图。

## 时间，以及故意出错

边车获得了一条事务时间轴，一个时钟不再把自己称作两个。当一个事实被取代时，
`resolved_by` 从失败的一侧关闭区间：不是赢家宣示地盘，而是输掉的那个事实记录下什么取
代了它。事实现在按内容检索，*未定期* 成了一个你可以主动要求的谓词，而不是一个你必须自
己注意到的空缺。

出错这件事也比以前处理得更直接。代理可以撤回一个事实——说"这是错的"——而不必被迫为它编
造一个替代品。死掉的节点 id 会解析到它的幸存者，因此合并两个节点不会把此前的每一处引
用都变成悬空指针。在一次运行中被拒绝的候选对，在下一次运行中仍然保持被拒绝。而且当有
人要求时，一次读取可以说出自己的读取方。

## 证据胜过主张

这个版本在一件项目所能做的最不光鲜的事情上花了真功夫：核查自己的 README 是否属实。

Tesserae 现在能回答 Neo4j 的 TCK，并且故意让 93 条一致性查询中的 34 条失败：Bronze
93 条中通过 57 条，Silver 67 条中通过 0 条。等级是明说的，而不是暗示的。有了 QA 评分
器，一次对手运行产出的是一个数字而不是一段叙述。在 LongMemEval-MAB 上，BM25 的
recall@10 为 0.843，稠密检索为 0.473，测量是免费的且可重复——这两者都是基线，而
Tesserae 自己在该基准上的那一列**尚未测量**，报告直说这一点，而不是任由表格暗示相反的
结论。

还有一套面向更难问题的测试装置：当语料*不*变化时，记忆是否会改进。它冻结一份语料，
在其上运行整合，然后重新测量。搭建过程中掉出来两个性质。关联不消耗任何 LLM 调用，因为
它是本地嵌入器之上的余弦相似度。而且它是幂等的，所以在冻结的语料上，曲线诚实的形状是
一级台阶而不是一道斜坡——这个主张比"无需输入也能持续改进"要窄，也是别人跑三个周期来核
对之后仍然站得住的那一个。

文档中七处夸大的说法得到订正，三项比较性主张被彻底撤回，因为仓库里没有任何东西度量过
它们。

## 不会悄悄腐烂的文档

`docs/` 下的每一篇文档都镜像成七种语言。现在有一道机械的对等棘轮跑遍全部 553 个镜像：
译文不得丢掉英文所拥有的标识符或结构元素。它抓不到错误的翻译，只能抓到缺失的翻译，所
以它与一份术语表一同发布——收录那些被误译过不止一次的词。对照它，四处真实的误译被清
掉了。

## 其他

没有终端的编译会讲述自己，而不是看起来像卡死了；而且是默认讲述，不是只在被要求时才
讲。图、表和公式成为一等的 Artifact 证据节点；一张图的编号属于它所在的文档，并随边一
起传递；Artifact 图以字节形式抵达站点。编译锁是可移植的，因此 Windows 的追加写不会把
它撕裂。`.tesserae/` 下的每一项现在都会说明谁拥有它、删掉它的代价是什么。本体成长闭环
终于合上了——提案会被浮现出来并接受 lint，而提升仍然是一次人工编辑。

## 升级

```bash
pip install --upgrade tesserae==0.32.0
```

现有图谱按原样读取，这里没有任何东西强制重建。宪章会在下一次编译时推导出来，引擎的其
余部分没有它也照常工作——一个再也不编译的项目，会原封不动地保留它已有的图谱。
