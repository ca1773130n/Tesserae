发布于 **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.23.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.23.0) · `pip install --upgrade tesserae==0.23.0`

分层代理内存 (v0.21) 可以蒸馏，但只在你要求时进行——在 `tesserae refresh` 时，在内存压力下。此版本为始终运行的引擎赋予了**睡眠周期**：它自己整合代理内存，就像大脑在休息时的整合方式一样。

## 在休息时整合

让 `tesserae engine` 保持运行，它现在会监视活动时钟。当项目进入**空闲**状态时——几分钟内没有编辑或新会话——它会对该项目的代理运行蒸馏过程，在你不在时重新组织和压缩它们积累的经验。定期的**上限**（默认 6 小时）保证即使持续繁忙的项目也会进行整合。

```bash
tesserae engine                      # idle consolidation on by default
tesserae engine --consolidate-idle 600 --consolidate-every 43200
tesserae engine --all                # every registered project, on idle
tesserae engine --no-consolidate     # opt out
```

空闲是符合脑科学的触发器：整合发生在系统处于休息状态时，而不是在任意的挂钟时间。

## 构造上的安全

该周期完全包装现有的 `maybe_distill_on_refresh` 过程，所以它的所有保证都延续到新版本：

- **除非你选择加入，否则无操作。** 在 `TESSERAE_AGENT_DISTILL=1` 之前什么都不运行——蒸馏一直使用的相同的门控，加上每个代理的水位线和内存压力检查。标志默认启用是因为该过程本身在没有选择加入的情况下拒绝做任何事情。
- **绝不与重新编译重叠。** 整合在编译门下运行，因此它与管道是互斥的——为了在单守护进程模式下保持这一点，未设置的门现在默认为私有信号量。
- **绝不影响守护进程。** 它在自己的线程上运行（守护进程现有的轮询习语），从不进入事件循环，在关闭时迅速退出，并且对一次性 `engine` 运行完全跳过。
- **确定性工件，保持不变。** 蒸馏后的图保持其字节幂等性；单调活动时钟永不持久化。

## 标志

| 标志 | 默认值 | 含义 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | 启用 | 启用睡眠周期 |
| `--consolidate-idle` | `300` | 整合前的静止秒数 |
| `--consolidate-every` | `21600` | 上限——至少这么频繁地整合（`0` = 关闭） |
| `--consolidate-check` | `30` | 线程检查时钟的频率 |
