Publicado **2026-09-08** · [PyPI](https://pypi.org/project/tesserae/0.39.2/) · [Release en GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.2) · `pip install --upgrade tesserae==0.39.2`

Dos huecos en el mismo sitio: nada te decía si tu backend LLM funciona de verdad, y `doctor --fix` no terminaba lo que empezaba.

## Qué pasó

`doctor --fix` aplicaba cada reparación una vez, en orden de registro. Una reparación que invalidaba una comprobación anterior dejaba ese trabajo a una segunda invocación que nadie sabía que debía ejecutar: arreglar el lint reescribe `graph.json`, lo que deja el sitio obsoleto, y la comprobación del sitio ya había pasado. Además, una ejecución con reparaciones imprimía la misma tabla que una de solo lectura, así que saber qué avisos eran deliberados exigía comparar dos pantallas. Mientras tanto, lo único que tocaba el backend era `config status --ping`, que hace una llamada como efecto secundario de imprimir la configuración.

## Qué cambió

- **`doctor --fix` converge.** Las reparaciones se repiten hasta que una pasada no cambia nada, con un tope de tres, y el contexto del proyecto se reconstruye entre pasadas, de modo que una reparación que crea lo que lee una comprobación posterior sí es vista por ella.
- **Todo lo que declina queda nombrado.** Lo que sigue mal aparece bajo **Still open** con el comando y el motivo. El motivo es honesto sobre la ejecución que lo produjo: una ejecución de solo lectura dice que el hallazgo es reparable con `--fix`, nunca que una reparación corrió y falló. Cuatro motivos permanentes cubren cada comprobación de solo informe — spend, install, authenticate, destroy — y un test falla si se añade una comprobación sin uno.
- **Tres comprobaciones más se reparan solas.** `config_valid` rellena atómicamente las claves requeridas que falten con los valores que escribe `init`; una configuración que no parsea se reporta y nunca se reescribe. `--fix --deep` añade reparaciones locales lentas, empezando por el backfill de fragmentos de sesión. Ninguna reparación, en ningún nivel, ejecuta una compilación.
- **`tesserae test` demuestra que el backend responde.** Resuelve los ajustes como lo hace la compilación, construye el mismo cliente y luego gasta una llamada JSON y una de prosa, porque una pasarela puede servir la primera y rechazar la segunda. Ninguna se cachea. Sale con 0 solo si vuelven ambas.

## Cómo usarlo

```bash
tesserae test                 # resolve, build, one JSON call, one prose call
tesserae doctor --fix         # repeats until a pass changes nothing
tesserae doctor --fix --deep  # + the slow local repairs
```

## Actualización

Nada que migrar. `doctor --fix` mantiene su vieja promesa — solo reparaciones seguras, nunca una compilación, nunca un proceso matado — simplemente ahora se repite e informa de lo que dejó. `--deep` sin `--fix` sale con 2.
