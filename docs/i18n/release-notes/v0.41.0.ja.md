公開日 **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.0/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.0) · `pip install --upgrade tesserae==0.41.0`

Tesseraeはそれ自体でナレッジを引き込むエンジンとして説明されており、指示を待つ代わりにそうしています。このリリースまで、それは何も引き込みませんでした。デーモンが持っていたすべてのトリガーソースはローカルファイルの変更を待ちました：ファイルシステムウォッチャー、ボルトウォッチャー、セッションテーラー、およびv0.40.0で追加されたサイトサーバー。それらはあなたがすでにディスクに置いたものを再構築します。

## 何が変わったか

- **`tesserae engine --proactive`がフェッチします。** プロジェクトの`proactive_sources`に一覧表示されたフィードをポーリングし、見たことのないドキュメントを引き込み、他の新しいファイルと同じデバウンスおよびコンパイルパスに渡します。RSSとAtomの両方が機能し、フィードではないURLはドキュメント自体として扱われ、1回だけ取り込まれます。
- **デフォルトではオフで、安い状態を保ちます。** これはキーボードに人がいなくても費用がかかるTesseraeの最初のものなので、`--proactive`はオプトイン、`--once`、`--harvest-only`、`--all`と一緒に拒否され、ポーリングあたり5つの新しいドキュメントで予算化されます。ポーラーは最初のティックの前に待つので、ログ行は最初に何をしようとしているかを示します。
- **何も2回フェッチされません。** グラフの横にあるレジャーはすべてのURLを記録します。Tesseraeが読むことができないもの（PDF専用リンクなど）は、機能したであろうエントリの前で毎時間再試行されるのではなく、拒否として記録されます。タイムアウトはドキュメントに関する判定ではなく、記録されることはないため、トランスポートの失敗は再試行します。
- **フィードは防御的に解析されます。** これはTesseraeが他の人が制御するURLからXMLを解析する唯一の場所なので、DTDを宣言するフィードは直ちに拒否されます。これにより、エンティティ展開と外部エンティティ攻撃が一緒に削除され、実際のフィードにはその必要はありません。
- **`tesserae sources add <url>`**はフィードを追加します。ディレクトリを追加するのと同じ動詞です。グラフのナレッジが来た場所は1つの質問なので、それは1つのコマンドです。`sources list`は各エントリをラベル付けします。
- **`tesserae completion bash|zsh|fish`**はシェル補完スクリプトを出力します。実際のコマンドツリーから生成されるため、CLIからドリフトできません。ジェネレーターはすぐに`sessions`の5つのサブコマンドのうち3つが広告されていたヘルプ内の古い行をキャッチしました。
- **誤入力されたコマンドが正しいコマンドを提案します。** `tesserae complie`は`compile`を指し、グループなしで入力されたサブコマンド（`sync`など）は両方のグループに名前を付けます。`tesserae vault`などのベアグループ名は、欠落引数についてのargparseエラーの代わりにそのグループのヘルプを出力します。
- **`write_sessions`はストアの所有者を推測しません。** その`producer`引数はデフォルトで空でした。これは全体的なストア権限を意味するため、破壊的なリーディングは何も渡さなかったことによって得られたものでした。これは現在必須です。全体的なストア権限はまだ利用可能で、`producer=""`と表記されています。これは省略ではなく決定として読み取られます。

## アップグレード

移行するものはありません。プロアクティブな取り込みは、フィードを追加して`--proactive`を渡すまで何もせず、その他のすべての変更は加算的です。唯一の重大な変更は`write_sessions`を直接呼び出すコードの場合です：`producer=`を渡してください。Tesserae内のすべての呼び出し元はすでにそうしていました。
