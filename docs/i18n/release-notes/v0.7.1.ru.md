Дата выпуска **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.1) · `pip install --upgrade tesserae==0.7.1`

`tesserae ingest <file|url>` — это новая команда верхнего уровня, которая объединяет **один** документ или URL в вашу базу знаний — без повторного извлечения всего корпуса — и при этом остаётся **побайтово идентичной** полной компиляции. Добавьте один файл или укажите веб-страницу, и ваш граф обновится инкрементально, вместо того чтобы каждый раз платить за полную перекомпиляцию.

## 1. `tesserae ingest <input>...` — инкрементальный приём одного источника

Новая команда принимает один или несколько входов — пути к локальным файлам или `http(s)` URL — и встраивает каждый в существующую базу знаний по отдельности. Она отличается от `tesserae code ingest`: это приём документа/источника в основной граф, а не индексирование кода.

По умолчанию `ingest` выполняет **инкрементальный быстрый путь**, который затрагивает только новый источник. Этот быстрый путь *защищён проверкой паритета*: он проверен на побайтовую идентичность полной компиляции, и если паритет нельзя гарантировать, он автоматически откатывается к полной перекомпиляции, так что корректность никогда не подвергается риску. Передайте `--exact`, чтобы принудительно выполнить полную перекомпиляцию самостоятельно.

Флаги: `--exact`, `--dry-run`, `--title`, `--source-kind`.

## 2. URL загружаются, преобразуются и отслеживаются с указанием происхождения

Дайте `ingest` URL `http(s)`, и он загрузит страницу, преобразует её в markdown и сохранит как отслеживаемый источник в `data/ingested/<slug>.md` с front-matter происхождения: `source_url`, `fetched_at`, `content_sha256` и `arxiv_id`, когда источник распознан как статья arXiv.

Приём URL поставляется за новым необязательным extra, чтобы базовая установка оставалась лёгкой:

```
pip install tesserae[ingest-url]
```

## 3. Локальные файлы вне корпуса становятся частью корпуса

Когда вы принимаете локальный файл, находящийся вне отслеживаемого корпуса, `ingest` копирует его в корпус. Благодаря этому последующая полная `tesserae compile` воспроизводит точно такой же результат — инкрементальный приём и компиляция с нуля сходятся к идентичным байтам.

## 4. Под капотом: инкрементальный шов (seam), сохраняющий паритет

Инкрементальный быстрый путь построен на шве `incremental_override`, действующем для каждого вызова в конвейере компиляции. По умолчанию он **инертен** — когда его ничто не переопределяет, движок ведёт себя в точности как прежде, и паритет полной компиляции сохраняется. Эталонный тест паритета защищает эту возможность, утверждая, что инкрементальный приём и полная компиляция дают побайтово идентичный вывод.

## Усиление

Front-matter происхождения теперь записывается через YAML-безопасный путь, закрывая инъекцию значений во front-matter (специально подготовленный заголовок или URL больше не может вырваться из блока front-matter).

## Обновление с v0.7.0

Без изменений в коде. `tesserae ingest <file>` работает «из коробки» для локальных файлов. Чтобы принимать URL, установите extra с помощью `pip install tesserae[ingest-url]`. Существующее поведение `tesserae compile` / `refresh` не изменилось — инкрементальный шов инертен, пока его не задействует `ingest`.
