发布于 **2026-08-30** · [PyPI](https://pypi.org/project/tesserae/0.36.0/) · [GitHub 发行版](https://github.com/ca1773130n/Tesserae/releases/tag/v0.36.0) · `pip install --upgrade tesserae==0.36.0`

这个版本是对已编译图两天的测量。每个数字都在这里，产生它的测试脚本都在仓库里。

## 每个文档一个锚点

分块提取为每个分块各造一个文档锚点 —— 一篇论文 9.4 个 —— 而检索器把整份原文交给每个锚点，于是一篇论文能独占 top-k 的十个位置。现在每个分块的锚点在合并前指向第一个分块的锚点，先出现的引用文档也不再被当成文档本身。用相同的缓存命中重新编译同样的 148 篇论文，文档 recall@10 从 **0.550 → 0.652**。

同根的第二个缺陷：图为每个会话保留两个锚点节点，文档优先检索的十个位置只装下四个会话。现在每个文档只列一个锚点，并填满剩余位置 —— LongMemEval recall@10 **0.867 → 0.891**。

## 一个名字就是一个实体，事实也能经由节点读出

`PDB` 在一篇论文里是 Benchmark，在另一篇里是 Dataset，每个按名字解析的消费者都拒绝这种歧义。三个合并阶段全都漏掉了它。现在同名在研究实体类型之间跨文档合并。并且 `verify_claim` 会读出提取器经由 Result 节点写下的事实 —— `S reports_result R, R evaluated_on D`。426 条陈述关系中正确数 **117 → 167**，426 条负例中伪造的 SUPPORTED 为 **0**。

## 复核标记默认就是准确的

免费检查单独使用不如模型准确（0.872 对 0.928），没有任何免模型变体能缩小差距 —— 逐一测过。级联可以：只把不确定区间交给模型，用 40% 的调用得到 **0.935**。在 `ask` 里它现在默认开启；`TESSERAE_VERIFY_BAND=off` 回到免费标记。

| 对话记忆检索 | 之前 | 之后 |
|---|---|---|
| LoCoMo，9 段对话，recall@10 | 0.878 | **0.930** |
| LongMemEval，第 0 组，recall@10 | 0.867 | **0.891** |

## 另外

- `tesserae graph-repair` 把后处理阶段应用到磁盘上已有的图 —— 不用模型，不走网络，几秒钟 —— 修复后的图与重新编译的图一致
- 面向对话记忆的文档优先排序（`document_first`）由 LoCoMo 和 LongMemEval 两条臂选用；在论文语料上它更差，因此不是默认

## 升级

对已有的图，运行 `tesserae graph-repair` 而不是重新编译。`ask` 现在默认为复核级联花费令牌；旧行为是 `TESSERAE_VERIFY_BAND=off`。
