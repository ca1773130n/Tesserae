## どの文を、なぜ確認するのか

`ask` はすでに `grounding` スコアを返していました。ひとつの数値は「何かがおかしい」とは告げても、「どこが」は決して告げません。エンベロープはこれに加えて `unsupported` を運びます — モデルが実際に受け取った証拠にその内容がほとんど存在しない文であり、それぞれ欠けていた語を伴います — そしてその隣に `supported_rate` が並びます。

しきい値は好みではなく陰性対照から得ました。442 件の実際の回答のすべての文を二度採点しています。自身の証拠に対して、そして別の質問の証拠に対して。

| 採点した相手 | 平均カバレッジ |
|---|---|
| 自身の証拠 | **0.682** |
| 別の質問の証拠 | **0.365** |

両者は **AUC 0.908** で分離します。出荷されたしきい値では、この検査は別の証拠に対して書かれた文の **78.5%** を捕らえ、本物の文の **11.3%** に印を付けます。最初は目分量で選んだしきい値で動いており、それは正しい出力の半分に印を付けていたはずです — 誰も信じない印は、印がないより価値がありません。だからこの数値は対照から出す必要がありました。

`UNSUPPORTED` は「これは偽である」ではなく、この文を確認せよという意味です。別の語彙で正しく言い換えた文もここに落ちます。`None` は検査を実行できなかったという意味であり、呼び出し側はそれを「潔白」ではなく「不明」と読まねばなりません。

## グラフが綴りのせいでエンティティを失うことはなくなりました

`ResNet-50` と `ResNet 50` は二つのノードで、名前で解決する利用者はみな曖昧さか取りこぼしを見ていました — あるコンパイル済みコーパスではそうした名前が 2,317 ありました。エンティティ解決は既存のノードが十分に近ければそれを再利用するようになり、しきい値は選ぶのではなく六つの値にわたって測定し、統合されて消えた名前はエイリアスとして残るので、どちらの綴りでも解決できます。

チャンク抽出はまた、二つのチャンクが型について食い違うたびに、ひとつのエンティティを二つのノードとして残していました — 一方は `Model`、他方は `Algorithm`。148 本のコーパスで 1,584 の名前がそうで、同じ型のものは一つもありませんでした。どちらも修正され、**試したすべてのしきい値で特異度は 1.000 を保ちました**。いかなる統合も、コーパスがしていない裏付けを作り出しませんでした。

## その他

- すでに公開された npm バージョンは、赤い CI 実行ではなく何もしない扱いになりました。タグはごく普通の理由で押し直されるからです
- エンティティ解決は `compile()` の中で走ります。あるリリースのあいだ、それは誰も呼ばないモジュールでした

## アップグレード

再コンパイルするまでは何も変わりません。確認の印に再コンパイルは要りません — 回答が受け取った証拠を読むので、いま手元にあるグラフでそのまま動きます。
