Publié **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

Les agents sont les consommateurs de premier rang de Tesserae, et après la scission des commandes en 0.18, deux capacités n'existaient plus que sur la CLI. Cette version comble ces deux lacunes avec de nouveaux outils MCP.

## `query` — récupération brute via MCP

Reflète `tesserae query` : recherche déterministe BM25/sémantique sur le wiki compilé avec `top_k` et un filtre `kind`, avec la garantie de ne jamais effectuer d'appel LLM (`force_no_llm` de bout en bout). `backend: "raganything"` atteint l'index RAG multimodal optionnel — qui n'avait **aucun chemin MCP** depuis que `ask` a perdu son paramètre backend lors de la scission 0.18. Utilisez `ask` quand vous voulez une réponse synthétisée et citée ; utilisez `query` quand vous voulez les preuves classées elles-mêmes.

## `doctor_run` — bilans de santé à la demande via MCP

`doctor_report` (0.18) ne servait que le dernier rapport persisté — un agent interrogeant un projet qui n'avait jamais exécuté doctor n'obtenait rien. `doctor_run` exécute à la demande le registre complet de 20 vérifications et renvoie les constats en JSON avec le code de sortie 0/1/2. Il est **toujours en lecture seule** : les correctifs ne s'exécutent jamais via MCP et aucun artefact de rapport n'est écrit ; les réparations restent une action humaine explicite via `tesserae doctor --fix`.

## Tout le reste circulait déjà

Aucun changement nécessaire pour le reste des fonctionnalités 0.18–0.19 : `ask` livre la réponse planifiée par LLM avec `llm` à true par défaut, `activity_summary` / `query_decisions` / `timeline` héritent de manière transparente du chemin rapide des chunks de session quotidiens, et les outils de setup acceptent les clés de fournisseur personnalisé avec `llm_api_key` délibérément non définissable et caviardée.
