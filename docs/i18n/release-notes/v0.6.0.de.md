Veröffentlicht am **2026-06-08** · [PyPI](https://pypi.org/project/tesserae/0.6.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.6.0) · `pip install --upgrade tesserae==0.6.0`

Tesserae 0.6.0 ist eine **Neugestaltung der CLI**. Alles, was die Engine tut, war unter `tesserae project <26 versteckte Unterbefehle>` vergraben, mit einem `setup` mit 29 Flags und einem `compile` mit 26; ein blankes `tesserae` kippte einen rohen Extraktions-Parser aus. 0.6.0 ersetzt das durch einen **flachen Verb-Befehlsbaum** — alltägliche Verben auf oberster Ebene, eine Handvoll kleiner Substantivgruppen, gruppierte Hilfe und `EXAMPLES` bei jedem Befehl. Dies ist eine **brechende Änderung**, die wir vor 1.0 bewusst vorgenommen haben: Alte Befehle werden nicht stillschweigend zu Aliassen, sondern geben eine einzeilige Umleitung `… has moved → …` aus und beenden sich mit Code 2, sodass die Migration offensichtlich statt rätselhaft ist. Engine, Graph, MCP-Werkzeuge und der `tesserae_mcp`-Server sind unverändert — bei dieser Version geht es ausschließlich um die Oberfläche, die ein Mensch tippt.

## 1. Der neue Befehlsbaum

```
tesserae <command>

EVERYDAY    init compile context ask serve status
AUTOMATION  engine refresh research
ANALYSIS    query lint
GROUPS      sessions vault export code config projects integrations extract
LAB         lab
```

- **Alltägliche Verben stehen auf oberster Ebene.** `tesserae compile`, `tesserae serve`, `tesserae ask`, `tesserae context "…"` — ohne `project`-Präfix.
- **`status`** ist eine neue, nur lesende Zusammenfassung (Knoten-/Kantenzahlen, letzte Kompilierung, Vault, Site).
- **`serve`** baut die Site automatisch, wenn sie fehlt oder veraltet ist (mit `--no-build` überspringen).
- **Spezialbefehle leben in kleinen Substantivgruppen:** `sessions import|discover|list`, `vault sync|export|prune|set-root|sync-all`, `export harness|graphiti|site`, `code ingest|sync`, `config llm|show`, `projects register|list|activate|unregister|mcp-config`, `integrations refresh <name>`, `extract`, `lab evolve|schema-drift`.
- **`export site`** schluckt die alten Verben `build-site`, `deploy` (`--deploy`) und `watch` (`--watch`).
- **Gruppierte Root-Hilfe + `EXAMPLES`** — `tesserae` ohne Argumente zeigt den gruppierten Baum; das `--help` jedes Befehls endet mit echten, ausführbaren Beispielen.

## 2. `init` und `compile` auf Diät

- **`init`: 29 → 8 Flags.** Standardmäßig ein Assistent; `--yes` führt ihn nicht-interaktiv aus (optionale Integrationen — Cognee, RAG-Anything, Understand-Anything — sind standardmäßig **aus**, und Farbe wird außerhalb eines TTY automatisch deaktiviert, was die alten Flags `--no-color`/`--no-cognee`/`--skip-*` mit abdeckt). `--bare` schreibt den Arbeitsbereich ohne den Assistenten. Die LLM-Backend-Flags (`--llm-provider`, `--claude-config-dir`, `--codex-home`) bleiben erhalten.
- **`compile`: 26 → 8 Flags.** Die alltäglichen Flags bleiben (`--changed-only`, `--no-sessions`, `--limit`, `--refresh-integrations`, die drei LLM-Flags und das ad-hoc `compile <paths>`). Jeder entfernte Integrations-Regler (kuzu/cognee/trends/vault-pull/…) wandert in einen **`compile_options`**-Block in `.tesserae/config.json` unter demselben Namen, mit erhaltenem altem Standardwert — das Verhalten ist also identisch, nur die Oberfläche ist still geworden. Die vollständige `compile_options`-Tabelle findest du im [Schnellstart](../quickstart.de.md).

## 3. Sauberer Schnitt bei der Migration — keine stillen Aliasse

Jeder veraltete Aufruf gibt genau eine Zeile aus und beendet sich mit Code 2:

```
$ tesserae project compile
tesserae project compile has moved → tesserae compile
```

Die Umleitungstabelle deckt jeden alten Befehl ab (einschließlich Drei-Token-Formen wie `project sessions import` und der alten Top-Level-Befehle `wiki`/`llm-defaults`), und ein blanker Markdown-Pfad (`tesserae notes/x.md`) verweist dich auf `tesserae extract`. Hooks, der CI-Smoke, der Release-Ablauf und alle Laufzeit-Strings im Repo wurden im Gleichschritt migriert; die Dokumentation und alle acht READMEs (samt jeder lokalisierten Kopie) sprechen nun die Sprache des neuen Baums.

## Aktualisierung von v0.5.0

- **Lerne die Verben neu, die du skriptest.** Die häufigsten Wechsel: `project setup --yes …` → `tesserae init --yes`, `project compile` → `tesserae compile`, `project build-site` → `tesserae export site`, `project serve` → `tesserae serve`, `project obsidian-sync` → `tesserae vault sync`, `project sync-code` → `tesserae code sync`, `tesserae llm-defaults …` → `tesserae config llm …`, `tesserae wiki …` → `tesserae projects …`. Führe die alte Form eines Befehls einmal aus — die Meldung `… has moved → …` nennt dir die neue.
- **Ein `compile`-Flag verschoben?** Wenn du `compile --trends`, `--no-vault-pull`, `--cognee-*` usw. geskriptet hast, setze stattdessen das passende `compile_options.<key>` in `.tesserae/config.json` (Tabelle im Schnellstart).
- **Die Integrations-Flags von `init` sind aus der CLI verschwunden.** Aktiviere Cognee / RAG-Anything / Understand-Anything, indem du die Eingabeaufforderungen des `tesserae init`-Assistenten beantwortest oder `.tesserae/config.json` bearbeitest und `tesserae integrations refresh <name>` ausführst.
- An **Graph, Vault, Site, MCP-Werkzeugen oder dem `tesserae_mcp`-Server** hat sich nichts geändert — nur an der dem Menschen zugewandten CLI.
