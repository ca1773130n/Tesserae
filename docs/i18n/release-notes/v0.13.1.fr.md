Une petite version additive : gérer l'étendue de la compilation d'un projet à partir de l'interface CLI au lieu de modifier manuellement `config.json`.

## `tesserae sources` — add / list / remove

`tesserae compile` (sans arguments) compile les répertoires de la liste `sources` du projet. Vous pouvez maintenant gérer cette liste à partir de l'interface CLI — et une source peut être **locale** (à l'intérieur du projet) ou **globale** (n'importe où sur le disque) :

```bash
tesserae sources add docs                 # local  — inside the project (stored project-relative)
tesserae sources add /data/shared-notes   # global — an absolute path outside the project
tesserae sources add ../sibling-project   # global — a relative path that escapes the root
tesserae sources list                     # tags each source local/global, flags missing ones
tesserae sources remove docs
```

- Un chemin **à l'intérieur** du projet est stocké **relative au projet** (donc `config.json` reste portable) ; tout ce qui est **en dehors** est stocké en **absolu**. Les deux se résolvent au moment de la compilation, donc une source globale se compile exactement comme une source locale.
- Les ajouts sont **dédupliqués par emplacement résolu** — les formes absolue et `../`-relative du même répertoire ne sont jamais comptabilisées deux fois.
- `list` marque chaque entrée `local` / `global` et signale celles qui n'existent plus sur le disque.

Auparavant, le tableau `sources` n'était défini qu'au moment de `init` (et réexécuter `init` reconstruit la config au lieu d'ajouter). C'est la façon additive et non-destructrice de développer l'étendue d'un projet.
