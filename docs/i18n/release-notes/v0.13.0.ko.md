Tesserae는 LLM 위키입니다. 따라서 `compile`은 이제 구조적 골격뿐 아니라 **개념/주장 계층을 기본으로 구축**합니다.

## `compile`은 기본적으로 개념 계층을 구축합니다

이전에는 `tesserae compile`이 **결정적** 추출기를 기본값으로 실행했습니다. 빠르고 바이트 안정적이지만 구조적일 뿐입니다 — 소스, 섹션, 명시적 링크, 희소 개념 계층. 더 풍부한 계층(개념, 주장, 기능, 기술 용어, 증거 범위 및 이들 사이의 타입 엣지)은 옵트인 Claude 전용 `--extractor claude-cli` 플래그 뒤에 숨겨져 있었습니다. LLM 위키의 경우, 이는 역순이었습니다.

이제:

- **`--extractor llm`이 기본값입니다.** `tesserae compile`은 **구성된 공급자** — codex / claude / Anthropic API, `llm_provider`에 따라 — 세션 추출이 이미 사용하는 것과 같은 `LLMJsonClient`를 사용하여 각 문서를 읽습니다. 더 이상 Claude 전용 경로가 없습니다.
- **`deterministic`은 명시적 거절입니다** — `tesserae compile --extractor deterministic`으로 빠르고, 키 없고, 바이트 안정적인 모드를 사용합니다(CI / 재현 가능 빌드). 바이트 멱등성은 변경되지 않습니다. 이것은 항상 이 모드의 속성이었습니다.
- **기본 제한 시간이 없습니다.** 이전의 `--claude-timeout=180`은 큰 설계 문서를 자동으로 성능 저하된 폴백으로 자릅니다. 추출은 이제 완료까지 실행됩니다. 제한 시간은 옵트인만 가능합니다.
- **공급자 중립 플래그:** `--llm-provider`, `--llm-model`, `--llm-include`, `--llm-limit`. (`claude-cli` / `selective-claude` 및 `--claude-*` 플래그는 여전히 사용 중단된 별칭으로 작동합니다.)
- **강력함 + 우아함.** 백엔드가 구성되지 않음? 실패하는 대신 경고와 함께 결정적으로 성능이 저하됩니다. 한 문서의 백엔드 오류는 전체 컴파일을 중단하는 대신 해당 문서에 대해 결정적으로 폴백되며, 콘텐츠 키 캐싱은 변경되지 않은 문서의 재컴파일이 이전 추출을 재사용함을 의미합니다.

```bash
tesserae compile                        # LLM 개념 계층, 구성된 공급자
tesserae compile --extractor deterministic   # 구조적 / 바이트 안정적 / 키 없음
tesserae compile --extractor selective-llm \
  --llm-include "docs/**/*.md" --llm-limit 20   # 비용 인식
```

## 더 빠른 페더레이션 `ask`

페더레이션 `ask`는 *모든* 쿼리에서 크로스 프로젝트 그래프를 다시 조립했습니다(모든 멤버 프로젝트 읽기 + 구문 분석 + 네임스페이스 + ID 병합) — 대기 시간의 약 1/4, 같은 프로젝트 세트에 대한 대화에서 각 후속 조치마다 다시 수행됩니다. 조립된 그래프는 이제 인프로세스로 메모이제이션되며, 각 멤버의 그래프 파일 변경 서명으로 키가 지정됩니다. 반복 쿼리는 즉시 캐시 히트이며, 항목은 **모든 멤버 프로젝트가 재컴파일되는 순간 자체 무효화됩니다**(디스크 캐시 없음, 부실 없음). 실제 6개 프로젝트 / 22.6k 노드 페더레이션에서 이는 반복 쿼리당 ~0.6초 어셈블리를 건너뜁니다.

## v0.12.x에서 업그레이드

한 가지 동작 변경: `tesserae compile`은 이제 기본적으로 LLM 추출을 수행합니다. 이전의 구조 전용 동작을 원하는 경우(예: CI에서 또는 LLM 백엔드 없이) `--extractor deterministic`을 전달합니다. — 구성된 공급자가 없는 머신에서는 컴파일이 이미 자동으로 폴백됩니다.
