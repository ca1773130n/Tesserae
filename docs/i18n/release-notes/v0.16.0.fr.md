Released **2026-07-06** · [PyPI](https://pypi.org/project/tesserae/0.16.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.16.0) · `pip install --upgrade tesserae==0.16.0`

La page Sessions de `tesserae serve` n'attend plus la prochaine compilation. Elle lit maintenant votre activité agent **en direct** directement depuis les racines du harnais — donc une session dans laquelle vous êtes *en ce moment même* s'affiche au fur et à mesure que vous travaillez.

## Sessions en direct sur la page serve

Lorsque vous exécutez `tesserae serve`, la page Sessions récupère un nouveau point de terminaison **`/api/sessions`** qui analyse vos racines Claude Code à la volée (limité par une fenêtre récente) et affiche les sessions actuellement actives au-dessus du tableau compilé — identifiant de session, compte, nombre de tours, heure de dernière activité et un aperçu du tour d'ouverture. Ouvrez une compilation statique (GitHub Pages) à la place et le panneau reste simplement masqué : le tableau compilé est la page entière, exactement comme avant.

La boîte de **recherche rapide de transcriptions** fonctionne de la même manière : les résultats frais analysés à partir des racines sont fusionnés *avant* les résultats de l'index memex (dédupliqués), donc une phrase que vous avez tapée il y a quelques instants est trouvable avant d'être indexée.

Les deux surfaces sont **à l'origine gated** — elles exposent l'historique local, donc une requête de navigateur intersites est rejetée, tout comme le point de terminaison de clip.

### Pourquoi Claude uniquement, et comment codex reste couvert

Les transcriptions Claude Code sont délimitées par répertoire, donc une analyse en direct par projet est sub-seconde. Les sessions Codex ne le sont pas — se limiter à un projet signifierait analyser chaque fichier de session récent (100 000+ sur une machine chargée, ~170 s par requête), bien trop lent pour une page interactive. Donc l'analyse en direct est **Claude uniquement** ; codex est servi depuis l'index memex et la projection compilée comme avant. Les commandes hors ligne `tesserae summary` et `tesserae decisions` analysent toujours **chaque** compte — Claude et codex — car elles peuvent se permettre le passage complet.

## `--max-turns` sur summary et decisions

`tesserae summary` et `tesserae decisions` gagnent un drapeau `--max-turns N` qui limite le nombre de tours lus par session avant fenêtrage. Utile pour limiter le coût d'une énorme session lorsque vous n'avez besoin que d'une tranche récente. La valeur par défaut reste effectivement illimitée.

```bash
tesserae summary --day 2026-07-06 --max-turns 200
tesserae decisions --week --max-turns 200
```

## Mise à jour

Compatible avec v0.15.x. Tout est additif — les points de terminaison en direct n'existent que sous `tesserae serve`, la page se dégrade proprement sur l'hébergement statique, et rien ne nécessite une migration ou une recompilation. Il lit vos sessions existantes à la volée.
