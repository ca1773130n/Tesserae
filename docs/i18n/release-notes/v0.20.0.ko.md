Released **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

에이전트는 Tesserae의 일급 소비자인데, 0.18의 명령 분리 이후 두 가지 기능이 CLI에만 존재했습니다. 이번 릴리스는 새로운 MCP 도구로 그 두 격차를 모두 메웁니다.

## `query` — MCP를 통한 원시 검색(raw retrieval)

`tesserae query`를 그대로 반영합니다: 컴파일된 위키에 대한 결정적(deterministic) BM25/시맨틱 검색으로, `top_k`와 `kind` 필터를 지원하며 LLM 호출을 절대 하지 않도록 보장됩니다(`force_no_llm`이 끝까지 적용). `backend: "raganything"`은 선택적 멀티모달 RAG 인덱스에 접근합니다 — 0.18 분리에서 `ask`가 backend 파라미터를 잃은 이후 **MCP 경로가 전혀 없던** 기능입니다. 합성되고 인용이 달린 답변이 필요하면 `ask`를, 순위가 매겨진 근거 자체가 필요하면 `query`를 사용하세요.

## `doctor_run` — MCP를 통한 신선한 상태 점검

`doctor_report`(0.18)는 마지막으로 저장된 리포트만 제공했습니다 — doctor를 한 번도 실행한 적 없는 프로젝트에 접근한 에이전트는 아무것도 얻지 못했습니다. `doctor_run`은 요청 시 20개 검사 레지스트리 전체를 실행하고, 결과를 0/1/2 종료 코드와 함께 JSON으로 반환합니다. 이 도구는 **항상 읽기 전용**입니다: MCP를 통해서는 수정이 절대 실행되지 않고 리포트 아티팩트도 기록되지 않으며, 복구는 여전히 `tesserae doctor --fix`를 통한 명시적인 사람의 행동으로 남습니다.

## 나머지는 이미 다 흐르고 있었습니다

0.18–0.19의 나머지 기능에는 변경이 필요 없었습니다: `ask`는 `llm` 기본값 true로 LLM이 계획한 답변을 제공하고, `activity_summary` / `query_decisions` / `timeline`은 일별 세션 청크 패스트 패스를 투명하게 상속하며, setup 도구들은 커스텀 프로바이더 키를 받되 `llm_api_key`는 의도적으로 설정 불가하고 마스킹(redacted) 처리됩니다.
