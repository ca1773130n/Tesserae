只有一处修复，位于本应把这个项目与对照组放在一起衡量的那个基准分支里。它什么也没有衡量。

## 这个分支要的是一张没人会构建的图

`_papers_by_arxiv` 要求一个带 `metadata["arxiv_id"]` 的 `Paper` 类型节点，而证据遍历要经由 `EvidenceSpan --part_of--> Paper` 抵达区块。`tesserae compile` 一个都不写。它输出带 `arxiv` 的 `SourceDocument`，用 `contains` 挂接区块，并把主张通过 `evidenced_by` 挂在区块上，而不是通过 `supports_claim` 挂在文档上。

在一个 14 篇论文的暂存语料库上实测，解析器只返回了**一个**节点——那是母论文，仅仅因为它自己的 `paper.md` 前置元数据声明了 `type: Paper`。14 篇被引论文全部落入跳过分支，于是这个分支只渲染出一张摘要兜底卡片，对上对照组的十四张。`part_of` 在那里是 0 条边，在另行编译的 1,552 篇论文池中同样是 0 条。

这个分支产出的每一个 DeepScholar 数字，都带着一处被当成图的性质来读的**18 倍证据亏空**。

## 一套检验想象之图的绿色测试

这套测试装置里有一个测试，它唯一的职责就是抓住这件事：两个分支必须向写作者展示相同数量的行，否则它们之间的差距无从归因。它自始至终都通过了。因为文件里的每一个夹具构建的都是 `Paper`/`arxiv_id`/`part_of`——那是代码所预期的形状，而不是编译器所写出的形状。

值得记住的正是这一点。测试只能拿代码去比对夹具心中的那个现实，而两者心中的现实是同一个。新测试构建的是 `tesserae compile` 实际输出的节点与边词汇，于是两者终于可以彼此不一致。

修复之后，这个分支渲染出**14 篇中的 14 张卡片**，42 行对上对照组的 42 行，其中 15 行是此前一句也没有的主张句。

## 其他

- 两套边词汇都被接受，因此旧的合成形状继续可用
- 模块 docstring 和 `evals/deepscholar/README.md` 此前描述的是不存在的路径，现在描述的是真正构建出来的那条
