Publié **2026-07-21** · [PyPI](https://pypi.org/project/tesserae/0.22.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.22.0) · `pip install --upgrade tesserae==0.22.0`

v0.21.0 a livré la mémoire par agent en couches, mais la moitié de celle-ci n'était accessible que via MCP et `tesserae agents init` déversait chaque agent sous `org:root`. Cette version rend la fonctionnalité complète utilisable à partir du terminal.

## `init` construit une véritable org

`tesserae agents init` déduit maintenant la hiérarchie à partir d'un signal qui existe déjà : un rôle de sous-agent (`claude-code:me:reviewer`) est attaché à l'agent principal qui l'a lancé (`claude-code:me:default`), au lieu que tout le monde atterrisse à plat sous `org:root`. Vous obtenez une org multi-niveaux fonctionnelle à partir d'une seule commande — pas besoin de `set-parent`. Passez `--flat` pour l'ancien comportement, et `init` affiche maintenant l'arborescence proposée pour que vous puissiez voir ce qu'il a décidé.

```
org:root
  claude-code:me:default   Main    sessions=42
    claude-code:me:reviewer   Reviewer   sessions=8   distilled_through=2026-07-20T…
    claude-code:me:planner    Planner    sessions=5   (not distilled)
```

## Lectures ciblées à partir du CLI

`--agent KEY` fonctionne maintenant sur `tesserae query`, `ask`, et `context` — la récupération et la synthèse s'exécutent sur la vue résolue de l'agent (une clé **worker** voit sa propre mémoire brute + distillée, une clé **manager** voit les couches distillées de ses rapports, `org` voit toute l'équipe). Auparavant, ce ciblage n'existait que comme argument MCP.

```bash
tesserae query "release checklist" --agent claude-code:me:reviewer
tesserae ask "what does my team know about deploys?" --agent org
```

Les clés inconnues et les agents non distillés échouent bruyamment avec la commande de remède exacte, jamais une réponse silencieusement vide.

## Inspecter l'org

- **`tesserae agents tree`** — l'organigramme sous forme d'arborescence indentée, chaque agent annoté avec le nombre de sessions et le degré d'obsolescence de sa mémoire distillée.
- **`tesserae agents show KEY`** — résoudre une vue et imprimer son mode, agents membres, chemins d'artefacts, décomptes de nœuds, et marques d'obsolescence.
- **`tesserae agents drill NODE_ID [--agent KEY]`** — l'escalade auditée d'une note distillée jusqu'à sa preuve brute L0, maintenant une commande CLI de première classe (alive / changed / absorbed / gone). La logique `drill_down` est partagée avec l'outil MCP, donc les deux interfaces se comportent de manière identique.

## Sous le capot

L'inférence de hiérarchie des rôles est une fonction pure et déterministe ; le cœur de `drill_down` a été extrait pour que le CLI et le serveur MCP partagent un seul chemin de code audité. Aucune modification des artefacts distillés ou de leurs garanties de déterminisme. Purement additif — chaque commande existante se comporte exactement comme avant quand `--agent` est absent.
