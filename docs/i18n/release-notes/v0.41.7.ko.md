공개일 **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.7/) · [GitHub 릴리스](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.7) · `pip install --upgrade tesserae==0.41.7`

v0.41.6부터 두 번째 Ctrl-C나 SIGTERM은 컴파일이 도는 메인 스레드에서 예외를 일으켜
`tesserae engine`을 컴파일 도중에도 멈춥니다. 플릿 모드인 `tesserae engine --all`은 예전 동작
그대로였습니다. 거기서는 프로젝트마다 자기 스레드에서 컴파일하므로 그 방식이 닿지 않았고, 플릿은
첫 신호 이후의 모든 신호에 컴파일이 끝나기를 기다리는 것으로만 답했습니다. 빠져나갈 방법은
SIGKILL뿐이었고, 그러면 `claude -p` 자식 프로세스가 모두 자기 세션에서 계속 돌며 비용을 썼습니다.

## 무엇이 바뀌었나

- **두 번째 신호는 플릿을 멈춥니다.** 플릿의 pidfile과 자신이 쓴 프로젝트 pidfile을 지우고,
  실행 중인 CLI 에이전트를 모두 종료하며 새 에이전트는 시작하지 않은 뒤, 관례적인 종료 상태로
  빠져나옵니다. 잃는 것은 없습니다. 각 프로젝트의 다음 컴파일이 매니페스트 차이로 바뀐 소스를 찾아냅니다.
- **첫 번째 신호는 모든 프로젝트에 한꺼번에 전달됩니다.** 예전에는 프로젝트를 하나씩 멈췄기 때문에,
  첫 프로젝트가 컴파일을 끝내는 동안 나머지는 계속 변경을 감시하다가 정지 요청 뒤에 새 컴파일을
  시작할 수 있었습니다. 각 프로젝트는 여전히 하던 일을 끝내며, 플릿은 이제
  `signal again to stop now`라고 알립니다.

## 업그레이드

이전할 것은 없습니다. 실행 중인 플릿은 재시작해야 반영됩니다. `engine --all --once`나 평범한
`tesserae compile`에 보낸 SIGTERM은 여전히 프로세스를 즉시 끝내며 `claude -p` 자식 프로세스를
남길 수 있습니다. Ctrl-C는 두 경우 모두 처리합니다.
