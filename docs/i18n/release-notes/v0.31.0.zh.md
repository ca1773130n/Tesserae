会话转录记录了某条命令被运行过。到目前为止，图谱保留的也仅止于此——调用这一事实，
而从不包括它的结果。一个读自己历史的智能体能看到自己跑过 `pytest`，却不知道测试
是否通过。这正是日志与记忆之间的差别，也是这个版本要补上的缺口。

## 工具结果也是一个轮次

现在退出码与错误标志能挺过摄取，并落到该轮次的 `Event` 节点上。图谱可以区分**失败
了**的命令与仅仅运行过的命令。

铸造这些节点的 `Event` 流程仍然不依赖 LLM、且遇错不抛：每个有意义的转变一个节点，
相邻事件之间以 `precedes` 相连，每个 id、正文与日期都由内容派生。重跑一次会产生逐
字节相同的输出——在一个 481 场会话的语料上验证过，并且用一个"任何属性访问都会抛
异常"的客户端再验证了一次，因为该流程对带会话的项目默认开启，而这份安全性完全建立
在"路径中没有模型"之上。

轮次文本会被复制进节点名称与描述，而它们会被序列化进 `graph.json` 及其所有投影，因
此**主目录在进入时就被遮蔽**。`/Users/<name>` 与 `/home/<name>` 永不抵达图谱——路径
正是那种没人有意写入、却出现在几乎每份转录里的个人数据。

## `recovers` 边

现在 Tesserae 会从同一会话中两个**被观测到**的结果推导出一条因果边：一次报告失败的
工具调用，以及其后一次报告成功的调用——同一工具、同一程序家族、同一工作目录、同一
操作对象，且期间没有观测到该操作对象上的任何成功。成功的 `Event` 是源，失败的那个
是目标；两个轮次 id 都写入证据，而 `metadata["basis"]` 列出这两次调用必须一致的每
一个维度。

`CAUSAL_EDGE_TYPES` 恰好只有一个成员，并且会保持如此。对四个领先的智能体记忆系统
的调研发现，没有任何一个真正推导出因果边：两个把最强的链接建立在共现之上，一个不
加验证地采信 LLM 给出的开放关系标签，还有一个根本没有边。这种克制要避免的失败，就
是发布一条实际上是 `happened_near` 的 `caused_by`——在图谱里两者无法区分，而错的那
个会被当成证据来读。

锚点是**操作对象**，不是命令。命令会在无关紧要的地方变化——参数、顺序——而被作用的
那个东西才是重试真正在重试的目标。这个选择来自 103 份真实转录、2,330 条工具结果与
94 次原始失败，用四个候选锚点键重新解析，并全程人工核验。

## 一个靠出处挣得的过程性预留槽位

`tesserae context` 现在为每个过程性池预留一个槽位——`Runbook`、`Gotcha`、`Event`、
`DistilledNote`、`ExpertiseProfile`——好让智能体实际运行了什么、结果如何，能够挤进
紧张预算遍历的最前面。

这个槽位是**挣来的，不是白给的**。这五个类型名同样可以由文档抽取铸造，所以一个读征
稿启事的 LLM 会名正言顺地铸造出名为 "CVPR 2026" 的 `Event`。预留是加性的——它会把
邻域中任意位置的节点提到预算最前——因此仅凭类型预留，会让一个会议截止日期挤掉真正
挣得该槽位的会话发现。区分二者的正是 `has_producer_provenance`；而预留只是对槽位的
主张，不是它被兑现的证明：`delivered` 在预算遍历之后才敲定，于是调用方能区分"过程
性记忆被预留了"和"过程性记忆真的到位了"。新增的 `PROCEDURAL_POOLS` lint 代码会报告
这中间的落差。

## 节点的日期取自它的来源是从哪里进来的

`first_seen_at` 现在由节点来源被摄取时所在的路径派生，而不是编译时的挂钟。读时钟会
让每次重跑都产生 diff，而这会摧毁逐字节幂等所依赖的内容哈希跳过。同一条规则也让
`Event` 流程保持可复现。

## 文档

文档已经落后代码整整一个周期，这个版本在全部八种语言中把它修正过来。五个此前完全
没有面向用户文档的子系统——章程、lint 代码词汇表、工具结果、`recovers` 边、过程性槽
位——现在有了文档；九个已提供却未列出的 MCP 工具也被记录下来，于是智能体能够发现为
它而写的工具。全部 35 个已提供工具在每种语言中都有覆盖。

同时还修了两个更早的缺陷：`docs/i18n/` 内的 70 个断链（翻译页面链接到英文文件名，而
那些名字在该目录下并不存在），以及架构文档中 `OKF v0.2 导出/导入` 一节——它随
v0.10.0 发布，却从未被翻译过。

## 升级

```bash
pip install --upgrade tesserae==0.31.0
```

这里没有任何东西需要迁移。`Event` 流程与 `recovers` 检测器会在带会话的项目下次编译
时运行；现有图谱无需强制重建即可获得新的节点与边。本版本之前导入的会话不带退出
码，因为那些信息在摄取时就被丢弃了，且无法从归一化记录中还原——如果你想让它们带上
结果，请重新导入那些转录。
