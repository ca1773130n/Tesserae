Veröffentlichungsdatum **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.1) · `pip install --upgrade tesserae==0.7.1`

`tesserae ingest <file|url>` ist ein neuer Befehl der obersten Ebene, der ein **einzelnes** Dokument oder eine URL in deine Wissensbasis einbindet — ohne den gesamten Korpus erneut zu extrahieren — und dabei **byte-identisch** zu einer vollständigen Kompilierung bleibt. Lege eine Datei ab oder verweise auf eine Webseite, und dein Graph wird inkrementell aktualisiert, statt jedes Mal die Kosten einer vollständigen Neukompilierung zu tragen.

## 1. `tesserae ingest <input>...` — inkrementelle Aufnahme einer einzelnen Quelle

Der neue Befehl nimmt eine oder mehrere Eingaben entgegen — lokale Dateipfade oder `http(s)`-URLs — und fügt jede einzeln in die bestehende Wissensbasis ein. Er unterscheidet sich von `tesserae code ingest`: Hier geht es um die Aufnahme von Dokumenten/Quellen in den Hauptgraphen, nicht um die Code-Indizierung.

Standardmäßig führt `ingest` einen **inkrementellen Schnellpfad** aus, der nur die neue Quelle berührt. Der Schnellpfad ist *paritätsgesichert*: Es ist verifiziert, dass er byte-identisch zu einer vollständigen Kompilierung ist, und wenn die Parität nicht garantiert werden kann, fällt er automatisch auf eine vollständige Neukompilierung zurück, sodass die Korrektheit nie gefährdet ist. Übergib `--exact`, um die vollständige Neukompilierung selbst zu erzwingen.

Flags: `--exact`, `--dry-run`, `--title`, `--source-kind`.

## 2. URLs werden abgerufen, konvertiert und mit Herkunftsangaben verfolgt

Gib `ingest` eine `http(s)`-URL, und es ruft die Seite ab, konvertiert sie nach markdown und speichert sie als verfolgte Quelle unter `data/ingested/<slug>.md` mit Herkunfts-Front-Matter: `source_url`, `fetched_at`, `content_sha256` und `arxiv_id`, wenn die Quelle als arXiv-Paper erkannt wird.

Die URL-Aufnahme wird hinter einem neuen optionalen Extra ausgeliefert, damit die Basisinstallation schlank bleibt:

```
pip install tesserae[ingest-url]
```

## 3. Lokale Dateien außerhalb des Korpus werden Teil des Korpus

Wenn du eine lokale Datei aufnimmst, die außerhalb des verfolgten Korpus liegt, kopiert `ingest` sie in den Korpus. Auf diese Weise reproduziert eine spätere vollständige `tesserae compile` exakt dasselbe Ergebnis — die inkrementelle Aufnahme und eine Kompilierung von Grund auf konvergieren zu identischen Bytes.

## 4. Unter der Haube: eine paritätserhaltende inkrementelle Naht (seam)

Der inkrementelle Schnellpfad baut auf einer pro Aufruf wirksamen `incremental_override`-Naht in der Kompilierungspipeline auf. Sie ist **standardmäßig inert** — wenn nichts sie überschreibt, verhält sich die Engine genau wie zuvor und die Parität der vollständigen Kompilierung bleibt erhalten. Ein Golden-Parity-Test sichert die Funktion ab und stellt sicher, dass eine inkrementelle Aufnahme und eine vollständige Kompilierung byte-identische Ausgaben erzeugen.

## Härtung

Das Herkunfts-Front-Matter wird nun über einen YAML-sicheren Pfad geschrieben, womit die Injektion von Werten ins Front-Matter geschlossen ist (ein manipulierter Titel oder eine manipulierte URL kann nicht mehr aus dem Front-Matter-Block ausbrechen).

## Upgrade von v0.7.0

Direkt einsetzbar. `tesserae ingest <file>` funktioniert für lokale Dateien sofort. Um URLs aufzunehmen, installiere das Extra mit `pip install tesserae[ingest-url]`. Das bestehende Verhalten von `tesserae compile` / `refresh` bleibt unverändert — die inkrementelle Naht bleibt inert, solange `ingest` sie nicht antreibt.
