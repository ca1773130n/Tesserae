公開 **2026-06-30** · [PyPI](https://pypi.org/project/tesserae/0.12.2/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.12.2) · `pip install --upgrade tesserae==0.12.2`

2つのバグ修正。v0.12.x からのドロップイン対応です。

## `tesserae engine` がファイルディスクリプタを枯渇させなくなった

長時間実行されるデーモン（特にフリートモード、多くのプロジェクトを監視している場合）は、`Too many open files` / `unable to open database file` エラーの嵐に陥る可能性がありました。これはコンパイルの失敗、フリートレジストリの読み取り不可、および codex テンポラリファイルエラーにカスケードし、すべてがプロセスファイルディスクリプタテーブルを共有していました。

原因：セッションテーラーはすべてのプロジェクトトランスクリプトを既知のセットに保持し、**新しいバイトをチェックするためだけにすべてのトランスクリプトの `.jsonl`（および sqlite 接続）をすべてのティックで開いていました**。完了したトランスクリプトが数万個あると、ティックあたり数万回の開閉が発生し、OSがそれらを再利用するよりも速くなっていました。現在は、トランスクリプトに新しいバイトがない場合、安価な `stat()` で開閉を完全にスキップします。消失したファイルは追跡セットから削除され、切り詰められた/ローテーションされたファイルは最初から再読み込みされます。定常状態では、アイドル状態の大多数に対して **~0 開閉** になり、成長中のトランスクリプトだけが読み込まれます。

## `tesserae ask` は最近性対応です

フェデレーション `ask` で*最近の*仕事について問い合わせると、数週間前のセッション合成ノード（例：*「直前に行われたすべての改善をレビュー」*という題名）がトップに表示される可能性がありました。これらは「最近の仕事」の最も強い*意味的*一致ですが、実は最も古いコンテンツでした。純粋な関連性ランキングには最近性シグナルがなかったためです。

フェデレーション回収は、ノードの関連性を**最近性スコア**とブレンドして、より新しいノードが表示されるようにします。関連性はまだ支配的です（デフォルト 0.25 で控えめ）。日付なしのノードはフレッシュではなくニュートラルとして扱われ、タイトルにのみ日付があるノード（`2026-05-18 — …`）はその日付にアンカーされます。`tesserae ask --recency-weight <0..1>` で調整または無効化できます（`0` = 純粋な関連性、以前の動作）。コンパイルおよびエクスポートされたアーティファクトは影響を受けず、バイト確定性を保ちます。

## v0.12.x からのアップグレード

ドロップイン対応です。多くのプロジェクトに対して `tesserae engine` を実行している場合、このアップグレードをお勧めします。
