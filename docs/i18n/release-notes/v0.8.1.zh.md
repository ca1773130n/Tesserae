发布日期 **2026-06-13** · [PyPI](https://pypi.org/project/tesserae/0.8.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.8.1) · `pip install --upgrade tesserae==0.8.1`

本补丁版本来自首次真实环境下的 `tesserae engine --all` 运行（5 个项目）。升级后请重启引擎。

## 1. 彻底消除 sqlite "unable to open database file" 风暴

进程内编译加上多个持续运行的会话尾随器会耗尽 macOS 默认的 **256 个打开文件软限制**；一旦耗尽，进程中的每个 sqlite open 都会失败，尾随器会对每个被追踪的文件打印一条回溯信息。`tesserae engine` 现在在启动时将 `RLIMIT_NOFILE` 提升至 8192，系统性 tick 失败只记录**一条**回溯信息及抑制计数摘要。

## 2. 重启时跳过冷扫描

会话尾随器的首次运行会对完整的 Codex 发布历史进行一次全量扫描以查找项目会话——在大型历史记录下需要数十分钟，而之前**每次**重启都会重复此操作。现在，扫描下限已持久化到会话 DB 中；重启时从该点恢复（对最近恢复的会话保留 7 天回溯），并通知冷启动或热启动、耗时及条目数。

## 3. 安静且信息丰富的日志

- 六种新的 Claude Code 转录行类型（`last-prompt`、`queue-operation`、`mode`、`ai-title`、`file-history-snapshot`、`pr-link`）被识别为良性元数据——实时尾随时不再产生警告刷屏；真正未知的类型**每个进程只警告一次**。
- 每次管道运行记录 `pipeline starting for <project>` ——不再看起来像卡死，因为之前唯一的其他输出只在完成*之后*才出现。

## 4. README 更新

README（及所有七个语言镜像）已重写：当前功能集（`ingest`、`engine --all`、sessions），正确的 Python 要求（3.10+），以及将对比矩阵和演示 GIF 折叠进可展开区域的更简洁结构。

## 从 v0.8.0 升级

直接替换即可。重启所有正在运行的 `tesserae engine` / `tesserae engine --all` 以应用修复——首次重启仍会执行一次最终冷扫描以初始化持久化下限；此后每次重启都很快。
