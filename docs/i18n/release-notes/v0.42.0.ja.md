リリース **2026-10-06** · [PyPI](https://pypi.org/project/tesserae/0.42.0/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.42.0) · `pip install --upgrade tesserae==0.42.0`

ノードとエッジの語彙は閉じていました。関係タイプを一つ増やすにはリリースが必要で、そのタイプを使った
グラフは古いインストールでは読めませんでした。毎週自分のオントロジーを育てるホストは、そのやり方では
回りません。このリリースでは、ホストが実行時にタイプを登録でき、各タイプはコアの親の下に置かれます。
ホストが書くファイルはすべて 0.41 でも読み込めます。

## 変更点

- **タイプレジストリ。** `tesserae.type_registry` は、コード、JSON ファイル、または
  `TESSERAE_TYPE_REGISTRY` から登録された `TypeSpec` 行を保持します。すべてのタイプは `core_parent` を
  指定します。ノードはコアタイプを保ったまま、より細かい種類を `metadata.subtype` に持ちます。有効な
  レジストリのエッジタイプはメモリ上で受け付けられます。
- **寛容な読み込み。** `TESSERAE_TYPE_MODE=lenient` は、読み手の知らないタイプをレジストリ上の親へ、
  なければ `Concept` か `references` へ対応付けます。元のタイプは `metadata.raw_type` に残し、
  `load_stats` で数えます。既定値は今も `strict` で、これまでとまったく同じように例外を送出します。
- **レジストリから決まるビュー。** レジストリのタイプは宣言したビューに、なければ親のビューに入ります。
  新しい `crossdomain` ビューは `transfers_to` や `inspired_by` のような分野をまたぐ関係を持ちます。
  ホストがそれらを登録するまでは空です。
- **エッジの信頼度と状態。** エッジは任意で `confidence`、`status`、`asserted_by`、`valid_from`、
  `invalid_at`、`provenance` を持てます。PPR はタイプの重みに `confidence` を掛け、指定がない限り
  `candidate`、`refuted`、`retracted` のエッジを飛ばします。反証された `supersedes` エッジは、もう
  対象を隠しません。
- **コンテンツリゾルバ。** `compile_context(content_resolver=...)` は、まずホストにノードの内容を最も
  安いビューから問い合わせ、その後で wiki ページと説明に戻ります。引用には実際に使った参照が残ります。
- **概念の同一性。** フェデレーションは、`metadata.concept_id`、Wikidata QID、または MSC2020 分類を
  共有するノードを統合します。`federate_graphs(identity_resolver=...)` を使うと、ホストはどの
  `graph.json` も編集せずに自分のテーブルから同一性を渡せます。
- **スキーマドリフト。** `analyze_schema_drift(kind="edge")` は下位関係を提案し、`embedder` が名前
  トークンの Jaccard に代わり、台帳のレコードにはゲート指標が付き、`apply_ledger_to_registry` は承認
  された提案をレジストリファイルに書き込みます。ノードのタイプを変えることはありません。
- **上限付きの近傍取得。** `store_neighbors` と `store_iterate_edges` は、ストアに独自の
  `neighbors` / `iterate_edges` があればそれを使い、なければ代替経路で動きます。`GraphStore` 自体は
  変わっていません。
- **生産者専用のエッジ。** `transfers_to`、`candidate_transfer`、`analogous_to`、`merged_into` は、
  LLM が抽出することも、エージェントがタイプとして書くこともできません。
- **エージェントによる書き込み。** `graph_write` はレジストリのタイプを記録する前にコアの親へ対応付け、
  `metadata.subtype` か `metadata.relation` を付けます。エッジは `metadata` を持てます。

## 互換性

0.41 の `graph.json` は厳格モードで、ノード数、エッジ数、タイプ数が同じまま読み込まれます。新しい
フィールドを持たないグラフは、以前とバイト単位で同じように直列化されます。このリリースが `graph.json` や
`agent-writes.jsonl` に書くものはどれもレジストリのタイプを使わないため、0.41 に戻しても安全です。

## アップグレード

移行作業はありません。レジストリがなければ、既定の動作はすべて 0.41 と同じです。
