Veröffentlicht am **2026-09-16** · [PyPI](https://pypi.org/project/tesserae/0.41.3/) · [GitHub-Release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.3) · `pip install --upgrade tesserae==0.41.3`

v0.41.2 hat die zwölf schwerwiegendsten Funde des Kommando-Audits geschlossen.
Dieses schließt die anderen neunzehn, also alle.

## Was sich geändert hat

- **Sieben Kommandos antworten auf einen Fehler mit einem Satz.** Ein falscher
  Pfad, ein nicht lesbares Datum, ein Konfigurationswert, der kein Anbieter ist:
  jedes davon endete zuvor in einem Stacktrace. Am schlimmsten war
  `tesserae compile`, das wegen einer einzigen unlesbaren Datei einen ganzen
  Korpus abbrach; es benennt nun, was es übersprungen hat, und kompiliert den
  Rest.
- **Sieben Kommandos berichten nicht mehr, was nicht geschehen ist.** `status`
  zeigte eine Kompilierzeit für ein Projekt, das nie kompiliert wurde.
  `config status` schrieb dem Standardwert zu, was eine Datei gesetzt hatte.
  `schema-drift` behauptete, für einen Typ keine Cluster gefunden zu haben, den
  es nie geclustert hatte. `graph-map` gab einen Paging-Cursor zurück, der dem
  erhaltenen glich, sodass ein Aufrufer, der ihm folgte, endlos kreiste.
- **Fünf Kommandos akzeptieren nicht mehr, was sie ablehnen sollten.** Ein falsch
  geschriebener Agentenname antwortete, als wäre er echt. `projects register`
  meldete stillschweigend ein anderes Projekt ab, wenn zwei Verzeichnisse
  denselben Namen ergaben. `domains status` riet einem Verzeichnis, das kein
  Projekt ist, eine Kompilierung auszuführen.
- **Eine Vorschau zeigt, was sie zu zeigen vorgibt.** `sessions prune-internal
  --dry-run` gab die Gesamtzahl gespeicherter Datensätze aus, wo es die Zahl der
  zu löschenden meinte.

## Upgrade

Nichts zu migrieren. Mehr Kommandos enden mit 2, wo sie zuvor still mit 0
endeten, sodass ein Skript, das sich auf diese Stille verließ, Fehlschläge zu
melden beginnt, die es ohnehin schon hatte.
