已发布 **2026-06-29** · [PyPI](https://pypi.org/project/tesserae/0.12.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.12.0) · `pip install --upgrade tesserae==0.12.0`

不再有"活动项目"了。每个已注册的项目都同时运行 — `ask` 跨项目自动路由，`serve` 在一个站点下为它们全部提供服务，`compile` 现在可以构建确定性提取器遗漏的 LLM 概念层。

## 无活动项目 — 智能 `ask` 路由器

"活动项目"的概念已经消失：`tesserae projects activate` 和 `activate_project` MCP 工具被移除，每个项目级命令都从你所在的目录解析项目。所有已注册的项目都是平等的。

裸 `tesserae ask` 现在 **自动路由**：

- 提及项目 → 该项目；
- 比较或通用 → **联合**(跨项目合并的单一交叉引用答案)；
- 跟进问题("为什么?")保持前一个路由；话题转变("另一个呢?")重新路由。

明确的情况可以免费解决；可选的 LLM 决策器处理确实模糊的情况，短的每次对话历史记录保持多问题线程的连贯性。显式 `--scope current|all-registered|federated` 仍然有效。

## 每个项目一个服务器 — `tesserae serve`

裸 `tesserae serve` 现在在一个服务器下服务 **每个已注册的项目**：项目登陆页在 `/`，每个项目在 `/<alias>/`，页头有项目切换器，以及每个项目的会话视图。页面内的 ask 小部件实时工作，路由到提出问题的页面的项目。`tesserae serve --project X` 仍然服务单个项目。请求是路径包含的(无法逃脱项目的站点目录)，ask 端点有同源检查和请求大小限制。

## 在 `compile` 中构建概念层 — `--extractor`

`tesserae compile --extractor claude-cli` (或 `--extractor selective-claude --claude-include "<glob>" --claude-limit N`) 构建确定性默认值遗漏的稀疏的概念/声明层 — 包括概念、声明、能力、证据跨度和类型化边。它针对真实语料库进行了强化，其中一个嘈杂或缓慢的文档过去会导致整个编译中止：

- 受控词汇之外的边类型被 **丢弃**，不是致命的；
- 超过每个文档超时的文档 **回退** 到该文件的确定性提取；
- 瞬态无效生成被 **重试**(模型是非确定性的，所以重新调用几乎总是验证)。

## 本版本中的其他内容

- **Cognee 1.0 兼容性** — Cognee 1.0 移除了 Tesserae 默认的 `INSIGHTS` 搜索类型，这悄悄破坏了 cognee `ask` 后端。它现在映射到 `GRAPH_COMPLETION`(知识图上的答案)，所以 cognee 再次工作；传递 `--cognee-search-type CHUNKS` 进行原始检索。
- **`tesserae setup`** — 一个顶级的、交互式的机器范围设置(LLM 提供者/工作量 + 要安装的可选依赖)；标志跳过提示，安装在无 pip 的 `uv tool` 环境中工作。
- **文档** — README、快速入门、安装、MCP 指南、功能地图和集成指南已更新(不再有"活动项目")。

## 从 v0.11.x 升级

主要是即插即用。**破坏性变更：** `tesserae projects activate` 和 `activate_project` MCP 工具被移除 — 每个项目命令通过当前目录解析，`ask` 跨项目自动路由。如果你编写了 `projects activate` 脚本，只需删除它。单项目使用不变。
