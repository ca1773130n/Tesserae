Publié le **2026-06-13** · [PyPI](https://pypi.org/project/tesserae/0.8.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.8.1) · `pip install --upgrade tesserae==0.8.1`

Version de correctifs issue du premier vrai déploiement de `tesserae engine --all` (5 projets). Redémarrez le moteur après la mise à niveau.

## 1. Fin des tempêtes sqlite "unable to open database file"

Les compilations en cours de processus combinées à plusieurs tailers de session actifs épuisent la **limite douce de 256 fichiers ouverts** de macOS par défaut ; une fois épuisée, chaque ouverture sqlite dans le processus échoue et le tailer imprimait un traceback par fichier surveillé. `tesserae engine` relève désormais `RLIMIT_NOFILE` à 8192 au démarrage, et un échec de tick systémique ne journalise **qu'un seul** traceback accompagné d'un résumé du nombre d'erreurs supprimées.

## 2. Les redémarrages sautent le balayage à froid

La première exécution du tailer de sessions parcourt l'intégralité de l'historique de déploiement Codex pour trouver les sessions de projet — plusieurs dizaines de minutes sur de grands historiques, et ce balayage était auparavant répété à **chaque** redémarrage. Le plancher du balayage est désormais persisté dans la base de données des sessions ; les redémarrages reprennent depuis ce point (avec un retour arrière de 7 jours pour les sessions récemment reprises) et annoncent le type de démarrage (froid ou chaud), la durée et les compteurs.

## 3. Des logs silencieux et informatifs

- Six nouveaux types de lignes de transcription Claude Code (`last-prompt`, `queue-operation`, `mode`, `ai-title`, `file-history-snapshot`, `pr-link`) sont reconnus comme des métadonnées bénignes — plus de spam d'avertissements lors du suivi en direct ; les types véritablement inconnus n'avertissent **qu'une fois par processus**.
- Chaque exécution du pipeline journalise `pipeline starting for <project>` — une longue compilation ne ressemble plus à un blocage, car la seule autre sortie apparaissait auparavant *après* la fin de celle-ci.

## 4. Mise à jour du README

Le README (et ses sept miroirs linguistiques) a été réécrit : ensemble de fonctionnalités actuelles (`ingest`, `engine --all`, sessions), prérequis Python correct (3.10+), structure plus claire avec la matrice de comparaison et les GIF de présentation repliés dans des sections déroulantes.

## Mise à niveau depuis v0.8.0

Remplacement direct. Redémarrez tout `tesserae engine` / `tesserae engine --all` en cours d'exécution pour appliquer les correctifs — le premier redémarrage effectue encore un dernier balayage à froid pour initialiser le plancher persisté ; tous les redémarrages suivants sont rapides.
