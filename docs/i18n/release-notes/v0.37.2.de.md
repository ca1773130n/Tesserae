Veröffentlicht am **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [GitHub-Release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1 hat die Client-Builder behoben. Drei Aufrufstellen bauen ihren eigenen Anthropic
SDK-Client und waren von dieser Behebung unberührt, daher gingen sie immer noch zu
`api.anthropic.com` mit einem hart codierten Modell, während alle anderen Pfade den
konfigurierten Endpunkt des Projekts respektierten. Diese Version schließt sie.

## Die drei Pfade

- **`query --llm`** hat seinen Client nur mit dem API-Schlüssel aufgebaut — kein `base_url` —
  und sandte das Standardmodell der Methode `claude-sonnet-4-6`.
- **Prosasynthese** (`TESSERAE_SYNTHESIS_LLM=1`) tat dasselbe, daher hatten Projekte
  mit einem benutzerdefinierten Endpunkt ihre Zusammenfassungen von Anthropic geschrieben.
- **`synthesis`** hat sein Modell aus `TESSERAE_SYNTHESIS_MODEL` oder einem Literal ausgewählt,
  nie aus `llm_model`. Es trägt einen Wiki-Speicher anstelle einer Projektwurzel, daher
  wird die Wurzel nun so abgeleitet, wie `ProjectPaths` sie bereits definiert.

## Drei weitere, gefunden durch das Testen des verteilten Pakets gegen einen echten Endpunkt

0.37.1 wurde von PyPI in einer sauberen Umgebung installiert und auf einen live
OpenAI-kompatiblen Server verwiesen. Es funktionierte — und enthüllte drei Dinge, die
das Lesen des Codes nicht offenbart hatte:

- **Die Fehlermeldung zur Verfügbarkeit war vage.** Sie sagte "rate-limited / auth / unsupported
  model", wenn der Client bereits klassifiziert hatte, welches es war. Sie liest jetzt
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`.
- **`tesserae config status` meldete die Quelle des Anbieters als `default`** auch
  wenn sie aus der Projektkonfiguration stammte. Der Anbieter wird aufgelöst, bevor
  der Hilfsprogramm zur Quellenaufzeichnung ausgeführt wird, daher wurde seine Ebene
  nie aufgezeichnet.
- **`tesserae setup` las `llm_claude_model` und `llm_claude_config_dir`** —
  singuläre Schlüssel, die nichts schreibt. Jeder Schreiber verwendet `llm_model` und die Pluralform
  `llm_claude_config_dirs`, daher sah der Assistent stillschweigend überhaupt keine Konfiguration.

## Tests

Die benutzerdefinierten Anbieter-Tests waren auf `importorskip("anthropic")` beschränkt — übersprungen
auf genau der Basisinstallation, wo der Anbieter kaputt war. Das `openai`-Kabel benötigt
kein SDK, daher kann die neue Abdeckung nicht übersprungen werden, und ein Test blockiert den `anthropic`-Import
ganz, um das zu beweisen.

## Upgrade

Nichts zu migrieren. Wenn du einen benutzerdefinierten Endpunkt konfiguriert hast und festgestellt hast, dass `ask` und
`compile` ihn respektierten, während `query --llm` oder Synthese das nicht taten, ist das genau das.
