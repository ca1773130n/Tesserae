发布于 **2026-07-06** · [PyPI](https://pypi.org/project/tesserae/0.16.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.16.0) · `pip install --upgrade tesserae==0.16.0`

`tesserae serve` 会话页面不再等待下一次编译。它现在直接从 harness roots 读取你的**实时**代理活动——所以你正在进行的会话会*立即*显示。

## Serve 页面上的实时会话

当你运行 `tesserae serve` 时，Sessions 页面会调用新的 **`/api/sessions`** 端点，实时扫描你的 Claude Code roots（限制在最近的时间窗口内），并在编译表上方渲染当前活跃的会话——会话 id、账号、转数、最后活跃时间和开场转的预览。如果你打开静态构建（GitHub Pages），该面板将被隐藏：编译表就是整个页面，与之前完全相同。

**快速转录搜索**框也以相同的方式上线：从 roots 扫描到的新结果合并到 memex 索引结果*之前*（去重），所以你片刻前输入的短语在索引之前就可以找到。

两个界面都是**源门控**的——它们暴露本地历史，所以跨站点浏览器请求会被拒绝，与 clip 端点相同。

### 为什么仅限 Claude，Codex 如何保持覆盖

Claude Code 转录是目录作用域的，所以实时按项目扫描可以在一秒内完成。Codex 会话不是——限制到一个项目意味着解析每个最近的会话文件（在繁忙的机器上 100k+，每次请求约 170 秒），对于交互式页面来说太慢了。所以实时扫描是 **Claude-only**；codex 像以前一样从 memex 索引和编译投影提供。离线的 `tesserae summary` 和 `tesserae decisions` 命令仍然扫描**每个**账号——Claude 和 codex——因为它们可以承受完整扫描。

## Summary 和 Decisions 上的 `--max-turns`

`tesserae summary` 和 `tesserae decisions` 获得了 `--max-turns N` 标志，可以限制在时间窗口化前每个会话读取多少转。当你只需要最近的片段时，这对于限制大会话的成本很有用。默认值保持有效无界。

```bash
tesserae summary --day 2026-07-06 --max-turns 200
tesserae decisions --week --max-turns 200
```

## 升级

直接覆盖 v0.15.x。一切都是附加的——实时端点仅存在于 `tesserae serve` 下，页面在静态托管上完全降级，不需要迁移或重新编译。它实时读取你现有的会话。
