Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

このリリースにランタイムの挙動変更はない。ランタイムの挙動変更を捕まえるはずの
仕組みを直しただけだ — その仕組みは、これまで存在していなかった。

## 誰もテストを実行していなかった

リポジトリにはワークフローが 2 つあった。1 つはデモ wiki をコンパイルし、もう 1
つはタグで npm ラッパーを公開する。どちらもテストを 1 つも実行していない。
「`main` はグリーンだ」は誰も確認していない主張だった — 2,993 個のテストがある
火曜日に赤くなっていたとしても、バッジの色は変わらなかっただろう。

`tests.yml` が、すべての push とすべての pull request で、Python 3.10 / 3.11 /
3.12 にわたってスイートを実行するようになった。`pyproject.toml` がサポートすると
主張してきた、まさにその 3 バージョンだ。その主張もまた、一度も実行されて
いなかった。

## 依存関係が 2 つ、1 台のマシンにしか存在しなかった

CI を入れるには、まず認めるべきことがあった。新しくクローンしたリポジトリでは、
そもそもテストを実行できない:

- **`pytest` はどこにも宣言されていなかった** — `pyproject.toml` にも
  `uv.lock` にも。スイートが動いていたのは、ずっと以前に誰かが手作業でローカルの
  `.venv` に pytest を入れたからだ。ロックファイルから環境を作り直す `uv` コマンド
  は、いずれもテストランナーのない環境を静かに生成していた。
- **`kuzu` は同じ問題をより鋭い形で抱えていた。** 2 つのテストが
  `importorskip` ガードなしに Kuzu ストアを呼ぶため、欠けているとスキップでは
  なく*失敗*する。

どちらも `dev` 依存グループに入った。重要なのはこの区別だ: テストされる環境と
コントリビューターが手にする環境が、いま同じ環境になった。グリーンなスイートが
何かを意味するための、唯一の前提条件である。

## ロックファイルがずれていた

コミット済みの `uv.lock` に対して `uv lock --check` が失敗していた。
`pyproject.toml` と同期が切れ、`markdownify` と `model2vec` が欠けていた。
`uv sync --locked` を実行する人、あるいはロックを固定する CI は、即座にこれに
ぶつかる。

ロックは再生成した。さらにワークフローは `uv sync --locked` を使う — 古いロック
なら静かに更新するのではなくビルドを失敗させるので、二度と静かにずれることは
ない。

## CI が最初の 4 分で見つけたもの

3 つの Python バージョンすべてで、まったく同じ失敗をして赤くなった。バージョンを
またいで同一ということは、バージョンではなくプラットフォームの問題だ。2 つの
テストが、ある macOS マシン 1 台の性質を埋め込んでいた。

5 つは `hooks/_lib.sh` を `zsh` で駆動していた。CI ランナーに zsh はない — そして
そのライブラリは、誰かのログインシェルに依存しないためにこそ、自らを POSIX
フレンドリーだと文書化している。

6 つ目は二度読む価値がある。このテストは `subprocess.run` をモンキーパッチして
いたが、対象コードはタイムアウト時にプロセスグループ全体を kill できるよう
`subprocess.Popen` へ移行済みだった。パッチは静かに無意味になり、以来このテストは
**本物の `claude` バイナリ**を起動していた — それがインストールされログイン済みの
マシンでだけ通り、名前が指すコードについては何一つ主張しないまま。

どちらもプロダクトのバグではない。どちらも「正しい理由では失敗しえない」テスト
であり、別の場所で実行しない限り見つけられなかった。

## デモサイトは凍結した

`build-demo.yml` を削除した。これは `main` への push ごとに Tesserae を自身の
ソースに対してコンパイルし、結果を GitHub Pages にデプロイしていた。

見落としやすいので明記する:
[ライブデモ](https://ca1773130n.github.io/Tesserae)は今も応答し、README も今も
リンクしているが、それを再デプロイするものはもう無い。あのページはワークフローが
最後に走った時点のスナップショットであり、`main` から静かに乖離していく。再公開
には手動の `tesserae export site`、または新しいワークフローが要る。

これにより `init` → `compile` → `export site` の経路にあった唯一の自動カバレッジ
も消えた。`tests.yml` はユニットスイートを走らせるだけで、その経路を通しでは実行
しない。いまそこを守っているのは公開チェックリストの手動スモークだけであり、
チェックリストにもそう書いてある。

## v0.28.4 からのアップグレード

ドロップイン。API 変更もスキーマ変更も挙動変更もない — このリリースのすべての
コミットは CI 設定、テストファイル、依存宣言、ドキュメントのいずれかにしか触れて
いない。再コンパイルする理由はない。

ロックファイルを固定してソースからインストールしているなら、`uv sync --locked`
が再び動くようになるのがこのリリースだ。
