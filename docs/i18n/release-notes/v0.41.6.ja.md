リリース **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.6/) · [GitHub リリース](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.6) · `pip install --upgrade tesserae==0.41.6`

コンパイルはエンジンのイベントループのスレッドで走り、停止シグナルはそのループ経由で届くため、
Ctrl-C や SIGTERM はコンパイルが終わるまで応答されませんでした。そのあと終了処理が、たまっていた
トリガーのためにもう一度コンパイルを走らせました。このプロジェクト自身のエンジンログには、シグナル
2 回のあとに 4,740 パスの最終コンパイルが始まった記録が残っています。

## 何が変わったか

- **2 回目のシグナルでエンジンが止まります。** 1 回目は今も手元の作業を終わらせ、そのことを
  `signal again to stop now` と伝えるようになりました。2 回目はメインスレッドが何をしていてもその場で
  例外を起こすので、コンパイルの途中でもエンジンは pidfile を消し、慣例どおりの終了ステータスで
  抜けます。失われるものはありません。次回起動時のコンパイルがマニフェストの差分から変更を見つけます。
- **停止が LLM を置き去りにしません。** CLI エージェントは自分のセッションで走るため端末の Ctrl-C は
  届かず、これまではタイムアウトのときだけ終了させていました。それ以外の形で待機が終わると、
  `claude -p` は依頼した側のプロセスが消えたあとも走り続け、課金され続けました。今は待機がどう終わっても
  そのプロセスグループを終了させます。ふつうの `tesserae compile` 中の Ctrl-C にも当てはまります。

## アップグレード

移行作業はありません。実行中のエンジンは再起動してください。フリートモード（`engine --all`）は
まだシグナル 1 回の挙動のままです。
