Выпущено **2026-06-19** · [PyPI](https://pypi.org/project/tesserae/0.9.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.1) · `pip install --upgrade tesserae==0.9.1`

Исправительный выпуск. Без изменений в API — прямая замена для v0.9.0.

## Исправления

- **Больше нет цикла обратной связи при самозахвате.** Монитор сессий записывал
  *собственные* вызовы codex/claude Tesserae во время компиляции (извлечение,
  синтез, дистилляция, …) как будто это были ваши рабочие сессии, наводняя БД
  сессий и заставляя следующую компиляцию "извлекать находки" из собственных
  вызовов извлечения. Теперь они исключаются при обнаружении и при живом
  отслеживании, с `tesserae sessions prune-internal` для очистки БД, загрязненных
  до этого исправления.

- **Движок больше не сообщает ложно об "уже запущено".** Когда движок прервался
  без очистки своего pidfile и ОС позже переиспользовала этот PID для непостороннего
  процесса, простая проверка живости проходила и движок отказывался запускаться.
  Теперь pidfile записывает уникальность для каждого воплощения (время начала
  процесса) и рассматривает блокировку как удерживаемую только когда PID живой
  *и* его уникальность все еще совпадает, поэтому устаревший pidfile самоисцеляется.

- **Политика конфиденциальности расширения Chrome.** Добавлена полная политика
  конфиденциальности для расширения "Clip to Tesserae" (требуется для Chrome Web Store).

## Обновление с v0.9.0

Прямая замена. Если список сессий проекта выглядит загрязненным собственными
приглашениями Tesserae, запустите `tesserae sessions prune-internal` один раз.
