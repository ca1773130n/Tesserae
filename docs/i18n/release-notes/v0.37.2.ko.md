공개일 **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [GitHub 릴리스](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1은 클라이언트 빌더를 고쳤다. 세 곳의 호출 지점은 자체 Anthropic SDK
클라이언트를 만들기 때문에 그 수정의 영향을 받지 않았고, 다른 모든 경로가 프로젝트에
설정된 엔드포인트를 존중하는 동안 여전히 하드코딩된 모델로 `api.anthropic.com`을
호출했다. 이번 릴리스가 그것들을 닫는다.

## 세 경로

- **`query --llm`** 은 API 키만으로 클라이언트를 만들었고 — `base_url` 없이 —
  메서드 기본값 `claude-sonnet-4-6`을 보냈다.
- **산문 합성**(`TESSERAE_SYNTHESIS_LLM=1`)도 마찬가지여서, 커스텀 엔드포인트를
  설정한 프로젝트의 요약을 Anthropic이 작성했다.
- **`synthesis`** 는 모델을 `TESSERAE_SYNTHESIS_MODEL`이나 리터럴에서 골랐고
  `llm_model`에서는 결코 고르지 않았다. 이 클래스는 프로젝트 루트가 아니라 위키
  스토어를 지니므로, 이제 `ProjectPaths`가 이미 정의한 방식으로 루트를 유도한다.

## 배포된 패키지를 실제 엔드포인트에 물려보고 찾은 세 가지 더

0.37.1을 PyPI에서 깨끗한 환경에 설치해 살아 있는 OpenAI 호환 서버를 가리켰다.
동작했고 — 코드를 읽는 것만으로는 드러나지 않던 세 가지가 드러났다:

- **가용성 실패 메시지가 모호했다.** 클라이언트가 이미 어느 쪽인지 분류해 두었는데도
  "rate-limited / auth / unsupported model"이라고 말했다. 이제는
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`라고 말한다.
- **`tesserae config status`가 프로바이더의 출처를 `default`로 보고했다.**
  프로젝트 설정에서 왔을 때도 그랬다. 프로바이더는 출처 기록 헬퍼보다 먼저
  해석되므로 그 레이어가 기록된 적이 없었다.
- **`tesserae setup`이 `llm_claude_model`과 `llm_claude_config_dir`을 읽었다** —
  아무도 쓰지 않는 단수 키다. 모든 작성자는 `llm_model`과 복수형
  `llm_claude_config_dirs`를 쓰므로, 마법사는 설정을 전혀 보지 못했다.

## 테스트

커스텀 프로바이더 테스트는 `importorskip("anthropic")`으로 막혀 있었다 — 프로바이더가
망가져 있던 바로 그 기본 설치에서 건너뛰었다는 뜻이다. `openai` 와이어는 SDK가 필요
없으므로 새 커버리지는 건너뛸 수 없고, 한 테스트는 `anthropic` 임포트를 아예 막아
그것을 증명한다.

## 업그레이드

이전할 것은 없다. 커스텀 엔드포인트를 설정했는데 `ask`와 `compile`은 존중하고
`query --llm`이나 합성은 그러지 않았다면, 그것이 이 문제였다.
