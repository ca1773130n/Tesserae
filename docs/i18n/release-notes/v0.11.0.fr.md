Publié **2026-06-27** · [PyPI](https://pypi.org/project/tesserae/0.11.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.11.0) · `pip install --upgrade tesserae==0.11.0`

Une nouvelle fonctionnalité : **interrogez tous vos projets enregistrés à la fois**, avec une réponse unique, croisée et citée. Compatible en amont avec v0.10.x.

## Fédération multi-projets

`tesserae ask --scope federated --scope-aliases research work "…"` (et l'outil MCP `ask` avec `scope: "federated"`) assemble **un seul** graphe à partir des projets que vous nommez et renvoie une réponse unique qui les référence entre eux — au lieu du fan-out `all-registered` qui retourne une réponse par projet. Votre `.tesserae/graph.json` par projet n'est jamais modifié ; la fédération est assemblée en mémoire au moment de la requête.

Les projets se connectent de deux manières :

- **Fusion d'identités (toujours activée).** La même *entité* entre projets — même ID arXiv, dépôt, hash de contenu ou symbole de code — se réduit à un nœud unique. Haute précision, déterministe, pas d'embeddings. Ainsi un article que vous avez découpé dans `research` et référencé dans `work` devient un nœud cité unique.
- **Liens sémantiques (activés par défaut, opt-out).** La même *idée* exprimée différemment — par exemple une décision de caching dans `work` et un article sur la mise en cache dans `research` — obtient un lien multi-projets soutenu par embeddings, permettant à la récupération de relier les concepts *connexes*, pas seulement identiques. Pondéré à la baisse pour qu'une correspondance d'identité l'emporte toujours sur un lien flou. Passez `--no-semantic` pour l'identité seule. Nécessite un véritable backend d'embeddings (`pip install tesserae[semantic]`); sans lui, il se dégrade proprement et vous le signale.

Le seuil de lien (`0.55`) et le poids du pont (`0.5`) ne sont pas des suppositions — ils sont définis à partir d'une évaluation de précision/rappel + saturation (`evals/federation/`, gardée en CI).

## Inspecter la fédération

- `tesserae federation status [aliases] [--semantic]` — nombre de nœuds par projet, fusions d'identités, nombre de liens sémantiques.
- `tesserae federation explain <node> [aliases]` — pourquoi un nœud croise les projets : quels projets il a fusionnés par identité et ses liens sémantiques (avec similarité et projet cible). Accepte un ID namespacé ou un ID qui a été fusionné.

Les liens sémantiques fédérés sont mis en cache à `~/.tesserae/federation/`, indexés par le contenu du projet pour que le cache s'invalide automatiquement quand n'importe quel projet est recompilé.

## Aussi dans cette version

- **Extension Chrome** — le README documente désormais le point de terminaison par défaut correct (`http://127.0.0.1:8765`, IPv4) pour correspondre au défaut de l'extension livrée.

## Migration depuis v0.10.x

Compatible en amont. La fédération est optionnelle par requête (`--scope federated`); rien ne change pour l'utilisation mono-projet. Pour la liaison sémantique, `pip install tesserae[semantic]`.
