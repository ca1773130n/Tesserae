发布于 **2026-07-21** · [PyPI](https://pypi.org/project/tesserae/0.22.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.22.0) · `pip install --upgrade tesserae==0.22.0`

v0.21.0 发布了分层的按代理内存，但其中一半仅通过 MCP 可达，`tesserae agents init` 将每个代理都倒入 `org:root` 下。本版本使整个功能可从终端使用。

## `init` 构建真实组织

`tesserae agents init` 现在从已经存在的信号推断层级：子代理角色（`claude-code:me:reviewer`）被置于生成它的主代理之下（`claude-code:me:default`），而不是所有人都落在 `org:root` 下。从一个命令你就获得一个可工作的多级组织——不需要 `set-parent`。传递 `--flat` 以获得旧行为，`init` 现在打印建议的树，所以你可以看到它的决定。

```
org:root
  claude-code:me:default   Main    sessions=42
    claude-code:me:reviewer   Reviewer   sessions=8   distilled_through=2026-07-20T…
    claude-code:me:planner    Planner    sessions=5   (not distilled)
```

## 从 CLI 进行作用域读取

`--agent KEY` 现在在 `tesserae query`、`ask` 和 `context` 上工作——检索和综合在代理的已解析视图上运行（**工作者**密钥查看其自身原始内存加上自身蒸馏笔记，**经理**密钥查看其报告的蒸馏层，`org` 查看整个团队）。以前这种作用域仅作为 MCP 参数存在。

```bash
tesserae query "release checklist" --agent claude-code:me:reviewer
tesserae ask "what does my team know about deploys?" --agent org
```

未知密钥和未蒸馏的代理失败时会大声指出确切的补救命令，永不会是默默无声的空答案。

## 检查组织

- **`tesserae agents tree`** —— 组织结构作为缩进树，每个代理标注有会话计数和其蒸馏内存的陈旧程度。
- **`tesserae agents show KEY`** —— 解析一个视图并打印其模式、成员代理、工件路径、节点计数和陈旧度水位标记。
- **`tesserae agents drill NODE_ID [--agent KEY]`** —— 从一个蒸馏笔记回到其原始 L0 证据的已审计升级，现在是一个一等 CLI 命令（存活/已更改/已吸收/已消失）。`drill_down` 逻辑被提取出来，所以 CLI 和 MCP 服务器共享一个已审计的代码路径。

## 引擎盖下

角色层级推断是一个纯函数、确定性函数；`drill_down` 核心被提取出来，所以 CLI 和 MCP 服务器共享一个已审计的代码路径。对蒸馏工件或其确定性保证没有改变。纯加性——当 `--agent` 不存在时，每个现有命令的行为完全相同。
