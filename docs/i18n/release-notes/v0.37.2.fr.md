Publié le **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [Version GitHub](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

La v0.37.1 a corrigé les constructeurs de clients. Trois sites d'appel construisent leur propre client SDK Anthropic et n'ont pas été affectés par cette correction, donc ils allaient toujours à `api.anthropic.com` avec un modèle codé en dur tandis que tous les autres chemins respectaient le point de terminaison configuré du projet. Cette version les ferme.

## Les trois chemins

- **`query --llm`** construisait son client avec la clé API seule — pas de `base_url` — et envoyait le `claude-sonnet-4-6` par défaut de la méthode.
- **La synthèse en prose** (`TESSERAE_SYNTHESIS_LLM=1`) faisait la même chose, donc un projet avec un point de terminaison personnalisé avait ses résumés écrits par Anthropic.
- **`synthesis`** choisissait son modèle de `TESSERAE_SYNTHESIS_MODEL` ou d'un littéral, jamais de `llm_model`. Il porte un magasin wiki plutôt qu'une racine de projet, donc la racine est maintenant dérivée de la manière que `ProjectPaths` définit déjà.

## Trois autres trouvés en exécutant le paquet fourni contre un véritable point de terminaison

0.37.1 a été installé de PyPI dans un environnement propre et pointé vers un serveur OpenAI-compatible en direct. Cela a fonctionné — et a exposé trois choses que la lecture du code n'avait pas révélées :

- **L'échec de la vérification de disponibilité était vague.** Il disait « rate-limited / auth / unsupported model » alors que le client avait déjà classifié lequel c'était. Il lit maintenant `the endpoint rejected the request (404 / unknown model) — check llm_base_url, llm_api_style, and that this model exists on that server`.
- **`tesserae config status` signalait la source du fournisseur comme `default`** même quand elle provenait de la configuration du projet. Le fournisseur est résolu avant que l'assistant d'enregistrement des sources ne s'exécute, donc sa couche n'a jamais été enregistrée.
- **`tesserae setup` lisait `llm_claude_model` et `llm_claude_config_dir`** — des clés singulières que rien n'écrit. Chaque auteur utilise `llm_model` et le pluriel `llm_claude_config_dirs`, donc l'assistant ne voyait silencieusement aucune configuration.

## Tests

Les tests du fournisseur personnalisé étaient bloqués sur `importorskip("anthropic")` — se sautaient sur exactement l'installation de base où le fournisseur était cassé. Le câblage `openai` n'a besoin d'aucun SDK, donc la nouvelle couverture ne peut pas se sauter, et un test bloque complètement l'import `anthropic` pour le prouver.

## Mise à jour

Rien à migrer. Si vous aviez configuré un point de terminaison personnalisé et trouvé que `ask` et `compile` le respectaient tandis que `query --llm` ou la synthèse ne le faisaient pas, c'est celui-ci.
