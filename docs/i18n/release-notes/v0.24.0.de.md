Veröffentlicht **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.24.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.24.0) · `pip install --upgrade tesserae==0.24.0`

v0.23 gab der Engine einen Schlaf-Zyklus, der den Speicher während der Ruhe komprimiert. Aber Konsolidierung im Gehirn ist nicht nur Kompression — sie **löscht auch das, was Sie nie wieder durchsehen** und **verbindet Erinnerungen, die sich als verwandt erweisen**. Diese Version fügt diese beiden Operationen hinzu, sodass der Schlaf-Zyklus des Daemon nun alle drei ausführt.

## 1 · Vergessen durch Nichtgebrauch (LRU)

Bisher basierte der Zerfall eines Findings auf seinem *Alter*. Das vergräbt systematisch alte, selten gesehene Problemstellen — genau die, die Sie brauchen, wenn sie wiederkehren. Jetzt **erfasst jeder bedeutungsvolle Lesezugriff den Zugriff**: search, `ask`, `query`, `context`, `node_context`, `drill_down`, Session-Finding-Lookups und Agent-Scoped-Lesevorgänge stemeln alle `last_accessed_at` in den Memory-Sidecar.

Der Konsolidierungspass zerfällt dann nach **Zugriffs-Aktualität, nicht Erstellungsalter**. Wissen, das Sie häufig verwenden, bleibt scharf; Wissen, das Sie nie wieder durchsehen, verblasst langsam und wird während des Schlaf-Zyklus absorbiert oder herabgestuft — echtes LRU-Vergessen. (Ein Finding wird immer noch nie *gelöscht*; es wird in die Destillate gefaltet, die es zitieren, erreichbar via `agents drill`.)

## 2 · Neue Verbindungen entdecken

Der Schlaf spielt auch Erinnerungen ab und verknüpft entfernte. Der neue **associate**-Pass läuft während der Konsolidierung: Er verwendet Embeddings, um *verwandte* — nicht identische — Knoten **über verschiedene Agents innerhalb eines Projekts** zu finden und fügt `shares_concept_with`-Verbindungen zwischen ihnen hinzu. Entdeckte Links **sammeln sich** über Zyklen hinweg an und sind durchsuchbar nach search, Personalized PageRank und föderierten Abfragen, sodass ein Agent relevantes Wissen erreichen kann, das er nie explizit verlinkt hat.

## Determinismus hielt

Beide Operationen schreiben **nur in den Sidecar** — Zugriffszustand zum `node_memory`-Store, entdeckte Links zu einem sich ansammelnden `.tesserae`-Overlay, das zur Lese-Zeit zusammengeführt wird. **`graph.json` wird nie angefasst**, sodass die Kompilierung byte-identisch bleibt. Entdeckte Links sind Embedding-basiert (und somit maschinenabhängig), genau deshalb befinden sie sich im Overlay und nie im deterministischen Graph. Die Zuordnung wird durch ein echtes Embedding-Backend geleitet (`pip install "tesserae[semantic]"`) und ist eine stille No-Op ohne eines.

## Der Zyklus, jetzt vollständig

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine        # idle → compress · forget-by-disuse · associate
```

Nichts Neues zu konfigurieren — die drei Operationen laufen innerhalb des bestehenden untätig-Konsolidierungs-Ticks, unter dem Compile-Gate, nie eine Recompile blockierend. Vollständige Details: [`docs/engine-consolidation.md`](../../engine-consolidation.md).

`pip install --upgrade tesserae==0.24.0` (oder `npm i -g @jokerized/tesserae@0.24.0`).
