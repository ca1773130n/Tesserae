Released **2026-06-14** · [PyPI](https://pypi.org/project/tesserae/0.9.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.9.0) · `pip install --upgrade tesserae==0.9.0`

機能リリース: LongMemEval-V2 の AgentRunbook からポーティングされた複数粒度のメモリレイヤーと、LLM バックエンドを可視化して正直にする一連の修正。これまでサイレント失敗していたものを実装しました。

## 1. AgentRunbook スタイルの複数粒度メモリ

生セッション結果の上に置く新しいオプトイン蒸留層 — 3 つの粒度すべてがバイト等冪性を持ち (内容派生 ID、ウォールクロック/RNG なし、決定論的フォールバック) LLM オプショナル:

- **`Event`** — セッションのターンからマイニングされた遷移ごとのレコード (動的状態追跡)、セッション検出抽出に統合
- **`Runbook`** — 反復するワークフロー用の蒸留再利用可能プロシージャ (クロスセッション、デフォルト ≥2 セッション)
- **`Gotcha`** — 反復する失敗モード / 誤った仮定の蒸留

さらに **マルチプール検索**: `compile_context(multi_pool=True)` がクエリを分解し、最も関連性の高い蒸留メモリノードのために予算スロットを確保します。`tesserae compile --distill`、`tesserae context --multi-pool`、設定内の `distillation.enabled`、および MCP `compile_context` の `multi_pool` 引数を経由して設定可能。すべてデフォルトオフなので、プレーン compile は変わりません。

## 2. 可視的で正直な LLM バックエンド

- **`tesserae config status`** — 解決されたプロバイダ + codex-home / claude-dirs をプリント、各設定の **ソース** (env > project config > `~/.tesserae/config.json` > デフォルト)、および **ライブピング** を表示。レート制限またはミス認証バックエンドが目に見えるようになります。
- **うるさいセッション抽出失敗** — 抽出が「モデルが何も返さなかった」と「モデルが答えなかった」を区別。失敗したチャンクは **空のままキャッシュされません** (バックエンドが機能したら再抽出)、compile は見落とせない警告をプリント。以前は、スロットルされたバックエンドがセッション付きグラフを静かに生成していました、しかし **ゼロ検出**。
- **Codex reasoning effort** は Tesserae 自身の呼び出しに対して `medium` に固定 (`llm_codex_reasoning_effort` / `TESSERAE_CODEX_REASONING_EFFORT` を経由して設定可能)、グローバルな `xhigh` インタラクティブ codex セットはもう every compile を何倍も遅くしません。

## 3. 決定論性強化

- バイト等冪性ガードは、実際に保証する決定論的 (非 LLM) compile を実行してエクササイズするようになりました — 周囲の LLM はもう それらをフレーキーにしません。
- 非 LLM compile は **キャッシュされたコミュニティサマリーを再発行** (それらをドロップするのではなく)、再コンパイルは LLM 利用可能性の変動全体で安定したままです。

## v0.8.x からのアップグレード

ドロップイン。新しいものはすべてオプトイン or 追加です；プレーン `tesserae compile` は以前と同様に動作。`tesserae config status` を実行してどの LLM バックエンドにいるかを確認してください。
