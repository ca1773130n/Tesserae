Дата выпуска **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.0) · `pip install --upgrade tesserae==0.7.0`

Теперь `tesserae ask` синтезирует настоящие ответы поверх **CLI, в который вы уже вошли** — без `ANTHROPIC_API_KEY` — и ротирует между всеми учётными записями на вашей машине, так что лимит запросов никогда его не останавливает. Плюс два исправления, которые делают сессии, *о которых* вы спрашиваете, доступными для поиска, и компиляция, которая больше не прерывается.

## 1. `tesserae ask` синтезирует поверх claude/codex CLI — без API-ключа

Раньше `tesserae ask` мог писать ответ только через Anthropic SDK, которому нужен `ANTHROPIC_API_KEY`. Если у вас распространённая конфигурация — вход в `claude` или `codex` CLI по OAuth — `ask` молча деградировал до сырых результатов поиска с `(no LLM answer: LLM disabled)`.

Теперь путь ответа повторно использует те же OAuth-клиенты, которые уже применяют экстракторы JSON. `tesserae ask --llm "<question>"` (или `TESSERAE_QUERY_LLM=1`) синтезирует ответ с цитатами при **нулевом числе API-ключей** — ровно то обещание «без ключа», которое даёт остальная часть движка.

## 2. Он ротирует между **каждой** учётной записью на машине

CLI-клиенты уже автоматически обнаруживают каждый каталог конфигурации `~/.claude*` и каждый домашний каталог `~/.codex*`. v0.7.0 заставляет `ask` это использовать — и связывает в цепочку между *провайдерами*: запрос сдаётся только тогда, когда исчерпана **каждая** учётная запись.

На практике: когда все ваши учётные записи Claude достигли своего лимита Sonnet/недельного лимита, настоящий `tesserae ask --llm` ротирует между ними, затем **проваливается к Codex** и отвечает (`model=cli-oauth`) — без ключа, без ручного переключения учётных записей. Учётная запись с превышенным лимитом или вышедшая из системы пропускается, а не приводит к фатальной ошибке.

## 3. Исправление: заголовки сессий больше не схлопываются в преамбулу harness

Codex добавляет `# AGENTS.md instructions for <path>` в начало каждой расшифровки, поэтому эвристика заголовка сессии принимала *именно это* за заголовок **каждой** сессии — и поиск по ключевым словам возвращал стену неотличимого шаблонного текста с одинаковыми оценками. Теперь заголовки пропускают внедрённую преамбулу AGENTS/CLAUDE/GEMINI.md (и системные обёртки) и берутся из вашей настоящей первой инструкции; `ask` снова возвращает различимые, релевантные результаты.

Вместе с этим едут два меньших исправления `ask`: ключ LLM (`--llm` / `TESSERAE_QUERY_LLM`) теперь учитывается на пути поиска по wiki (раньше он был жёстко отключён), а когда `--backend auto` откатывается из-за ошибки более богатого бэкенда (например, сбоя аутентификации cognee), он теперь сообщает об этом, а не молча выглядит так, будто wiki был единственным опробованным бэкендом.

## 4. Исправление: компиляция больше не прерывается из-за устаревшей кешированной ссылки

Полная `tesserae compile` / `refresh` могла завершиться сбоем с `KeyError: 'CodeFunction:…'` — id узла кода, которого больше не существует. Находки сессий (findings) фильтруют свои ссылки относительно doc-графа во время *извлечения*, но находки кешируются по чанкам; когда id ссылочного узла позже меняется (например, у кодовой функции, чей id на основе content-hash сдвигается при редактировании кода) или исчезает, кешированная находка воспроизводила **устаревшую** ссылку, фабрикуя висячий узел, который ломал нижестоящий шаг code-graph. Ссылки теперь повторно проверяются относительно живого графа во время слияния — связываются, когда цель ещё существует, и отбрасываются, когда нет.

## Обновление с v0.6.1

Без изменений в настройке. Чтобы получать ответы от `ask` без API-ключа, просто войдите в `claude` или `codex` CLI и передайте `--llm`. Если вы сталкивались с `KeyError` при компиляции, перезапустите `tesserae compile` (или `refresh`) — теперь он пропускает устаревшие ссылки вместо прерывания.
