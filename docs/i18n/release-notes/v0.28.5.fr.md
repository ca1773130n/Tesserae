Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

Aucun changement de comportement à l’exécution dans cette version. Elle répare la
mécanique censée détecter les changements de comportement à l’exécution — une
mécanique qui, jusqu’ici, n’existait pas.

## Rien n’exécutait les tests

Le dépôt avait deux workflows. L’un compilait le wiki de démo ; l’autre publiait
le wrapper npm sur un tag. Aucun n’exécutait le moindre test. « `main` est au
vert » était une affirmation que personne ne vérifiait — 2 993 tests auraient pu
virer au rouge un mardi sans que la couleur du badge ne bouge.

`tests.yml` exécute désormais la suite à chaque push et à chaque pull request, sur
Python 3.10, 3.11 et 3.12 — précisément les trois versions dont `pyproject.toml`
revendique la prise en charge. Ces revendications n’avaient jamais été exécutées
non plus.

## Deux dépendances n’existaient que sur une seule machine

Ajouter la CI a d’abord obligé à admettre qu’un clone neuf ne pouvait tout
simplement pas lancer les tests :

- **`pytest` n’était déclaré nulle part** — ni dans `pyproject.toml`, ni dans
  `uv.lock`. La suite tournait parce que quelqu’un avait installé pytest à la main
  dans un `.venv` local, bien des commits plus tôt. Toute commande `uv`
  reconstruisant l’environnement depuis le lockfile produisait silencieusement un
  environnement sans lanceur de tests.
- **`kuzu` posait le même problème, en plus mordant.** Deux tests appellent le
  store Kuzu sans garde `importorskip` : quand il manque, ils *échouent* au lieu
  d’être ignorés.

Les deux vivent maintenant dans un groupe de dépendances `dev`. La distinction qui
compte : l’environnement testé et l’environnement que reçoit un contributeur sont
désormais le même — seule condition sous laquelle une suite au vert veut dire
quelque chose.

## Le lockfile avait dérivé

`uv lock --check` échouait sur le `uv.lock` commité : désynchronisé de
`pyproject.toml`, il lui manquait `markdownify` et `model2vec`. Quiconque lance
`uv sync --locked`, ou toute CI qui fige le lock, tombait dessus immédiatement.

Il est régénéré, et le workflow utilise `uv sync --locked` — qui fait échouer le
build sur un lockfile obsolète au lieu de le mettre à jour en silence. Cette
dérive ne peut donc plus passer inaperçue.

## Ce que la CI a trouvé en quatre minutes

Elle est passée au rouge sur les trois versions de Python, avec des échecs
identiques. Identiques d’une version à l’autre : c’est donc la plateforme, pas la
version. Deux tests encodaient les propriétés d’une machine macOS précise.

Cinq pilotaient `hooks/_lib.sh` via `zsh`, absent des runners de CI — alors que la
bibliothèque se documente elle-même comme compatible POSIX justement pour ne
dépendre du shell de connexion de personne.

Le sixième mérite deux lectures. Il monkeypatchait `subprocess.run`, mais le code
testé était passé à `subprocess.Popen` afin qu’un timeout puisse tuer tout le
groupe de processus. Le patch est devenu silencieusement un no-op, et depuis, le
test lançait le **vrai binaire `claude`** — passant sur les machines où il se
trouve installé et connecté, sans rien affirmer du tout sur le code qu’il
prétendait tester.

Aucun des deux n’est un bug produit. Les deux sont des tests incapables d’échouer
pour la bonne raison, et introuvables sans les exécuter ailleurs.

## Le site de démo est gelé

`build-demo.yml` a été supprimé. Il compilait Tesserae contre ses propres sources
à chaque push sur `main` et déployait le résultat sur GitHub Pages.

La conséquence, dite clairement parce qu’elle est facile à manquer :
[la démo en ligne](https://ca1773130n.github.io/Tesserae) répond toujours et le
README y renvoie toujours, mais plus rien ne la redéploie. Cette page est
désormais un instantané de la dernière exécution du workflow, et elle divergera de
`main` en silence. Republier, c’est un `tesserae export site` manuel, ou un
nouveau workflow.

Cela a aussi supprimé la seule couverture automatisée du chemin `init` →
`compile` → `export site`. `tests.yml` exécute la suite unitaire et ne parcourt
pas ce chemin de bout en bout ; il ne reste que le smoke manuel de la checklist de
publication — et la checklist le dit.

## Mise à niveau depuis v0.28.4

Drop-in. Aucun changement d’API, de schéma ni de comportement — chaque commit de
cette version ne touche que la configuration CI, des fichiers de test, des
déclarations de dépendances ou de la documentation. Aucune raison de recompiler.

Si vous installez depuis les sources avec un lockfile figé, c’est la version qui
refait fonctionner `uv sync --locked`.
