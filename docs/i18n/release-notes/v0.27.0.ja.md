Released **2026-07-26** · [PyPI](https://pypi.org/project/tesserae/0.27.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.27.0) · `pip install --upgrade tesserae==0.27.0`

これまでエージェントはテッセラに散文を渡して、抽出器が正しい型を推測してくれることを望むしかありませんでした。本リリースでは書き込みパスと検証パスが開かれ、エージェントは型付けされた構造として発見を記録し、グラフが主張を実際にライセンスしているかどうかを尋ねることができます。

## エージェントが型付けされた発見を書き込む

**`graph_write`** はスキーマ検証された型付けノードとエッジを必須のプロヴェナンスとともに受け取ります。強制するのではなく **拒否** します — 型なしエッジ、管理対象語彙外の型、ぶら下がったエンドポイント、欠落したプロヴェナンスはすべて拒否され、重複した書き込みはべき等です。

エージェントが書き込んだノードは完全な再コンパイル、削除された `graph.json`、`--limit`、および全コーパス削除を生き残ります。対抗的テストの下で、ライブコンパイルに対する60の並行書き込みは **1,483の読み取り全体でゼロの破断読み取り** で完了しました。

## エージェントがグラフに対して検証する

**`verify_claim`** はグラフが三つ組をライセンスしているかどうかを答えます。判決はグラフバイトの純粋な関数です。**LLMなし、エンべディングなし、決定パスの任意の場所でファジィマッチングなし。** ハルシネーションする検証器は検証器がないよりも悪いです。

これは `(subject, predicate, object)` を受け取り、**自然言語パラメータを持ちません** — 意図的です。`PRESENT_UNEVIDENCED`（エッジが存在するが、それを裏付けるドキュメント内容がない）や `ABSENT`（「このグラフはそれを主張していない」— 反論ではありません）を含む7つの判決があります。

明確に述べる価値のある2つの保証があります。`supersedes` は判決を生じることはありません。三つ組が偽であるのではなく、*ノード* が置き換えられたと言っています。そしてエージェント書き込みはプロヴェナンスクラスを *弱める* ことしかできず、アップグレードすることはできません — エージェントが主張することは、ドキュメント根拠として提示することはできません。

## その他

- **セマンティックエンティティ解決。** エンべディング聚類されたキャンディデートは自動マージではなく、*既存の* レビューキューに供給されるようになりました。リコールではなく精度：誤ったマージは2つの実エンティティをサイレントに融合させ、すべての下流トラバーサルが誤差を継承します。
- **`ask` のための質問形式ルーティング。** グラフはマルチホップ、時間的、合成質問に勝ち、単純事実照会とコストで失われるため、すべてのグラフ価格を支払うことは損失です。ルーティング決定はエンベロープ内にあるため、安価な回答は監査可能です。`--route` でオーバーライドします。
- **時間的事実の有効性間隔。** ソースタイムスタンプから導出され、ウォールクロックからは導出されません。
- **`--llm-limit` が並行抽出の下で保持されます。** v0.26.0が抽出を並列化したので、古いチェック・インクリメント方式は、それらが書き込む前にすべてのワーカーがカウンターを読むことを許可したため、`--llm-limit 1` はワーカー *ごとに* 1呼び出しを購入しました。これは使用上限なので、現在はクローズドで失敗します。
- **コンパイルカバレッジは主張ではなく不変です。** 4つのサイレントデータ損失パスが閉じられ、その後、その背後にあるメカニズムが **完全に削除** されました — `compile(loader=…)` には本番呼び出し元がなく、そのライブラリ専用APIを防御することは、いくつかのレビューラウンド全体でのあらゆる重大な欠陥の原因でした。その1つはv0.26.0自体が導入した回帰でした。
- **[新しいドキュメント](../tuning.ja.md)** が書き込み、検証、ルーティングサーフェスに対応しています。

## 出荷されなかった理由

`contradicts_claim` / `derived_from` / `criticizes` エッジをマイニングする **コントラストパス** が構築、測定、および **カット** されました。2つの実コーパス全体で **80の判定ペアから0エッジ** を作成し、60の60の判定根拠が同じ理由を示しました：ペアはほぼ重複していて、矛盾するものはありませんでした。

原因は構造的でした。候補生成は共有レアトークンでブロックされ、*類似性* を最適化します — しかし矛盾と導出は *異なる* 主張間で成立します。再設計は、ゼロLLMコストでオフラインで5つの新しいジェネレーターを評価しました：高容量なものは手検査で0/10をスコアリングしました（その「矛盾する数字」はarXiv IDと発行日でした）、最も正確なものは1つのコーパスで6つの候補ペアを生成し、もう1つでは何も生成しませんでした。

制御実行はそれを解決しました — *既に存在する* 15の推論エッジを判定すると、リコール7/15が返されました。判定者は常に機能していました。候補は常に間違っていました。

`REASONING_EDGE_RATIO` リント規則は保持され、誠実なベースラインをピンします。**7.5%** のエッジは推論を実行し、`contradicts_claim`、`derived_from`、`attributes_improvement_to`、`criticizes` は **ゼロインスタンス** です。

## v0.26.0からのアップグレード

ドロップイン。`TESSERAE_CONTRAST_PASS` を設定した場合、それはもはや何もしません — パスは消えました。
