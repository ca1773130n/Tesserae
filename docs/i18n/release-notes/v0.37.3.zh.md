发布于 **2026-09-02** · [PyPI](https://pypi.org/project/tesserae/0.37.3/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.3) · `pip install --upgrade tesserae==0.37.3`

v0.37.1 和 v0.37.2 让本地的 OpenAI 兼容服务器可以被访问。真正运行一个之后，
下一个问题暴露了出来：提取池是按有速率限制的云 API 来定大小的，而本机上的
模型服务器一次只处理一个请求。

## 发生了什么

`TESSERAE_EXTRACT_CONCURRENCY` 默认为 4。Ollama、llama.cpp 和 LM Studio 一次只处理
一个请求，因此每次调用后面都排着三个请求，而被服务器丢弃的排队请求会在整个
`TESSERAE_EXTRACT_TIMEOUT` 期间阻塞它的工作线程。从外面看这和内存问题一模一样，
在被正确解读之前花掉了好几个小时。

## 改了什么

- **未设置时，这个值跟随端点。** 回环的 `llm_base_url`
  （`localhost`、`127.0.0.1`、`::1`）意味着一次只处理一个文档，并且 stderr
  上的提示会说明端点和覆盖方式。
- **批处理运行器向提取器询问请求发往何处。**
  `LLMResearchExtractor` 暴露其客户端的 `base_url`，选择性路由器替它的 LLM
  那一半作答，因此不必穿过四个调用地点铺设管道。确定性提取器没有端点，保持 4。
- **显式设置的值总是优先。** 转发到云 API 的回环代理（LiteLLM、带批处理的 vLLM）
  可以承受更多：自行设置即可。

`docs/tuning.md` 记录了新的默认值。

## 升级

无需迁移。如果本地模型的编译看起来卡住或内存不足，很可能就是这个问题。
你作为变通办法加上的 `TESSERAE_EXTRACT_CONCURRENCY=1` 留着或删掉都可以，结果相同。
