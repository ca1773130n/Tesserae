Date de publication **2026-06-08** · [PyPI](https://pypi.org/project/tesserae/0.6.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.6.0) · `pip install --upgrade tesserae==0.6.0`

Tesserae 0.6.0 est une **refonte de la CLI**. Tout ce que fait le moteur était enfoui sous `tesserae project <26 sous-commandes cachées>`, avec un `setup` à 29 options et un `compile` à 26 ; un `tesserae` nu déversait un analyseur d'extraction brut. 0.6.0 remplace cela par un **arbre de commandes à verbes plats** : les verbes du quotidien au plus haut niveau, une poignée de petits groupes de noms, une aide groupée et des `EXAMPLES` sur chaque commande. C'est un **changement cassant**, assumé délibérément avant la 1.0 : les anciennes commandes ne deviennent pas silencieusement des alias, elles affichent une redirection d'une ligne `… has moved → …` et se terminent avec le code 2, de sorte que la migration est manifeste plutôt que mystérieuse. Le moteur, le graphe, les outils MCP et le serveur `tesserae_mcp` sont inchangés — cette version porte entièrement sur la surface qu'un humain saisit.

## 1. Le nouvel arbre de commandes

```
tesserae <command>

EVERYDAY    init compile context ask serve status
AUTOMATION  engine refresh research
ANALYSIS    query lint
GROUPS      sessions vault export code config projects integrations extract
LAB         lab
```

- **Les verbes du quotidien sont au plus haut niveau.** `tesserae compile`, `tesserae serve`, `tesserae ask`, `tesserae context "…"` — sans préfixe `project`.
- **`status`** est un nouveau récapitulatif en lecture seule (nombre de nœuds/arêtes, dernière compilation, vault, site).
- **`serve`** construit le site automatiquement lorsqu'il est absent ou périmé (à ignorer avec `--no-build`).
- **Les commandes spécialisées vivent dans de petits groupes de noms :** `sessions import|discover|list`, `vault sync|export|prune|set-root|sync-all`, `export harness|graphiti|site`, `code ingest|sync`, `config llm|show`, `projects register|list|activate|unregister|mcp-config`, `integrations refresh <name>`, `extract`, `lab evolve|schema-drift`.
- **`export site`** absorbe les anciens verbes `build-site`, `deploy` (`--deploy`) et `watch` (`--watch`).
- **Aide racine groupée + `EXAMPLES`** — `tesserae` sans argument affiche l'arbre groupé ; le `--help` de chaque commande se termine par des exemples réels et exécutables.

## 2. `init` et `compile` au régime

- **`init` : 29 → 8 options.** Assistant par défaut ; `--yes` l'exécute de façon non interactive (les intégrations optionnelles — Cognee, RAG-Anything, Understand-Anything — sont **désactivées** par défaut, et la couleur se désactive automatiquement hors d'un TTY, englobant les anciennes options `--no-color`/`--no-cognee`/`--skip-*`). `--bare` écrit l'espace de travail sans l'assistant. Les options de backend LLM (`--llm-provider`, `--claude-config-dir`, `--codex-home`) demeurent.
- **`compile` : 26 → 8 options.** Les options du quotidien restent (`--changed-only`, `--no-sessions`, `--limit`, `--refresh-integrations`, les trois options LLM et le `compile <paths>` ad hoc). Chaque molette d'intégration supprimée (kuzu/cognee/trends/vault-pull/…) migre vers un bloc **`compile_options`** dans `.tesserae/config.json` sous le même nom, avec son ancienne valeur par défaut préservée — le comportement est donc identique, seule la surface s'est tue. Voir le tableau complet de `compile_options` dans le [guide de démarrage rapide](../quickstart.md).

## 3. Migration en rupture nette — pas d'alias silencieux

Chaque invocation héritée affiche exactement une ligne et se termine avec le code 2 :

```
$ tesserae project compile
tesserae project compile has moved → tesserae compile
```

La table de redirection couvre toutes les anciennes commandes (y compris les formes à trois jetons comme `project sessions import` et les anciennes commandes de premier niveau `wiki`/`llm-defaults`), et un chemin markdown nu (`tesserae notes/x.md`) vous oriente vers `tesserae extract`. Les hooks, le smoke CI, le flux de publication et toutes les chaînes d'exécution du dépôt ont été migrés de concert ; la documentation et les huit README (ainsi que chaque copie localisée) parlent désormais le langage du nouvel arbre.

## Mise à niveau depuis v0.5.0

- **Réapprenez les verbes que vous scriptez.** Les substitutions les plus courantes : `project setup --yes …` → `tesserae init --yes`, `project compile` → `tesserae compile`, `project build-site` → `tesserae export site`, `project serve` → `tesserae serve`, `project obsidian-sync` → `tesserae vault sync`, `project sync-code` → `tesserae code sync`, `tesserae llm-defaults …` → `tesserae config llm …`, `tesserae wiki …` → `tesserae projects …`. Exécutez une fois l'ancienne forme d'une commande — le message `… has moved → …` vous indique la nouvelle.
- **Vous avez déplacé une option de `compile` ?** Si vous scriptiez `compile --trends`, `--no-vault-pull`, `--cognee-*`, etc., définissez plutôt le `compile_options.<key>` correspondant dans `.tesserae/config.json` (tableau dans le guide de démarrage rapide).
- **Les options d'intégration de `init` ont disparu de la CLI.** Activez Cognee / RAG-Anything / Understand-Anything en répondant aux invites de l'assistant `tesserae init`, ou en éditant `.tesserae/config.json` puis en exécutant `tesserae integrations refresh <name>`.
- Rien concernant le **graphe, le vault, le site, les outils MCP ou le serveur `tesserae_mcp`** n'a changé — seule la CLI tournée vers l'humain.
