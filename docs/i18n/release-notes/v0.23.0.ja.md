Released **2026-07-22** · [PyPI](https://pypi.org/project/tesserae/0.23.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.23.0) · `pip install --upgrade tesserae==0.23.0`

レイヤー化されたエージェントメモリ（v0.21）は蒸留できましたが、要求されたときだけ — `tesserae refresh`で、メモリ圧力下でのみ実行できました。このリリースは常時オンのエンジンに**スリープサイクル**を与えます：脳が休息中に統合する方法と同じように、エージェントメモリを自動的に統合します。

## 休止中に統合

`tesserae engine` を実行したままにすると、アクティビティクロックを監視するようになります。プロジェクトが**アイドル状態**になると — 数分間編集や新しいセッションがない場合 — そのプロジェクトのエージェント間で蒸留パスを実行し、あなたが離れている間に蓄積した経験を再編成してコンパクト化します。定期的な**上限**（デフォルト 6h）は、継続的にビジーなプロジェクトでも確実に統合されるようにします。

```bash
tesserae engine                      # idle consolidation on by default
tesserae engine --consolidate-idle 600 --consolidate-every 43200
tesserae engine --all                # every registered project, on idle
tesserae engine --no-consolidate     # opt out
```

アイドル状態は脳に正確なトリガーです：統合は任意の壁時計時間ではなく、システムが休止しているときに発生します。

## 構成で安全

サイクルは既存の `maybe_distill_on_refresh` パスを正確にラップするため、すべてのその保証が引き継がれます：

- **オプトインしない限り、何もしません。** `TESSERAE_AGENT_DISTILL=1` ゲートまで何も実行されません — 蒸留がずっと使用してきた同じゲート、およびエージェントごとのウォーターマークとメモリ圧力チェック。フラグはデフォルトでオンになっています。パス自体がオプトインなしで何もしないことを拒否するためです。
- **再コンパイルと重複しません。** 統合はコンパイルゲートの下で実行されるため、パイプラインとは相互に排他的です — そしてシングルデーモンモードでそれを保持するために、設定されていないゲートはプライベートセマフォにデフォルト設定されるようになりました。
- **デーモンを妨害しません。** これは独自のスレッド（デーモンの既存のポーラーイディオム）で実行され、イベントループに引き上げられることはなく、シャットダウン時に迅速に終了し、1回限りの `engine` 実行では完全にスキップされます。
- **決定的な成果物は未触です。** 蒸留されたグラフはそのバイト冪等性を保ちます。単調なアクティビティクロックは永続化されません。

## フラグ

| フラグ | デフォルト | 意味 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | スリープサイクルを有効にする |
| `--consolidate-idle` | `300` | 統合前の静か秒数 |
| `--consolidate-every` | `21600` | 上限 — 少なくともこの頻度で統合（`0` = off） |
| `--consolidate-check` | `30` | スレッドがクロックをチェックする頻度 |

完全な動作とフロート注記：[`docs/engine-consolidation.md`](../engine-consolidation.md)。
