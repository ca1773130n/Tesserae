Выпущено **2026-09-06** · [PyPI](https://pypi.org/project/tesserae/0.39.0/) · [GitHub-релиз](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.0) · `pip install --upgrade tesserae==0.39.0`

`tesserae compile` всегда собирала слой концепций и утверждений через настроенный
LLM. Все остальные пути не делали этого: `refresh`, демон движка, MCP-путь
`materialize` и `deploy --build` требовали компиляции без указания экстрактора,
а "none" означал детерминированный.

## Что произошло

Один `tesserae refresh` на реальном проекте пересобрал весь слой документов без LLM.
Каждый файл остался помечен как графированный, ни один документ не был отмечен как
резервный, а граф вернулся без своих концепций, возможностей, моделей и тем — 466
концепций стали 0. Демон на цикле обновления сделал бы то же самое при первой
перекомпиляции. Исправление было зафиксировано сначала через fixture: инкрементный
диффер сохраняет LLM-типизированные узлы неизменённых файлов; входные точки были
дырой.

## Что изменилось

- **Компиляция без указанного экстрактора теперь собирает настроенный LLM**, той же
  формы, что и `tesserae compile`, с детерминированным экстрактором как резервный
  вариант для каждого документа. Ни один пригодный бэкенд не деградирует до
  структурного графа с предупреждением, никогда не молча. `compile --extractor deterministic`
  остаётся явным отказом.
- **Пакеты контекста указывают и упаковывают документ, который раскрывает сущность.**
  v0.38.0 хранила плотность упоминаний для каждого документа; никто её не читал.
  Раздел пакета для сущности теперь упаковывает прозу этого документа и называет его,
  возвращаясь к первому встреченному пути, когда нет свежего зеркала SQLite.
  `node_context` получает добавляющий `documents` список, ранжированный. Измерено на
  двух корпусах, первый встреченный называет владельца статьи примерно половину времени;
  документ с наибольшим упоминанием — девять из десяти.
- **`verify_attribution`**, как инструмент MCP и глагол CLI `verify-attribution`.
  Проверка покрытия проходит через реальное число, поднятое из строки таблицы соседа,
  потому что каждый токен в свидетельстве. Это проверяет принадлежность вместо этого:
  чей рекорд сидит в фигуре, и называет ли этот документ бенчмарк. Детерминированно,
  без графа, без LLM; проверено на 14 из 15 неправильных атрибуций, поймано с 4 ложными
  срабатываниями в 33 верных ответах.
- **Истощённый счёт codex — это исчерпание, а не сбой транспорта.** Один spawn,
  вердикт `exhausted`, запомнен на прогон — и цепь поставщика проходит до
  залогированного CLI Claude во время вызова, как всегда обещала его docstring.
  Раньше каждый вызов тратил около 55 секунд на повторные попытки четырёх домов и
  не возвращал ничего.

## Обновление

Если вы запускаете демон или цикл `refresh`, ожидайте, что он потратит LLM-вызовы на
изменённых документах с этого момента; неизменённые документы попадут в кэш, адресуемый
по приглашению. Граф, скомпилированный `refresh` под более ранней версией, имеет только
структурный вид — одна полная `tesserae compile` восстанавливает LLM-слой. Больше ничего
не нужно мигрировать.
