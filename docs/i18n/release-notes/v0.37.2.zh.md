发布于 **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1 修复了客户端构建器。三个调用地点构建它们自己的 Anthropic SDK
客户端，因此未被该修复触及，它们仍然使用硬编码的模型调用
`api.anthropic.com`，而每条其他路径都遵守项目配置的端点。本次发布关闭了这三个地点。

## 三条路径

- **`query --llm`** 仅使用 API 密钥构建其客户端 — 没有 `base_url` —
  并发送方法的默认 `claude-sonnet-4-6`。
- **散文合成**（`TESSERAE_SYNTHESIS_LLM=1`）做法相同，所以拥有自定义端点的项目会让
  Anthropic 撰写其摘要。
- **`synthesis`** 从 `TESSERAE_SYNTHESIS_MODEL` 或字面值选择其模型，
  从不从 `llm_model` 选择。它携带的是维基存储而非项目根，所以
  现在按照 `ProjectPaths` 已定义的方式派生根。

## 通过对实际端点运行已发布包发现的再多三个问题

0.37.1 从 PyPI 安装到干净环境并指向一个活动的
OpenAI 兼容服务器。它工作了 — 并暴露了三件阅读代码未曾发现的事情：

- **可用性失败消息模糊不清。** 它说"speed-limited / auth / unsupported
  model"，而客户端已经分类出了是哪一个。它现在读作
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`。
- **`tesserae config status` 将提供商的来源报告为 `default`**，
  即使它来自项目配置。提供商在源记录助手前被解析，所以
  该层从未被记录。
- **`tesserae setup` 读取 `llm_claude_model` 和 `llm_claude_config_dir`** —
  没有任何东西写入的单数键。每个写入者都使用 `llm_model` 和复数形式
  `llm_claude_config_dirs`，所以向导完全看不到任何配置。

## 测试

自定义提供商测试被禁用在 `importorskip("anthropic")` — 意味着在
提供商出现问题的确切基础安装处跳过。`openai` 线路不需要
SDK，所以新覆盖范围无法跳过，一个测试完全阻止 `anthropic`
导入来证明这一点。

## 升级

无需迁移。如果您配置了自定义端点，发现 `ask` 和
`compile` 遵守它而 `query --llm` 或合成没有，这就是那个问题。
