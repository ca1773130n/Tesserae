## 밀집 레인이 학습된 인코더를 요청할 수 있다

논문 148편 코퍼스에서, 기본 탑재된 정적 `model2vec` 임베더가 그래프와 단순 벡터
저장소 사이 격차의 전부였다. 같은 융합, 같은 그래프, 같은 문서 중복 제거로 측정한
서로 다른 문서 기준 재현율:

| 방식 | @10 문서 | @50 문서 |
| --- | --- | --- |
| Mem0 OSS 원시 청크 저장소, 자체 인코더 | 0.784 | 0.942 |
| Mem0 OSS 원시 청크 저장소, 동일한 bge-base | 0.775 | 0.944 |
| Tesserae, 기본 탑재 정적 model2vec | 0.754 | 0.914 |
| **Tesserae, 밀집 레인의 bge-base** | **0.791** | **0.962** |

`TESSERAE_EMBEDDING_PREFER`는 호출자가 `auto`를 요청할 때 백엔드를 고른다
(`model2vec`, `st`, `openai`, `hash`). 어떤 백엔드도 가리키지 않는 값은 해시
스텁으로 조용히 흘러가지 않고 보고된 뒤 무시된다. `TESSERAE_ST_MODEL`은
sentence-transformers 모델을 지정하며, 기본값이 측정된 적 없는
`all-MiniLM-L6-v2`에서 측정된 `BAAI/bge-base-en-v1.5`로 바뀐다.

```bash
uv pip install sentence-transformers
export TESSERAE_EMBEDDING_PREFER=st
export TESSERAE_ST_MODEL=BAAI/bge-base-en-v1.5   # the default; any Hugging Face name
```

auto 사다리는 그대로다: `model2vec`이 먼저이므로 `pip install tesserae`는 torch
없이 유지되고, 이 변수를 설정한 적 없는 설치는 이전과 똑같이 동작한다.

## 측정이 실제로 보여준 것

같은 인코더를 주면 그래프와 원시 청크 저장소는 같은 문서를 찾는다: 질문 57개를
짝지어 보면 문서 10개 기준으로 8승 8패 41무다(부호 검정 p=1.0). 이는 동등이며,
문서도 이제 동등이라고 말한다 — 이전 문구는 그래프가 앞선다고 했지만 서로 다른
인코더 두 개를 비교한 것이었다.

또한 리트리버는 더 이상 LongMemEval 자체의 날짜 스탬프와 지시문을 보지 않는다.
그동안 모든 방식에서 질의의 일부였다.

## 설계가 실제로 갈리는 지점

그래프가 고른 문서를 추출된 주장 대신 원문 산문으로 담으면 `gpt-4o-mini`
판정기에서 패시지 대조군 대비 +28.9%였다. 로컬 7B 판정기로 다시 돌리면 +7%로
유의하지 않고, 두 번째 코퍼스에서는 진다. README는 가장 좋은 수치가 아니라 세
수치를 모두 싣는다.

## 업그레이드

이전할 것은 없다. 기존 그래프는 영향을 받지 않으며, 노브는 선택 사항이고 기본
백엔드는 그대로다.
