릴리스 일자 **2026-06-10** · [PyPI](https://pypi.org/project/tesserae/0.7.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.7.1) · `pip install --upgrade tesserae==0.7.1`

`tesserae ingest <file|url>`는 **단일** 문서 또는 URL을 지식 베이스에 병합하는 새로운 최상위 명령입니다 — 전체 코퍼스를 다시 추출하지 않으면서 — 그러면서도 전체 컴파일과 **바이트 단위로 동일**하게 유지됩니다. 파일 하나를 넣거나 웹 페이지를 가리키기만 하면, 매번 전체 재컴파일 비용을 치르는 대신 그래프가 증분적으로 업데이트됩니다.

## 1. `tesserae ingest <input>...` — 증분 단일 소스 인제스트

새 명령은 하나 이상의 입력 — 로컬 파일 경로 또는 `http(s)` URL — 을 받아 각각을 기존 지식 베이스에 독립적으로 통합합니다. 이는 `tesserae code ingest`와 구별됩니다: 이것은 코드 인덱싱이 아니라 메인 그래프로의 문서/소스 인제스트입니다.

기본적으로 `ingest`는 새 소스만 건드리는 **증분 패스트 패스**를 실행합니다. 이 패스트 패스는 *패리티 게이트*가 적용됩니다: 전체 컴파일과 바이트 단위로 동일함이 검증되며, 패리티를 보장할 수 없는 경우 자동으로 전체 재컴파일로 폴백하므로 정확성이 위험에 처하는 일이 결코 없습니다. 직접 전체 재컴파일을 강제하려면 `--exact`를 전달하세요.

플래그: `--exact`, `--dry-run`, `--title`, `--source-kind`.

## 2. URL은 가져오기, 변환, 그리고 프로비넌스와 함께 추적됩니다

`ingest`에 `http(s)` URL을 주면 페이지를 가져와 markdown으로 변환하고, `data/ingested/<slug>.md` 아래에 프로비넌스 front-matter와 함께 추적되는 소스로 저장합니다: `source_url`, `fetched_at`, `content_sha256`, 그리고 소스가 arXiv 논문으로 감지될 때의 `arxiv_id`.

URL 인제스트는 기본 설치를 가볍게 유지하기 위해 새로운 선택적 extra 뒤에 제공됩니다:

```
pip install tesserae[ingest-url]
```

## 3. 코퍼스 외부의 로컬 파일이 코퍼스의 일부가 됩니다

추적되는 코퍼스 외부에 있는 로컬 파일을 인제스트하면, `ingest`가 이를 코퍼스 안으로 복사합니다. 그러면 나중에 전체 `tesserae compile`을 실행할 때 정확히 동일한 결과가 재현됩니다 — 증분 인제스트와 처음부터의 컴파일이 동일한 바이트로 수렴합니다.

## 4. 내부 동작: 패리티를 보존하는 증분 심(seam)

증분 패스트 패스는 컴파일 파이프라인의 호출별 `incremental_override` 심 위에 구축됩니다. 이는 **기본적으로 비활성(inert)** 상태입니다 — 아무것도 이를 재정의하지 않으면 엔진은 이전과 정확히 동일하게 동작하며 전체 컴파일 패리티가 보존됩니다. 골든 패리티 테스트가 이 기능을 게이트하여, 증분 인제스트와 전체 컴파일이 바이트 단위로 동일한 출력을 생성함을 단언합니다.

## 하드닝

프로비넌스 front-matter는 이제 YAML 안전 경로를 통해 작성되어, front-matter 값 주입을 차단합니다(조작된 제목이나 URL이 더 이상 front-matter 블록을 벗어날 수 없습니다).

## v0.7.0에서 업그레이드하기

드롭인입니다. `tesserae ingest <file>`는 로컬 파일에 대해 바로 작동합니다. URL을 인제스트하려면 `pip install tesserae[ingest-url]`로 extra를 설치하세요. 기존 `tesserae compile` / `refresh` 동작은 변경되지 않습니다 — 증분 심은 `ingest`가 구동하지 않는 한 비활성 상태입니다.
