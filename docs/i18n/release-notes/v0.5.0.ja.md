Tesserae 0.5.0 は、本プロジェクトがそのミッションの描く**コンテキストエンジン**になるリリースです。**エンジンスパイン** — パイプラインオーケストレータ、スーパーバイザデーモン、ライブセッションモニタ — と、**柱 3 の目玉機能であるオンデマンドコンテキストコンパイラ**を出荷します。これは「X についてのコンテキストをくれ」を、あつらえた、引用付きの、エージェントがすぐ使えるバンドルに変えます。その下では、自己改善パスが `node_memory` サイドカーを通じて**有効化・永続化**され（出力に表示される数値的な再発信頼度、supersede デフォルト有効）、**本物のデフォルト埋め込み**がハッシュバケットのスタブを置き換え（トラック B）、増分コンパイルの**インフラ**が着地しますが**フラグ OFF/実験的**のままです。その途上で見つかった 2 つの実コンパイルバグが修正され（変更分のみの冪等性、注入ストア契約）、テストスイートは **1544 パス / 0 失敗**に到達します。これは[コンテキストエンジンロードマップ](../context-engine-roadmap.ja.md)のフェーズ 0–6 を届けるリリースです。

## 1. オンデマンドコンテキストコンパイラ — `compile_context`（柱 3、目玉）

### 何か

ロードマップ全体が指し示していた機能です。**クエリ（または一連のシードノード）が入り、あつらえた、引用付きの、エージェントがすぐ使えるコンテキストバンドルが出ます。** `compile_context` は**純粋**関数です — グラフを読み、インメモリの `ContextBundle` を返し、ディスクには何も書きません。パイプラインは次の通り: クエリ/シード → シードのための **PPR + ハイブリッド検索** → **深さ制限 k ホップ**近傍ウォーク → 関連するウィキ本文の組み立て → **任意の LLM 統合**（優雅な決定的フォールバック付き）→ 単語境界の切り詰めマーカー付き**予算制御**。寄与するすべてのノードが `ContextCitation` として記録されるため、バンドルの引用はすべて実在のグラフノードに解決されます。

| 型 | 役割 |
|---|---|
| `compile_context(query \| seeds, depth, budget, …)` | 純粋なエントリーポイント; `ContextBundle` を返す。 |
| `ContextBundle` | 組み立てられたコンテキストとその引用リスト。 |
| `ContextCitation` | 解決可能な単一の引用（ノード id → 寄与本文）。 |

コンパイラは 3 つの方法で公開されます。

- **MCP ツール** `compile_context` — エージェントが会話中に呼び出す。`budget=0` は上限なしを意味する。
- **CLI** `tesserae project context` — exit-0 / stdout / `--output` / 決定的、スクリプティングとパイプライン用。
- **トピックスコープのエクスポート** — `slice_export_context_for_topic` がトピックスコープの `llms.txt` スライスを生成し、エージェントハーネスのブリーフは、ハードコードされた上位 12 件ではなく `compile_context` を通じて**トピックごと**にレンダリングされるようになります（パターン 4 + パターン 6）。

2 つの関連する検索アップグレードが付随します: `node_context` が **`use_ppr`** ランク付けパスを得（抑制を考慮した近傍埋めとエッジ/上限制御付き）、トピックスライスが**正規のウィキ slug** を使い、引用とエクスポートが揃います。

### 使い方

```bash
# CLI: トピックの引用付きコンテキストドキュメントをコンパイルし、stdout かファイルに出力
tesserae project context "検索ランキングと RRF 統合"
tesserae project context "検索ランキング" --output ./context-retrieval.md
```

MCP クライアントから:

```jsonc
{
  "tool": "compile_context",
  "arguments": {
    "query": "私たちの検索スタックは候補をどうランク付けするか？",
    "depth": 2,
    "budget": 4000
  }
}
// → ContextBundle を返す: 組み立てられた本文 + 解決可能な引用のリスト。
//   budget: 0 は上限なしを意味する。
```

アンカーがすでに分かっているときは、ノード id から直接シードする（検索ステップをスキップ）こともできます。

```jsonc
{
  "tool": "compile_context",
  "arguments": {
    "seeds": ["decision-2026-05-22-switch-to-rrf-fusion"],
    "depth": 2,
    "budget": 0
  }
}
```

### いつ使うか

- エージェントが全コーパスの `llms.txt` ダンプや単一の `wiki_page` 本文ではなく、**1 つのトピックに絞ったブリーフ**を必要とする場合。
- **解決される引用** — バンドル内のすべての主張がグラフノードに遡れる — が欲しく、エージェントが追跡できる必要がある場合。
- ハンドオフをスクリプト化し、トピックごとに再生成される**決定的**なコンテキストアーティファクト（`--output`、no-LLM 組み立てモード）が欲しい場合。

### どこにあるか

中核実装: [`tesserae/context_compiler.py`](https://github.com/ca1773130n/Tesserae/blob/main/tesserae/context_compiler.py)（`compile_context`、`ContextBundle`、`ContextCitation`）。MCP 登録とディスパッチ: `tesserae/mcp_server.py`。CLI 配線: `tesserae/cli.py` の `context` サブパーサと `_handle_context`。トピックスコープのハーネス/エクスポートレンダリングは `compile_context` を通じてルーティングされます。

### 注意事項

- 統合品質は LLM バックエンドに依存します。バックエンドがない場合、コンパイラは決定的な組み立てにフォールバックします（依然として引用付き、ただし未統合）。フォールバックは優雅です — 統合の失敗がバンドルを中止させることはありません。
- k ホップウォークは**深さ制限**され、PPR は深さ制限されたサブグラフ上で実行されます。非常に大きなグラフは、`budget=0` よりタイトな `depth` と実際の `budget` の恩恵を受けます。
- 予算の切り詰めは**単語境界**で切り、切り詰めマーカーを付けるため、切り取られたバンドルもトークンの途中で終わらず、依然として読めます。

## 2. エンジンスパイン — オーケストレータ、デーモン、ライブセッションモニタ

### 何か

監査が最大のギャップと呼んだ 3 つの基礎部品が、`tesserae/engine/` の下に出荷されました。

- **パイプラインオーケストレータ**（`pipeline.py`）— `ingest → compile → project → publish` チェーンを、スラッシュコマンドの markdown スキルから一級のインプロセスオブジェクトへ引き上げ、デーモン・CLI・MCP がすべて呼び出します。これがすべての継続的なものがぶら下がる共有コードパスです。
- **スーパーバイザデーモン**（`daemon.py`）— 1 つのイベントループを所有し、トリガーのバーストを単一のパイプライン実行にまとめ、優雅な `SIGTERM` / `SIGINT` シャットダウンを処理し、パイプライン例外でも死なずに生き残る、監督された長時間実行プロセス。
- **ライブセッションモニタ**（`session_tail.py`）— ライブハーネスのトランスクリプトをテーリングし、セッションが実行されるにつれてターンを取り込み、事後の `sessions discover --import` スキャンを置き換えます（柱 1）。

これらが揃って、Tesserae を一回限りのバッチ CLI から、継続的に監視・取り込みできるプロセスに変えます。

### いつ使うか

- 手動コマンドなしでセッションと編集がグラフに流れ込む**「更新され続ける」性質**が欲しい場合。
- Tesserae の上に構築しており、リフレッシュチェーンを再実装する代わりに、デーモン・CLI・MCP のための**1 つの共有パイプラインエントリーポイント**が欲しい場合。

### どこにあるか

`tesserae/engine/pipeline.py`、`tesserae/engine/daemon.py`、`tesserae/engine/session_tail.py`（エンジンスパインとしてマージ、ロードマップフェーズ 0–2）。

## 3. 有効化・永続化された自己改善（`node_memory` サイドカー）

### 何か

「自己改善型ベース」の柱が、ボルトオンのパスから永続化された **`node_memory` サイドカー**（`tesserae/memory/`）へと移ります。2 つのユーザー可視の変更:

- **決定的な判定を伴う supersede デフォルト有効。** supersede パスがデフォルトで実行されるようになり（`TESSERAE_SUPERSEDE_PASS=true` 不要）、双方向の決定的で明確なセッション id 判定としきい値ガード、さらに下流の**抑制**を備え、置き換えられた事実が単にエッジを得る代わりにコンテキスト出力から消えます。
- **出力に表示される数値的な再発信頼度。** 再発知見の強化が、クロスセッション頻度から**数値的な**信頼度を生み、`memory_by_id` を介して `TemporalFactProjector` に注入され、従来の粗い文字列ヒューリスティックを置き換えます。セッションをまたいで事実を再述すると、出力でその信頼度が測定可能に上がります。

### いつ使うか

- 同じ知見が再発する**マルチセッションプロジェクト**を運用する場合 — 強化はその再発を、エージェントがランク付けできる信頼度シグナルに変えます。
- 陳腐化した事実が単にフラグされるのではなく、コンパイルされたコンテキストから**消える**ことを望む場合。

### どこにあるか

`tesserae/memory/` — `store.py`、`reinforce.py`（数値的な再発信頼度）、`supersede.py`（デフォルト有効、決定的判定 + 抑制）、さらに `decay.py`、`contradiction.py`、`insight_symbol_link.py`。自己改善テストスイート（以前はテストゼロ）が、決定性、冪等性、LLM オーバーライドパスをカバーするようになりました。

### 注意事項

- 減衰と矛盾のスキャフォールディングは同じサイドカーに出荷されます。v0.5.0 のユーザー対面のデフォルト有効動作は supersede + 数値的な再発信頼度です。

## 4. 本物のデフォルト埋め込み（トラック B）

### 何か

デフォルトの「セマンティック」レーンは、もはや決定的なハッシュバケット疑似埋め込みではありません。v0.5.0 は本物の **`Model2VecBackend`** を出荷し、`active_embedding_backend` が無音で blake2b にダウングレードする代わりに**失敗時に明示的に知らせる**ようにします。使用中のセマンティックバックエンドは **`embedding_status`** に表示され、コサイン下限が埋め込みレーンに候補を（再ランクだけでなく）**採用**させるため、言い換えや同義語のクエリが BM25 が逃すノードを浮上させます。

### 使い方

```jsonc
{ "tool": "embedding_status" }
// → どのセマンティックバックエンドがアクティブか（本物 vs フォールバック）を報告するため、
//   すぐ使える検索が本当にセマンティックかを一目で分かります。
```

### どこにあるか

`tesserae/retrieval/hybrid.py`（バックエンド選択、失敗時に明示的に知らせる `active_embedding_backend`、埋め込みのみ採用のためのコサイン下限）と `Model2VecBackend`。`embedding_status` MCP ツールを通じて表示されます。

### 注意事項

- 本物のバックエンドがロードできない場合、検索はハッシュスタブがセマンティックであるふりをする代わりに、**大きな声で知らせる**ようになります — これは意図された動作変更です。

## 5. 増分コンパイルのインフラ（フラグ OFF）+ 2 つのコンパイル修正

### 何か

`GraphStore` ポート経由の設計された増分レイヤが**インフラ**として着地します: プロヴェナンスサイドカー、`GraphStore` 削除サーフェス、フル時の照合、エッジ認識の準備性、プロデューサープロヴェナンス配管、そして永続 `url_resolver` 非同期ランタイム（もはや呼び出しごとの `asyncio.run` なし）。フルコンパイルに対するバイト等価性は、カバー済みパス（リネーム、エイリアス同一性、両端点移動の等価ゲート）について証明されています。

**`incremental_compile` フラグは OFF/実験的のままです。** Codex レビューが複数オーナー/プロデューサーライフサイクル/キャップフォールバックのギャップを明らかにしたため、フラグはそれらのギャップが閉じるまで、カバー済みパスについてのみオプトインでバイト等価性が証明されています。

この作業で明らかになった 2 つの**実コンパイルバグ**がデフォルトパスで修正されます。

- **変更分のみの冪等性** — `compile` が変更分のみの冪等性を尊重するようになり、no-op の再コンパイルがグラフをかき回しません。
- **注入ストア契約** — プロジェクトコンパイルでの注入ストア契約が尊重され、直接取り込みパスでの一群の失敗が修正されます。

### どこにあるか

増分インフラは `GraphStore` ポートとプロヴェナンスサイドカーにまたがります。2 つの修正はプロジェクトコンパイルパスに着地します（`fix(project): honor changed-only idempotence + injected-store contract in compile`）。

### 注意事項

- 本番グラフではまだ `incremental_compile` を有効にしないでください — 複数オーナー/ライフサイクル/キャップフォールバックのギャップが閉じるまで、設計上実験的です。フルコンパイルが信頼されるパスのままです。

## v0.4.0 からのアップグレード

```bash
pip install --upgrade tesserae==0.5.0
```

既存のワークフローにとって、v0.5.0 は**加算的**です — `tesserae project compile` は以前とまったく同じに動作し、2 つの正確性修正（変更分のみの冪等性、注入ストア契約）が加わります。新しいサーフェスは呼び出しがオプトインです。

**新しいオンデマンドコンテキストコンパイラ:**

```bash
tesserae project context "<トピック>"            # 引用付きコンテキストバンドルを stdout へ
tesserae project context "<トピック>" --output out.md
```

```jsonc
{ "tool": "compile_context", "arguments": { "query": "<トピック>", "depth": 2, "budget": 4000 } }
```

**デフォルト有効になった動作（以前はオプトインまたは不在）:**

- supersede パスのデフォルト有効（置き換えられた事実の出力抑制付き）。
- 投影出力に表示される数値的な再発信頼度。
- 失敗時に明示的に知らせるバックエンドを伴う本物のデフォルト埋め込み（無音のハッシュスタブダウングレードなし）。

**依然として実験的 — 本番グラフではオフに:**

- `incremental_compile`（インフラ出荷、フラグ OFF）。

それ以外のすべて — `graph_ppr`、ハイブリッド `search_nodes`、`sync-code`、`research`、ライブ hook、`embedding_status`、`fresh_insights`、schema-drift、スラッシュコマンド、ウィキ / Obsidian 投影 — は v0.4.0 から引き継がれます。

## 戦略的文脈

[コンテキストエンジン監査](../context-engine-audit.ja.md)（2026-06-02）はギャップを一行で名指ししました: Tesserae は*機械的に健全でよくテストされたバッチ CLI コンパイラ*であり、三本の柱すべてで手動トリガーかつ事後的で、最大の欠落部品は**1 つのイベントループを所有する長時間実行スーパーバイザ**でした。v0.5.0 はその一行を閉じます。エンジンスパインがスーパーバイザであり、ライブセッションモニタが柱 1 を事後ではなくライブにし、`node_memory` サイドカーが柱 2 をその場で自己改善型にし、そして**オンデマンドコンテキストコンパイラが柱 3** です — 型付きグラフ、ボールト、サイトを静的な投影から、クエリスコープの、引用付きの、エージェントがすぐ使えるオンデマンド出力へと変える目玉機能です。

私たちが調査した 2026 年の PKM-AI ランドスケープで、この構成をするツールはありません。**Cursor Memories**、**Claude `CLAUDE.md`**、**Cline memory-bank**、**Aider `CONVENTIONS.md`** は、エンジンループも、型付きの自己改善も、オンデマンドの引用付きコンテキストコンパイラもない静的なテキストバッグです。Microsoft **GraphRAG** は型付きエンティティとコミュニティ要約を持ちますが、継続実行のプロジェクトメモリエンジンではなく、コーパス-RAG システムです。v0.5.0 はベースを新鮮に保つループと、エージェントが求めるまさにそのコンテキストを渡すコンパイラを出荷します — `AGENTS.md` に明白に述べられたミッションが、今やコードで動いています。

残るもの: **フェーズ 7** — 継続的な公開のために serve + watch + deploy をスーパーバイザの下で統一し、増分コンパイルフラグの残るギャップが閉じたらそれを有効にすること。スパインと目玉は入りました。収束リリースが次です。
