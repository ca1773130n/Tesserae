Выпущено **2026-06-20** · [PyPI](https://pypi.org/project/tesserae/0.10.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.10.0) · `pip install --upgrade tesserae==0.10.0`

Выпуск новой функции: обмен знаниями, более быстрый поиск сессий и одноразовая 
машинная конфигурация. Все дополнения являются добавками — простой `tesserae compile` 
остаётся неизменным, и конфигурация по проекту всё ещё переопределяет новые глобальные значения по умолчанию.

## 1. Импорт/экспорт Google OKF v0.1

`tesserae export okf` записывает граф как пакет [Google **Open Knowledge Format**
v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog) — дерево
Markdown файлов с YAML frontmatter и относительными связями. `--import
DIR` читает один обратно. Собственные пакеты Tesserae выполняют переход **без потерь** через
пространство имён `x_tesserae` в frontmatter (реальные id узлов + типизированные рёбра + метаданные рёбер);
иностранные пакеты импортируются наилучшим усилием (неизвестный `type` → `Concept`, 
несвязанные ссылки → `references`), допуская отсутствующие типы и разорванные/символические ссылки согласно спецификации.

## 2. Быстрый поиск транскриптов на панели сессий

Панель сессий `tesserae serve` получает полнотекстовое поле поиска над каждым
индексированным транскриптом Claude/Codex, работающим на базе
[`nicosuave/memex`](https://github.com/nicosuave/memex) (BM25). Это опционально и
корректно: без двоичного файла `memex` поле показывает полезное сообщение и
остаток панели не затронут. Конечная точка `GET /api/transcript-search` ограничена к
вызывающим с одного источника/loopback, поэтому посещённая веб-страница не может исследовать локальную
историю, и результаты отображаются через `textContent` (без инъекции разметки).

## 3. Дисциплина чтения в стиле memex для MCP

Вдохновлённый "программируемым блокнотом" Databricks, `compile_context` теперь принимает
`preview=N`: вместо сброса огромного тела в контекст агента он возвращает
ограниченный предпросмотр плюс **дескриптор** на основе содержимого, и новый инструмент **`get_handle`**
подгружает остальное по требованию. По умолчанию `preview=0` сохраняет поведение с полным телом.

## 4. Сигналы качества извлечения

Находки сессии теперь содержат `confidence` + `confidence_rationale` + `revisit_signals`
дистиллированные из экстрактора (идеи от Jonasb8/memex; код не скопирован). Они находятся в
кэше извлечения на основе содержимого, поэтому остаются байт-идемпотентными, и отображаются в
инструменте MCP `fresh_insights` как флаги (никогда не гарантии истины).

## 5. Машинная конфигурация + установка зависимостей

`tesserae config setup` устанавливает стандартные значения LLM для **всех** проектов
(`--llm-provider`, `--reasoning-effort`, `--codex-home`, `--claude-config-dir`)
**и** устанавливает опциональные зависимости (`--install all`) в одно действие.
`tesserae config deps` перечисляет/устанавливает **memex**, **cognee**, **raganything** и
**understand-anything**; `tesserae config llm` получил `--reasoning-effort`; и
`tesserae init` предлагает установить memex при интерактивной настройке. Порядок разрешения:
env → конфиг проекта → машинная конфиг → встроенное.

## Обновление с v0.9.x

Прямая замена. Всё новое опционально или аддитивно; простой `tesserae compile` ведёт себя как раньше. 
Запустите `tesserae config setup`, чтобы один раз настроить машинные стандартные значения,
или сохраняйте свой `/.tesserae/config.json` для каждого проекта — он всё ещё выигрывает.
