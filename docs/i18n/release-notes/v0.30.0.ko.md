세 가지가 들어갑니다. 요청하지 않는 한 소스 코드는 더 이상 색인되지 않습니다.
작성되고 테스트까지 되어 있었지만 닿을 수 없던 검색 표면이 열립니다. 그리고
그래프에 조직도가 생겨, 범용 에이전트를 특정 도메인에 붙여 전문가처럼 쓸 수
있게 됩니다.

## 소스 코드는 이제 요청해야 하는 것입니다

예전에는 프로젝트가 저장소처럼 *보이기만* 하면 코드 레이어를 만들었습니다
(`kind`가 `CodeProject`, `Repository`, `Project`인 경우). 그것은 프로젝트가
무엇인지에 대한 설명일 뿐, 소유자가 소스를 파싱해 달라고 말한 것이 아닙니다.
빠져나갈 방법은 종류를 거짓으로 적는 것뿐이었습니다.

비용은 아무도 보지 않는 곳에 쌓였습니다. `graph.json`은 리서치 파티션만
담기 때문에 코드 노드가 **0개**로 보이는 동안, SQLite 프로젝션과 생성된
페이지에는 약 22만 행과 22만 페이지가 있었습니다. 설정한 적 없는 옵션에 그
비용을 연결짓는 사람은 없습니다. 메인테이너의 머신에서는 그 기능을 끈
프로젝트에 327MB의 산출물이 남아 있었습니다.

이제는 프로젝트가 직접 요청합니다:

```json
"external_tools": [{"id": "codegraph"}]
```

항목이 없으면 꺼진 상태입니다. 프로젝트 종류는 전혀 참조하지 않습니다.
두 번째 스위치를 새로 만드는 대신 RAG-Anything 연동이 이미 읽는 형태를
재사용합니다.

**유지 관리도 같은 게이트를 따릅니다.** 그렇지 않으면 새는 쪽이 바로 이쪽입니다.
두 sync-code 훅 모두 자기 자신의 `sync_code_on_*` 설정보다 *먼저* 옵트인을
확인합니다. 따라서 그 설정들은 이미 부여된 권한을 좁힐 수만 있고, 없던 권한을
만들어낼 수는 없습니다. 디스크에 CodeGraph 데이터베이스가 있다는 것은 동의가
아닙니다 — 에이전트가 자기 목적으로 `codegraph init`을 실행했을 뿐, Tesserae가
30초마다 추적해야 하는지에 대한 의견은 아닙니다.

`code-graph.json`은 스위치를 양방향으로 따릅니다. 켜면 쓰고, 끄면 지웁니다.
남겨진 파일에는 시간 정보가 없어서, 이미 달라진 저장소의 스냅샷으로 계속
응답하게 됩니다.

삭제된 것은 없습니다. CodeGraph 어댑터, 추출기, 캐시, `tesserae code
ingest|sync`는 모두 스위치 뒤에 그대로 있습니다.

## 원래 있던 검색 노브들

`facts_as_of` — "이 날짜에 그래프는 무엇을 믿고 있었는가"를 묻는 바이템포럴
질의 — 는 작성되어 있고, 바이트 단위로 멱등하며, 테스트가 7개 붙어 있는데
호출자가 **0개**였습니다. `personalized_pagerank`는 이미 `edge_type_weights`를
존중하고 있었습니다. `compile_context`는 파라미터가 16개인데 MCP 서버는 7개만
전달했습니다. Tesserae는 바이템포럴리티와 뷰 선택적 순회를 가지고 있으면서도
그 어느 것도 요청할 수 없었습니다.

이제 가능합니다. `search_facts`와 `timeline`에 `as_of`가 붙고,
`undated_included`가 반환된 행 중 날짜 없는 것이 몇 개인지 알려줍니다.
`compile_context`에는 `strategy`, `scope`, `edge_type_weights`, `tame_hubs`,
`recency_weight`가 열립니다.

`as_of`와 `current_only`는 함께 쓰면 거부됩니다. 의도적입니다. 서로 다른 시계를
뜻하며, 과거 시점에 무엇이 참이었는지 물었을 때 나중에 대체되었다는 이유로
조용히 아무것도 돌려주지 않아서는 안 되기 때문입니다.

## 그래프 위의 조직도

`tesserae domains status`는 지식 그래프 위에 세워진 구조를 보여줍니다.
커뮤니티에서 유도된 부서, 한 도메인의 브리프가 에이전트가 한 번에 읽을 수 있는
분량을 넘으면 재귀적으로 이루어지는 분할, 그리고 재편 이후에도 살아남는 정체성
— 에이전트에 고정해 둔 슬러그가 그래프가 움직인 뒤에도 그대로 유효합니다.

이것은 기반입니다. 이를 사용하는 라우팅은 다음에 들어갑니다.

## 인제스트는 하지도 않은 일을 성공이라 보고하지 않습니다

예전에는 `tesserae ingest paper.pdf`가 파일을 복사하고, `.md`만 읽는 워커로
컴파일을 돌린 뒤, 나머지 코퍼스에서 나온 노드 수를 출력했습니다. 그 경로의 어떤
것도 "PDF를 인제스트했다"와 "아무것도 인제스트하지 않았다"를 구분하지 못했습니다.
PDF가 든 디렉터리도 마찬가지였고, 출력되던 `processed=1`은 디렉터리를 센 것이었습니다.

이제는 파일 단위로 거부하며, 실행 가능한 해결책을 함께 제시합니다:

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

URL 가져오기도 엄격해졌습니다. 예전에는 PDF URL을 텍스트로 디코딩해 `.md`
확장자로 쓰고 깨진 문자열에 대해 해시를 계산했고, 그래서 워커가 그것을 산문으로
추출기에 넘겼습니다. 이제는 바이트가 바이너리라고 말하는 본문, 선언된 타입이
바이너리인 본문, 읽을 텍스트가 없는 200 응답을 모두 거부합니다.

새 `INTERVAL_COVERAGE` 린트는 그래프 중 얼마나 시간 위에 놓일 수 있는지
보고합니다. 이 프로젝트의 그래프에서는 **103,705개 사실 중 76,095개(73.4%)에
`valid_from`이 없어**, `timeline()`에서 문자열 "undated" 아래로 정렬됩니다.
`info` 수준으로 보고하며 `--strict`를 실패시키지 않습니다. 기준선을 정하려면
최신 코퍼스에서 나온 숫자가 필요한데, 아직 그렇지 않기 때문입니다.

세션 임포트는 읽지 못하는 콘텐츠 블록을 조용히 버리는 대신 셉니다. 실제 트랜스크립트
150개에서 **이전에는 보이지 않던 이미지 블록 9개**가 드러났습니다. 그것들은
`tool_result` 안에 중첩되어 있었고, 예전 카운터는 그곳을 본 적이 없습니다.

## 업그레이드

```bash
pip install --upgrade tesserae==0.30.0
```

Claude Code 플러그인으로 Tesserae를 쓰고 있었다면, **훅 게이트는 이 버전의
플러그인이 설치된 뒤에야 적용됩니다.** 이전 플러그인 사본은 CodeGraph
데이터베이스가 있는지만 보고 옵트인을 볼 수 없습니다. 그때까지는
`.claude/tesserae.local.md`의 `sync_code_on_edit: false`와
`sync_code_on_start: false`가 그 훅들이 이해하는 스위치입니다.

기존 프로젝트는 그대로 동작합니다. 코드 레이어를 다시 원하는 프로젝트는 위
`external_tools` 항목을 추가하면 되고, 원하지 않는 프로젝트는 아무것도 바꾸지
않아도 더 작은 그래프와 더 작은 데이터베이스를 얻고 코드 페이지는 생기지
않습니다.
