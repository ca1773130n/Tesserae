Veröffentlicht **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.20.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.20.0) · `pip install --upgrade tesserae==0.20.0`

Agenten sind die First-Class-Konsumenten von Tesserae, und nach dem Command-Split in 0.18 existierten zwei Fähigkeiten nur auf der CLI. Dieses Release schließt beide Lücken mit neuen MCP-Tools.

## `query` — rohe Retrieval über MCP

Spiegelt `tesserae query`: deterministische BM25-/semantische Suche über das kompilierte Wiki mit `top_k` und einem `kind`-Filter, garantiert ohne jemals einen LLM-Aufruf zu machen (`force_no_llm` durchgehend). `backend: "raganything"` erreicht den optionalen multimodalen RAG-Index — der seit dem 0.18-Split, als `ask` seinen Backend-Parameter verlor, **überhaupt keinen MCP-Pfad** mehr hatte. Verwende `ask`, wenn du eine synthetisierte, zitierte Antwort willst; verwende `query`, wenn du die gerankte Evidenz selbst willst.

## `doctor_run` — frische Health-Checks über MCP

`doctor_report` (0.18) lieferte nur den zuletzt persistierten Report — ein Agent, der auf ein Projekt traf, das nie doctor ausgeführt hatte, bekam nichts. `doctor_run` führt das vollständige Register mit 20 Checks auf Abruf aus und gibt die Befunde als JSON mit dem Exit-Code 0/1/2 zurück. Es ist **immer read-only**: Fixes laufen niemals über MCP und es wird kein Report-Artefakt geschrieben; Reparaturen bleiben eine explizite menschliche Aktion über `tesserae doctor --fix`.

## Alles andere floss bereits durch

Keine Änderungen nötig für den Rest der 0.18–0.19-Features: `ask` liefert die LLM-geplante Antwort mit `llm` standardmäßig auf true, `activity_summary` / `query_decisions` / `timeline` erben den täglichen Session-Chunk-Fast-Path transparent, und die Setup-Tools akzeptieren die Custom-Provider-Schlüssel, wobei `llm_api_key` bewusst nicht setzbar ist und redigiert wird.
