发布于 **2026-10-06** · [PyPI](https://pypi.org/project/tesserae/0.42.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.42.0) · `pip install --upgrade tesserae==0.42.0`

节点和边的词汇表原本是封闭的:每增加一种关系类型就需要一次新发布,而使用了新类型的图无法被旧安装读取。
每周都在扩展自己本体的宿主无法这样工作。本次发布允许宿主在运行时注册类型,每个类型都挂在一个核心父类型
之下,并保证宿主写出的每个文件都能被 0.41 读取。

## 变更内容

- **类型注册表。** `tesserae.type_registry` 保存 `TypeSpec` 条目,可以从代码、JSON 文件或
  `TESSERAE_TYPE_REGISTRY` 注册。每个类型都指定一个 `core_parent`。节点保留核心类型,把更细的种类放在
  `metadata.subtype` 中。处于活动状态的注册表边类型可以在内存中使用。
- **宽松加载。** `TESSERAE_TYPE_MODE=lenient` 把读取方不认识的类型映射到它在注册表中的父类型,否则映射为
  `Concept` 或 `references`。原始类型保留在 `metadata.raw_type` 中,并计入 `load_stats`。默认值仍是
  `strict`,其报错行为与之前完全相同。
- **来自注册表的视图。** 注册表类型加入它声明的视图,否则加入父类型的视图。新的 `crossdomain` 视图收纳
  `transfers_to`、`inspired_by` 等跨领域关系。在宿主注册这些类型之前,它是空的。
- **边的置信度和状态。** 边可以带有可选的 `confidence`、`status`、`asserted_by`、`valid_from`、
  `invalid_at` 和 `provenance`。PPR 把类型权重乘以 `confidence`,除非显式要求,否则跳过 `candidate`、
  `refuted` 和 `retracted` 的边。被驳回的 `supersedes` 边不再隐藏其目标。
- **内容解析器。** `compile_context(content_resolver=...)` 先向宿主请求节点内容,从最便宜的视图开始,
  然后再回退到 wiki 页面和描述。引用会列出实际使用的引用标识。
- **概念身份。** 联邦会合并共享 `metadata.concept_id`、Wikidata QID 或 MSC2020 分类的节点。
  `federate_graphs(identity_resolver=...)` 让宿主从自己的表中提供身份,而无需修改任何 `graph.json`。
- **模式漂移。** `analyze_schema_drift(kind="edge")` 提出子关系,`embedder` 取代名称词元的 Jaccard,
  台账记录附带门控指标,`apply_ledger_to_registry` 把已批准的提案写入注册表文件。它从不改变节点的类型。
- **有上限的邻居查询。** 如果存储自带 `neighbors` / `iterate_edges`,`store_neighbors` 和
  `store_iterate_edges` 就直接使用它们,否则走回退路径。`GraphStore` 本身没有变化。
- **仅限生产者的边。** `transfers_to`、`candidate_transfer`、`analogous_to` 和 `merged_into` 永远不能
  由 LLM 抽取,也不能由代理作为类型写入。
- **代理写入。** `graph_write` 在记录之前把注册表类型映射到其核心父类型,并附上 `metadata.subtype` 或
  `metadata.relation`。边可以携带 `metadata`。

## 兼容性

0.41 的 `graph.json` 在严格模式下加载,节点、边和类型的数量都不变。不含新字段的图序列化结果与之前逐字节
相同。本次发布写入 `graph.json` 或 `agent-writes.jsonl` 的内容都不使用注册表类型,因此回退到 0.41 依然
安全。

## 升级

无需迁移。没有注册表时,所有默认行为都与 0.41 相同。
