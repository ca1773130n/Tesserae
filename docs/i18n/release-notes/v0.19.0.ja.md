Released **2026-07-11** · [PyPI](https://pypi.org/project/tesserae/0.19.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.19.0) · `pip install --upgrade tesserae==0.19.0`

バックエンドの終焉（end-of-life）リリースです。v0.18.0 以降、デフォルトのナレッジグラフの更新と取得のループは完全に内製化されました — 型付き ResearchGraph パイプラインがグラフを書き込み（ネイティブのコードグラフ抽出を含む）、`ask` は LLM でその上の取得を計画します。このリリースでは、もはや存在価値を失った 2 つの後付けバックエンドを削除します。

## understand-anything: 削除

その唯一の貢献 — 外部で生成されたコード構造ノードの `knowledge-graph.json` を ResearchGraph にマージすること — は、ネイティブのコードグラフ抽出器の出荷以来、冗長になっていました。アダプタ、refresh モジュール、コンパイル時マージ、deps 検出、setup エントリは削除されました。`tesserae integrations refresh understand-anything` はネイティブのコード ingest への 1 行のポインタを表示して 2 で終了します。understand-anything の `external_tools` エントリを含む古い設定は、1 つの注記とともにロードされます；既存のグラフ内の UA が生成したノードは引き続き有効です。

## cognee: 削除

cognee はグラフを*外側へ*自身のストアに複製するだけで、何もフィードバックしませんでした；0.18 以前は、デフォルトインストールで `ask` の出力にログスパムと `OperationalError` フォールバックも漏らしていました。1 リリース分のデフォルトオフの猶予期間を経て、完全に削除されました：アダプタ/ダイレクト/クエリの各モジュール、コンパイル時の cognify パスとバンドルエクスポート、`[cognee]` extra、ウィザードのプロンプト、MCP スキーマ参照（約 1,100 LOC と 6 つのテストファイル）。`query --backend cognee` およびすべての `--cognee-*` / `--enable-cognee` フラグは、1 行の削除スタブを表示して 2 で終了します。`memory_backends.cognee` セクションを含む設定は引き続きロードおよびコンパイルできます — プロセスごとにちょうど 1 つの注記付きで。

## rag-anything: 意図的に維持

ナレッジグラフに本当に欠けている能力 — マルチモーダルドキュメント RAG（PDF、画像）— を持つ唯一のバックエンドは、オプションの `tesserae[raganything]` extra として残ります。デフォルトはオフで、`tesserae query --backend raganything` で利用できます。

## 破壊的変更

プロジェクトの慣例に従い、何もサイレントに失敗しません — 削除されたすべてのサーフェスは、代替または説明を表示して 2 で終了します：`integrations refresh understand-anything`、`query --backend cognee`、`--cognee-search-type`、`--cognee-dataset`、`--enable-cognee` および残りの `--cognee-*` setup/extract フラグ。2 つの削除の正味の効果：+1,600 行に対して **−5,500 行**、フルテストスイートはグリーン（2,251 passed）です。
