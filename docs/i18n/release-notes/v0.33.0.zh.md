发布 **2026-08-24** · [PyPI](https://pypi.org/project/tesserae/0.33.0/) · [GitHub 发布](https://github.com/ca1773130n/Tesserae/releases/tag/v0.33.0) · `pip install --upgrade tesserae==0.33.0`

内存系统的好坏取决于它能向模型提供什么，以及这样做的代价有多大。这个版本改进了这两个数字，然后花费大部分精力来验证它们是否可信。

## 证据变得更便宜

检索预算被花费了两次在同一件事上。`documents_of` 将一个会话的命中合并到该会话，所以一个十个命中的预算换来了 **6.90 个不同的文档** — 大约每个提示的三分之一都是已经读过的材料。`fanout_search` 限制每个源的命中，并在问题的自身单词在语料库中无处不在时分别提出问题的判别性部分。

然后单位本身改变了。打包整个会话文档花费了提示的 94.2% 在粘贴的记录上；打包 TURN 花费它在问题实际需要的转向。在 LoCoMo conv-26 上测量，**43,413 个字符变成了 27,921** — 35.7% 的削减，具有更好的黄金证据覆盖率。

预算匹配的对照是让这成为结果而不是节省的。相同的会话单位给予相同的 28,000 字符达到 0.870 覆盖率而包达到 0.928，对照在失去时预算下 1,215 个字符。

## 答案提示是最大的单一杠杆

发布的规则要求证据支持的最短答案，仅此而已。`--deliberate` 取代它，在字节相同的证据上将准确率 **从 0.816 移至 0.8947 在 7,084 个标记处**，之前是 10,991。

因为答案长度与法官得分相关联，长度通道是测量而非讨论的。用 11.4 个单词的无内容填充垫旧答案在发布的等级者下获得 +0.0197，在宽松的等级者下获得 **+0.0000**。该变更添加 1.89 个单词，中位数不变，这将长度定价为收益的 4-7%，第二等级者下为零。

## 出处变成了一个过滤器，过滤器在攀升

`tesserae.vetting` 询问一个源是否由独立的人审查过，并让调用者对其进行过滤证据。一个过滤器，永远不是一个分数：分数将审查、出处和判决混为一体成一个数字，隐藏使问题值得提出的分歧。

`UNVETTED` 和 `UNKNOWN` 与 `REJECTED` 保持不同，因为没有记录的源还未被拒绝 — 它还未被发现。在一条链内，最薄弱的环节统治，因为一个段落不会比它引用的研究更经过审查。跨越独立链它们互相证实，所以由评审论文和预印本支持的声明比仅由预印本支持的更强，而不是更弱。蒸馏的社区摘要通过 `part_of` 解析为其下面的源：蒸馏可能总结，但可能不会洗白出处。

## 工具，以及检查它们的成本

检查了三个基准，每个都以不同的方式被破坏。LoCoMo 的答案关键字错了 6.4%，所以一个完美的系统得分约 0.936，它的法官将 **62.81% 的故意错误答案标记为正确** 当它们模糊但主题相关时。DeepScholar 的 `cite_p` 将人为编写的相关工作排名低于重建它的机器。它的 `reference_coverage` 表现正确，现在是度量 `evals/deepscholar/` 的目标。

三个相同形状的错误被固定，这个形状值得命名：一个静默的零代替"未测量"。`complete_json` 丢弃了它无法解析的回复 — 二十四个被探测的调用中的六个，其中两个携带了正确的答案。`_anchor_index` 按类型选择了一个节点，其中答答路径按身份决定，所以二百七十二个会话文件中的三十三个选了冒充者。发布的 LoCoMo 等级者完全无法从此代码库访问，这就是为什么每个报告都打印了 `judge: UNMET`。

## `init` 不再覆盖你的提供商

`tesserae init` 检查安装了哪个 CLI 并将该提供商写入每个新项目中，覆盖了机器范围的配置，并固定了没有人要求的特定账户目录。优先级现在是 **覆盖，然后全局配置，然后检测** — 因为检测是猜测，全局配置是决定。`llm_model` 和 `llm_codex_home` 也从全局层继承。

## 还有

- 可选 `rerank` 额外功能后面的交叉编码器重排机，其前向传递从 4.97 GB 的 `logits` 张量修复为 2.4 MB
- `--judge-rules mem0-2026`，竞争对手的宽松等级者被重现并在每个制品中标记为宽松，所以它不能被引用为严格的
- `uv.lock` 陈旧性和一个固定的标记化符获取，这使 CI 变红

## 关于检索的诚实说法

在一个 1,552 篇论文的池中，平面 BM25 得分 0.541 reference_coverage，而这个项目的混合堆栈得分 0.518。这个周期的四个独立测量都说额外的通道会稀释 BM25 而不是改进它。会测试图本身的手臂 — 针对相同对照的编译概念和 `evidenced_by` 边 — 已建立，尚未运行。
