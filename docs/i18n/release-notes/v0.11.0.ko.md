## 크로스 프로젝트 페더레이션

`tesserae ask --scope federated --scope-aliases research work "…"` (그리고 `scope: "federated"` 포함 MCP `ask` 도구)는 명시한 프로젝트에서 **하나의** 그래프를 조립하고 크로스 레퍼런싱된 단일 답변을 반환합니다 — 프로젝트별로 하나의 답변을 반환하는 `all-registered` 팬아웃 대신. 프로젝트별 `.tesserae/graph.json`은 절대 변경되지 않습니다. 페더레이션은 쿼리 시간에 메모리에서 조립됩니다.

프로젝트가 연결되는 두 가지 방법:

- **Identity merge (항상 켜짐).** 프로젝트 전체에서 동일한 *엔티티* — 동일한 arXiv id, 저장소, 콘텐츠 해시 또는 코드 심볼 — 는 하나의 노드로 축소됩니다. 높은 정밀도, 결정론적, 임베딩 없음. 따라서 `research`에서 클립한 논문과 `work`에서 참조한 논문이 단일 인용된 노드가 됩니다.
- **Semantic links (기본값 켜짐, 옵트아웃 가능).** 다른 단어의 동일한 *아이디어* — 예: `work`의 캐싱 결정과 `research`의 캐시 논문 — 은 임베딩 기반 크로스 프로젝트 링크를 받으므로, 검색이 *관련* 개념뿐만 아니라 동일한 개념을 연결할 수 있습니다. 다운 가중치되어 identity 매치가 항상 퍼지 브리지를 능가합니다. identity만 사용하려면 `--no-semantic`을 전달합니다. 실제 임베딩 백엔드가 필요합니다 (`pip install tesserae[semantic]`); 없으면 깔끔하게 성능 저하되고 그렇게 표시됩니다.

링크 임계값 (`0.55`)과 브리지 가중치 (`0.5`)는 추측이 아닙니다 — precision/recall + swamping 평가에서 설정됩니다 (`evals/federation/`, CI에서 보호됨).

## 검사하기

- `tesserae federation status [aliases] [--semantic]` — 프로젝트별 노드 수, identity 병합, semantic 링크 수.
- `tesserae federation explain <node> [aliases]` — 노드가 프로젝트를 브리지하는 이유: identity 병합된 프로젝트와 semantic 링크 (유사성 및 대상 프로젝트 포함). 네임스페이스 id 또는 병합되지 않은 id를 수락합니다.

페더레이션된 semantic 링크는 `~/.tesserae/federation/`에서 캐시되며, 프로젝트 콘텐츠에 따라 키가 지정되어 프로젝트가 다시 컴파일될 때 캐시가 자동으로 무효화됩니다.

## 이 릴리스의 다른 사항

- **Chrome extension** — README는 이제 올바른 기본 엔드포인트 (`http://127.0.0.1:8765`, IPv4)를 문서화하여 배포된 확장 기본값과 일치합니다.

## v0.10.x에서 업그레이드

드롭인. 페더레이션은 쿼리별로 옵트인입니다 (`--scope federated`); 단일 프로젝트 사용은 변경되지 않습니다. semantic 브리징의 경우, `pip install tesserae[semantic]`을 실행합니다.
