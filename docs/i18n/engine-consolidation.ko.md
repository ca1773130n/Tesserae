# 자동 통합 — 엔진의 수면 주기

뇌는 휴식 중에 기억을 통합합니다. 당신이 자는 동안, 그날의 원시 경험은 재구성되고 압축되며 통합됩니다 — 최근의 크고 시끄러운 내용들이 지속적인 구조로 흡수됩니다. Tesserae의 엔진도 마찬가지입니다. 프로젝트가 **유휴 상태**에 들어가면, 항상 켜져 있는 데몬은 다음 편집을 기다리는 것을 멈추고 이미 알고 있는 것을 조용히 재구성합니다: 각 에이전트의 메모리를 재구성, 압축, 안전하게 잊어버리는 증류 패스를 실행합니다.

지금까지는 이 패스는 요청할 때만 실행되었습니다 — 메모리 부하 중 `tesserae refresh` 또는 명시적 `tesserae distill`. 엔진은 모든 파일과 세션 이벤트에서 다시 컴파일했지만 절대 자동으로 통합하지 않았습니다. **수면 주기**는 이 간격을 닫습니다: `tesserae engine`을 실행된 상태로 두면 휴식 중에 통합이 발생하며, 기억할 명령이 없습니다.

[계층화된 메모리](agent-memory.md) 시스템의 모든 것처럼, 이는 **옵트인하지 않으면 no-op**입니다 — 데몬은 유휴 상태에서 통합되지만, 그 아래의 증류는 `TESSERAE_AGENT_DISTILL`이 설정되었을 때만 작동합니다.

## 언제 실행되는가

전용 통합 스레드는 고정 **확인 간격**(기본값 30초)에서 깨어나며 단조 활동 시계에 대해 두 개의 독립적인 트리거를 평가합니다:

- **유휴 트리거.** 프로젝트가 최소 `--consolidate-idle` 초 동안 트리거 이벤트 또는 파이프라인 실행을 보지 않았습니다(기본값 **300s = 5분**). 이는 "휴식 중에 통합" 사례입니다 — 엔진이 당신이 작업을 멈추었다는 것을 알아차리고 잠시 동안 사용했습니다. **바닥**은 마지막 통합 이후를 방지하므로, 방금 조용해진 바쁜 프로젝트는 민감한 트리거에서 통합되지 않습니다. - **상한 트리거.** 최소 `--consolidate-every` 초가 마지막 통합 이후 경과했습니다, **활동과 관계없이**(기본값 **21600s = 6시간**). 이는 계속 바쁜 프로젝트가 조용한 순간을 얻지 못하고 주기적으로 통합되는 것을 보장합니다. `0`으로 설정하면 상한을 비활성화합니다 — 유휴가 유일한 트리거가 됩니다.

모든 편집, 세션 턴 또는 재컴파일은 활동 시계를 범프하므로, 유휴 창은 실제 휴식 중에만 경과합니다. 두 시계 모두 **단조**로우며, 절대 벽시계가 아니며, 어떤 아티팩트에도 지속되지 않습니다 — 통합 타이밍은 절대 바이트 결정성 그래프를 방해할 수 없습니다.

## 무엇이 실행되는가

각 실행은 `.tesserae/graph.json`에서 컴파일된 그래프를 로드하고(파일이 없으면 패스는 건너뜁니다) `tesserae refresh`가 사용하는 `maybe_distill_on_refresh` 진입점을 호출합니다. 그 함수는 **삼중 게이트**되며 에이전트별 오류에 대해 절대 발생하지 않습니다:

1. **옵트인 게이트** — `TESSERAE_AGENT_DISTILL=1` (또는 `config.json`의 `{"agent_distill": {"enabled": true}}`). 기본값은 꺼짐; 전체 주기는 안전한 no-op입니다.
2. **에이전트별 워터마크** — 발견 사항이 마지막 증류 이후 변경되지 않은 에이전트는 건너뜁니다.
3. **에이전트별 메모리 압력** — 증류되지 않은 발견 사항이 더 이상 컨텍스트 읽기 절반에 맞지 않는 에이전트만 통합됩니다(MemGPT 스타일 트리거).

따라서 통합이 일정에 *실행*되더라도, 옵트인하고 실제로 충분한 새 메모리를 축적한 에이전트에 대해서만 *작동*합니다. 증류가 생성하는 것은 [계층화된 에이전트 메모리](agent-memory.md)를 참조하세요.

## 안전 및 결정성

- **컴파일 게이트에서 실행.** 통합은 재컴파일과 동일한 잠금을 획득하므로 컴파일과 직렬화되고 **절대 겹치지 않습니다**. 대기 중인 컴파일은 진행 중인 통합을 기다리고 그 반대도 마찬가지입니다 — 그래프는 쓰기 중에 읽히지 않습니다.
- **데몬 루프로 절대 발생하지 않음.** 전체 패스는 래핑되며, 모든 오류는 로깅되고 스레드는 계속 루핑합니다. 실패한 통합은 절대 엔진을 내리지 않습니다.
- **게이트가 꺼진 상태에서는 no-op.** `TESSERAE_AGENT_DISTILL`이 설정되지 않으면 패스는 비용이 많이 드는 것을 로드하지 않고 즉시 반환하므로, 수면 주기를 켜두는 것은 실질적으로 비용이 없습니다.
- **결정성 아티팩트, 변경 없음.** 증류된 아티팩트는 입력이 주어지면 결정성을 유지합니다; 수면 주기는 증류가 실행되는 *시기*만 변경하며, 생성되는 *대상*은 변경하지 않습니다. 유휴 타이밍은 절대 `graph.json` 또는 증류된 계층으로 유출되지 않습니다.
- **깔끔한 종료.** 통합 스레드는 데몬의 중지 이벤트를 관찰하고 `Ctrl-C` / 종료에서 신속하게 종료합니다. 이는 장기 실행 모드 기능일 뿐입니다: `tesserae engine ... --once`는 절대 시작하지 않습니다.

## CLI 플래그

| 플래그 | 기본값 | 효과 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | 수면 주기 전체를 활성화 또는 비활성화합니다. 기본적으로 켜집니다(증류 게이트가 설정되지 않으면 no-op). |
| `--consolidate-idle SECONDS` | `300` | 휴식 창: 이 많은 초 동안 활동이 없으면 통합합니다. |
| `--consolidate-every SECONDS` | `21600` | 상한: 활동과 관계없이 최소한 이 자주 통합합니다. `0`은 상한을 비활성화합니다. |
| `--consolidate-check SECONDS` | `30` | 통합 스레드가 트리거를 재평가하기 위해 깨어나는 빈도입니다. |

## 플릿 동작(`--all`)

`tesserae engine --all`은 모든 등록된 프로젝트를 하나의 프로세스에서 새로 유지합니다. 각 프로젝트의 단위는 동일한 노브로 자체 통합 스레드를 가지며, 모든 단위는 하나의 플릿 전체 컴파일 게이트를 공유합니다 — 따라서 한 프로젝트의 통합은 전체 플릿에 걸쳐 컴파일과 직렬화되며, 절대 겹치지 않습니다.

## 작업 예

증류를 켜고 더 빠른 수면 주기로 엔진을 실행하려면 — 60초 유휴 후 통합하고, 무엇이든 최소 30분마다 통합합니다:

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine \
  --consolidate-idle 60 \
  --consolidate-every 1800 \
  --consolidate-check 15
```

편집기와 에이전트에서 평소처럼 작업하세요; 엔진은 보고, 디바운스하고, 모든 변경 사항을 다시 컴파일합니다. 1분 동안 멈추면 유휴 트리거가 발생합니다: 통합 스레드는 컴파일 게이트를 획득하고 메모리 압력 상태의 모든 에이전트를 증류합니다 — 재구성, 압축, 안전하게 잊어버림 — 그 후 다시 잠을 잡니다. 반 시간 마크를 지나 일시 중지 없이 작업을 계속하면 상한도 발생하므로, 무자비한 프로젝트도 통합됩니다.

엔진을 실행 상태로 유지하지만 통합을 수동 `tesserae distill` 실행으로 남겨두려면 `--no-consolidate`를 전달합니다. 유휴 상태에서는 실행하지만 고정 일정에서는 절대 실행하지 않으려면 `--consolidate-every 0`을 전달합니다.
