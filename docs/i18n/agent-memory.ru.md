Никто не помнит все — и контекстное окно агента не вмещает все.
Ответ Tesserae — это **многоуровневая база знаний**: каждый агент развивает собственную
память из собственных сеансов, эта память периодически **дистиллируется**
(организуется, сжимается, полируется, уточняется — и безопасно забывается),
и менеджеры видят только дистиллированный уровень своих отчетов. Менеджер менеджера
видит дополнительную свертку. Как в реальной организации, ни один читатель не нуждается
в полном архиве.

Все ниже является дополнительным и необязательным: проекты, которые никогда не запускают
`tesserae distill`, ведут себя точно так же, как раньше.

## Уровни

- **L0 — граф проекта** (`.tesserae/graph.json`). Неизменен, остается
  байт-идемпотентным. Структурный проход компиляции теперь создает один узел
  `Agent` на наблюдаемого агента и ребра `performed_by` из каждого сеанса —
  сырая атрибуция, нулевые затраты LLM.
- **L1 — один артефакт на агента** (`.tesserae/agents/<key>/distilled.graph.json`).
  Написано `tesserae distill`. Обычный файл графа ограничен **одним чтением 48k**,
  поэтому любой агент может загрузить всю свою дистиллированную память за один вызов.
- **L2 — свертки менеджеров.** При дистилляции агента, имеющего отчеты, свертываются L1 отчетов:
  дедубликация по происхождению, группировка по общим сырым доказательствам и сохранение
  лучшей заметки **дословно** — глубина повторного резюмирования LLM ограничена 1,
  поэтому резюме никогда не является переформулировкой резюме. Тот же проход рекурсирует
  на любую глубину организации.

## Идентификация агента

Агенты кодируются как `harness:account:role` — уровень роли, так что подагент-рецензент
(`reviewer`) и подагент-планировщик (`planner`) развивают *разные* навыки даже на одной машине.
Роли происходят из дескрипторов подагентов в расшифровках, затем из правил сопоставления
декларативного реестра, затем откатываются на `default`.

```bash
tesserae agents init         # сканировать сеансы, предложить .tesserae/agents/registry.json
tesserae agents list         # наблюдаемые ключи, ярлыки, родители, счетчики сеансов
tesserae agents set-parent claude-code:me:reviewer claude-code:me:manager
tesserae agents rename <old> <new>   # атомно мигрирует директорию артефактов + реестр
```

Работает без конфигурации: каждый наблюдаемый агент неявно докладывает в `org:root`,
и `agent="org"` дает плоский обзор команды без реестра.

## Дистилляция

```bash
tesserae distill                      # все агенты, листья сначала, менеджеры последними
tesserae distill --agent <key>        # один агент
tesserae distill --dry-run            # оценить вызовы LLM, ничего не писать
tesserae distill --max-llm-calls 50   # жесткий бюджет; ограниченные запуски сходятся при переза́пуске
tesserae distill --retry-fallbacks    # пересчитать кластеры, отступившие на резервные
tesserae distill --full               # игнорировать водяные знаки, перепроработать с нуля
```

Проход кластеризует выводы агента, суммирует каждый кластер (в белом списке цитирования
и проверен на верность) и создает дистиллированные заметки, чья идентичность —
**ключ происхождения** — хеш сырых доказательств L0 снизу, никогда не формулировка LLM.
Кеширование агрессивно и общеиспользуемо: неизменные входы пропускаются по водяным знакам,
растущие кластеры складываются постепенно, сбои провайдеров прерываются и производят
детерминированные структурные резервные варианты (помечены, повторяемы, никогда не кешируются
как успех).

Дистилляция — **дополнительна**: установите `TESSERAE_AGENT_DISTILL=1`
(или `{"agent_distill": {"enabled": true}}` в `config.json`). При включении `tesserae refresh`
также автоматически дистиллирует — но только агенты под *давлением памяти* (их недистиллированные
выводы больше не помещаются в половину чтения контекста), триггер консолидации в стиле MemGPT.

## Забывание — никогда удаление

- **Поглощение**: затухающий, низконадежный вывод, охватываемый дистиллированным
  высокого качества llm, складывается в него (`absorbed_refs`) и подавляется при
  чтении по умолчанию — но остается достижимым через `include_superseded` и `drill_down`.
- **Деградация**: все остальное в худшем случае падает с полного текста на строку
  названия+ссылки в заметке индекса агента. Сам по себе возраст никогда не делает
  знания невидимым.
- **Реестр**: каждое повышение/понижение/поглощение добавляется в реестр забывчивости
  и выводится `tesserae lint` (`AGENT_FORGET_LEDGER`), наряду с метрикой недостиллированного
  невыполненных работ на агента (`AGENT_UNDISTILLED_BACKLOG`).

## Чтение как агент — аргумент `agent=`

Каждый инструмент чтения графика MCP принимает `agent=`:

- **ключ рабочего** → собственный сырой опыт ∪ собственные дистиллированные заметки,
  предпочтительно дистиллированные (поглощенные сырые автоматически подавляются наложением,
  полученным при загрузке — ничего никогда не переписывается обратно в `graph.json`).
- **ключ менеджера** → федерация только L1 артефактов отчетов. Сырые выводы никогда
  не просачиваются вверх.
- **`org`** → все дистиллированные артефакты, без конфигурации.

Вспомогательные инструменты: `agent_view_explain` (члены + водяной знак
`distilled_through` устарелости — насколько старик опыт каждого отчета),
и `drill_down` (разрешить `member_refs` дистиллированной заметки обратно
к сырым доказательствам L0 со статусом живой/измененный/поглощенный/исчезнувший —
каждый вызов ведется в журнале аудита). `compile_context --multi-pool` резервирует
бюджеты для дистиллированных заметок и профилей опыта и помечает устаревшие или
резервные знания качества в выводе.

## Цикл роста

- **Привязность на агента**: режим агента `write_harness` выпускает директорию
  привязности на агента, чья конфигурация MCP достигает решенного представления
  агента, плюс страница миссии `purpose.md`, посеянная один раз, созданная из его
  профиля опыта.
- **Руководство на агента**: рулевое управление дистилляцией одного агента через
  `.tesserae/extraction-guidance-<key>.md`, наложенное на уровень проекта
  `.tesserae/distill-guidance.md`. Редактирование потока одного агента перепроизводит
  только этого агента.
- **Семантические мосты** (дополнительно): свяжите *связанные* дистиллированные
  с ребрами `shares_concept_with` в представлениях менеджера/организации — ребра,
  никогда не слияния.
- **Карты тем**: `agent_topics` сворачивает набор дистиллированных агента в
  детерминированный `topics.md` — оглавление агента.
- **Повышение подагента**: типизированные запуски подагента создают выводы под
  собственным ключом подагента, поэтому делегированная работа накапливается в
  навыках делегата.

## Гарантии детерминизма

Граф проекта остается байт-идемпотентным; дистиллированные артефакты детерминированы
при наличии (байты графа, реестр, каталог кеша, предыдущий артефакт, опции).
Время всегда — **часы корпуса** — самый новый момент в самих сеансах, рекурсивно
самый новый дочерний водяной знак для менеджеров — никогда стенные часы. Идентичность
узла не зависит от прозы LLM. Зонд lint отклоняет метаданные в форме временной метки/счетчика
на узлах уровня агента, потому что именно этот класс состояния раньше нарушал байт-идемпотентность.

Полное обоснование проекта: `docs/superpowers/specs/2026-07-19-layered-agent-kg.md`.
