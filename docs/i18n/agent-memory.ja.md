誰もがすべてを覚えているわけではありませんし、どのエージェントのコンテキストウィンドウもすべてを収めることができません。Tesserae の答えは**レイヤー化知識ベース**です。すべてのエージェントは自分のセッションから独自のメモリを成長させ、そのメモリは定期的に**蒸留**（整理、圧縮、磨く、精製——そして安全に忘れ）され、マネージャーは自分のレポートの蒸留済みレイヤーのみを見ます。マネージャーのマネージャーはさらなるロールアップを見ます。実際の組織のように、単一の読み手も完全なアーカイブが必要ではありません。

以下のすべてはオプトインで付加的です。`tesserae distill` を実行しないプロジェクトは以前とまったく同じように動作します。

## レイヤー

- **L0 — プロジェクトグラフ** (`.tesserae/graph.json`)。変更されない、依然としてバイト冪等です。コンパイルの構造パスは、観察されたエージェントごとに 1 つの `Agent` ノードを生成し、各セッションから `performed_by` エッジを生成します——生の帰属、LLM コストなし。
- **L1 — エージェントごと 1 つのアーティファクト** (`.tesserae/agents/<key>/distilled.graph.json`)。`tesserae distill` で書き込まれます。通常のグラフファイルは**単一の 48k 読み取り**に制限されているため、どのエージェントも単一の呼び出しで蒸留済みメモリ全体をロードできます。
- **L2 — マネージャーロールアップ。** レポートを持つエージェントを蒸留する場合、レポートの L1 をロールアップします。血統による重複排除、共有の生の証拠によるグループ化、最高のメモを**逐語的に**実行する——LLM 再要約の深さは 1 に制限されているため、要約は要約の言い換えになることはありません。同じパスは任意の組織の深さに再帰します。

## エージェント ID

エージェントは `harness:account:role`でキー付けされます——役割レベルなので、`reviewer` サブエージェントと `planner` サブエージェントは 1 台のマシンでも*異なる*専門知識を開発します。役割はトランスクリプト内のサブエージェント記述子から来て、次に宣言的レジストリマッチングルールから来て、最後に `default` にフォールバックします。

```bash
tesserae agents init         # セッションスキャン、.tesserae/agents/registry.json を提案
tesserae agents list         # 観察されたキー、ラベル、親、セッション数
tesserae agents set-parent claude-code:me:reviewer claude-code:me:manager
tesserae agents rename <old> <new>   # アーティファクトディレクトリ + レジストリをアトミックに移行
```

ゼロコンフィグが機能します。観察されたすべてのエージェントは暗黙的に `org:root` にレポートし、`agent="org"` はレジストリなしでフラットなチームの概要を提供します。

## 蒸留

```bash
tesserae distill                      # すべてのエージェント、葉優先、マネージャー最後
tesserae distill --agent <key>        # 1 つのエージェント
tesserae distill --dry-run            # LLM 呼び出しを推定、何も書き込まない
tesserae distill --max-llm-calls 50   # ハード予算；制限付き実行は再実行で収束
tesserae distill --retry-fallbacks    # フォールバックしたクラスターを再試行
tesserae distill --full               # ウォーターマークを無視、最初から再蒸留
```

パスはエージェントの検索結果をクラスター化し、各クラスターを要約し、蒸留済みメモを生成します。そのアイデンティティは**血統キー**——基礎となる生の L0 証拠のハッシュであり、LLM の表現ではありません。キャッシング は積極的で共有されています。変更されていない入力はウォーターマークスキップされ、成長するクラスターは段階的に折りたたまれ、プロバイダーの障害はサーキットブレークされて決定論的構造フォールバックを生成します（フラグが立てられ、再試行可能、成功としてキャッシュされない）。

蒸留は**オプトイン**です。`TESSERAE_AGENT_DISTILL=1` を設定します（または `config.json` で `{"agent_distill": {"enabled": true}}`）。有効な場合、`tesserae refresh` も自動的に蒸留します——ただし*メモリ圧力*下のエージェントのみ（蒸留されていない検索結果がコンテキスト読み取りの半分に収まらなくなった場合）、MemGPT スタイルの統合トリガー。

## 忘却 — 削除ではなく

- **吸収**：減衰、低信頼発見が llm 品質蒸留に覆われると、それに折りたたまれ（`absorbed_refs`）、デフォルト読み取りで抑制されます——ただし `include_superseded` と `drill_down` を通してアクセス可能です。
- **降格**：他のすべてては最悪の場合、完全な本体からエージェントのインデックスノートのタイトル+参照行に低下します。年齢だけでは知識が見えなくなることはありません。
- **台帳**：すべての昇格/降格/吸収は忘却台帳に追加され、`tesserae lint` で表示されます（`AGENT_FORGET_LEDGER`）。また、エージェントごとの蒸留されていないバックログメトリック（`AGENT_UNDISTILLED_BACKLOG`）。

## エージェントとして読み取り — `agent=` 引数

すべてのグラフ読み取り MCP ツールは `agent=` を受け入れます。

- **ワーカーキー** → 独自の生の経験 ∪ 独自の蒸留済みメモ、蒸留済み優先（吸収された生は読み込み時に派生オーバーレイで自動抑制——何も `graph.json` に書き戻されない）。
- **マネージャーキー** → レポートの L1 アーティファクトのみの連合。生の検索結果は上方に漏らされることはありません。
- **`org`** → すべての蒸留済みアーティファクト、ゼロコンフィグ。

サポートツール：`agent_view_explain`（メンバー + `distilled_through` 陳腐ウォーターマーク——各レポートの専門知識がどの程度古いか）、および `drill_down`（蒸留メモの `member_refs` を生の L0 証拠に解決。活気のある/変更された/吸収された/消失した状態——各呼び出しは監査ログ）。`compile_context --multi-pool` は蒸留メモと専門知識プロファイルの予算スロットを予約し、出力内の陳腐またはフォールバック品質の知識にラベルを付けます。

## 成長ループ

- **エージェントごとのハーネス**：`write_harness` エージェントモードは、そのエージェントの解決されたビューに到達する MCP 構成を含むエージェントごとのハーネスディレクトリを生成します。さらに一度だけシードされた `purpose.md` ミッションページが、その専門知識プロファイルから生成されます。
- **エージェント別ガイダンス**：`.tesserae/extraction-guidance-<key>.md` を通じて、プロジェクトレベル `.tesserae/distill-guidance.md` の上に層を重ね、1 つのエージェントの蒸留を操舵します。1 つのエージェントのストリームを編集すると、そのエージェントのみが再蒸留されます。
- **セマンティックブリッジ**（オプトイン）：マネージャー/組織ビューで `shares_concept_with` エッジで関連する蒸留済みをリンクします——エッジ、マージなし。
- **トピックマップ**：`agent_topics` はエージェントの蒸留セットを決定論的 `topics.md` に巻き込みます——エージェントの目次。
- **サブエージェント昇格**：型付きサブエージェント実行はサブエージェント独自のキーの下に検索結果を生成するため、委派された作業は委派者の専門知識に蓄積されます。

## 決定論的保証

プロジェクトグラフはバイト冪等を維持します。蒸留済みアーティファクトは（グラフバイト、レジストリ、キャッシュディレクトリ、以前のアーティファクト、オプション）が与えられると決定論的です。時間は常に**コーパスクロック**です——セッション自体の最新瞬間、再帰的にマネージャーの場合は最新の子ウォーターマーク——壁時計ではありません。ノード ID は LLM の散文に依存しません。Lint プローブは、エージェント層ノードのタイムスタンプ/カウンタ形状のメタデータを拒否します。正確にその種の状態がバイト冪等性を以前破ったから。

完全な設計の根拠：`docs/superpowers/specs/2026-07-19-layered-agent-kg.md`。
