# 自动合并 — 引擎的睡眠周期

大脑在休息时会整合记忆。当你睡觉时，一天的原始经验会被重新组织、压缩和集成——最近的、嘈杂的东西会被折叠成持久的结构。Tesserae的引擎也做同样的事情。当一个项目变得**空闲**时，始终运行的守护进程停止等待下一次编辑，并花费安静的时间重新组织它已经知道的东西：它**压缩并遗忘**最近的嘈杂记忆，让没有人检索过的知识**因不使用而褪色**，以及**发现生存下来的东西之间的新连接**。

到目前为止，该通道仅在你要求时运行——在内存压力下使用`tesserae refresh`，或显式`tesserae distill`。引擎在每个文件和会话事件上重新编译，但从不自动合并。**睡眠周期**关闭了这个间隙：让`tesserae engine`继续运行，合并会在休息期间发生，没有需要记住的命令。

像[分层记忆](agent-memory.zh.md)系统中的所有东西一样，这是**除非你选择加入，否则无操作** ——守护进程在空闲时合并，但其下的蒸馏仅在设置`TESSERAE_AGENT_DISTILL`时才起作用。

## 何时触发

专用合并线程在固定**检查间隔**（默认30秒）醒来，并根据单调活动时钟评估两个独立触发器：

- **空闲触发器。** 项目在至少`--consolidate-idle`秒内没有看到触发事件或管道运行（默认**300s = 5分钟**）。这是"休息时合并"的情况——引擎注意到你停止了工作，并利用了暂停。自上次合并以来的**下限**可防止抖动，因此刚刚变得安静的繁忙项目不会在敏感的触发器上合并。
- **上限触发器。** 自上次合并以来**无论活动如何**至少已经过了`--consolidate-every`秒（默认**21600s = 6h**）。这保证了持续繁忙的项目仍会定期合并，而不是永远没有安静的时刻。将其设置为`0`会禁用上限——那么空闲是唯一的触发器。

每次编辑、会话轮次或重新编译都会增加活动时钟，所以空闲窗口仅在真正的休息期间经过。两个时钟都是**单调的**，永不壁钟，也永不持久化为任何工件——合并计时永远无法扰乱字节确定性图。

## 运行内容——五个操作

每次触发都会从`.tesserae/graph.json`加载编译的图（如果文件不存在，跳过通道），并按顺序运行五个合并操作。总的来说，它们反映了休息的大脑所做的事情：压缩最近的嘈杂东西，让从未重新访问过的东西褪色，在生存下来的东西之间进行新的关联，并进行排练——现在花费一些精力，而没人在等待，在读者接下来想要的描述上。

### 1. 压缩/遗忘——蒸馏

调用`tesserae refresh`用来重新组织、压缩和安全遗忘每个代理记忆的相同`maybe_distill_on_refresh`入口点。该函数在内部是**三重门控**的，永远不会因每个代理的失败而上升：

1. **选择加入门** ——`TESSERAE_AGENT_DISTILL=1`（或`config.json`中的`{"agent_distill": {"enabled": true}}`）。默认关闭；整个周期是安全的无操作，直到你设置它。
2. **每个代理的水位标记** ——自上次蒸馏以来发现没有改变的代理会被跳过。
3. **每个代理的内存压力** ——仅当未蒸馏的发现不再适合上下文读取的一半时，代理才会被合并（MemGPT风格的触发）。

所以即使合并在计划上**触发**，它也仅对选择加入并实际积累了足够新内存的代理**有效**。有关蒸馏产生的内容，请参见[分层代理内存](agent-memory.zh.md)。

### 2. 因不使用而遗忘——检索上的LRU衰减，而非仅年龄

蒸馏的衰减不再仅由创建年龄驱动。每个读取表面都会记录对其返回的发现的访问——`last_accessed_at`和`access_count`——到**`node_memory`侧车**中，永不进入`graph.json`。在蒸馏通道计算衰减之前，它将该实时访问状态合并到其工作视图中，因此自创建以来未检索过的发现会衰减并有资格被吸收或降级，而最近读取的发现则保持新鲜，无论其年龄。这是**检索最近性**，这是应用于记忆的LRU（最近最少使用）直觉：你持续提取的知识保留；没有人请求的知识首先褪色。空的侧车完全准确地重现了旧的仅年龄的行为，因此完全向后兼容。

### 3. 关联——发现新连接

最终操作寻找生存者之间的*新*关系。它嵌入蒸馏的笔记并链接意义接近的对——**嵌入门控**，因此仅当配置了真实嵌入后端时才运行（哈希存根被跳过，永不产生噪声链接）。发现在项目内和**跨代理**运行，它找到的连接被铸造为携带`federation_semantic`标记的`shares_concept_with`边。

至关重要的是，这些发现的边被写入`.tesserae`下的**侧车覆盖层**，*永远不会*进入`graph.json`。覆盖层**跨周期累积**——每个关联通道对先前通道发现的内容进行去重并扩展。在读取时（查询、PPR扩展、联合视图），覆盖层仅在内存中**合并到图中**，完全像每个代理视图覆盖层一样——所以字节确定性`graph.json`永远不会被接触。整个操作被包装且永不上升到守护进程循环中。

### 4. 总结——预热代理下降的社区缓存

`graph_map`为每个作用域提供一张卡片。一个其汇总缓存为冷的作用域会得到一个确定性的*结构性*卡片——一个成员计数和顶部成员列表——第一个访问它的代理需要支付一个同步LLM调用来获取散文。此操作将成本从读取路径转移开：在每个tick预算内(`--summarize-budget`，默认25；`0`禁用它)，它为最可能接下来被访问的作用域实现总结，以便访问找到一个已预热的缓存。

候选按**需求**排列——作用域自己从`graph_map`遍历加上其成员的访问计数的访问增加——然后按大小、度数和级别，以总序，所以两个tick在相同状态下会选择相同的作用域。一个已经预热且摘要仍然有效的缓存不花费预算；仅冷物化才花费。没有LLM客户端，整个操作是无操作的。

### 5. 摘要——预热宪章的领域摘要

相同的形状，一个轴在上面：候选是[宪章](../README.md)的活跃领域，而不是树状图的社区。一个冷领域呈现为一个结构性卡片，无论在何处出现——在`graph_map`中、在`charter_route`的评分语料库中、在lint的`CHARTER_FALLBACK`普查中——所以此通道是使特许机构散文的原因。

预算是它自己的开关(`--brief-budget`，默认8；`0`禁用它)，故意与`--summarize-budget`分离，使两个操作都不会使另一个饥饿，并故意更小：宪章的**分部**是`graph_map`作为其根卡片集提供的，并且仅有少数几个，所以8在第一个空闲tick时预热入口点，更深的层在其后面以每个tick8跟随。

顺序是**广度优先**，不是需求排列。一个领域的成员集包含其整个子树，所以父母的需求总是支配其孩子的，没有领域在其祖先之前预热。这是故意的：代理从根下降，所以粗卡片是首先读取的，也是值得有散文的。访问计数为既不包含另一个的领域排序，而活跃的**分部**——没有活跃父母的领域，与`graph_map`的根使用的规则相同，不是`tier == 1`——在所有其他之前排序。

一些领域永不花费预算插槽，因为插槽意味着是LLM调用：已退役的域、`intake`普查（它没有主题，所以从其数千个成员中的25个编写的摘要将是不到百分之一的自信描述）、其成员已离开图的领域，以及任何已经预热的。并且一个其物化**失败**的领域——最常见是因为其散文没有引用任何其子域而被拒绝——是保持关闭的加倍数量的tick，而不是以相同排列永远重试，所以永久无法预热的领域不能保持一个可预热领域可以使用的插槽。

### 每小时花费的成本

两个预算每**tick**，并且tick最多每`--consolidate-idle`窗口触发一次。在默认值：

| | 每tick | 每小时tick数（`--consolidate-idle 300`时） | 上限 |
|---|---|---|---|
| 总结 | 25 | 12 | 300 个LLM调用/小时 |
| 摘要 | 8 | 12 | 96 个LLM调用/小时 |
| **合计** | **33** | **12** | **396 个LLM调用/小时** |

这是一个**仅在缓存冷时达到的上限**，它衰减到**零**：一个预热的、摘要有效的缓存花费无调用和无插槽，所以一旦项目的作用域和领域被总结，睡眠周期花费零直到图改变。设置任一预算为`0`以关闭其操作，或提高`--consolidate-idle`以使tick更少见。

**预算是上限，不是配额。** 两个预算在一个tick内*按顺序*花费，tick在整个通道中保持编译门——所以在默认值下，tick可以在33个连续的LLM调用中占用门。文件保存落在tick中期时，必须等待每个剩余调用完成后其管道运行才能启动，使用CLI提供程序时这是分钟级的。两个预热循环现在在每个迭代的顶部检查管道运行是否被阻塞在门上，如果是则**放弃其剩余预算**：

- 检查发生在调用*之间*，从不在调用中途，所以已经在进行中的运行总是完成，管道最多等待那一个调用；
- 提前停止是无损的。预热是幂等的，所以tick从未到达的作用域或领域在下一个仍然是冷的，排名相同——没有任何东西被丢失、破坏或支付两次；
- 被遗弃的领域不承受**后退打击**。打击是针对其预热尝试消耗了一个调用并失败的领域；被遗弃的领域从未被尝试过，所以对其计费会因为不相关的文件被保存而将可预热的领域推下队列；
- 它被报告，不是沉默的。tick的摘要字典获得`abandoned`和`unspent`（有多少预算插槽未使用），因此守护进程日志区分"为管道让路"与"没有可预热的东西"。

**为什么在这里而不在编译中。** 一个摘要花费一个LLM调用。在编译期间铸造它们会对每个领域的每个编译放置一个调用，而编译是该项目保持确定性和廉价的路径。在读取时懒惰铸造它们意味着`graph_map`调用可能阻塞在模型上。空闲睡眠周期是剩下的唯一地方，可以花费没人在等待的调用。

## 安全性和确定性

- **在整个通道期间都在编译门下运行。** 合并获取与重新编译相同的锁，因此与编译**序列化**且**从不重叠**。待处理的编译等待进行中的合并，反之亦然——图永远不会在写入中途被读取。门故意**不**在LLM调用之间释放：tick中的每个操作都读取tick加载的同一个`graph.json`，所以在通道中途交还门会让编译重写图，并使早期在通道中编写的摘要描述与晚期编写的不同的图。这就是为什么等待管道的tick会**放弃其剩余预算**而不是交还编译门——它用投机性预热换取延迟，永不用一致性换取延迟。
- **永不上升到守护进程循环。** 整个通道都被包装；任何错误都被记录，线程继续循环。失败的合并永远不会使引擎关闭。
- **当门关闭时无操作。** 未设置`TESSERAE_AGENT_DISTILL`时，通道不加载任何昂贵的东西并立即返回，因此让睡眠周期保持开启本质上没有成本。
- **确定性工件，不变。** 蒸馏的工件给定其输入时保持确定性；睡眠周期仅改变蒸馏何时**运行**，永远不改变它**产生**的内容。空闲时间永不泄露到`graph.json`或任何蒸馏层。
- **`graph.json`保持字节幂等。** 此处的任何操作都不会写入它。访问状态存在于`node_memory`侧车中，发现的连接在累积覆盖中，以及总结和领域摘要都在`community_summaries`缓存中——所有都在`.tesserae`下，所有都仅在读取时在内存中合并。权威图字节不受检索历史、发现链接或预热散文的影响。总结和摘要是**缓存，不是知识**：删除缓存目录使下一个读者花费一个结构性卡片，无其他。
- **干净关闭。** 合并线程观察守护进程的停止事件，并在`Ctrl-C` /关闭时迅速退出。它仅是长运行模式特性：`tesserae engine ... --once`永不启动它。

## CLI标志

| 标志 | 默认值 | 效果 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | 完全启用或禁用睡眠周期。默认启用（如果未设置蒸馏门，则无操作）。 |
| `--consolidate-idle SECONDS` | `300` | 休息窗口：在这许多秒无活动后合并。 |
| `--consolidate-every SECONDS` | `21600` | 上限：无论活动如何，至少这么频繁地合并。`0`禁用上限。 |
| `--consolidate-check SECONDS` | `30` | 合并线程唤醒以重新评估触发器的频率。 |
| `--summarize-budget N` | `25` | 每tick最多花费的LLM调用次数来预热社区总结。`0`禁用SUMMARIZE操作。 |
| `--brief-budget N` | `8` | 每tick最多花费的LLM调用次数来预热宪章领域摘要。`0`禁用BRIEF操作。 |

## 舰队行为(`--all`)

`tesserae engine --all`在一个进程中保持每个注册项目的最新状态。每个项目单元获得自己的合并线程，具有相同的旋钮，所有单元共享一个舰队范围的编译门——因此一个项目的合并与整个舰队的编译序列化，从不重叠任何一个。

## 完成的示例

打开蒸馏，然后使用更快的睡眠周期运行引擎以获得演示——在60秒空闲后合并，无论如何至少每30分钟：

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine \
  --consolidate-idle 60 \
  --consolidate-every 1800 \
  --consolidate-check 15
```

像往常一样在编辑器和代理中工作；引擎观察、防抖并重新编译每项更改。停止一分钟，空闲触发器触发：合并线程获取编译门并蒸馏任何内存压力下的代理——重新组织、压缩和安全遗忘——然后回到睡眠。继续工作超过半小时标记，无需暂停，上限也触发，因此无情的项目仍会合并。

要保持引擎运行但将合并留给手动`tesserae distill`运行，请传递`--no-consolidate`。要让它在空闲时运行但从不在固定计划上，请传递`--consolidate-every 0`。
