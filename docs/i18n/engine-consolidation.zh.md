# 自动整合 — 引擎的睡眠周期

大脑在休息时整合记忆。当您睡觉时，那一天的原始经历被重新组织、压缩和整合 — 最近的、嘈杂的东西被折叠成持久的结构。Tesserae 的引擎也是如此。当项目**空闲**时，始终运行的守护程序停止等待下一次编辑，并花费安静时间重新组织它已经知道的内容：它运行一个蒸馏通道，重新组织、压缩并安全地遗忘每个代理的记忆。

到目前为止，该通道仅在您要求时运行 — 在内存压力下 `tesserae refresh`，或显式 `tesserae distill`。引擎在每个文件和会话事件上重新编译，但从不自动整合。**睡眠周期**弥补了这个差距：让 `tesserae engine` 运行，整合在休息期间发生，没有要记住的命令。

像[分层记忆](agent-memory.md)系统中的一切一样，这是**除非您选择加入否则为 no-op** — 守护程序在空闲时整合，但下面的蒸馏仅在设置 `TESSERAE_AGENT_DISTILL` 时才起作用。

## 何时触发

专用的整合线程以固定的**检查间隔**（默认 30 秒）唤醒，并针对单调活动时钟评估两个独立的触发器：

- **空闲触发器。** 项目在至少 `--consolidate-idle` 秒内未看到触发事件或管道运行（默认 **300s = 5 分钟**）。这是"休息时整合"的情况 — 引擎注意到您停止工作，并利用间隙。**下限**因上次整合而阻止抖动，因此刚刚变安静的繁忙项目不会在敏感触发上整合。 - **上限触发器。** 自上次整合以来至少 `--consolidate-every` 秒已经过去，**无论活动如何**（默认 **21600s = 6 小时**）。这保证持续繁忙的项目仍然周期性地整合，而不是永远没有安静的时刻。将其设置为 `0` 禁用上限 — 那么空闲是唯一的触发器。

每次编辑、会话轮次或重新编译都会增加活动时钟，因此空闲窗口仅在真正的休息期间经过。两个时钟都是**单调的**，永远不是墙钟，永远不会持久化到任何工件中 — 整合计时永远无法扰乱字节确定性图表。

## 运行什么

每次触发从 `.tesserae/graph.json` 加载已编译的图形（如果文件不存在，通道被跳过），并调用 `tesserae refresh` 使用的相同 `maybe_distill_on_refresh` 入点。该函数是**三重门控**内部，永远不会为每个代理故障引发：

1. **选择加入门控** — `TESSERAE_AGENT_DISTILL=1`（或 `config.json` 中的 `{"agent_distill": {"enabled": true}}`）。默认关闭；整个周期是安全的 no-op，直到您设置它。
2. **每个代理水位线** — 自上次蒸馏以来发现未改变的代理被跳过。
3. **每个代理内存压力** — 仅整合其未蒸馏发现不再适合上下文读取一半的代理（MemGPT 风格触发器）。

因此，即使整合在时间表上*触发*，它也仅对已选择加入且实际上积累了足够新记忆以保证的代理*起作用*。有关蒸馏产生的内容，请参见[分层代理记忆](agent-memory.md)。

## 安全和确定性

- **在编译门下运行。** 整合获得与重新编译相同的锁，因此与编译序列化，**永远不重叠一个**。挂起的编译等待进行中的整合，反之亦然 — 图在写时从不被读。
- **永远不会进入守护程序循环。** 整个通道被包装；任何错误都被记录，线程继续循环。失败的整合永远不会导致引擎崩溃。
- **门关闭时为 no-op。** 未设置 `TESSERAE_AGENT_DISTILL` 时，通道不加载任何昂贵内容并立即返回，因此让睡眠周期运行基本上不花费任何成本。
- **确定性工件，不变。** 蒸馏的工件在给定其输入时保持确定性；睡眠周期仅改变*何时*蒸馏运行，从不改变*它*产生的。空闲计时永远不会泄露到 `graph.json` 或任何蒸馏层。
- **干净关闭。** 整合线程观察守护程序的停止事件，并在 `Ctrl-C` / 关闭时及时退出。它仅是长运行模式功能：`tesserae engine ... --once` 永远不启动它。

## CLI 标志

| 标志 | 默认值 | 效果 |
|---|---|---|
| `--consolidate` / `--no-consolidate` | on | 启用或禁用整个睡眠周期。默认启用（不设置蒸馏门时为 no-op）。 |
| `--consolidate-idle SECONDS` | `300` | 休息窗口：在此多秒无活动后整合。 |
| `--consolidate-every SECONDS` | `21600` | 上限：无论活动如何至少这么经常整合。`0` 禁用上限。 |
| `--consolidate-check SECONDS` | `30` | 整合线程醒来重新评估触发器的频率。 |

## 舰队行为（`--all`）

`tesserae engine --all` 在一个进程中保持每个注册项目的新状态。每个项目的单位获得自己的整合线程，具有相同的旋钮，所有单位共享一个舰队范围的编译门 — 因此一个项目的整合与整个舰队的编译序列化，永远不重叠任何一个。

## 工作示例

打开蒸馏，然后以更快的睡眠周期运行引擎进行演示 — 60 秒空闲后整合，无论如何至少每 30 分钟整合：

```bash
export TESSERAE_AGENT_DISTILL=1
tesserae engine \
  --consolidate-idle 60 \
  --consolidate-every 1800 \
  --consolidate-check 15
```

像往常一样在编辑器和代理中工作；引擎监视、去抖动和重新编译每个更改。停止一分钟，空闲触发器触发：整合线程获得编译门并蒸馏任何内存压力下的代理 — 重新组织、压缩、安全遗忘 — 然后回到睡眠。继续工作超过半小时标记，无需暂停，上限也会触发，因此无情的项目仍然整合。

要保持引擎运行但将整合留给手动 `tesserae distill` 运行，请传递 `--no-consolidate`。要让它在空闲时运行但从不按固定时间表运行，请传递 `--consolidate-every 0`。
