Released **2026-09-07** · [PyPI](https://pypi.org/project/tesserae/0.39.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.1) · `pip install --upgrade tesserae==0.39.1`

Point the `claude` provider at a gateway of your own — a base URL, a bearer token, a config dir that is not `~/.claude` — and Tesserae kept spending the CLI's default account anyway. Not one bug: one per entry point.

## What happened

`ClaudeCLIJsonClient` had no way to receive `llm_auth_token`, so the CLI reached the gateway without a credential and fell back to whatever login its config dir held. `tesserae ask`, `query --llm`, the activity summaries and the daemon built their client without the configured `llm_claude_config_dirs`, rotating over every `~/.claude*` on the box while `compile` obeyed the list. `init --yes` and the wizard accepted `--llm-auth-token` and `--llm-api-style` and dropped both before writing the plan. The clip TL;DR shelled out to `claude` on its own. And two keys older wizards wrote, `llm_claude_config_dir` and `extraction.claude_config_dir`, were read by nothing, so the dir chosen at setup never counted.

## What changed

- **Every entry point hands the CLI the endpoint and the token.** The builders thread `llm_base_url`, `llm_api_key` and `llm_auth_token` together, and the child process sees them as `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`. Verified against a real `claude -p` with an empty config dir: the request hit `/v1/messages` with the bearer token, no `claude /login` involved.
- **The configured config dirs are honoured everywhere, `~` included.** The rotating client reads `llm_claude_config_dirs` from the resolved settings; a configured dir outside `~/.claude*` counts as usable; the legacy singular key and `extraction.claude_config_dir` rank as project config below the plural key; and `config status` names the layer that won instead of printing `default`.
- **`init`, `setup` and the wizard keep every knob.** `--llm-auth-token` and `--llm-api-style` are persisted on the wizard path too, and under the `claude` provider the wizard now asks for an endpoint and a bearer token.
- **Doctor and the clip TL;DR follow the same configuration.** `llm_login` reports a routed CLI as needing no login; the clip summary goes through `build_default_json_client` with the project's settings instead of its own `claude` calls.

## Upgrade

If an older wizard left `extraction.claude_config_dir` in your `.tesserae/config.json`, that dir is honoured from now on. Run `tesserae config status --no-ping` to see which layer won; set `llm_claude_config_dirs` to change it. Nothing else to migrate.
