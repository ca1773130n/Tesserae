Released **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.0) · `pip install --upgrade tesserae==0.41.0`

Tesserae describes itself as an engine that pulls in knowledge on its own
rather than waiting to be told. Until this release it never pulled anything.
Every trigger source the daemon had waited for a local file to change: the
filesystem watcher, the vault watcher, the session tailer, and the site server
added in v0.40.0. They reconstruct what you already put on disk.

## What changed

- **`tesserae engine --proactive` fetches.** It polls the feeds listed in a
  project's `proactive_sources`, pulls in documents it has never seen, and
  hands them to the same debounce and compile path as any other new file. RSS
  and Atom both work, and a URL that is not a feed is treated as the document
  itself and ingested once.
- **It is off by default, and stays cheap.** This is the first thing in
  Tesserae that spends without a person at the keyboard, so `--proactive` is
  opt-in, refused alongside `--once`, `--harvest-only` and `--all`, and
  budgeted at five new documents per poll. The poller waits before its first
  tick, so the log line saying what it is about to do arrives first.
- **Nothing is fetched twice.** A ledger beside the graph records every URL.
  One that Tesserae cannot read, such as a PDF-only link, is recorded as
  refused rather than retried every hour ahead of entries that would have
  worked. A timeout is not a verdict about a document and is never recorded, so
  transport failures retry.
- **Feeds are parsed defensively.** This is the only place Tesserae parses XML
  from a URL someone else controls, so a feed that declares a DTD is refused
  outright. That removes entity-expansion and external-entity attacks together,
  and a real feed has no use for one.
- **`tesserae sources add <url>`** adds a feed, the same verb that adds a
  directory. Where a graph's knowledge comes from is one question, so it is one
  command; `sources list` labels each entry.
- **`tesserae completion bash|zsh|fish`** prints a shell completion script,
  generated from the real command tree so it cannot drift from the CLI. The
  generator immediately caught a stale line in the help that had advertised
  three of `sessions`' five subcommands.
- **A mistyped command suggests the right one.** `tesserae complie` points at
  `compile`, and a subcommand typed without its group, like `sync`, names both
  groups that have one. A bare group name such as `tesserae vault` now prints
  that group's help instead of an argparse error about a missing argument.
- **`write_sessions` will not infer who owns a store.** Its `producer`
  argument defaulted to empty, which means whole-store authority, so the
  destructive reading was the one you got by not passing anything. It is now
  required. Whole-store authority is still available and is spelled
  `producer=""`, which reads as a decision rather than an omission.

## Upgrade

Nothing to migrate. Proactive ingestion does nothing until you add a feed and
pass `--proactive`, and every other change is additive. The one breaking
change is for code that calls `write_sessions` directly: pass `producer=`. Every
caller inside Tesserae already did.
