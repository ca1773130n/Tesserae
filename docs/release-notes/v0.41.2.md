Released **2026-09-12** · [PyPI](https://pypi.org/project/tesserae/0.41.2/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.2) · `pip install --upgrade tesserae==0.41.2`

Every command was audited by running it. Of 42 candidate defects, 31 survived
reproduction and an adversarial second opinion. This release closes the twelve
most serious: five that reported success for work they had not done, five that
destroyed data, one flag that was ignored, and one left alone on purpose.

## Reported success for work they did not do

- **A compile over paths holding no markdown is refused.** `tesserae compile
  README.txt` — a real file with the wrong suffix — rebuilt the graph from
  nothing, replaced it with an empty one, and exited 0. The refusal comes
  before any write, so the graph is still there when you read it. Paths now
  resolve against `--project` rather than the working directory.
- **`code ingest` refuses a path that is not there**, instead of writing an
  empty code graph over a real one and reporting success.
- **`query` on something that is not a project is an error.** It answered "No
  matches" with exit 0, which is what a real search that found nothing looks
  like, so a typo in `--project` read as an empty corpus.
- **`lint` says when it cannot read the graph.** It swallowed the parse error,
  ran every check over an empty graph, and reported "No findings. Wiki is
  clean." with exit 0 about a `graph.json` that cannot be parsed at all.
- **`engine --once` exits non-zero when the compile failed.** It returned 0
  whatever happened, so continuous integration saw green for a pipeline that
  raised. The same bug is why a fleet printed `2/2 units ok` for a batch in
  which a project failed: it reads each unit's exit code.

## Destroyed data

- **A machine-wide config that cannot be parsed is no longer replaced.** Every
  writer merges onto an empty dictionary when the file is unreadable, and then
  wrote the result, so one stray comma cost the stored clip token and every
  saved key. Reading past a corrupt file is still fine; writing over one is not.
- **`projects register` no longer re-initialises a project that was never compiled.**
  That replaced its configuration and lost its sources, name and
  provider. The guard's own comment already promised this; it tested for the
  wrong file.
- **`sessions discover --import` keeps records from a root it could not read.**
  A `--root` that is not on disk was still handed to the prune scope, so the
  import deleted everything harvested from it while having learned nothing
  about it. An unmounted disk was enough.
- **`vault sync` saves the override it says it applied.** It reported the edit,
  wrote only the vault, and the next run put your change back the way it was.
- **`vault export` keeps an orphan page that holds your notes** — exactly what
  `vault prune` already refuses to delete. The two disagreed, and the silent
  one ran on every export.

## Ignored

- **`engine --all --harvest-only` no longer compiles.** The flag reached a
  single project and was dropped in fleet mode, which is the shape it was
  written for: several machines sharing a directory, each reading what only it
  can see, one of them compiling.

## Left alone on purpose

`lint --fix-trivial` lists the findings it just repaired. That reads as "here
is what I fixed", a test pins it, and it is not a defect. It is named here
because the audit raised it and the answer is no.

## Upgrade

Nothing to migrate. Commands that used to exit 0 while doing nothing useful now
exit 2 and say why, so a script that depended on the silence will start
reporting failures it was already having.
