Released **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.6/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.6) · `pip install --upgrade tesserae==0.41.6`

A compile runs on the engine's event-loop thread, and stop signals were
delivered through that loop, so Ctrl-C or SIGTERM sat unanswered until the
compile ended. Shutdown then ran one more compile for whatever had piled up
behind it. This project's own engine log shows two signals followed by a final
compile over 4,740 paths.

## What changed

- **A second signal stops the engine.** The first still finishes the work in
  hand, and now says so: `signal again to stop now`. A second signal raises in
  the main thread whatever it is running, so the engine leaves mid-compile, with
  its pidfile removed and the conventional exit status. Nothing is lost — the
  next start's compile finds the changed sources through the manifest differ.
- **A stop no longer leaves the LLM behind.** The CLI agent runs in its own
  session, so a terminal Ctrl-C never reaches it, and only a timeout killed it.
  Any other way out of the wait left `claude -p` running, and billing, after
  the process that asked for it was gone. Its process group is now killed
  whichever way the wait ends. This covers Ctrl-C during a plain `tesserae
  compile` too.

## Upgrade

Nothing to migrate. Restart a running engine to pick this up. Fleet mode
(`engine --all`) still has the one-signal behaviour.
