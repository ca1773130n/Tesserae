Released **2026-09-17** · [PyPI](https://pypi.org/project/tesserae/0.41.4/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.4) · `pip install --upgrade tesserae==0.41.4`

`engine --serve` and `engine --proactive` shipped with unit tests but had never
been run end to end on a real machine. Running them found two defects, both in
how the engine starts and what triggers a compile. `--proactive` itself worked.

## What changed

- **The engine starts serving at once.** On its first run in a project, the
  session tailer reads every Codex transcript on the machine to find the ones
  that belong to the project. That read ran before anything else started. On a
  machine with 15 GB of transcripts, `engine --serve` answered no requests for
  344 seconds and ignored SIGTERM for as long, so a supervisor had to kill it,
  which left a stale pidfile. The read now runs on its own thread.
- **A compile no longer schedules another compile.** Every compile rewrites the
  Obsidian vault, and the vault watcher took those writes for a user edit. It
  queued a full recompile each time, even after logging `applied (no changes)`.
  One document edit ran three compiles, two of them full. The engine now
  recompiles only when a vault edit changed the graph.

## Upgrade

Nothing to migrate. If the engine is running, restart it: a running process
keeps the old code.
