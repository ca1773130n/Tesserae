Released **2026-08-30** · [PyPI](https://pypi.org/project/tesserae/0.36.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.36.0) · `pip install --upgrade tesserae==0.36.0`

This release is two days of measurement on the compiled graph. Every number is here, and the harness that produced it is in the repository.

## One anchor per document

Chunked extraction was minting one document anchor per chunk — 9.4 per paper — and the retriever hands each anchor the whole source text, so a single paper could fill all ten slots of a top-k. Each piece's anchor now points at the first piece's before the merge, and a cited document listed earlier is no longer mistaken for the document. Recompiling the same 148 papers on the same cache hits took document recall@10 from **0.550 → 0.652**.

A second defect of the same root: the graph kept two anchor nodes per session, so document-first search's ten slots held four sessions. One anchor per document is listed now and the remaining slots are filled — LongMemEval recall@10 **0.867 → 0.891**.

## One name is one entity, and facts are read through a node too

`PDB` was a Benchmark in one paper and a Dataset in another, and every consumer that resolves by name refused the ambiguity. All three merge passes let it through. Same names now merge across documents, across the research-entity types. And `verify_claim` reads facts the extractor wrote through a Result node — `S reports_result R, R evaluated_on D`. Of 426 stated relations, correct **117 → 167**; fabricated SUPPORTED across 426 negatives, **0**.

## Review flags are accurate by default

The free check alone is less accurate than a model (0.872 against 0.928), and no model-free variant closed the gap — each was measured. The cascade does: deferring only the uncertain band, it reaches **0.935** on 40% of the calls. Inside `ask` it is now on by default; `TESSERAE_VERIFY_BAND=off` returns the free flags.

| Conversational-memory retrieval | before | after |
|---|---|---|
| LoCoMo, 9 conversations, recall@10 | 0.878 | **0.930** |
| LongMemEval, group 0, recall@10 | 0.867 | **0.891** |

## Also

- `tesserae graph-repair` applies the post-extraction passes to a graph already on disk — no model, no network, seconds — and a repaired graph agrees with a recompiled one
- document-first ranking (`document_first`) for conversational memory is opted into by the LoCoMo and LongMemEval arms; on the paper corpus it is worse, so it is not the default

## Upgrade

For existing graphs, run `tesserae graph-repair` instead of recompiling. `ask` now spends tokens on the review cascade by default; the old behaviour is `TESSERAE_VERIFY_BAND=off`.
