Released **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.8/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.8) · `pip install --upgrade tesserae==0.41.8`

`tesserae init` and `tesserae compile` add their project to the machine-wide
registry, `~/.tesserae/registry.json`, and a query with no project scope searches
every project in it. On the machine where this surfaced, the registry held 286
entries over 204 directories, and 6 of them were real projects. The rest were
throwaway projects from benchmark runs, agent scratch directories and a test,
plus a second alias for every project named at `init`.

## What changed

- **No second alias.** `init --name` registers the name it was given, and the
  compile after it, which has no `--name`, used to register the directory name
  as well. HypePaper names each expert it builds `hp-topic-<topic>`, and every
  one was listed twice. A directory already in the registry, under any alias, is
  now left alone.
- **Benchmark runs keep their projects to themselves.** The DeepScholar, growth,
  LongMemEval and LoCoMo harnesses build one project per query or conversation.
  Their `init` and `compile` now use a registry inside the work directory. One
  DeepScholar run had left 63 projects named `0` to `62`.
- **The test suite no longer writes your registry.** One test ran `init` in a
  subprocess that the suite's registry isolation never reached, and registered
  `cwd_wiki` under a temporary directory.

## Upgrade

Nothing to migrate. Entries already in your registry stay until you remove them:
`tesserae projects list` shows them, and `tesserae projects unregister <name>`
removes one without touching the project itself.
