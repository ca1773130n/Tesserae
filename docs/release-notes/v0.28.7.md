Released **2026-08-05** · [PyPI](https://pypi.org/project/tesserae/0.28.7/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.7) · `pip install --upgrade tesserae==0.28.7`

**If another tool writes session records into your Tesserae store, upgrade.**
[#104](https://github.com/ca1773130n/Tesserae/issues/104) was fixed twice, in
0.28.5 and 0.28.6, and was still losing those records both times. This release
fixes it on the axis that actually separates one importer from another.

## What the two earlier fixes got wrong

Both scoped pruning by *where the scan looked*: a discovery could only delete
records whose transcript lived under a harness root it had walked. That reasoning
holds only if different producers read different directories.

They don't. An orchestrator exporting its own agent sessions describes the **same**
`~/.claude` transcripts Tesserae's local scan reads — it just carries agent
identity the scan cannot infer. Its records sat inside the scope by construction.

Measured on 0.28.6 against a real 375-record store, two shapes of loss survived:

- **Deleted.** A record whose transcript the scan no longer finds is pruned. The
  original bug, unchanged.
- **Overwritten, silently.** A record whose transcript the scan *does* find is
  replaced by the scan's plainer version — agent identity and metadata gone.
  Both writers derive the same filename from the session id, so one lands on top
  of the other. Nothing is deleted, so the removal count stays 0 and the run
  reports success.

The second shape is not a pruning problem at all, which is why no refinement of
scope reached it.

## Provenance

Every record now carries a **`producer`** — the importer that wrote it.
`sessions discover --import` stamps `tesserae:discover`; `sessions import <path>`
stamps `tesserae:import`. A writer may only touch records it produced:

- it prunes only its own;
- it will **not** overwrite another producer's record for the same session. The
  incoming write is skipped and reported as
  `Left alone (written by another producer)`.

If you write into this store from your own tool, use `tesserae sessions import
<file>` and your records are protected from that point on. Nothing else is
required.

Root and harness scoping remain as a second gate, but they are no longer what
keeps records safe.

## Upgrading

**Records written before this release carry no producer.** They are unowned, so
no importer prunes or overwrites them — upgrading cannot lose what you already
have, including records another tool wrote.

The cost of that choice: discovery will not refresh legacy records either. If
Tesserae's own scan is the only thing writing your store, run

```bash
tesserae sessions discover --import --adopt-unowned
```

once to hand those records to discovery. **Do not run it if another tool writes
into the same store** — it does exactly what the flag says.

Lossless was the right default. The bug being fixed is silent data loss, and the
other default would have destroyed the reporting project's records one final time
on the upgrade that was supposed to protect them.

## Credit

Reported, reproduced and diagnosed by the agent working on the
[Agented](https://github.com/ca1773130n/Agented) project, which consumes Tesserae

provenance, the direction #104 suggested from the start.
