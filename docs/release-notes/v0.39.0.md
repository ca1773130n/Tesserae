Released **2026-09-06** · [PyPI](https://pypi.org/project/tesserae/0.39.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.0) · `pip install --upgrade tesserae==0.39.0`

`tesserae compile` has always built the concept and claim layer through your
configured LLM. Every other way into a compile did not: `refresh`, the engine
daemon, the MCP `materialize` path and `deploy --build` all asked for a compile
without naming an extractor, and "none" meant the deterministic one.

## What happened

One `tesserae refresh` on a real project rebuilt the whole document layer
without the LLM. Every file stayed marked as graphed, no document was flagged as
a fallback, and the graph came back with its concepts, capabilities, models and
topics gone — 466 concepts became 0. A daemon on a refresh loop would have done
the same on its first recompile. The fix was pinned with a fixture first: the
incremental differ keeps the LLM-typed nodes of untouched files; the entry
points were the hole.

## What changed

- **A compile with no extractor named now builds the configured LLM one**, the
  same shape `tesserae compile` builds, with the deterministic extractor as the
  per-document fallback. No usable backend degrades to the structural graph with
  a warning, never silently. `compile --extractor deterministic` remains the
  explicit opt-out.
- **Context bundles cite and pack the document that elaborates an entity.**
  v0.38.0 stored per-document mention density; nothing read it. The bundle's
  section for an entity now packs that document's prose and its citation names
  it, falling back to the first-seen path when no fresh SQLite mirror exists.
  `node_context` gains an additive `documents` list, ranked. Measured on two
  corpora, first-seen names the owning paper about half the time; the
  most-mentioning document, nine times in ten.
- **`verify_attribution`**, as an MCP tool and the `verify-attribution` CLI verb.
  A coverage check passes a real number lifted from a neighbour's table row,
  because every token is in the evidence. This checks ownership instead: whose
  record the figure sits in, and whether that document names the benchmark.
  Deterministic, no graph, no LLM; audited at 14 of 15 misattributions caught
  with 4 false alarms in 33 true answers.
- **An out-of-credit codex account is exhaustion, not a transport blip.** One
  spawn, verdict `exhausted`, remembered for the run — and the provider chain
  falls through to a logged-in Claude CLI at call time, as its docstring always
  promised. Before this, every call spent about 55 seconds retrying four homes
  and returned nothing.

## Upgrade

If you run a daemon or a `refresh` loop, expect it to spend LLM calls on
changed documents from now on; unchanged documents hit the prompt-addressed
cache. A graph compiled by `refresh` under an earlier version is structural
only — one full `tesserae compile` restores the LLM layer. Nothing else to
migrate.
