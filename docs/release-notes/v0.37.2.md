Released **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.2/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.2) · `pip install --upgrade tesserae==0.37.2`

v0.37.1 fixed the client builders. Three call sites build their own Anthropic
SDK client and were untouched by that fix, so they still went to
`api.anthropic.com` with a hardcoded model while every other path honoured the
project's configured endpoint. This release closes them.

## The three paths

- **`query --llm`** built its client with the API key alone — no `base_url` —
  and sent the method's default `claude-sonnet-4-6`.
- **Prose synthesis** (`TESSERAE_SYNTHESIS_LLM=1`) did the same, so a project
  with a custom endpoint had its summaries written by Anthropic.
- **`synthesis`** picked its model from `TESSERAE_SYNTHESIS_MODEL` or a literal,
  never from `llm_model`. It carries a wiki store rather than a project root, so
  the root is now derived the way `ProjectPaths` already defines it.

## Three more, found by running the shipped package against a real endpoint

0.37.1 was installed from PyPI into a clean environment and pointed at a live
OpenAI-compatible server. It worked — and exposed three things reading the code
had not:

- **The liveness failure was vague.** It said "rate-limited / auth / unsupported
  model" when the client had already classified which one it was. It now reads
  `the endpoint rejected the request (404 / unknown model) — check llm_base_url,
  llm_api_style, and that this model exists on that server`.
- **`tesserae config status` reported the provider's source as `default`** even
  when it came from the project config. The provider is resolved before the
  source-recording helper runs, so its layer was never recorded.
- **`tesserae setup` read `llm_claude_model` and `llm_claude_config_dir`** —
  singular keys that nothing writes. Every writer uses `llm_model` and the plural
  `llm_claude_config_dirs`, so the wizard silently saw no configuration at all.

## Tests

The custom-provider tests were gated on `importorskip("anthropic")` — skipping on
exactly the base install where the provider was broken. The `openai` wire needs
no SDK, so the new coverage cannot skip, and one test blocks the `anthropic`
import outright to prove it.

## Upgrade

Nothing to migrate. If you configured a custom endpoint and found that `ask` and
`compile` honoured it while `query --llm` or synthesis did not, this is that.
