Released **2026-09-08** · [PyPI](https://pypi.org/project/tesserae/0.39.3/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.3) · `pip install --upgrade tesserae==0.39.3`

Logged into two Claude accounts and told to run `claude /login`. One account was out of quota, and it was the only one the run was allowed to try.

## What happened

A configured account list was treated as a wall. Name one dir in `llm_claude_config_dirs` — or in the singular `extraction.claude_config_dir` an older `init` wrote — and that dir was the entire rotation. When its weekly quota ran out, the mechanism that exists to survive an exhausted account had nothing to rotate to, and the compile degraded to deterministic extraction while a healthy account sat idle on the same machine.

The second machine is where it turns into a login prompt. An account list holds absolute paths, and those do not travel: the CLI is handed a config dir that is not on disk, answers `Not logged in`, and the remedy printed is a login the user has already done.

Neither diagnostic caught it. `doctor` reported `[ok] llm_login` because the dir existed, which is all it checks. `tesserae test` reported "Backend is answering" because the provider chain had quietly fallen through to codex — true, and not the question being asked.

## What changed

- **A configured list is tried first, not exclusively.** Every other credentialed `~/.claude*` / `~/.codex*` on the machine is appended behind it. The accounts you named are still the only ones spent while one of them works — the client returns on first success — and the tail is reached only once every named account is a proven dead end. `llm_claude_config_dirs_exclusive` and `llm_codex_homes_exclusive` restore the old behaviour for whom spending an unnamed account is a billing problem rather than a rescue.
- **An expired OAuth session is an auth failure.** The substring test was `not logged in` alone, so the shape a MAX account presents once its refresh token dies — `Failed to authenticate: OAuth session expired and could not be refreshed` — fell through to the generic error path and earned "read the error" instead of the one command that fixes it.
- **`tesserae test` names every account it tried.** Both CLI clients now record one row per account the rotation spawned, at no extra cost, and the command renders them: the config dir, what happened, and the CLI's own words. It adds the remedy each outcome earns, calls out configured dirs that are not on this machine, and reports a **degraded** verdict when the provider you configured is dead and a fallback answered for it.
- **`doctor` stops going green over that.** A configured dir absent from this machine is a warning, and `doctor --fix` drops it from `config.json` — a dir that is not there cannot be logged into, so removing it cannot cost you an account. Credentialed accounts excluded from the rotation are named too. Doctor still spends no LLM call; these are the two things it can settle for free.

## Using it

```bash
tesserae test          # which account answered, and what the others said
tesserae doctor --fix  # drops account dirs that are not on this machine
```

## Upgrade

Nothing to migrate, and no config change is needed to get the fix. If you were relying on a configured list being exclusive — one account pinned so no other is ever billed — set `"llm_claude_config_dirs_exclusive": true` (or `llm_codex_homes_exclusive`) to keep that.
