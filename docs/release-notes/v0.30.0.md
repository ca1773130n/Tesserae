Released **2026-08-08** · [PyPI](https://pypi.org/project/tesserae/0.30.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.30.0) · `pip install --upgrade tesserae==0.30.0`

Three things land here. Source code stops being indexed unless you ask for it. A
retrieval surface that was written, tested and unreachable becomes reachable. And
the graph gains an org chart, so a general-purpose agent can be pointed at one
domain and act as an expert in it.

## Source code is now something you ask for

Tesserae used to build a code layer whenever a project *looked* like a repository
— `kind` was `CodeProject`, `Repository` or `Project`. That is a description of
what a project is, not a statement that its owner wanted their source parsed. The
only way out was to lie about the kind.

The cost was invisible where anyone would look. `graph.json` carries the research
partition, so it showed **zero** code nodes while the SQLite projection and the
generated pages carried roughly 220k rows and 220k pages. Nobody attributes that
to a setting they never set. On the maintainer's own machine it was 327 MB of
artifacts for a feature that project had turned off.

Now a project asks:

```json
"external_tools": [{"id": "codegraph"}]
```

Absence is off. Project kind is not consulted at all. This reuses the shape the
RAG-Anything integration already reads rather than inventing a second switch.

**Maintenance follows the same gate**, which is the half that would otherwise
leak. Both sync-code hooks check the opt-in *before* their own `sync_code_on_*`
setting, so those can only narrow a permission you already granted, never widen
it into one. A CodeGraph database on disk is not consent — an agent may have run
`codegraph init` for its own purposes with no view on whether Tesserae should
track it every 30 seconds.

`code-graph.json` follows the switch in both directions: written when enabled,
removed when disabled. A stale one carries no timestamp and goes on answering
reads with a snapshot of a repository that has since moved.

Nothing was deleted. The CodeGraph adapter, the extractor, the cache and
`tesserae code ingest|sync` are all still here, behind the switch.

## The retrieval knobs that were always there

`facts_as_of` — bitemporal query, "what did the graph believe on this date" — was
written, byte-idempotent and covered by seven tests, with **zero** callers.
`personalized_pagerank` already honoured `edge_type_weights`. `compile_context`
took sixteen parameters and the MCP server forwarded seven. Tesserae had
bitemporality and view-selective traversal and could not ask for either.

Now it can. `as_of` on `search_facts` and `timeline`, with `undated_included`
reporting how many of the rows you got carry no date at all. `strategy`, `scope`,
`edge_type_weights`, `tame_hubs` and `recency_weight` on `compile_context`.

`as_of` and `current_only` are refused together, deliberately: they express
different clocks, and asking what was true on a past date should not silently
return nothing because the answer was later superseded.

## An org chart over the graph

`tesserae domains status` reports a chartered structure over your knowledge
graph: divisions derived from its communities, split recursively when a domain's
brief outgrows what an agent can read in one pass, and identities that survive a
reorganisation — so a slug you pinned an agent to still resolves after the graph
moves.

This is the substrate. The routing that uses it lands next.

## Ingest stops reporting success for work it did not do

`tesserae ingest paper.pdf` used to copy the file in, run a compile whose walker
reads `.md` only, and print node counts from the rest of your corpus. Nothing in
that path could tell "ingested your PDF" from "ingested nothing". A directory of
PDFs behaved the same way, and the `processed=1` it printed was counting the
directory.

It now refuses, per file, with a remedy you can run:

```
tesserae ingest cannot read these files — compile only extracts from .md:
  - paper.pdf (.pdf): RAG-Anything parses this format, but it is opt-in ...
  - figure.zip (.zip): No Tesserae backend parses this format. Convert it to
    markdown first, then `tesserae ingest figure.md`.
```

Fetching a URL is stricter too. A PDF URL used to be decoded as text, written
under a `.md` suffix, and hashed over the mojibake — so the walker then fed it to
the extractor as prose. A body the bytes say is binary, a body whose declared
type is binary, and a 200 with no readable text are all refused now.

A new `INTERVAL_COVERAGE` lint reports how much of the graph can be placed in
time. On this project's own graph: **76,095 of 103,705 facts (73.4%) carry no
`valid_from`**, so they sort under the literal string "undated" in `timeline()`.
It reports at `info` and does not fail `--strict`; setting a floor needs a
number from a corpus that is current, and this one is not yet.

Session import counts the content blocks it cannot read instead of dropping them
silently. On 150 real transcripts that surfaced **9 image blocks that were
previously invisible** — they sit nested inside `tool_result`, where the old
counter never looked.

## Upgrading

```bash
pip install --upgrade tesserae==0.30.0
```

If you have been running Tesserae as a Claude Code plugin, **the hook gate only
takes effect once this version's plugin is installed** — earlier plugin copies
gate on whether a CodeGraph database exists and cannot see the opt-in. Until
then, `sync_code_on_edit: false` and `sync_code_on_start: false` in
`.claude/tesserae.local.md` is the switch those hooks do understand.

Existing projects keep working. A project that wants its code layer back adds the
`external_tools` entry above; one that does not gets a smaller graph, a smaller
database and no code pages, without changing anything.
