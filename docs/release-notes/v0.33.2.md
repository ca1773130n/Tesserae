Released **2026-08-25** · [PyPI](https://pypi.org/project/tesserae/0.33.2/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.33.2) · `pip install --upgrade tesserae==0.33.2`

One fix, in the benchmark arm that was supposed to be measuring this project
against a control. It was measuring nothing.

## The arm asked for a graph nothing builds

`_papers_by_arxiv` required a node of type `Paper` carrying `metadata["arxiv_id"]`,
and the evidence walk reached spans through `EvidenceSpan --part_of--> Paper`.
`tesserae compile` writes none of those. It emits `SourceDocument` carrying
`arxiv`, attaches spans with `contains`, and hangs claims off the span through
`evidenced_by` rather than off the document through `supports_claim`.

Measured on a staged 14-paper corpus, the resolver returned **one** node — the
parent paper, matched only because its own `paper.md` frontmatter declares
`type: Paper`. All 14 cited papers hit the skip, and the arm rendered a single
abstract-fallback card against the control's fourteen. `part_of` is 0 edges
there and 0 in a separately compiled 1,552-paper pool.

Every DeepScholar number this arm ever produced carried an
**18x evidence deficit** that read as a property of the graph.

## A green suite testing an imagined graph

The harness has a test whose entire job is to catch this: both arms must show
the writer the same number of lines, or any gap between them is unattributable.
It passed throughout. Every fixture in the file builds
`Paper`/`arxiv_id`/`part_of` — the shape the code expected, rather than the
shape the compiler writes.

That is the part worth keeping. A test can only compare the code against the
fixture's idea of reality, and both had the same idea. The new test builds the
node and edge vocabulary `tesserae compile` actually emits, so the two can
disagree.

After the fix the arm renders **14 cards of 14**, 42 lines against the control's
42, with 15 of them claim sentences where there had been none.
