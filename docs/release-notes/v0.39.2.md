Released **2026-09-08** · [PyPI](https://pypi.org/project/tesserae/0.39.2/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.39.2) · `pip install --upgrade tesserae==0.39.2`

Two gaps in the same place: nothing told you whether your LLM backend actually works, and `doctor --fix` would not finish what it started.

## What happened

`doctor --fix` applied each repair once, in registry order. A repair that invalidated an earlier check left that work for a second invocation nobody knew to run: fixing lint rewrites `graph.json`, which makes the site stale, and the site check had already gone by. A repair run also printed the same table as a read-only run, so learning which warnings were deliberate meant diffing two screens. Meanwhile the only thing that touched the backend was `config status --ping`, which makes one call as a side effect of printing configuration.

## What changed

- **`doctor --fix` converges.** Repairs repeat until a pass changes nothing, capped at three, with the project context rebuilt between passes so a repair that creates what a later check reads is seen by it.
- **Everything it declines is named.** Whatever is still wrong lands under **Still open** with the command and the reason. The reason is honest about the run that produced it: a read-only run says the finding is repairable by `--fix`, never that a fix ran and failed. Four standing reasons cover every report-only check — spend, install, authenticate, destroy — and a test fails if a check is added without one.
- **Three more checks repair themselves.** `config_valid` backfills missing required keys with the values `init` writes, atomically; a config that does not parse is reported and never rewritten. `--fix --deep` adds slow local repairs, starting with the session-chunk backfill. No fixer at any tier runs a compile.
- **`tesserae test` proves the backend answers.** It resolves the settings the way compile does, builds the same client, then spends one JSON call and one prose call, because a gateway can serve the first and refuse the second. Neither is cached. Exit 0 only if both come back.

## Using it

```bash
tesserae test                 # resolve, build, one JSON call, one prose call
tesserae doctor --fix         # repeats until a pass changes nothing
tesserae doctor --fix --deep  # + the slow local repairs
```

## Upgrade

Nothing to migrate. `doctor --fix` keeps its old promise — safe repairs only, never a compile, never a killed process — it simply repeats now and reports what it left. `--deep` without `--fix` exits 2.
