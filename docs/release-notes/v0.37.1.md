Released **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.1/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.1) · `pip install --upgrade tesserae==0.37.1`

Configuring a custom LLM provider could not work, for three independent
reasons, and the symptom every time was an error about a model you never
configured. An audit of the provider code confirmed 23 defects; this release
fixes them.

## The wire protocol was never modelled

`llm_provider` conflated *which backend* with *which HTTP dialect*, and
`custom` always built the Anthropic client, which posts to
`{base}/v1/messages`. Every OpenAI-compatible server — vLLM, LiteLLM,
OpenRouter, Together, Ollama, LM Studio — answers 404 to that. The one class
that speaks `chat/completions` was built by no code path and hardcoded
`api.openai.com`, so it could not have served your endpoint either.

`llm_api_style` now names the wire and is the only thing that picks the client.
Left unset it stays `anthropic` for `custom`, so an existing custom
configuration behaves exactly as before.

```bash
# an OpenAI-compatible endpoint (vLLM, LiteLLM, OpenRouter, Ollama, LM Studio)
tesserae config llm --llm-provider custom --llm-api-style openai \
  --llm-base-url https://gw.example/v1 --llm-model qwen3-coder --llm-auth-token sk-…

# an Anthropic-compatible endpoint — no /v1, the SDK appends it
tesserae config llm --llm-provider custom --llm-api-style anthropic \
  --llm-base-url https://gw.example --llm-model my-model --llm-api-key sk-…

tesserae config status --project .
```

## The model was dropped, and something else answered

The configured `llm_model` was scoped against whichever config *layer* supplied
`llm_provider` — set the provider by flag and the model in a config file and
your model was discarded for a hardcoded default. The custom endpoint then fell
through to the Claude CLI, which was spawned with `--model sonnet` against your
own base URL and reported an unsupported model. Nothing named the real cause.

An explicitly configured **endpoint** provider (`anthropic`, `openai`, `custom`)
is now a contract: it is built alone, and a failure raises an error naming the
provider, the wire, the base URL, the model and which credential kind was used.
`llm_allow_fallback: true` restores the old chaining. The two OAuth CLIs still
fall back to each other, since neither carries an endpoint of yours.

## There was no bearer credential

One `llm_api_key` was sent as `X-Api-Key` by the SDK and as a bearer token by
the CLI, and passing it to the SDK suppressed that SDK's own auth-token
resolution — so a gateway wanting `Authorization: Bearer` was unreachable.
`llm_auth_token` is the bearer credential, on both wires.

## Configuration you can see

One precedence for every key: `TESSERAE_LLM_*` environment → project
`.tesserae/config.json` → `~/.tesserae/config.json` → default, with the legacy
`ANTHROPIC_*` variables one rung lower. The resolver records which layer won
each key and `tesserae config status` prints that — it used to guess, and
credited an environment variable the resolver deliberately ignores. Status also
shows the wire, the credential kind, and the client that served its probe.

`ask`, `query`, lint, the MCP summaries and the engine daemon resolved against
the environment and the global config only, so a project-level endpoint was
honoured by `compile` and silently ignored everywhere else. They all read the
project now.

## Also

- An invalid `llm_provider` is reported instead of silently becoming `claude`.
- Anthropic base URLs are normalised, fixing the doubled `/v1/v1/messages` that
  this project's own quickstart documented.
- `401`/`403` are classified as auth failures and `404`/model-not-found as
  endpoint failures, rather than all being reported as "unavailable".
- `init` and `setup` persist the new keys; they used to accept and discard them.

## Upgrade

Nothing to migrate. Two visible changes: an explicit endpoint provider no longer
falls back to a different backend, and `config status` prints the credential
*kind* rather than `set`/`unset`.
