Released **2026-08-31** · [PyPI](https://pypi.org/project/tesserae/0.37.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.37.0) · `pip install --upgrade tesserae==0.37.0`

This release adds one knob and corrects several claims.

## The dense lane can ask for a trained encoder

On a 148-paper corpus the shipped static `model2vec` embedder was the whole gap
between the graph and a plain vector store. Distinct-document recall, same
fusion, same graph, same document dedupe:

| arm | @10 docs | @50 docs |
| --- | --- | --- |
| Mem0 OSS raw-chunk store, its own encoder | 0.784 | 0.942 |
| Mem0 OSS raw-chunk store, the same bge-base | 0.775 | 0.944 |
| Tesserae, shipped static model2vec | 0.754 | 0.914 |
| **Tesserae, bge-base in the dense lane** | **0.791** | **0.962** |

`TESSERAE_EMBEDDING_PREFER` picks the backend when the caller asks for `auto`
(`model2vec`, `st`, `openai`, `hash`); a value naming no backend is reported and
ignored rather than falling silently through to the hash stub. `TESSERAE_ST_MODEL`
names the sentence-transformers model — the default moves from the unmeasured
`all-MiniLM-L6-v2` to the measured `BAAI/bge-base-en-v1.5`.

```bash
uv pip install sentence-transformers
export TESSERAE_EMBEDDING_PREFER=st
export TESSERAE_ST_MODEL=BAAI/bge-base-en-v1.5   # the default; any Hugging Face name
```

The auto ladder is unchanged: `model2vec` first, so `pip install tesserae` stays
torch-free and an install that never sets the variable behaves exactly as before.

## What the measurement actually showed

Given the same encoder, the graph and a raw chunk store find the same documents:
paired over 57 questions the difference is 8 wins, 8 losses, 41 ties at ten
documents (sign test p=1.0). That is parity, and the documentation now says
parity — the earlier wording claimed the graph was ahead, and it was comparing
two different encoders.

The retriever also no longer sees LongMemEval's own date stamp and instruction
text, which had been part of the query for every arm.

## Where the design does differ

Packing graph-selected documents as source prose rather than as extracted claims
scored +28.9% against a passage control under a `gpt-4o-mini` judge. Re-run with
a local 7B judge it is +7%, not significant, and on a second corpus it loses. The
README carries all three numbers rather than the best one.

## Upgrade

Nothing to migrate. Existing graphs are unaffected; the knob is opt-in and the
default backend is unchanged.
