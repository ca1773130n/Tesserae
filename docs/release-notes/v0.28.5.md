Released **2026-08-01** · [PyPI](https://pypi.org/project/tesserae/0.28.5/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.28.5) · `pip install --upgrade tesserae==0.28.5`

No runtime behaviour changes in this one. It fixes the machinery that is supposed
to catch runtime behaviour changes, which until now did not exist.

## Nothing ran the tests

The repository had two workflows. One compiled the demo wiki; one published the
npm wrapper on a tag. Neither executed a single test. "`main` is green" was an
assertion nobody checked — 2,993 tests could have gone red on a Tuesday and the
badge would have stayed the same colour.

`tests.yml` now runs the suite on every push and every pull request, across
Python 3.10, 3.11 and 3.12 — the three versions `pyproject.toml` has been
claiming support for. Those claims had never been executed either.

## Two dependencies existed only on one machine

Adding CI meant first admitting that a fresh clone could not run the tests at
all:

- **`pytest` was declared nowhere** — not in `pyproject.toml`, not in `uv.lock`.
  The suite ran because pytest had been installed by hand into a local `.venv`
  years of commits ago. Any `uv` command that rebuilt the environment from the
  lockfile silently produced an environment with no test runner in it.
- **`kuzu` had the same problem with sharper teeth.** Two tests call the Kuzu
  store with no `importorskip` guard, so they *fail* rather than skip when it is
  missing.

Both now live in a `dev` dependency group. The distinction that matters: the
environment being tested and the environment a contributor gets are now the same
environment, which is the only condition under which a green suite means
anything.

## The lockfile had drifted

`uv lock --check` failed against the committed `uv.lock`: it was out of sync with
`pyproject.toml` and missing `markdownify` and `model2vec`. Anyone running
`uv sync --locked`, or any CI that pins the lock, hit that immediately.

It is regenerated, and the workflow runs `uv sync --locked` — which fails a build
on a stale lockfile rather than silently updating it, so this cannot drift
quietly again.

## What CI found in its first four minutes

It went red on all three Python versions with identical failures. Identical
across versions means platform, not version: two tests encoded properties of one
macOS machine.

Five drove `hooks/_lib.sh` through `zsh`, which is not present on the CI runners
— while the library documents itself as POSIX-friendly precisely so it does not
depend on anyone's login shell.

The sixth is the one worth reading twice. It monkeypatched `subprocess.run`, but
the code under test had moved to `subprocess.Popen` so a timeout could kill the
whole process group. The patch quietly became a no-op, and the test had been
shelling out to the **real `claude` binary** ever since — passing on machines
where that binary happens to be installed and logged in, and asserting nothing
whatsoever about the code it was named after.

Neither was a product bug. Both were tests that could not have failed for the
right reason, and neither was findable without running them somewhere else.

## The demo site is frozen

`build-demo.yml` was removed. It compiled Tesserae against its own source on
every push to `main` and deployed the result to GitHub Pages.

The consequence, stated plainly because it is easy to miss:
[the live demo](https://ca1773130n.github.io/Tesserae) still answers, and the
README still links it, but nothing redeploys it. That page is now a snapshot of
whenever the workflow last ran, and it will drift from `main` silently.
Republishing is a manual `tesserae export site`, or a new workflow.

It also removed the only automated coverage of `init` → `compile` →
`export site`. `tests.yml` runs the unit suite and does not exercise that path
end to end; the manual smoke step in the publishing checklist is now the only
thing standing there, and the checklist says so.

## Upgrading from v0.28.4

Drop-in. No API change, no schema change, no behavioural change — every commit in
this release touches CI configuration, test files, dependency declarations, or
documentation. There is no reason to recompile.

If you install from source with a pinned lockfile, this is the release that makes
`uv sync --locked` work again.
