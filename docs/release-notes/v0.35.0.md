Released **2026-08-29** · [PyPI](https://pypi.org/project/tesserae/0.35.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.35.0) · `pip install --upgrade tesserae==0.35.0`

An answer you cannot check is an answer you have to trust. This release makes
every answer checkable, sentence by sentence, for no tokens and no network.

## Which sentences to review, and why

`ask` already returned a `grounding` score. One number tells a reader that
something is wrong and never where. The envelope now also carries
`unsupported` — the sentences whose content is largely absent from the evidence
the model was actually handed, each naming the words that were missing — and
`supported_rate` beside it.

The threshold came from a negative control, not from taste. Every sentence of
442 real answers was scored twice: against its own evidence, and against a
different question's.

| scored against | mean coverage |
|---|---|
| its own evidence | **0.682** |
| a different question's | **0.365** |

That separates at **AUC 0.908**. At the shipped threshold the check catches
**78.5%** of sentences written against foreign evidence while flagging **11.3%**
of genuine ones. It first ran at a threshold chosen by eye, which would have
flagged half of all correct output — a flag nobody trusts is worth less than no
flag, so the number had to come from the control.

`UNSUPPORTED` means REVIEW THIS, never "this is false": a correct paraphrase in
different vocabulary lands there too. `None` means the check could not run, and
a caller must read that as unknown rather than as clean.

## The graph stopped losing entities to spelling

`ResNet-50` and `ResNet 50` were two nodes, so every consumer resolving by name
saw an ambiguity or a miss — 2,317 such names on one compiled corpus. Entity
resolution now reuses a node when an existing one is close enough, with the
threshold measured across six values rather than picked, and the merged-away
name kept as an alias so both spellings still resolve.

Chunked extraction had also left one entity as two nodes whenever two chunks
disagreed about its type — `Model` in one, `Algorithm` in another, 1,584 names
on a 148-paper corpus and none of them same-type. Both are fixed, and
**specificity held at 1.000 through every threshold tested**: no merge ever
manufactured support the corpus does not make.

## Also

- a published npm version is now a no-op rather than a red CI run, because a
  tag gets re-pushed for ordinary reasons
- entity resolution runs inside `compile()`; it shipped one release as a module
  nothing called

## Upgrading

Nothing changes until you recompile. The review flags need no recompile — they
read the evidence an answer was given, so they work on the graph you have.
