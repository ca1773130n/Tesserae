# Tesserae v0.31.0 — the graph learns what happened, not just what was said

Released **2026-08-10** · [PyPI](https://pypi.org/project/tesserae/0.31.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.31.0) · `pip install --upgrade tesserae==0.31.0`

A session transcript records that a command was run. Until now that is all the
graph kept — the fact of the call, never its outcome. An agent reading its own
history could see it had run `pytest` and had no idea whether the suite passed.
That is the difference between a log and a memory, and it is what this release
closes.

## A tool result is a turn

Exit codes and error flags now survive ingest and land on the `Event` node for
the turn. The graph can distinguish a command that **failed** from one that
merely ran.

The `Event` pass that mints those nodes stays LLM-free and degrade-never-raise:
one node per significant transition, `precedes` edges between consecutive
events, every id, body and date content-derived. A rerun produces byte-identical
output — verified over a 481-session corpus, and verified again against a client
that raises on any attribute access, because the pass is default-on for
session-bearing projects and that only stays safe while no model is in the path.

Turn text is copied into node names and descriptions, and those are serialized
into `graph.json` and every projection of it, so **home directories are redacted
on the way in**. `/Users/<name>` and `/home/<name>` never reach the graph — a
path is the one piece of personal data that appears in nearly every transcript
without anyone intending it to.

## The `recovers` edge

From two **observed** outcomes in a single session, Tesserae now derives one
causal edge: a tool call that reported failure, and a later call — same tool,
same program family, same working directory, same operand, with no success on
that operand in between — that reported success. The succeeding `Event` is the
source, the failing one the target, both turn ids are named in the evidence, and
`metadata["basis"]` names every dimension the two calls had to agree on.

`CAUSAL_EDGE_TYPES` contains exactly one member, and it stays that way. A survey
of four leading agent-memory systems found that not one of them derives a causal
edge: two infer their strongest link from co-occurrence, one takes an LLM's word
for an open vocabulary of relation labels with no verification, and one has no
edges at all. The failure this narrowness exists to avoid is shipping a
`caused_by` that is really a `happened_near` — in a graph the two are
indistinguishable, and the wrong one gets read as evidence.

The anchor is the **operand**, not the command. Commands vary in ways that do not
matter — flags, ordering — while the thing being acted on is what a retry is
actually retrying. That choice came out of 103 real transcripts, 2,330 tool
results and 94 raw failures, re-parsed against four candidate anchor keys with
hand verification throughout.

## A reserved procedural slot, earned by provenance

`tesserae context` now reserves a slot per procedural pool — `Runbook`,
`Gotcha`, `Event`, `DistilledNote`, `ExpertiseProfile` — so that what an agent
actually ran, and what came of it, can reach the front of a tight budget walk.

The slot is **earned, not granted**. Those five type names are also mintable by
document extraction, so an LLM reading a call-for-papers legitimately mints a
typed `Event` called "CVPR 2026". Reservation is additive — it promotes a node
from anywhere in the neighbourhood to the front of the budget — so reserving on
type alone would let a conference deadline evict the session finding that earned
the slot. `has_producer_provenance` is what separates them, and a reservation is
a claim on a slot rather than proof of one: `delivered` is settled after the
budget walk, so a caller can tell "procedural memory was reserved" from
"procedural memory arrived". The new `PROCEDURAL_POOLS` lint code reports the
gap.

## A node is dated from where its source came in

`first_seen_at` now derives from the path a node's source was ingested under,
rather than from wall-clock at compile time. Reading the clock made every rerun
a diff, which defeats the content-hash skip that byte-idempotence rests on. The
same rule is what keeps the `Event` pass reproducible.

## Documentation

The docs had drifted a full cycle behind the code, and this release corrects
that across all eight languages. Five subsystems that had shipped with no
user-facing documentation now have it — the charter, the lint code vocabulary,
tool-result outcomes, the `recovers` edge, and the procedural slot — and nine
MCP tools that were served but unlisted are now documented, so an agent reading
the docs can discover the tools written for it. All 35 served tools are covered
in every language.

Two older defects went with it: 70 broken links inside `docs/i18n/` (translated
pages linking to English filenames that resolve to nothing from there), and the
`OKF v0.2 export/import` section of the architecture document, which shipped in
v0.10.0 and had never been translated.

## Upgrading

```bash
pip install --upgrade tesserae==0.31.0
```

Nothing here requires a migration. The `Event` pass and the `recovers` detector
run on the next compile of a session-bearing project; existing graphs gain the
new nodes and edges without a rebuild being forced. Sessions imported before
this release carry no exit codes, because the information was discarded at
ingest time and cannot be recovered from the normalized record — re-import those
transcripts if you want outcomes on them.
