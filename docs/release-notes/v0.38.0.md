Released **2026-09-04** · [PyPI](https://pypi.org/project/tesserae/0.38.0/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.38.0) · `pip install --upgrade tesserae==0.38.0`

`node_provenance` answers which documents mention an entity and stops there. A
node seen in 30 papers hands back 30 documents that look identical, and the one
that actually elaborates the entity is somewhere among them.

## What happened

Measured across two corpora on 2026-09-02: the provenance set holds the
elaborating document 55-64% of the time, and ranking that set surfaces it only
10-15% of the time. The set is right and the order is a coin flip, because from
the sidecar every document in it looks the same.

## What changed

- **A derived `node_mentions` sidecar** — `(node_id, source_path, mentions)`. A
  compile-time pass counts each node's name and its aliases, word-bounded, in
  every document its provenance names.
- **`SqliteGraphStore.node_documents` returns those documents most-mentioning
  first.** The read is driven by `node_provenance` and LEFT-joins the counts, so
  the two sidecars cannot drift: a document with no count still appears, with 0.
- **A separate table, not a column.** An existing `sqlite.db` needs no migration
  and provenance byte-stability is untouched.
- **Overlapping name and alias spans are merged**, so `BERT-base` counts once
  rather than twice.
- **The count can only be taken while the corpus text is in hand**, which is why
  it happens at compile. Nothing downstream can reconstruct it from the graph.

Measured cost: 31.5s for 43,151 pairs over 148 full papers, and 5.2s for 27,669
pairs over 1,552 abstracts, against compiles measured in hours.

## What this does not do yet

Nothing in the shipped retrieval path ranks by these counts. `node_documents` is
an API you can call; the packer still orders a node's documents by where the node
was first seen. On the benchmark that motivated the work, mention density picks
the owning document 0.92 and 0.85 of the time on the two corpora, against 0.52
and 0.55 for the shipped rule. Wiring it in is a later release, not this one.

## Upgrade

Nothing to migrate. The table appears on the next `tesserae compile` and the
counts with it. Until you recompile, `node_documents` returns the provenance set
in path order with every count at 0 — the same documents you had, no worse.
