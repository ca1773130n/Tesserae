Released **2026-09-18** · [PyPI](https://pypi.org/project/tesserae/0.41.7/) · [GitHub release](https://github.com/ca1773130n/Tesserae/releases/tag/v0.41.7) · `pip install --upgrade tesserae==0.41.7`

v0.41.6 made a second Ctrl-C or SIGTERM stop `tesserae engine` mid-compile by
raising in the main thread, where that compile runs. Fleet mode,
`tesserae engine --all`, kept the old behaviour. There each project compiles on
its own thread, out of that reach, so the fleet met every signal after the first
by waiting the compile out. The only way out was SIGKILL, and that left every
`claude -p` child running, and billing, in its own session.

## What changed

- **A second signal stops the fleet.** It removes the fleet pidfile and the
  project pidfiles it wrote, kills every running CLI agent and refuses to start
  another, then exits with the conventional status. Nothing is lost: each
  project's next compile finds the changed sources through the manifest differ.
- **The first signal reaches every project at once.** Projects used to stop one
  at a time, so while the first finished its compile, the rest kept watching and
  could start a new compile after the stop. Each still finishes the work in
  hand, and the fleet now says `signal again to stop now`.

## Upgrade

Nothing to migrate. Restart a running fleet to pick this up. A SIGTERM to
`engine --all --once` or to a plain `tesserae compile` still ends the process
at once and can leave a `claude -p` child running. Ctrl-C covers both.
