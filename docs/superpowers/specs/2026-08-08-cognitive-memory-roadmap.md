# Agent cognitive memory — where Tesserae stands, and what to absorb

**Status:** research finding, 2026-08-08. Not a plan; input to future specs.

## Verdict

Tesserae is not behind on mechanism — it is behind on wiring, and it is measurably ahead on honesty. Verified on the live corpus: the bitemporal machinery Graphiti is famous for is fully built and materialised (621,561 facts in .tesserae/temporal_facts.jsonl carrying valid_from/valid_to/valid_to_basis/current/invalidated_by), yet `facts_as_of` has six passing tests and ZERO production callers (grep finds it only in temporal.py:392 and tests/test_temporal_validity.py), and the string `as_of` appears nowhere in mcp_server.py. The pattern repeats: personalized_pagerank already deletes zero-weight edge classes from the walk (ppr.py:159-163), which IS MAGMA's view mechanism, but MCP compile_context forwards 7 of the function's 16 parameters (context_compiler.py:376-393 vs mcp_server.py:2424-2450), so edge_type_weights, scope, strategy, tame_hubs and recency_weight are unreachable from any agent surface. Where Tesserae genuinely lacks something it lacks it completely: of 57 edge types the only causal-adjacent ones are attributes_improvement_to (264 edges), reports_result, resolved_by (17) and supersedes, and no tool_result survives ingest at all — _claude_turns (harness_sessions.py:1278-1300) mints turns from tool_use INPUTS only, and HarnessSession.errors is declared at :49 and never populated anywhere in the repo. Two silent degradations are live invariant violations: `tesserae ingest paper.pdf` copies the file, reports a successful compile and adds nothing (ingest/orchestrator.py:58-60 validates existence only; project.py:3827-3828 returns [] for a non-.md file, with no pdf/png/jpg test anywhere), and multi_pool reserves five 48k-budget slots for Runbook/Gotcha/Event where all 226 Events, 46 Runbooks and 103 Gotchas on the live graph carry ZERO `extractor: session-event` and zero distill provenance — they are document extractions wearing procedural type names. Against the field, Tesserae uniquely enforces byte-idempotence by test, re-grounds cited spans against source bytes, and refuses rather than guesses. The strategy is therefore not to copy seven systems: it is to unhide four already-built capabilities in about a week, fix two invariant violations, and then buy exactly one new rung — causal/recovery — which is gated behind exactly one medium ingest change.

## What only Tesserae has

- Byte-idempotent memory artifacts ENFORCED BY TEST, not asserted in a README. tests/test_idempotence.py:299-303 asserts both graph.json AND temporal_facts.jsonl are byte-identical across two compiles. Graphiti, Cognee and Neo4j Agent Memory all bake datetime.now() into stored episode reference times, so no two of their ingests are comparable. temporal.py:56-62 documents excluding last_accessed_at from the timestamp ladder specifically because letting mutable sidecar state decide an artifact field 'is precisely the wall-clock leak that broke byte-idempotence four times in this repo'.
- Content-hash drill-down with a four-state verdict and an audit ledger. drill_down (agent_view.py:316-412) resolves any member_ref against raw L0 and returns alive|changed|absorbed|gone by content-hash comparison, appending an audit row to the drill_down_audit sidecar. Neo4j's :TOUCHED tells you what a reasoning step touched; it cannot tell you that what you are citing has since changed underneath you.
- Span re-grounding against source bytes, with the failure rate measured rather than assumed. verify_claim (verify.py:486-575) refuses SUPPORTED when the cited text is provably absent from the file on disk; verify.py:378-395 records that on the real 5,197-node graph 198 of 2,088 SUPPORTED verdicts (9.5%, across 56 files) cited a span not present, because the extractor stitched a fragment across headings. Graphiti carries provenance TO an episode and stops there.
- Anti-hallucination enforcement on the distilled procedure itself. _validate_summary (agent_distill.py:1235-1262) rejects any note citing an id outside the member whitelist, and _faithfulness_ok (:1265-1276) rejects a body containing any backticked identifier, version token, number or quoted string absent from the cited members. HiSkill and SkillGraph both synthesise skill descriptions from trajectories with no published mechanism preventing an invented command from entering an executable structure — which for a runbook is a live hazard, not a cosmetic one.
- Every agent-authored claim must anchor OUTSIDE the graph. agent_write.py:92 and :198-203 refuse any write whose provenance lacks url|file|commit|session_id, with the rationale in source: 'a claim whose only support is the graph itself cannot be verified against anything outside it.' This is the anti-self-reference constraint made mechanical, and it is exactly the guard that would have prevented the v0.29.0 self-capture loop from becoming knowledge. No surveyed system requires it.
- Credential-free deterministic supersession. _deterministic_verdict (memory/supersede.py:299-327) is a pure function of immutable content fields with no datetime.now(), no RNG and no I/O, so the same corpus yields the same 3,194 `supersedes` edges with or without an LLM; the LLM path caches on a content hash rather than a node id (memory/contradiction.py docstring). Every surveyed system requires an LLM in the arbitration path, making their consolidation non-reproducible.
- A constructor-level ontology guard. ResearchEdge.__post_init__ (research_graph.py:412-422) raises ValueError for any type outside a 57-member whitelist, and every writer including the OKF importer is forced through it (okf.py:667 drops foreign types). verify_claim refuses with `predicate_not_in_ontology` rather than synonym-resolving (verify.py:564-575). Schema drift is structurally impossible, not merely discouraged — which is also why adding a causal edge here costs one set-literal entry and would cost a migration elsewhere.
- The time-travel answer reports its own epistemic coverage. facts_as_of (temporal.py:392-430) returns (kept, undated_included) so an agent is told how much of an 'as of DATE' answer is undated, and raises on an unparseable pivot rather than silently widening to the whole corpus. _boundary_precedes_start (:145-162) refuses to emit an interval that would be empty at every instant, falling back to valid_to=None — 'under-claim, never a guessed boundary'. No surveyed bitemporal system reports its own coverage back to the caller.
- A hard 48,000-char one-read bound on agent-facing artifacts (ARTIFACT_CHAR_BUDGET, agent_distill.py:155), treated as an enforced property with a measured split strategy — the CHARTER spec records two agents at 118,360 and 71,624 chars against it (spec:22-26) and designs recursive sub-community splitting to fix it, with DOMAIN_MASS_CAP a literal constant so an env override cannot reshape the tree (spec:104-107). None of the surveyed systems bounds what an agent must read in one shot.
- Reads that count and reads that must not are distinguished, and the distinction is defended in source. _bump_nodes_access fires from ~11 read surfaces but is deliberately withheld where it would poison the demand signal (mcp_server.py:3336 'READ-ONLY invariants: no _bump_nodes_access'; the org-scope rationale at :3215). No listed system reasons about which reads are allowed to move memory state.
- Documented, in-code capability ceilings with an ordered upgrade path. verify.py:743-754 states in a source comment that the `execution_verified` provenance value is reserved and deliberately never emitted because the data does not exist, names _claude_turns as the function responsible, and lists the three steps to fix it. That is a more honest artifact than any of the eight surveyed systems' documentation, and it is why this audit's central gap took minutes to confirm rather than days.

## Ladder position

Episode/Artifact — SOLID for text, ABSENT for everything else. Sessions are first-class (1,214 derived_from_session edges live) and drill_down reaches L0 by content hash. Non-text artifacts are parsed and then thrown away: raganything_adapter._block_summary (:54-68) already extracts img_path, img_caption, table_body and latex, and :133 buries them in a metadata['multimodal_blocks'] list because _collect_text (:71-78) keeps only blocks of type 'text'. img_path carries no content hash, so this is the ONE place the drill-down-to-L0 invariant terminates in an unverifiable string. A claim cannot cite a figure.

Entity/Semantic — SOLID as vocabulary, UNDIFFERENTIATED as traversal. 74 node types, 57 constructor-guarded edge types, 46,924 nodes / 103,705 edges live. But entity and semantic collapse into one PPR walk over one all-edges adjacency; nothing partitions the edge set, and the two largest classes are abstraction/provenance (summarizes 36,795 = 35%, evidenced_by 15,004 = 14%).

Temporal — FULLY BUILT, ENTIRELY UNWIRED, AND THIN. Measured on the live 621,561-fact projection: valid_from == 'undated' for 587,311 (94.49%); valid_to non-null for 1,628 (0.26%); current true for 617,965 (99.42%); valid_to_basis histogram exactly {None: 619933, supersedes: 1628}, so 100% of interval ends ride on supersedes edges. Top predicates are defines 311,937 / contains 119,194 / imports 81,448 — 82% code-structure edges whose endpoints carry no source timestamp. On the research layer only 1,213 of 46,924 nodes (2.6%) carry first_seen_at, and SourceDocument (2,022), Claim (4,785) and EvidenceSpan (11,437) carry it on ZERO nodes.

Causal — ABSENT. Verified programmatically against ALLOWED_EDGE_TYPES: of 57 types the only causal-adjacent ones are attributes_improvement_to (264 edges), reports_result, resolved_by (17) and supersedes. No caused_by, led_to, blocked_by or recovered_by. CausalClaim exists as a NODE type (210 live) assigned by keyword heuristic — classify_claim_type matches the bare substring 'by ' (research_graph.py:2714-2722) — and carries no causal edges. `precedes` is documented as turn order, not causality (session_event.py:45-46), and there are only 56, of which 3 join Event to Event.

Decision/Reasoning — PARTIAL. AskUserQuestion decisions are captured (decisions.py:100-105) and query_decisions is exposed; Event nodes carry {session_id, turn_id, actor, action, tool}. But there is NO :TOUCHED equivalent — no edge attributes an entity set to an individual reasoning step, so 'which entities did this decision consult' is unanswerable.

Lesson — PARTIAL AND MISLABELLED. Gotcha exists (103 nodes) and reinforce.py converts distinct-session recurrence into confidence. But zero of those 103 came from the distill pass, and recurrence is not outcome: a procedure that recurs because it keeps FAILING is reinforced identically to one that works.

Procedure — NAME ONLY. Runbook exists (46 nodes, none with distill provenance). The summariser contract is four keys — {kind, title, body, citations} (agent_distill.py:506-509) — with no steps, preconditions, postconditions or expected outcome. Runbook and Gotcha are minted by the same pass from the same clusters and there are ZERO edges between them in either direction on the live graph, so 'this procedure avoids that pitfall' is unrepresentable.

Skill — ABSENT. No tier above Runbook, no prerequisite/enhancement/co-occurrence relations, no split/merge as graph operations over procedures. CHARTER's reorg-ledger vocabulary (founded/stable/promoted/demoted/split/merged/retired, spec:284-289) is precisely the right lifecycle vocabulary to reuse when this rung is built — invent nothing new.

AtomicOp — SUBSTRATE BUILT, PIPELINE NOT RUNNING. session_event.extract_events (:62-163) mints deterministic, LLM-free per-transition Events with `precedes` chains and finding→Event `derived_from`, stamping metadata['extractor'] = 'session-event' at :132. Verified: ZERO of the 226 live Event nodes carry that stamp — every one is an LLM document extraction. And no Event carries an outcome, because no exit code survives ingest.

## Roadmap (ordered by leverage)


### 1. Unhide the retrieval surface — expose the bitemporal and view-selective parameters that are already built, tested, and unreachable  
**Cost:** small · **Borrowed from:** Graphiti (bitemporal query) and MAGMA (view-selective traversal) — though nothing is actually borrowed here, only unlocked

**Why now:** Highest capability-per-line in the entire audit. facts_as_of (temporal.py:392-430) is written, byte-idempotent and covered by six tests, and grep proves ZERO production callers; `as_of` appears nowhere in mcp_server.py. compile_context takes 16 parameters (context_compiler.py:376-393) and MCP forwards 7 (mcp_server.py:2424-2450), so edge_type_weights — which personalized_pagerank already honours by DELETING zero-weight edge classes from the aggregated projection (ppr.py:159-163) — reaches only graph_ppr, which returns a ranked id list rather than a compiled bundle. Tesserae already has bitemporality and view-selective traversal and cannot ask for either.

**Change:** mcp_server.py: add `as_of` to the search_facts inputSchema (:957-972) and the timeline inputSchema (:974-988), call temporal.facts_as_of, and surface its second return value `undated_included` in the response body — never drop it. Add `strategy`, `scope`, `edge_type_weights`, `tame_hubs`, `recency_weight` to the compile_context inputSchema (:1360-1428) and forward them in the dispatcher (:2424-2450). Report which knobs actually ran, the way search_nodes already appends `mode` (:3653-3654). No changes to temporal.py, context_compiler.py or ppr.py.

**Correction, as implemented:** surfacing `facts_as_of`'s second return value verbatim, as prescribed above, is wrong and shipped a defect. The pivot runs before the query filter and the limit and budget caps, so that number counts undated rows across the whole as-of corpus — a two-row answer reported 41 undated, inverting the "how thin is this answer?" judgement the counter exists to support. What ships is `undated_included` computed over the rows actually returned. The two filters also run on different clocks and must not compose: `as_of` (live THEN) with `current_only` (live NOW) drops exactly the facts that were the state of knowledge at the pivot and have since been superseded, so the pair is refused with an error rather than silently answered under one clock or the other.

**Composes with CHARTER:** This IS CHARTER's new-code item 5 pulled forward and widened. Spec:353 already requires '`scope=` and `strategy=` added to compile_context's inputSchema and dispatcher (pure wiring for already-tested code)', so doing it now means CHARTER lands with less wiring, not more, and the `domain:<slug>` scope branch it plans has a live dispatcher to attach to. Adopts CHARTER's honesty split verbatim (spec:257-258): artifact bytes stay idempotent, the knobs that ran are reported rather than buried.


### 2. Make the three silent degradations loud — binary ingest, undated interval coverage, dropped non-text content  
**Cost:** small · **Borrowed from:** Nothing. This is Tesserae's own fail-loud invariant, currently violated in three places

**Why now:** `tesserae ingest paper.pdf` today copies the file into data/ingested/ (ingest/orchestrator.py:29-33), drives a compile whose default walker matches .md only (project.py:705 -> :3827-3828 returns [] for a non-.md file), and reports success with node/edge counts from the rest of the corpus. Verified there is no test coverage: grep for pdf/png/jpg across tests/test_ingest_cli.py and tests/test_ingest_orchestrator.py returns nothing. fetch.py:104 reads response.text unconditionally and hashes the DECODED string, so an arXiv PDF URL writes mojibake under a content_sha256 over garbage. And an agent calling timeline gets an ordering in which 94.49% of rows sort under the literal string 'undated' with no signal. Landing this first converts every remaining gap in the roadmap from 'silently nothing' into a named, actionable error.

**Change:** (a) ingest/orchestrator.py:58-60 — raise when a resolved local input's suffix falls outside the active loader's extension set, naming the raganything opt-in as the remedy (same shape as raganything_refresh._install_hint_for at :177-195); add a content-type guard at ingest/fetch.py:104. (b) lint.py — a new INTERVAL_COVERAGE probe alongside STALE_CITATION (:447) and CODE_GRAPH_STALE_FILE (:1091), reporting undated-valid_from percentage and the valid_to_basis histogram. (c) harness_sessions.py:1385-1396 — _content_to_text counts and logs non-text content blocks instead of discarding them silently, which makes the multimodal gap measurable before anything is built for it. Plus the missing pdf/png/jpg cases in both ingest test files.

**Composes with CHARTER:** Pure addition; touches nothing CHARTER reads. The interval-coverage lint slots into the same lint_report surface CHARTER extends with charter_drift / charter_fallback (spec:353), and it takes exactly the CH-06 fallback-census posture (spec:324) — count the degraded population and exit non-zero above a threshold rather than let it freeze silently.


### 3. Source-derived first_seen_at across the research layer  
**Cost:** medium · **Borrowed from:** Graphiti (valid-time coverage), though the fix is entirely inside Tesserae's own ingest path

**Why now:** Simultaneously the largest available temporal gain AND a CHARTER blocker, which is why it outranks everything below. Measured: only 1,213 of 46,924 research nodes (2.6%) carry first_seen_at, and SourceDocument, Claim and EvidenceSpan carry it on ZERO nodes. CHARTER's _domain_clock(members, as_of) = max(first_seen_at) hard-fails when no member carries one (spec:297-300, :344), so on today's corpus almost every document-derived domain would raise DistillError or fall back to an operator-supplied --as-of. Separately, 82% of the 621,561 temporal facts are defines/contains/imports from the code layer, which stamps no timestamp at all. Git commit dates are source-derived and deterministic. One change lifts facts_as_of (just unlocked in step 1) from answering 5.5% of the corpus to plausibly a large majority, and unblocks CHARTER's corpus clock.

**Change (as specified — SUPERSEDED, see below):** Stamp metadata['first_seen_at'] at node construction from a source-derived ladder only, extending the existing one at temporal.py:50-70: (1) YAML front-matter date / fetched_at already written by ingest/fetch.py:110-121, (2) git commit date of source_path via a cached per-file lookup, (3) session.started_at where it already applies. Additionally sharpen session-finding first_seen_at from session level to turn level using the turn_ids already present on finding metadata — temporal.py:44-47 notes this needs no schema change. Do NOT use file mtime (not reproducible across clones) and do NOT touch last_accessed_at (temporal.py:56-62 names it as the leak that broke byte-idempotence four times).

**Change (as BUILT, 2026-08-09 — this is the binding text):** The turn-level sharpening of session-finding first_seen_at shipped as specified (`session_graph._finding_first_seen_at`, a write-side change). The rest did NOT. Each rung the spec named was measured against the live corpus and reaches almost nothing: front-matter `fetched_at` appears on 0 of 2,524 files; the git commit date of `source_path` reaches 14.4% of nodes because `data/` is gitignored and holds 80.4% of the dated population, and it breaks in a shallow clone; `session.started_at` already applies where it applies. What actually reaches the corpus is a rung the spec did not consider — the dated directory an ingest already writes into (`data/research/daily/2026-04-06/…`), which is a string already inside graph.json. It is read on the READ side, as the last rung of `temporal._source_ts`, and lifts node-level ladder coverage 7.6% → 81.9% and fact-level `valid_from` coverage 26.6% → 88.1%.

**Ruling: read-side, NOT stamped at node construction.** Three reasons, in order of force.

1. Stamping would bake a value derived from a *directory name* into graph.json for ~34,851 nodes. The derivation must be bounded to the project-root-relative path or the checkout's own location dates the corpus (`~/.blackhole/<project>/<YYYY-MM-DD>/<slug>/`, which OPERATIONS.md mandates for every agent worktree, would stamp the whole graph with the worktree's creation date). Read-side, a wrong bound is one function away from being fixed and the same graph.json re-reads correctly. Stamped, it is in the artifact's bytes and needs a full recompile of every project to correct — and the byte-idempotence guard would then be certifying a value derived from where the repository sits.
2. `metadata['first_seen_at']` is today a **write-side session-provenance field** with a narrower meaning than the ladder's. It is written only by `session_graph.py`, `session_event.py`, `session_graph_structural.py` and `agent_distill.py`, always from a session or turn timestamp — *the moment a session observed this*. `activity_summary.gather_findings` depends on that narrow meaning (it drops a finding whose `first_seen_at` equals its Session's `started_at`), and `agent_distill` uses it as a decay anchor, a cluster sort key, and part of a memo key `(id, name, first_seen_at)`. Stamping a coarse ingest-directory day onto Claim/EvidenceSpan/Concept nodes overloads one key with two provenance classes and silently reweights decay and re-partitions clustering — none of which this step asked for or measured.
3. The ladder the spec named cannot deliver the coverage the spec claims (point above), so stamping would pay the full cost of (1) and (2) for 14.4%.

**Cost of the ruling, stated plainly:** every consumer that reads `metadata['first_seen_at']` directly still sees 2.6% node coverage. The gain is entirely in `valid_from` (26.6% → 88.1% of facts) and everything downstream of `facts_as_of` / `timeline()`.

**Composes with CHARTER — CONSTRAINT, not an unblock.** The spec's claim that this step unblocks `_domain_clock` is **withdrawn**. `_domain_clock(members, as_of) = max(first_seen_at)` (charter design spec:297-300, :344) is not yet written; when it is, it must call `temporal._source_ts(node, graph_project_roots(graph))` rather than read `metadata['first_seen_at']` off the node, or it will see 2.6% coverage and hard-fail exactly as before. That is the whole of what this step gives CHARTER: one shared derivation to call. Determinism is preserved either way — the rung reads bytes already in graph.json, no file, no git history and no clock — so the never-invent-a-timestamp posture CHARTER inherits from `_corpus_clock` still holds.

**Also NOT additive at fact level, contrary to the first reading.** Because `_latest_ts` takes the MAX over both endpoints, dating a previously-undated endpoint changes which endpoint wins for an edge that already had a date. Measured on the live graph: of 103,705 facts, 63,780 gain a date, 38,499 are unchanged, and **1,426 have a real date replaced** — every one of them moving LATER, none earlier. That is correct under the max rule (a fact cannot predate either endpoint) but "strictly additive" was false and is not claimed.


### 4. Producer-scope the procedural pools, and turn on the LLM-free Event pass  
**Cost:** small · **Borrowed from:** HiSkill (the AtomicOp tier) — the substrate is already written, it simply is not running

**Why now:** A live correctness defect and the precondition for measuring anything procedural. Verified on the live graph: 226 Event, 46 Runbook and 103 Gotcha nodes, and ZERO of any of them carry metadata['extractor'] == 'session-event' (the stamp set at session_event.py:132) or any distill provenance. Every one is an LLM document extraction that happened to land on a procedural type name — one Event is a conference deadline. context_compiler.py:598-641 reserves one 48k-budget slot per pool filtering ONLY on node type and distill_quality, so an agent calling multi_pool today receives conference deadlines labelled 'procedural memory'. Any eval of procedural quality run before this change is measuring the document extractor.

**Change:** context_compiler.py:598-641 — add one predicate to the pool loop: a node qualifies for a reserved procedural slot only if metadata['extractor'] == 'session-event' or it carries member_refs / distill_quality. Then enable the session-event pass by default for session-bearing projects (memory/distill.py:107-134 gates it today); it is fully LLM-free and template-only by design (session_event.py:118-123), so it carries zero byte-idempotence risk. Expect the immediate effect to be reserved slots going EMPTY — that is correct, and step 2's lint should report it.

**Composes with CHARTER:** Additive and favourable. Event nodes are ordinary research-layer L0 members attached on CHARTER's fast clock by majority vote of existing neighbours (spec:262-268), so they never trigger a reorg. They are not synthesis-family, so settled decision 4 (spec:363) does not exclude them — correctly, since a real session transition is ingested knowledge whereas a Daily Digest page is Tesserae's own output. Adding thousands of Events does shift community detection, so re-run the DOMAIN_MASS_FLOOR measurement (spec:109-111) rather than assuming the 3,000 tuning holds.


### 5. Tool results survive ingest — exit codes, error flags, and outcomes stamped onto Event nodes  
**Cost:** medium · **Borrowed from:** Cognee's Claude Code plugin (captures tool traces, not just invocations); HiSkill (a failed anchor is a precondition for any recovery edge)

**Why now:** The single genuinely blocking dependency for the entire top half of the ladder, and the codebase already prescribes the fix against itself. verify.py:743-754 states in source that 'no exit code survives ingest... this tool can say a document says so, never this ran and passed', names _claude_turns as responsible, and lists the three ordered steps. Verified: _claude_turns (harness_sessions.py:1278-1300) mints turns from tool_use INPUTS only and _codex_turns (:1303-1321) from function_call arguments only; tool_result is parsed in exactly two places and neither becomes a turn. HarnessSession.errors is declared at :49, round-tripped at :102, and never populated anywhere in the repo. Without this, Causal, Lesson, Procedure and Skill are all built on prose keyword votes.

**Change:** harness_sessions.py:1278-1321 — mint a `tool_result` turn carrying is_error / exit_code alongside the existing tool_use turn; the turn shape is an open dict {role, timestamp, name, text} (:1291-1297) so no type change is needed. Populate HarnessSession.errors from it. session_event.py:127-140 — stamp status / exit_code onto Event.metadata next to the existing `if tool_name:` guard (deterministic, no LLM, no wall clock). Add a `failure` kind to the finding taxonomy (session_graph_llm.py:32-37 and its prompt). Manage _TURN_LIMIT_BACKSTOP and _turn_text truncation because results are large, and gate on the v0.29.0 host/producer scoping (harness_sessions.py:53-71) so widening ingest does not re-inflate the store that turned out to be 98.4% Tesserae's own LLM calls.

**Composes with CHARTER:** Neutral to CHARTER's structure and positive for its clocks — tool_result turns carry timestamps, feeding step 3's first_seen_at ladder and therefore _domain_clock. The one thing to watch is mass: richer Event metadata increases what _render_member_block emits, and charter.mass() (charter.py:35-42) measures split thresholds in exactly those characters, so DOMAIN_MASS_CAP behaviour must be re-measured rather than assumed.

**Shipped, and what it does NOT reach (2026-08-09).** Steps (1) and (2) of the three verify.py prescribed are in: a `tool_result` is a turn, `HarnessSession.errors` has a writer, `Event.metadata` carries `{status, exit_code}` as an explicit tri-state (`ok` / `error` / `unreported`), and `failure` is a finding kind the extracting model can both see evidence for and emit. Step (3) — `execution_verified` provenance — is deliberately NOT in, and `verify_claim` still cannot say "this ran and passed". The rule as written ("promote a finding when one of its `derived_from` Events carries a zero exit code") promotes any finding that happens to be co-located with an unrelated passing command; a wrong provenance edge reads as evidence, so it stays reserved. The blocking gap is a taxonomy one, not an ingest one: no finding kind asserts "this passed", so nothing exists for a zero exit code to verify. See the ponytail note at the foot of verify.py for the shape a sound rule needs.

Two asymmetries any consumer of this data must carry, measured over 2,330 results on 103 transcripts: **"this ran and exited N" is Codex-only** (1,232 of 1,286 Codex results carry an exit code, 95.8%; Claude carries none anywhere), and **absence of `is_error` on a Claude result is not success** (present on 431 of 1,044, 41.3%; true on 37, 3.5%) — which is why the third state is named rather than left as a missing key. Steps 6-8 below inherit both: a `recovers` edge may anchor on `status == "error"` or a non-zero exit code, never on the absence of a failure signal.


### 6. A recovery edge and a minimal causal vocabulary — 'this succeeded after that failed' as executable structure rather than a log line  
**Cost:** small · **Borrowed from:** HiSkill (recovery edges — the owner's central interest); MAGMA (causal as an orthogonal view)

**Why now:** Causal is the emptiest rung on the ladder and the one the whole target stack (Decision -> Lesson -> Procedure -> Skill) sits on top of. Verified: of 57 edge types the only causal-adjacent ones are attributes_improvement_to (264), reports_result, resolved_by (17) and supersedes. Session transcripts are full of 'X failed, so we did Y' and none of it becomes structure. Once step 5 lands this is nearly free, because the detector is deterministic and session-local.

**Change:** research_graph.py:286-393 — add `recovers` (and, only if measurement justifies them, `caused_by` / `blocked_by`) to the ALLOWED_EDGE_TYPES set literal; the guard is automatic via ResearchEdge.__post_init__ (:420-422) and schema.md regenerates from the set (karpathy_layer.py:15-17). session_event.py:62-163 — mint `succeeded --recovers--> failed` when an erroring Event on tool T is followed, before any intervening success, by a succeeding Event on the same tool/file/command, with evidence naming both turn ids and metadata['basis'] recording how it was derived. No LLM, no wall clock, byte-idempotent, drill-down unchanged. Explicitly do NOT promote the 210 existing CausalClaim nodes into edges: classify_claim_type fires on the bare substring 'by ' (research_graph.py:2714-2722) and that precision will not survive becoming structure. Take the graph-structural half (merge/split/retire as operations) and reuse CHARTER's existing reorg-ledger vocabulary (spec:284-289) for it; leave RL alone until step 5 has produced real outcomes, and even then prefer the deterministic proxy 'session ended with a commit that survived to main' over a learned reward.
- Graphiti's learned / open ontology. Opening ResearchNodeType (74 members) or ALLOWED_EDGE_TYPES (57 members, verified) to LLM-minted entries destroys ResearchEdge.__post_init__'s constructor-level guard (research_graph.py:420-422) and verify_claim's predicate_not_in_ontology refusal (verify.py:564-575) — two of the capabilities Tesserae is measurably ahead on, and the reason adding a causal edge here costs one set-literal entry and would cost a migration elsewhere. The valuable half, an ontology-growth PROPOSAL loop, is already 90% built in schema_drift.py; finish that (step 12) and never open the enum.
- EvoGraph-R1's full retrieval-as-MDP with autonomous mid-reasoning graph mutation. A write executed inside a retrieval plan means a query mutates the corpus: it collides with compile_lock and makes `ask` non-repeatable, which is a direct hit on the determinism invariant rather than a tunable trade-off. Ship the 90% capture instead — the planner PROPOSES a graph_write payload the agent submits explicitly, so every mutation stays audited, externally anchored (agent_write.py:198-203) and content-hashed. The reward half has no substrate here at all.
- A full multimodal hypergraph. Per-block hyperedges over figures, tables and equations would multiply node count against a graph.json that is already 54.7MB and against a 48,000-char one-read bound, for a corpus where non-text blocks are a minority of evidence. The 95% capture is Artifact nodes joined by `part_of` and `evidenced_by` — edge shapes that already exist (research_graph.py:1360-1367) and that drill_down, verify_claim and CHARTER's briefs already understand without change. A new hypergraph substrate would require retrofitting all of them.
- MAGMA's four SEPARATELY STORED graphs. Tesserae should have four VIEWS over one graph, not four materialised stores. personalized_pagerank already removes zero-weight edge classes from the walk (ppr.py:159-163), so a view costs a weight map; four stores would quadruple the artifact surface, quadruple the byte-idempotence test matrix, and create four things that can disagree about the same fact.
- Promoting the 210 existing CausalClaim nodes into causal edges as a shortcut to the causal rung. classify_claim_type assigns that type by matching the substrings '활용', 'because', '통해' and the bare 'by ' (research_graph.py:2714-2722). That precision is tolerable for a node label and will not survive becoming structure that agents traverse and cite. Mint causal edges from Event ordering and outcomes (step 6) instead.
- Cognee's best-effort-everywhere ingestion posture. agent_write.py:19-22 already reasons about this explicitly — graph_from_llm_payload deliberately drops bad edges, 'the right call for a 137-doc LLM compile, the wrong call for a typed API where a dropped edge is a silent lie about what was recorded.' Two postures for two purposes, chosen deliberately. Adopting best-effort on the typed path would delete the refusal contract at agent_write.py:256-276, which is one of the things Tesserae wins on.
- Neo4j Agent Memory's 16-MCP-tool surface as a target. Tool count is not capability, and Tesserae's problem is the inverse: compile_context already takes 16 parameters and exposes 7 (mcp_server.py:2424-2450). Widening what existing tools can express beats adding tools, and it costs ~60 lines instead of a new surface to document in seven languages.
- Adopting a graph-database substrate. Out of scope by rule, and nothing in this audit argues for revisiting it — every gap found is wiring, extraction, or vocabulary, and not one of them is blocked by SQLite plus JSON artifacts. The substrate is what makes byte-idempotence testable in the first place.
- Adding valid_from / valid_to fields to ResearchNode and ResearchEdge to make bitemporality 'first class'. It puts derived state into the authoritative artifact, and the timestamp ladder can only produce what sources supply — on today's corpus ~94% of it would be the literal string 'undated' written into a graph.json that is already 54.7MB. Keep intervals in the projection; fix the coverage instead (step 3).

## Mechanisms extracted from primary sources


### A — Self-evolving and multimodal knowledge graphs

- **EvoGraph-R1 (GRAPHEDIT.DELETE, explicitly specified as 'soft removal by lowering the confidence scores of low-quality or contradicted elements')** — Soft delete by confidence decay instead of removal. Give every edge a mutable confidence scalar (EvoGraph-R1 uses sigma in (0,10] on each hyperedge) and make the retraction operation LOWER sigma rather than unlink the edge. Retrieval filters on sigma; the node stays in graph.json.
- **EvoGraph-R1 (visual subgraph construction: u_x = (id=x, type=image, mod=vis) is forced into V_e for every visual hyperedge, 'preventing visual facts from floating without source attribution')** — Source-anchor membership as a hard schema invariant. Require that every derived/extracted node's participant set CONTAINS the anchor node identifying the source unit it came from, enforced at write time by the extractor, not reconstructed afterwards.
- **EvoGraph-R1 (the action space and transition dynamics, with GRPO removed)** — The GraphEdit protocol driven by a deterministic planner rather than a learned policy: a fixed loop of {retrieve -> evaluate a coverage predicate -> emit typed edits (insert / supersede / soft-delete) -> stop} with an explicit step cap, replacing pi_theta with an if-then rule.
- **EvoGraph-R1 (Table 4 refinement statistics)** — Structural-drift audit across compiles: record node count, edge count, graph density, Watts-Strogatz clustering coefficient, and mean edge-embedding semantic similarity before and after each refinement pass, and diff them.
- **V-Mem (rounds, units, lanes)** — Round-as-retrieval-unit with max-over-units scoring: index each turn's spans individually but rank and return whole turns, where a turn's score is the maximum score over its constituent units.
- **V-Mem (scoring and fusion)** — Rank fusion (RRF, smoothing constant 60) over dense and lexical signals, fusing RANKS not raw scores, with a per-signal candidate pool of 20.
- **V-Mem (context assembly)** — Neighbor-window expansion of returned units: return each top-ranked turn wrapped with its immediately adjacent turns as one time-ordered span, window +/-1.
- **V-Mem (routing, image-round filter, aggregation branch)** — Cheap keyword-rule query gating with no LLM call, deciding what to search over, what to search with, and how much to return — plus a fail-safe: if a candidate filter would empty the result set, fall back to the unfiltered ranking.
- **V-Mem (memory construction — 0 LLM tokens, seconds, incremental and append-only)** — A zero-extraction verbatim retrieval lane running alongside the distilled-artifact lane: index every session span as-is at ingest with local encoders only, and defer all selection to query time.
- **MemLeak (the IPG's tau function)** — Deletion-affordance labelling on derived nodes: a per-node enum {addressable, linked, unreachable} over the existing derivation edges, answering 'if this source is retracted, what can actually be reached and removed'.
- **MemLeak (the 18.3% retained-text leakage channel and its entailment stratification: 17% entailed, 72% merely correlated)** — Correlation-aware supersession sweep: when a claim is superseded or retracted, scan RETAINED sibling claims for ones that entail or strongly imply it, and flag them (do not auto-delete) for review.
- **MemLeak (metric design and human validation)** — Judge-ensemble calibration rule for Tesserae's own eval harness: take majority vote across independent judges, treat AMBIGUOUS as negative, and treat non-unanimous verdicts as uncertain rather than as decisions.

**Not transferable:**

- GRPO policy training (EvoGraph-R1's entire optimization half). Requires trajectory rollouts, gradient updates, and 4x80GB A100s. Tesserae has no training infrastructure and no reason to acquire it. The learned object is only the action-selection and stopping rule; every data structure and edit operation survives without it.
- The trajectory reward function R(tau) itself. R_ans is token-level F1 against a GOLD ANSWER — Tesserae's corpus is documents and session transcripts with no gold answers to score against, so the signal cannot be constructed at any cost. Note the one exception worth stealing outright: R_struct is not a learned signal at all, it is a schema-validity check on each step (min(1.0, 0.5 * count of well-formed blocks)), which in a deterministic system is simply a lint rule.
- The efficiency term -lambda * sum_t c(a_t) and the whole notion of a learned action budget. This optimizes cost at INFERENCE time across multi-turn rollouts. Tesserae compiles in batch; there is no per-query action budget to trade against accuracy, and no way to learn lambda without the reward signal above.
- Query-conditional in-place graph mutation — EvoGraph-R1's UPDATE revising existing hyperedges mid-answer, and INSERT committing web-derived content during a query. This makes graph.json a function of query history and query order, which directly breaks byte-idempotence and determinism. The paper is also internally inconsistent here, calling the result both a 'persistent' hypergraph and a 'query-specific knowledge state'. Only compile-time edits, journaled and replayed in a fixed order, preserve Tesserae's invariants — and UPDATE must be re-expressed as supersession (new node + supersedes edge) rather than mutation, or the prior claim's bytes are lost and drill-down to it dies.
- WEBSEARCH as a graph-expanding action. Network content fetched mid-answer and committed to the graph injects a nondeterministic, unversioned, unhashed input into artifact bytes. (The underlying capability is fine through the normal ingestion path — fetch, hash, store as a source document, then compile — but not as an inline edit action.) The ablation shows this is EvoGraph-R1's second-largest contributor (-9.6 F1 / -11.2 acc when removed), so removing it is a real capability loss, not a free simplification.
- Learned joint multimodal embedding spaces (GME in EvoGraph-R1, SigLIP/CLIP-style cross-modal retrieval generally). Adds a vision-model dependency and a second embedding substrate. V-Mem's central empirical finding is that you do not need one: matching within a modality and crossing via shared-round membership beat cross-modal similarity search, and the modality gap persists even in a trained joint space. Tesserae is text; there is nothing to gain.
- An n-ary hyperedge substrate as a first-class storage type. Borderline rather than absolute — an n-ary fact can be reified as a node with typed participant edges in Tesserae's existing binary typed-JSON graph, which preserves the useful part (a fact with more than two participants and its own confidence and description). What should NOT be adopted is replacing the storage model to make hyperedges primitive.
- Content-aware semantic deletion via a VLM auditor (MemLeak's mitigation). Needs a vision model, is nondeterministic pass-to-pass, and paid its 12.0% -> 2.0% improvement by flagging 21.0% of all retained images for removal with the downstream recall cost never measured. For a knowledge base whose value is completeness, destroying a fifth of retained content to close a residual channel is the wrong trade. The deterministic half of the same idea — flagging correlated survivors for review without deleting them — is in the transferable list.
- Post-storage embedding scrubbing and privacy-aware encoders (MemLeak's proposed directions for the final 2.0% residual). These are representation-level interventions requiring model surgery or retraining. Open research problems, not integration work, and they target a multimodal channel Tesserae does not have.

### B — Procedural and skill memory (turning "failed → tried another strategy → succeeded" into executable structure)

- **HiSkill** — The direct recovery-edge mint rule: scan a session for the pattern (op_a, op_a, op_b) — a repeated ineffective action followed by a different action — and mint recovers_with with op_b (what worked) as SOURCE and op_a (what was stuck) as TARGET. If the two ops belong to different higher-level procedures, mint a second recovery edge at the procedure level as well.
- **HiSkill** — Two-source recovery minting: the deterministic sequence rule above, PLUS a semantic pass that builds a recovery query from a failing node's failure evidence (error text, missing precondition, non-progress signal) and scores candidate recovery nodes with score = 2*dense + 1*sparse + [Jaccard(pre(u),pre(v)) + Jaccard(post(u),post(v))], keeping edges above a fixed threshold with at most 4 incoming recovery edges per failure node.
- **HiSkill** — Typing edges by TRIGGER rather than by content: 'supports' fires BEFORE an action when a precondition is detected missing (preventive); 'recovers_with' fires AFTER failure, stagnation, or repeated ineffective behaviour has been observed (corrective). Same underlying advice, two different edges, because the agent needs them at different moments.
- **HiSkill** — Constrain the LLM's candidate set by edge type at execution time instead of asking it to reason freely: when the state shows stuck/repeated failure, present ONLY nodes reachable by recovers_with and instruct 'select only from candidates connected by recovers_with'; when the current step completed, present only can_follow/compatible_with successors; when a precondition is missing, present only supports neighbours.
- **HiSkill** — Canonicalization to a sorted-key normalized template: parse each action into action_type + structured args, replace context-specific entities with placeholders while retaining reusable literals, serialize as 'action_type|key=value|...' with keys SORTED, dedupe identical templates into one node accumulating a support count, and keep the raw action verbatim on the node for traceability.
- **HiSkill** — Structure is mined, the LLM only refines prose: frequent-subsequence mining (retain a candidate only if it appears in >=2 successful sessions AND spans >=2 steps) produces the procedure; the LLM is then given a prompt that explicitly forbids adding, removing, or reordering steps, or inventing arguments/states/tools, and may only rewrite name, description, and failure hints.
- **HiSkill** — Edges carry a support count and a confidence, with explicit fan-out caps and thresholds baked into induction rather than applied at output time: can_follow conf = count(u->v)/sum count(u->*), keep <=3 (skill) or <=2 (op) with count>=2 and conf>=0.2; compatible_with <=4 with count>=2; supports Jaccard-over-state-predicates conf>=0.45 with count>=2, <=4 per skill; recovers_with <=4 incoming per target.
- **HiSkill** — Direction-aware one-hop hydration: from seed nodes, follow decomposition edges FORWARD (a procedure's steps), and follow every other edge type BACKWARD — include v whenever (v, seed, l) is an edge. Rank the resulting neighbours by the same hybrid score and keep the top 2 per relation type.
- **HiSkill** — Rank node types SEPARATELY and take top-K of each, then union — rather than one global ranked list; and min-max normalize the dense and sparse scores independently before the lambda blend.
- **SkillGraph** — Counter-driven maintenance operators that read only outcome labels and topology: SPLIT a node whose success rate sits in a middling band despite heavy use (p in [0.15,0.4], n_use>=10) because it conflates sub-strategies; DEPRECATE a node that is frequently retrieved and consistently fails (n_use>=20, p<0.15); MERGE two nodes whose graph NEIGHBOURHOODS have Jaccard overlap >= 0.85, with the merged node inheriting the union of edges and duplicates resolved by max weight.
- **SkillGraph** — Present retrieved nodes in TOPOLOGICALLY SORTED dependency order, capped at K_max, computed over directional edge types only (excluding symmetric co-occurrence edges, which would introduce cycles).
- **SkillGraph** — Failure-driven node insertion: at a checkpoint, hand a BATCH of failed trajectories plus the CURRENT node set to a model and ask for at most m new nodes that address the identified failure causes — explicitly conditioning on what already exists so it proposes gaps rather than duplicates.
- **MAGMA** — A static intent-to-edge-type weight table used to steer traversal: classify the query intent, then bias the beam-search transition score by phi(edge_type, intent) = w_intent . onehot(edge_type), combined multiplicatively with semantic affinity.
- **MAGMA** — Fast/slow write split where the fast path is LLM-free (segment the event, embed, index, append one edge to an immutable temporal backbone, enqueue the id) and an asynchronous worker later pulls only the 2-HOP NEIGHBOURHOOD of that node and asks an LLM to infer the expensive relation types within that bounded scope.

**Not transferable:**

- SkillGraph's GRPO policy co-training — group-normalized advantage estimation, clipped surrogate objective, KL penalty to an SFT reference policy. This needs gradients, a trainable policy, rollout infrastructure and GPUs. Tesserae has no policy to train; its 'agent' is whatever model reads the compiled context. Note the consequence for evidence, not just engineering: EVERY number in the SkillGraph paper, including all four ablation rows, is measured inside the RL loop, so the paper never shows its graph helps an agent that is not simultaneously adapting to it.
- SkillGraph's progressive unlocking curriculum (topological levels gated by theta_unlock=0.6, warmup, level-by-level activation). Its purpose is to shape a LEARNING policy's exposure so it does not see compositional skills before mastering prerequisites. In a context engine the equivalent behaviour — hiding a known-good runbook from an agent because its level is not yet 'unlocked' — is actively harmful, and there is no learner whose curriculum it could be. Keep the topological LEVELS for ordering; discard the gating.
- SkillGraph's success attribution by prompt co-occurrence: a node gets +1 usage when retrieved into the prompt and +1 success when that rollout succeeds. This is only meaningful with many rollouts of the same task under a changing policy (G=8 per task, many epochs), and even there it credits every co-retrieved node for the outcome. Tesserae's sessions are one-shot, non-repeatable, and not counterfactually controlled, so p_hat computed this way would be noise dressed as a statistic — and it would then drive split/deprecate decisions. Adopt the OPERATORS but drive them from directly observed per-node outcomes (this runbook was followed and the command errored) rather than from co-retrieval.
- Environment rollout / online exploration to manufacture the corpus. HiSkill's ALFWorld graph is mined from 1262 successful and 1545 failed trajectories generated on demand in a closed, small action vocabulary; SkillGraph rolls out a base policy to bootstrap. Tesserae observes whatever sessions happen to occur and cannot re-run a task to get a failure. This does not block the mechanisms, but it does mean support thresholds calibrated on thousands of trajectories (and the frequent-subsequence mining that assumes a closed action vocabulary) will not port unchanged — the canonicalizer and the minimum-support constants need recalibration against real transcript volume.
- Multiplicative edge-weight decay as a mutable accumulator (w <- gamma*w at every checkpoint, prune below w_min, reinforce +alpha along successful paths). The IDEA of ageing relations is fine; the IMPLEMENTATION is a stateful counter mutated per checkpoint, which makes edge weights a function of how many times the compiler has run rather than of the corpus. That breaks byte-idempotence outright. Adopt only if reformulated as a pure recomputation at compile time — weight = f(observed counts, corpus-clock age of the evidence) — never as an accumulator carried across runs.
- Free-form LLM synthesis of a replacement node on merge and split (SkillGraph has the teacher model write a new unified skill from two originals, and decompose one skill into sub-skills). Each such rewrite is a paraphrase of an existing paraphrase, and after a few generations of merging the text has no traceable relationship to any source span — a direct violation of verbatim carry and drill-down. Transferable only in HiSkill's constrained form: detect the merge/split structurally, but have the model reorganize and label rather than restate, keeping the source spans and their hashes attached.
- MAGMA's physical substrate: a separate vector database alongside four separately maintained relation graph stores, with a storage abstraction layer for swapping graph/vector backends. Tesserae's typed JSON graph plus sqlite projection already covers dense and sparse retrieval; adding parallel stores is the substrate change explicitly ruled out, and MAGMA's own results give no evidence that the physical separation (as opposed to the logical edge typing) contributes anything.
- MAGMA as a source of procedural mechanism at all. It has no skill, procedure, retry, or recovery construct — it is episodic conversational memory evaluated on LoCoMo and LongMemEval question answering. Its inclusion in a procedural-memory group is a filing error; take the intent-dispatch table and the fast/slow write split and nothing else, and do not read its LoCoMo numbers as evidence about procedural memory.

### GROUP C — memory architecture and multi-view graphs. IMPORTANT NEGATIVE FINDING FIRST: the multi-view idea the brief describes (one memory projected simultaneously as semantic/temporal/causal/entity graphs, with query-intent classification selecting views and fused subgraphs merged without double-counting) does NOT appear in any of these four papers. Nothing here classifies query intent. Nothing here fuses subgraphs from parallel views, so the double-counting problem is never addressed — G-Memory concatenates insights and sparsified trajectories into one prompt with no dedup between them, and AriGraph concatenates triplets and episodes into working memory likewise. The closest things to "views" are AriGraph's two coupled memory types (semantic KG + episodic hypergraph over the same extraction event) and G-Memory's three ABSTRACTION TIERS (insight/query/interaction) — both selected by a fixed traversal order, not by query type. Consistency between them is maintained by construction, not by reconciliation: AriGraph's semantic view is mutable/current-state and the episodic view is append-only/immutable, joined by a hyperedge; G-Memory's tiers are related by containment (a query node owns its interaction graph; an insight node owns a supporting-query set). ON CAUSAL EDGES, the part you said everyone waves at: no paper in this group derives one. G-Memory's insight edge (i_m, i_n, q_j) — the only candidate — records that insight i_m was retrieved and in context when i_n was distilled during query q_j; that is retrieval-co-presence with a witness id, not causation, and the paper does not claim otherwise. AriGraph's episodic hyperedge is explicitly and self-admittedly "happened at the same time". Mem0-g's relation labels are LLM-asserted from an open vocabulary with no verification and no causal semantics. Mem^p has no edges at all. So the answer is: co-occurrence-derived in two cases, LLM-asserted in one, absent in one; nothing stronger anywhere. Also worth stating: none of these four uses reinforcement learning. Mem^p uses a benchmark environment's binary success oracle, which is not the same thing as a learned reward signal, and that distinction is what makes part of it salvageable.

- **G-Memory** — Supporting-set projection as view selection with NO intent classifier: Pi_{Q->I}(S_q) = {artifact a : supporting_sessions(a) intersect S_q != empty}. Store on every distilled artifact (runbook/gotcha/note) the explicit set of session ids that justify it; getting from 'these sessions are relevant to the question' to 'these artifacts are relevant' is then one set intersection.
- **AriGraph (episodic vertex + episodic hyperedge)** — Make the extraction EVENT a first-class node, joined by a hyperedge to every fact derived from it in that one event: e = (source_read_node, {derived_fact_ids}). The source node holds the verbatim excerpt; the hyperedge means 'these facts were all produced by this single read'.
- **AriGraph (outdated-triplet selection)** — Supersession via an explicit many-to-one REPLACEMENT MAP over a bounded candidate set. Candidates = only the existing facts incident to entities mentioned in the new source. The LLM must return [old_fact -> named successor] pairs; a retirement with no named successor is a parse error, not a silent delete.
- **Mem0** — Bounded four-op reconciliation against a retrieved neighborhood: for each candidate fact, fetch the top-s existing facts, then decide exactly one of ADD / UPDATE / DELETE / NOOP, with the op required to name the ids it acted on.
- **Mem0-g (LLM update resolver marks relationships invalid rather than removing them, expressly to preserve temporal reasoning)** — Soft-invalidate rather than delete: a superseded edge/fact is marked invalid with a timestamp and stays in the graph, so 'what did we believe at time T' is answerable without replay.
- **Mem0 (asynchronous summary generation module)** — Separate ingestion from consolidation: the summary/abstraction that ingestion reads is regenerated OFF the ingest path, so ingest never blocks on consolidation — BUT the artifact must pin the content hash of the exact summary version it consumed.
- **G-Memory (hop and k sensitivity sweeps)** — Cap graph expansion at 1 hop and top-k at k<=2, as a measured budget rule rather than a taste preference.
- **G-Memory (triple-indexed insight edge E_i subset of I x I x Q)** — An edge between two derived artifacts that carries its WITNESS: (artifact_older, artifact_newer, session_id), meaning 'the older artifact was in the agent's context during session S when the newer one was distilled'.
- **G-Memory (sparsifier + merge_rules prompts)** — Enforce verbatim carry MECHANICALLY, not by prompt trust: G-Memory's sparsifier is told 'strictly follow the original trajectory; absolutely no steps that are not in the trajectory should be added', and its merge pass is told 'all merged insights must be based strictly on the given inputs'. Add the post-hoc check the papers omit — every retained line must be a substring of the named source.
- **AriGraph (EmbedAndRetrieve embeds edges, so 'grill' retrieves ('bbq','used for','grilling'))** — Index and retrieve on FACT strings (the whole triplet/claim text), not on entity names.
- **Mem^p (Validation update policy)** — Gate distillation on a DETERMINISTIC, observable session outcome rather than distilling from everything — and record that outcome as an explicit auditable fact on the session node.
- **Mem^p (Proceduralization beats Trajectory beats Script beats none)** — Keep the verbatim trace RETRIEVABLE ALONGSIDE the distilled artifact, and serve both, rather than choosing one.

**Not transferable:**

- The multi-view architecture the brief was looking for is not in this group at all, so there is nothing to transfer: no paper here classifies query intent to select a view, and no paper fuses subgraphs from parallel views, which means the double-counting-on-merge problem is never even posed. G-Memory concatenates insights and sparsified trajectories into one per-agent prompt with no cross-dedup; AriGraph concatenates triplets and episodes into working memory, likewise. If Tesserae wants intent-driven view selection with dedup on fusion, it will be designing it, not porting it — and G-Memory's supporting-set intersection is the cheaper, more auditable alternative to an intent classifier anyway.
- Causal edges: nothing in this group derives one, so there is no mechanism to adopt. G-Memory's (i_m, i_n, q_j) is retrieval-co-presence with a witness id; AriGraph's episodic hyperedge is self-described as 'happened at the same time'; Mem0-g's relation labels are LLM-asserted with zero verification. Tesserae should NOT build a causal edge type on any of these — doing so would launder co-occurrence into causation, which is exactly the failure Tesserae's drill-down auditability exists to prevent. If a causal edge is ever wanted it needs an evidence standard none of these papers supplies (intervention, counterfactual, or at minimum a verifiable temporal-precedence-plus-mechanism claim traceable to a specific source span).
- Mem^p's Validation and Adjustment update loop as specified: both depend on the benchmark environment's ground-truth reward r = R(env, s_T, tau) in [0,1] to decide what to keep and what to rewrite. The authors concede in Future Work that real-world tasks have no such signal. Their proposed substitute — an LLM-as-judge scoring completion — would place a nondeterministic scorer directly in the write path, breaking byte-idempotency and determinism. Not RL, but still an oracle Tesserae does not have. Only the deterministic-outcome variant listed under transferable survives.
- Neo4j as substrate, plus Cypher-style traversal (Mem0-g). Everything Mem0-g actually does structurally — typed entity nodes carrying embedding and creation timestamp, labeled triplet edges with a validity flag, in-and-out traversal from anchor nodes to build a subgraph — is expressible in a typed JSON graph with a sqlite projection. Adopting Neo4j would be a substrate change purchasing no mechanism.
- Open-vocabulary LLM-invented relation labels (Mem0-g's relationship generator choosing lives_in / prefers / owns / happened_on per entity pair). Two independent disqualifiers for Tesserae: an open label set is not a typed schema and destroys the point of having one, and label choice is nondeterministic across runs, which breaks byte-idempotent artifacts directly. If relation labels are wanted they must come from a closed enum with a fail-loud 'unclassifiable' bucket.
- Mem0's asynchronous summarizer as literally specified — wall-clock-periodic refresh of an unpinned summary that ingestion then reads. The decoupling idea is worth having; this scheduling is not. An artifact whose content depends on when a background job last ran is not reproducible from the corpus, which contradicts both determinism (corpus clock, never wall-clock, in artifact bytes) and byte-idempotency.
- Mem^p's strong-to-weak model transfer as an operating principle: one figure, one direction (GPT-4o memory consumed by Qwen2.5-14B), +5% on one benchmark, no repeats and no variance reported. Interesting, nowhere near enough evidence to build a mechanism on.
- AriGraph's domain-hardcoded exploration heuristics (Algorithm 3 unexplored-exit detection, which relies on 'expert knowledge about what elements of the semantic graph can represent locations and exits'). Text-game-specific; no analogue in a document and session-transcript corpus.
- No RL infrastructure is required by anything in this group, which is itself the finding worth recording: G-Memory, AriGraph and Mem0 need no reward signal whatsoever, and Mem^p needs a binary environment oracle rather than a learned reward. So the 'attractive but needs a reward model' category — the thing to be most skeptical of — turns out to be nearly empty here. The real infrastructure hazards in this group are nondeterminism (LLM-chosen labels, unpinned async summaries, LLM-judge gating) rather than training.

### D

- **evolving-memory (ISA v1.0, 17 opcodes; CognitiveVM, 16 handlers, 500-instruction cap, per-handler side-effects audit log)** — Make the distillation LLM emit a small fixed OPCODE PROGRAM instead of a free-form JSON mutation blob, and execute it in a validating interpreter with a hard instruction cap and accumulate-then-commit semantics (VM builds results in memory; the caller persists only on clean completion, so a mid-program failure can never leave a half-written graph).
- **evolving-memory (vm/handlers.py, $LAST_PARENT resolution)** — A symbolic forward-reference token ($LAST_PARENT) that lets the LLM link to the node it just created without emitting an ID.
- **evolving-memory (ISA_VERSION + ISAVersionRegistry + version-aware parser with 3-mode fallback + Phase 0 'Cognitive Migration' + MigrationTransform protocol)** — Stamp a schema/prompt version on every derived node and keep a registry of migration transforms, then run a migration pass that re-derives old nodes under the new rules before the normal compile phases.
- **evolving-memory (ParentNode carries embedding_vector, ChildNode never does — enforced in the type, not by convention)** — Embed ONLY the summary/parent tier; reach detail nodes exclusively by structural edges.
- **evolving-memory (Phase 3 connector, cosine > 0.85 merge; success_count/failure_count/confidence/version on ParentNode) with the admission-gating variant from the survey (Mem0/FLEX LLM semantic gating on information gain)** — Merge-on-similarity with EVIDENCE ACCUMULATION rather than duplicate-or-overwrite: above a configured threshold, fold the new observation into the existing node — increment success/failure counts, append to a negative_constraints list, raise confidence — and record which sources were fused.
- **evolving-memory (EXTRACT_CONSTRAINT opcode, ParentNode.negative_constraints, 9-value FailureClass enum)** — Promote 'what not to do' from prose into a typed field: a negative_constraints[] list on the node plus a closed FailureClass enum, extracted by a dedicated instruction rather than hoped for in a summary.

- **the survey, §VI-A6 agent-based operator** — Return the retrieval TRACE as a first-class object: the bounded working memory of a multi-hop lookup — the question, the partial plan, the visited-node set, and for each piece of evidence which store and which path it came from.

**Not transferable:**

- RL-trained graph-maintenance policy (survey §VII-B): the agent 'autonomously learns an optimal policy for maintaining the graph' from downstream task-accuracy rewards, and MemEvolve applies the same feedback loop at the architectural level, dynamically adjusting storage structures and indexing at runtime. Requires a reward signal, an environment, and a training loop — none of which Tesserae has or should build. Worse, it is structurally incompatible with the determinism invariant: a learned policy means the same corpus compiles to different bytes depending on accumulated policy state, which breaks byte-idempotency testing outright. The attractive-sounding part ('memory that tunes itself') is exactly the part that cannot be had without the reward signal.
- Autonomous self-exploration to preemptively populate memory (survey §VII-B: AgentEvolver generating new sub-tasks to force navigation through unexplored states; KIMI K2.5 spawning parallel sub-agent swarms over disjoint branches). Needs an environment to act in and an open-ended budget for speculative LLM exploration. It also directly violates Tesserae's core contract: it manufactures synthetic experiences that have no source document and no session transcript behind them, so they cannot drill down to a content hash. A graph whose value proposition is auditable provenance must not contain invented evidence.
- Hypergraph storage (survey §V-D: E ⊆ 2^V, HyperGraphRAG's e_i=(e_i^text,{v1..vn}) with dual entity/hyperedge retrieval). Not an RL problem, but a substrate change of the exact kind ruled out of scope: every edge consumer, the SQLite projection schema, the artifact serializer, and Louvain community detection (defined on dyadic graphs — hyperedges need clique or star expansion first, which reintroduces the decomposition the hypergraph existed to avoid) would all have to change. The stated benefit, avoiding semantic fragmentation of n-ary facts, is real but small for Tesserae, because a typed JSON graph can already represent an n-ary fact as a node carrying typed role edges.
- FAISS or any ANN index as the primary retrieval substrate (evolving-memory's storage/vector_index.py). Approximate-nearest-neighbour results depend on index build order, float non-determinism, and library version, so anything an ANN index influences cannot appear in artifact bytes without breaking byte-idempotency. If embeddings are used at all they belong in the SQLite projection as a non-artifact ranking hint, with any artifact-visible ordering either exactly recomputed or pinned.
- A binary container format for the graph. First, the factual correction: NO SUCH FORMAT EXISTS IN THE FETCHED SOURCE — arXiv 2602.05665v1 is a survey, and its only use of 'binary' is 'binary graph' meaning a 2-ary/dyadic edge as opposed to a hyperedge. There is nothing here to adopt. Second, on the merits, Tesserae should decline anyway: a binary container costs git-diffability, costs plain-text byte-idempotency assertions, costs human-readable drill-down (an auditor can read graph.json; nobody can read a container without a tool that must itself be trusted), and costs the ability to review a graph change in a pull request. What it buys is size — which is not the binding constraint. The 48,000-char bound is a PRESENTATION budget on what an agent reads in one go, and on-disk encoding does not move it by one character. The one real benefit, random access without loading everything, Tesserae already has via its SQLite projection.
- ACT-R-style decay driven by lastAccessed and accessCount (openclaw #13991 enhancement 3: 'frequently accessed memories stay stronger, rarely accessed ones fade'). Access counters are wall-clock, per-installation runtime state. Letting them influence artifact bytes means the same corpus compiles differently on two machines and differently on Tuesday than on Monday — a direct violation of both the corpus-clock rule and byte-idempotency. It can live in the SQLite projection as a session-local ranking hint that never reaches an artifact, but not as a memory-strength model.
- Access-gated LLM re-summarization (evolving-memory Phase 4 Compactor: compact nodes where access_count < min_access AND len(summary) > max_summary). Rejected twice over — the gate is wall-clock runtime state as above, and the operation itself is a lossy re-summarization of an existing summary, which is precisely the paraphrase-of-a-paraphrase that Tesserae's verbatim-carry rule exists to prevent. Compaction, if wanted, must re-derive from the original source with its hash, never from the prior summary.
- The dual-embedding resolver (evolving-memory src/evolving_memory/resolver/dual_index.py). Listed here not because of infrastructure but because its own author measured it and published the negative result: 80% acc@1 versus 80% for plain description matching — no advantage. Commit message: 'Recover the dual-embedding resolver, and measure that it does not help.' Do not reimplement a mechanism whose only comparative measurement says it does nothing.
