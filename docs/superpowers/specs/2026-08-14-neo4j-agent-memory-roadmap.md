# Neo4j's agent memory — what to take, what it costs, and why the database stays out

**Status:** research finding, 2026-08-14. Roadmap; input to implementation PRs. Successor in form to `2026-08-08-cognitive-memory-roadmap.md`, which that format's twelve shipped steps have now closed.

## Verdict

**Adopt the capabilities into Tesserae's own file-based model. Do not integrate Neo4j as a storage backend, and do not promote kuzu into one.**

The comparison is lopsided in both directions, which is why the shortlist is short. Neo4j's own reference server, `mcp-neo4j-memory`, implements no temporal modelling at all — in 325 lines not a single timestamp, version or validity field; identity is the literal name string; relationship types are string-interpolated into Cypher and the caller-supplied entity type is f-stringed into a label position; `create_entities` writes each entity in its own auto-commit `execute_query` inside a Python for-loop, so it is not atomic; the only index is one lazily-created Lucene fulltext index over `:Memory(name, type, observations)`; and deletes are `DETACH DELETE`, `DELETE r`, and an in-place list filter. The third-party @knowall-ai server deliberately implements zero memory intelligence: `create_memory` calls plain `CREATE`, so duplicate calls produce duplicate nodes, dedup exists only as prose in `get_guidance`, `search_memories` does a full `MATCH (memory)` with no label or index predicate and substring-matches in Node.js after pulling every property, and memories are addressed by internal `id(n)` — which Neo4j deprecates as a stable identifier because it is reusable after deletion. Tesserae is ahead of both on every axis those two have, and ahead of `neo4j-graphrag-python` on fusion specifically: both of its hybrid rankers max-normalize each channel, so the top hit in each channel always normalizes to exactly 1.0 regardless of absolute quality, while `hybrid.py:48,431-471` runs real weighted RRF at k=60 over three lanes.

Only two systems are worth learning from — `neo4j-labs/agent-memory` (PyPI `neo4j-agent-memory` v0.5.0, with an embedded MCP server) and Graphiti — and what they have that Tesserae does not is three things: **a persisted vector index, a soft-merge tombstone, and a transaction-time clock.** Every one of the three is a data-structure decision, not a storage-engine decision.

Adopting Neo4j CE would cost more than it buys, and the cost is measurable rather than aesthetic. CE supports only property uniqueness constraints; property existence, property type and NODE/RELATIONSHIP KEY constraints are all Enterprise-only, so **Neo4j CE cannot make a property mandatory at the database level** — while `ResearchEdge.__post_init__` raises today on any type outside the whitelist, for free, and `llm_extractor.validate_research_graph` refuses to compile a graph carrying an unsupported node type, an unsupported edge type or a dangling endpoint. Moving to CE would trade a hard guarantee for post-hoc pruning, which is exactly what `neo4j-graphrag` does: a `GraphPruner` between extractor and writer recording `NOT_IN_SCHEMA` / `MISSING_REQUIRED_PROPERTY` into `PruningStats`, with `additional_*` flags defaulting permissive whenever the corresponding list is empty. The rest of the cliff compounds it — online backup/restore is EE-only and CE gets offline dump plus offline full import; CE runs only the slotted Cypher runtime; multiple and composite databases are EE-only; all access control beyond basic user creation is EE-only; autonomous clustering is EE-only and CE is single-instance with no HA; CDC, Neo4j's only native change feed, is EE-only and its own docs warn it is not an exact-copy mechanism; and GDS Community enforces a hard concurrency cap of 4 in code (`CONCURRENCY_LIMITATION = 4`). Against all that, what CE actually gives away for free is two indexes: Lucene HNSW vector indexes and Lucene fulltext indexes, both confirmed available in Community Edition, the latter covering relationships as well as nodes. Two indexes are worth building. They are not worth a database.

**On GPLv3, the verified part is narrow and the unverified part is the part people usually decide on.** Verified: `neo4j/neo4j` ships an unmodified GPLv3 `LICENSE.txt` with no Classpath or linking exception and contains only Community Edition source, with Enterprise shipping closed-source components absent from the repository; the GDS repo is likewise GPLv3, and distributed GDS is open sources plus closed sources, the GPLv3-buildable subset being "OpenGDS". **Not** verified, and not asserted here: the common claim that running CE as an external server over Bolt is safe while bundling its jars or linking it in embedded mode raises copyleft obligations. No Neo4j statement on network use versus distribution was found, and "linking in-process triggers copyleft" is a contested legal reading rather than a finding — a question for counsel, not a fact to plan against. The practical consequence points the same way regardless, and it is an argument *for* the capabilities path rather than a caveat on it: **if Tesserae never vendors, bundles, links or ships Neo4j, nobody ever has to answer the question.** "We would need legal advice to know whether our own distribution is compliant" is a permanent tax on every release, and no capability in this comparison is worth paying it. Learning from GPLv3 source is unrestricted — reading `apoc.refactor.mergeNodes` and then deliberately not copying its destructiveness is not a derivative work.

kuzu is the tempting middle path — MIT-licensed, embedded, no server, already in the tree — and it should be ruled on rather than left ambiguous. `KuzuResearchGraphStore` (persistence.py:160-267) is reachable only through `--kuzu-output` (cli.py:5995, 6208), is declared a dev/test dependency (pyproject.toml:72) with an in-file comment that two tests call it unguarded, and has no runtime story at all. Promoting it means owning a second authoritative store that can disagree with `graph.json`, and putting byte-idempotence — the one property no compared system even attempts — behind a database's write ordering. Step 12 rules it an export, beside `okf.py` and `graphiti_adapter.py`, which is what it already is.

The strategy: build two indexes as sidecars, add a transaction-time axis that never touches artifact bytes, give merges a back-reference, and take agent-memory's pending third state and read-audit posture. Twelve steps, eight of them small, none of them requiring a server.

## What only Tesserae has

- **True weighted reciprocal-rank fusion, not max-normalization.** `RRF_K = 60` (hybrid.py:48), `_rrf_ranks` (:431-448) emitting dense 1-indexed ranks with ties sharing a rank, `_fuse` (:451-471) accumulating `weight / (RRF_K + rank)` per lane. Score magnitude never leaks between lanes. Both `neo4j-graphrag` rankers normalize by max score *within the current result set*, so the top hit in each channel always normalizes to exactly 1.0 no matter how bad it is; the default `naive` ranker is not RRF at all (max-normalize, UNION, per-node MAX), and `linear` is `alpha·vector + (1-alpha)·fulltext` with **no default for alpha** — a non-truthy value raises. Tesserae's weights merge onto defaults (:547-553), so `{"embedding": 0}` disables one lane instead of zeroing all three.
- **Measured proof that no entity-merge threshold exists, written into the source that declines to use one.** `_build_embedding_review_items` (canonicalization.py:199-224) records the numbers against the shipped backend: `Edwin Aldrin`~`Buzz Aldrin` 0.665 — the true merge — against `GPT-4`~`GPT-3` 0.959, `Llama 2`~`Llama 3` 0.957, `BERT-base`~`BERT-large` 0.689, all false; adding descriptions makes it worse (`Buzz Aldrin`~`Neil Armstrong` 0.792 beats the target pair's 0.758). Every compared resolver auto-merges on a score — 0.8 defaults in `neo4j-graphrag`, a three-band 0.95/0.85 in agent-memory, domain-tuned cascades at 0.98/0.90, 0.95/0.85, 0.92/0.75. Tesserae emits review items and stops. That is a stronger empirical position than any tuned default, and it predicts the exact failure the 0.95 band would hit.
- **The retrieval layer knows whether its own vectors mean anything.** `active_embedding_backend` (hybrid.py:231-289) tries model2vec, then sentence-transformers, then emits a `UserWarning` naming `tesserae[semantic]` before falling back to the hash stub — and re-raises when an *explicit* backend fails to construct. `backend_is_semantic` (:292-294) lets callers refuse semantic work on a stub, which `canonicalization.py:233-235` and `federation.py` both do, and the candidate gate is backend-quality dependent rather than a flat cosine (`EMBED_CANDIDATE_MIN_COSINE = 0.30`, :64). Nothing in the Neo4j stack distinguishes "vector search ran" from "vector search ran on a placeholder"; agent-memory gates on a fixed cosine of 0.7 either way.
- **Type-scoped merge refusal, with the provenance reason inline at each refusal.** `_merge_same_type_aliased_duplicates` (research_graph.py:1076-1120) refuses five families outright — session findings (identical text in two sessions is two provenances), Events and distilled memory (session- and cluster-scoped, content-hashed ids), code symbols (two modules each with `def main()` are distinct), agent-layer types (identity is `agent_key`/`lineage_key`, not text), and Artifacts (two figures captioned "Pipeline overview" are distinct evidence). agent-memory's `type_strict=True` is the nearest analogue and only says "do not compare across types" — never "these particular types must not fuse even within themselves, because their identity *is* provenance".
- **Identity is content, not a string or a reusable integer.** `federation.identity_key` (:73-118) merges across projects only on verified metadata — `arxiv_id`, normalized repo, `content_hash` for SourceDocument and Artifact, `agent_key`, a `lineage_key` hashed from sorted transitive raw L0 member ids ("LLM wording is change detection only, never identity"), `(type, source_path, qualified_name)` for code — and returns `None` rather than guessing, with fuzzy and embedding matches excluded in the docstring because a false merge cross-contaminates answers. Against `mcp-neo4j-memory`, where identity is the literal name string, and KnowAll, which hands back internal `id(n)`.
- **A write contract that refuses rather than coerces.** `agent_write.py`: `DENIED_NODE_TYPES` is *derived* from the producer-owned type sets so a new code or agent type is denied the day it enters the vocabulary; `DENIED_EDGE_TYPES = CAUSAL_EDGE_TYPES`, because a `recovers` edge's whole value is that it was derived from two observed outcomes; `write_id` is `sha256` of the canonical payload with `written_at` deliberately excluded, so the same finding written twice returns `duplicate`; `EXTERNAL_ANCHORS` refuses any write whose provenance points only at the graph; `replay_agent_writes` (:507-537) replays **sorted by `write_id`**, so two agents appending in either interleaving converge on the same bytes. `mcp-neo4j-memory` creates no constraints and interpolates the caller's type into a label; KnowAll's plain `CREATE` duplicates on retry.
- **A retraction edge that extraction is forbidden to assert.** `RETRACTION_EDGE_TYPES` is the single source from which `ALLOWED_EDGE_TYPES`, `graph_filters.retracted_ids`, `temporal.INVALIDATING_PREDICATES` and the view partition all derive; `retracts` is subtracted from `EXTRACTABLE_EDGE_TYPES` not because a model cannot observe it but because a model *must not be able to silence things*. Nothing is deleted, `include_superseded=true` still reaches it, and one `suppressed_ids()` union backs all five read call sites. Strictly better than agent-memory's `merged_into` (which covers merges only, never "this is simply wrong") and in a different universe from `DETACH DELETE`.
- **Byte-idempotence as a tested invariant.** `tests/test_byte_idempotence_phase5.py` pins that two compiles produce byte-identical `graph.json`, that relocating the project does not change output, and that a compile *after an MCP read* is byte-identical — with sessions and LLM-minted findings. Every mutable scalar is quarantined in the `node_memory` table, whose own comment records the rule (graph_stores/sqlite.py:919-925). No compared system attempts this, and several make it impossible: agent-memory's SAME_AS carries `created_at`, `mcp-neo4j-memory` has no notion of a reproducible artifact at all.
- **The degenerate-interval guard, and coverage reported back to the caller.** `_boundary_precedes_start` (temporal.py:339-357) refuses to emit a `valid_to` that precedes its own `valid_from` — an interval empty at every instant, which would silently vanish from every time-travel query — and under-claims with `valid_to=None` instead. `facts_as_of` returns `undated_included` computed over the rows actually returned, and `as_of` combined with `current_only` is a hard error rather than a silent answer under one of two clocks. Graphiti records that an edge was invalidated; it does not check the interval it just wrote, and no compared system reports its own coverage.
- **Similarity materialized as scored edges in a sidecar, never as a merge.** `memory/associate.py` persists `shares_concept_with` links to an accumulating `.tesserae/` overlay with an atomic tmp+replace (:197-199) and never touches `graph.json` — which is precisely the shape *Neo4j's own field guidance* for entity resolution recommends (per-field `apoc.text.levenshteinSimilarity`, then `MERGE (a)-[:SIMILAR_ADDRESS {…scores…}]->(b)`, never `mergeNodes`) and precisely what its own shipped resolvers ignore.
- **An operational doctor and a severity-ranked lint that fail loudly when they cannot run.** 23 named `doctor` checks with safe autofixes, `_safe_detect` turning a crashing check into a finding rather than an exception, and `compile_lock` annotated report-only, **never kill**. In `lint`, a probe that cannot run yields `LINT_PROBE_FAILED` rather than a silent zero — added after swallowing one made "fully dated" and "never ran" identical in the report. `PROFILE` is the closest thing in the compared set, and it profiles a query, not the system.

## Where Tesserae is behind, measured

- **No persisted vectors.** `_embedding_scores` (hybrid.py:406-423) embeds query plus the entire candidate corpus on every call. Exactly three `.embed(` sites exist in the package and none caches. Neo4j ships HNSW k-ANN in Community Edition; agent-memory runs six per-type vector indexes. Biggest scaling deficit, and a present cost, not only a future one.
- **No inverted index.** `_bm25_scores` (:327-376) recomputes IDF over the whole corpus per query, against a Lucene fulltext index that is free in CE and covers relationships too.
- **Facts are barely searchable.** `search_facts` (temporal.py:630-643) counts query-term substrings inside `json.dumps(fact.model_dump())` — ids and metadata included — and `timeline` (:646-650) sorts on the raw `valid_from` string, so the literal `"undated"` sorts after every ISO date. On this graph that is 73% of facts, silently piled at the end.
- **Valid-time only, and the MCP schema says otherwise.** `TemporalFact` carries `valid_from` / `valid_to` / `valid_to_basis` / `invalidated_by` — one axis. Graphiti carries four timestamps and never takes event time and transaction time from the same clock. `mcp_server.py:801` advertises a "Bitemporal time-travel pivot"; `_apply_as_of`'s docstring (:316) repeats it.
- **`resolved_by` never closes an interval.** `INVALIDATING_PREDICATES` (temporal.py:49-53) is `{contradicts_claim, supersedes, invalidates} | RETRACTION_EDGE_TYPES`. `memory/contradiction.py:43` mints `resolved_by`, marks the loser low-confidence in the sidecar, and the projector ignores it — so an arbitrated loser still reads as live.
- **One pairwise pass blocks and the other does not.** `canonicalization` blocks by inverted token with a `max_block = 1500` cap truncating by sorted id (:260-263); `memory/supersede._candidate_pairs` (:347-359) is uncapped all-pairs Jaccard at 0.55, the same shape the `neo4j-graphrag` resolvers are criticized for. Arbitration (`_deterministic_verdict`:299-327) is newer session, longer name, id order — no confidence input.
- **Merge losers are dropped, not tombstoned.** `CanonicalizationResult.merged_nodes` is a complete loser→canonical map and is discarded at the end of compile; the builder's two merges never build one. A stale node id returns not-found where agent-memory would answer `merged_into`.
- **No durable review verdict.** Candidate pairs regenerate every compile; a human "these are different" is not remembered.
- **No read audit, no actor.** `bump_access` (memory/store.py:97) counts and stamps; `agent_distill`'s forgetting reads that signal and cannot say who produced it.
- **No query observability.** No `PROFILE` analogue, no per-lane cost, no plan.
- **A Windows concurrency hole.** `compile_lock` (locking.py:120-123) is `if fcntl is None: yield; return`, so the overlay append — the one write path that is not a single locked producer — is unprotected there.
- **59 unclassified entries in `.tesserae/`**, including three `graph.json.bak-*`, five orphaned `manifest.tmp.*`, and eight compile logs and pid files, with nothing declaring which are regenerable.
- **kuzu is vestigial.** One CLI flag, a dev-only dependency, two unguarded tests, no runtime story.

## Roadmap (ordered by leverage)


### 1. Persist the vectors — stop re-embedding the corpus on every query — and deliberately do NOT build an ANN index
**Cost:** medium · **Borrowed from:** Neo4j CE vector indexes (Lucene HNSW k-ANN, confirmed available in Community Edition, one index able to span multiple labels) — and, just as load-bearing, neo4j-graphrag's own filtered-search fallback as a warning

**Why now:** The single largest measured deficit in the comparison. `_embedding_scores` (hybrid.py:406-423) calls `backend.embed([query, *corpus_texts])` on EVERY query, re-embedding the entire candidate corpus each time; exhaustive grep finds exactly three `.embed(` call sites in the package (hybrid.py:413, canonicalization.py:267, federation.py:449) and not one writes or reads a cached vector. agent-memory maintains six per-type HNSW indexes queried through `db.index.vector.queryNodes`; Tesserae maintains none. Two of the three call sites already build the IDENTICAL text — `f"{n.name}. {(n.description or '').strip()}".strip()` appears verbatim in canonicalization.py:267 and federation.py:449 — so one cache serves all three by construction.

**Change:** A `node_vectors` table in `graph_stores/sqlite.py` beside `node_memory` (:919-935), inheriting its stated discipline verbatim — CREATE TABLE IF NOT EXISTS, SQLite-only, NEVER serialized into `graph.json`. Key on `(backend_name, backend_dim, sha256(embedded_text))`, not on node id, so a renamed node re-embeds and an unchanged node in a relocated project does not. Add a typed accessor module beside `memory/store.py`, which exists precisely so no call site embeds raw SQL. Route all three `.embed(` sites through one shared text-builder plus cache read.

THE RULING, and the reason this is medium rather than large: **do NOT adopt HNSW.** `hybrid_search` is filter-first by design — `candidate_filter` (hybrid.py:487) takes an arbitrary pre-filtered node iterable and the MCP layer uses it for type / kind / code-node / `include_superseded` filtering — and filtered vector search in `neo4j-graphrag` abandons the ANN index for exact brute-force KNN via `vector.similarity.cosine` anyway, while metadata filtering under hybrid search is categorically unsupported there (a bare `Exception`). Caching removes the cost that actually dominates, the model call; exact cosine over cached vectors preserves the filtering Tesserae is ahead on. Revisit ANN only when a profile from step 9 shows cosine rather than embedding is the cost.

**Mandatory companion (~15 lines):** `embedding_status` (mcp_server.py:4073) reports `vectors_cached`, `cache_hits`, `cache_misses` and the key's backend and dim, so a silently-cold cache cannot look like a fast path — the same fail-loud posture `active_embedding_backend` already takes when it warns before falling back to the hash stub.

**Composes with:** Steps 2, 6 and 7 all become cheaper the moment vectors are cached — the fact corpus, the shared blocker and the embedding review lane are three more consumers of one cache. Land this first or all three pay the full embedding cost again.


### 2. Facts become searchable as facts, with `undated` a first-class predicate rather than a string that sorts under 'u'
**Cost:** medium · **Borrowed from:** Neo4j full-text indexes — Lucene-backed, available in CE, covering RELATIONSHIPS as well as nodes; and Graphiti's `SearchFilters.valid_at`, typed `list[list[DateFilter]]` (an OR of ANDs) with `is_null` and `is_not_null` as first-class comparison operators

**Why now:** The temporal layer is Tesserae's deepest investment and its retrieval is the weakest thing in the system. `search_facts` (temporal.py:630-643) does `json.dumps(fact.model_dump()).casefold()` and counts how many query terms appear as substrings anywhere in that blob — ids, metadata and all — then sorts by that count. `timeline` (:646-650) calls it and sorts on `str(item.get("valid_from") or "")`, so the literal string `"undated"` sorts after every ISO-8601 date; on this project's own graph that is 73% of facts silently piled at the end of every timeline. Meanwhile `hybrid_search` — real RRF over three lanes, with `candidate_filter` and mode selection — sits one import away and has never been pointed at a fact. Neo4j's fulltext index covering relationships is the proof that the fact level deserves the same retrieval as the node level.

**Change:** `temporal.py` — replace the substring counter in `search_facts` with a call into `retrieval/hybrid.hybrid_search` over a fact corpus built from `subject_name / predicate / object_name / description` only, never the serialized blob, which is what makes an id fragment score today. Give both `search_facts` and `timeline` a `dated` filter with three states — `any` / `dated` / `undated` — mirroring Graphiti's `is_null` / `is_not_null` rather than inventing a fourth vocabulary for the same idea, and make `timeline` sort on a parsed key with undated rows bucketed separately and counted, never interleaved. Keep `undated_included` computed over the rows actually returned (`mcp_server._undated_included`:339) — already the corrected behaviour, and the reason this step cannot regress into reporting a corpus-wide number.

Do NOT adopt the DNF filter language. `list[list[DateFilter]]` is the right shape for a library taking arbitrary caller predicates and the wrong shape for two MCP tools whose whole value is that an agent can call them without composing a query.

**Composes with:** Step 3 adds a second pivot to exactly these two tools, so the filter argument shape decided here is the one `observed_as_of` slots into. Do them in this order or the second pivot lands on a substring counter.


### 3. A transaction-time axis in the sidecar — and stop calling one clock bitemporal
**Cost:** medium · **Borrowed from:** Graphiti's four-timestamp `EntityEdge` (`created_at`, `expired_at`, `valid_at`, `invalid_at`), and specifically its rule that `invalid_at` comes from the other edge's `valid_at` (event time) while `expired_at` comes from `utc_now()` (transaction time) — never from the same clock

**Why now:** `TemporalFact` (temporal.py:360-374) carries one axis with two endpoints plus `valid_to_basis` and `invalidated_by`. There is no transaction axis, so "when did we learn this" is unanswerable from any artifact — and the MCP schema already claims otherwise: `as_of_prop` (mcp_server.py:801) advertises a "Bitemporal time-travel pivot" and `_apply_as_of`'s docstring (:316) repeats it. A shipped description that overstates a shipped capability is the same defect class this repo has now corrected twice. Graphiti's two-clock rule is the exact discipline required, and Tesserae already has the harder half: `_source_ts` (temporal.py:248) is a documented source-derived ladder that deliberately excludes `last_accessed_at` because a wall clock in artifact bytes broke byte-idempotence four times.

**Change:** Transaction time lives ONLY in SQLite, never in `graph.json` — the `node_memory` precedent (graph_stores/sqlite.py:919-925) is binding, and this is the same class of value. Add a `fact_observed` table keyed on the fact's stable key `(subject_id, predicate, object_id)` recording `first_compile_at` and `last_seen_compile_at`, both stamped at the compile boundary rather than per row, so the clock ticks once per compile and cannot vary within one. Populate it from `TemporalFactProjector` (temporal.py:387) as a write-through. Expose `observed_as_of` on `search_facts` / `timeline` as a SECOND pivot that composes with `as_of` — "what did we believe on DATE, as we knew it on DATE2" — never merged into the existing one, which is the same refusal `as_of` + `current_only` already makes. Fix `as_of_prop` and `_apply_as_of` to say valid-time.

Determinism: `graph.json` and `temporal_facts.jsonl` bytes are untouched, so both idempotence suites stay green by construction. Pin that with an explicit negative assertion naming `fact_observed`, not with "the suites are green" — that is precisely the blind spot that hid the step-12 metadata leak, and both suites were structurally unable to see it. Do NOT add `valid_from` / `valid_to` / `observed_at` fields to `ResearchNode` or `ResearchEdge`.

**Composes with:** Step 5 gives `valid_to_basis` a new value and step 3 gives the projector a new write; both touch `TemporalFactProjector.project` and should land in a known order to keep the fact-level byte comparison interpretable.


### 4. The merge ledger — a dead node id resolves to its survivor instead of returning nothing
**Cost:** small · **Borrowed from:** neo4j-labs agent-memory's soft-merge tombstone: `merged_into` / `merged_at` on the loser, MENTIONS re-MERGEd onto the target, `SAME_AS` transferred with `match_type: 'merged'`, the loser's name appended to `aliases`, and every later read filtering `merged_into IS NULL`

**Why now:** The information already exists in memory and is thrown away at the end of every compile. `CanonicalizationResult.merged_nodes` (canonicalization.py:68, populated :104-108) is a complete `loser_id -> canonical_id` map — strictly more than the aggregate `ResolutionStats` (`number_of_nodes_to_resolve`, `number_of_created_nodes`) that `neo4j-graphrag` resolvers report, and strictly more than `apoc.refactor.mergeNodes` leaves behind, which is nothing at all: every node after the first is deleted, no tombstone, no back-reference, no record, survivor always `nodes[0]`, and each relationship deleted and recreated so element ids change. But Tesserae never writes its map anywhere, and the builder's own merges (`_merge_same_type_aliased_duplicates` research_graph.py:1051, `_merge_cross_type_duplicates` :1197) never build one. Today an agent holding a node id from a previous compile whose node lost a merge gets a not-found, with no way to learn it was absorbed — the exact gap `drill_down`'s `absorbed` verdict already fills one layer up for distillates.

**Change:** Write `.tesserae/merge-ledger.json` from the compile itself — not out-of-band node metadata; the step-12 ruling stands, since an out-of-band key survives an incremental compile and vanishes on a full one — carrying `{loser_id, survivor_id, basis: exact-key|aggressive-key|cross-type, loser_name, loser_type}`. Populate from `merged_nodes` plus new equivalents returned by the two builder merges. Teach `node_context`, `get_handle` and `_find_node` (mcp_server.py) to resolve a miss through the ledger and answer `{status: "merged", merged_into: <id>}` rather than raising.

Do NOT store the loser's description or metadata: the graph is recompiled from sources, so those are recoverable from the source, and copying them in would put derived state somewhere that must stay derivable. One lesson taken from the other direction — agent-memory's `:ConsolidationRun` audit node is only ever CREATEd and no code path ever reads one back, so **the acceptance test for this ledger is that a read surface consumes it**, not that it exists.

**Composes with:** Step 10's registry classifies this as `derived` (regenerable from a compile), which is what distinguishes it from step 7's ledger, classified `accumulated` and never regenerated. Getting that distinction wrong is how a human verdict gets deleted by a cleanup.


### 5. `resolved_by` closes an interval — wire the one memory pass the temporal projector ignores
**Cost:** small · **Borrowed from:** Graphiti's contradiction resolution, which is interval-overlap-aware — it skips non-overlapping validity intervals before invalidating, and only invalidates when the candidate's `valid_at` is strictly earlier

**Why now:** A silent hole in Tesserae's own fail-loud contract. `INVALIDATING_PREDICATES` (temporal.py:49-53) is `{contradicts_claim, supersedes, invalidates} | RETRACTION_EDGE_TYPES` — verified in source, and `resolved_by` is not in it. `memory/contradiction.py:43` mints exactly that edge from the losing claim to the winner, and the loser gets `confidence="low"` in the sidecar, but its validity interval is never closed. So the one memory pass that explicitly arbitrates a contradiction produces a fact `facts_as_of` still reports as live. That is not a coverage gap, it is a wrong answer. Payoff is honestly small today — 17 `resolved_by` edges on the live graph — and grows exactly as contradiction resolution runs more; it is placed here on correctness and cost, not on volume.

**Change:** `temporal.py:49-53` — add `RESOLVED_BY_EDGE`, imported from `memory/contradiction.py` rather than re-spelled, so one source of truth survives; `valid_to_basis` gains `"resolved_by"` in its enumerated set (:374). Take Graphiti's overlap guard while wiring it: `_boundary_precedes_start` (:339-357) already refuses a `valid_to` preceding its own `valid_from` and falls back to `None`, which covers the degenerate case; add the strictly-earlier check so a loser dated AFTER its winner does not get a boundary invented for it.

**Composes with:** The step-7 view partition test will fail until `resolved_by`'s view assignment is confirmed — that is the loud gate working exactly as it did for `retracts`, and it should be treated as the step's own checklist rather than an obstacle.


### 6. One blocking layer for every pairwise pass, and confidence before recency in supersede arbitration
**Cost:** medium · **Borrowed from:** agent-memory's `CompositeResolver` cascade — Exact(1.0) → Fuzzy/RapidFuzz(0.85) → Semantic(0.8), first match wins, `type_strict=True` never comparing across types, `max_candidates=10` — and its highest-confidence-wins conflict resolution

**Why now:** Tesserae runs two pairwise passes over the same graph and only one of them blocks. `canonicalization._build_review_items` (:155-197) does inverted-token blocking on tokens ≥ 3 chars with a `max_block = 1500` cap that truncates **by sorted id, never by iteration order** (:260-263) — materially better than `SpaCySemanticMatchResolver` / `FuzzyMatchResolver`, which block only by label, pull all text into Python and compare all pairs with `itertools.combinations` with no cap at all. But `memory/supersede._candidate_pairs` (:347-359) *is* that uncapped all-pairs shape: Jaccard over name strings at threshold 0.55 (:366), documented as such in the module header (:11). And `_deterministic_verdict` (:299-327) arbitrates on newer `session_id`, then longer name, then id order — no confidence input at all, while the memory layer computes one.

**Change:** Extract the blocking from `canonicalization` into a shared helper and call it from `_candidate_pairs`; keep the `max_block` cap and its sorted-id truncation, which is what makes the capped path deterministic. Gate the shared blocker with Tesserae's type-scoped refusals (research_graph.py:1076-1120) rather than agent-memory's `type_strict`, which only says "do not compare across types" where Tesserae says "these particular types must never fuse even within themselves". Then add confidence as the FIRST arbitration key in `_deterministic_verdict`, ahead of session recency, keeping the existing tiebreaks so the function stays pure.

THE CONSTRAINT that makes this medium rather than small: `supersedes` edges land in `graph.json` (3,194 of them), so the confidence read MUST come from `reinforce`'s re-derived score — pure, recomputed each compile, no cumulative counter — and must NOT come from `node_memory.decay_score` or `access_count`, which are MCP-accumulated read state. Reading mutable read state into an artifact edge would make `graph.json` a function of query history: the byte-idempotence blind spot in its purest form. Pin it with a compile → MCP reads → recompile byte comparison, the shape `tests/test_byte_idempotence_phase5.py:176` already uses.

**Composes with:** Step 1's cache is what makes an embedding rung in the cascade affordable at all; without it, adding a semantic tier to supersede would re-embed the corpus per pass. Step 7 consumes the same candidate pairs this step now generates once instead of twice.


### 7. Candidate pairs become durable, with a third state, so "no, these are different" is remembered
**Cost:** medium · **Borrowed from:** agent-memory's three-band policy — 0.95 auto-merge / 0.85 flag as `SAME_AS status='pending'` / else distinct — taking ONLY the pending band; and Neo4j's own field guidance for entity resolution, which materializes similarity as scored edges and never calls `mergeNodes`

**Why now:** `_build_review_items` and `_build_embedding_review_items` (canonicalization.py:155-224) regenerate the same candidate pairs on every compile, and `ReviewQueue.apply_decisions` (:396) consumes verdicts that have nowhere durable to live. A human who answers "these are different" is asked again next compile, forever, and the queue's length is a function of corpus size rather than of unresolved work. Tesserae already has the right mechanism one module over: `memory/associate.py` persists discovered links to an ACCUMULATING `.tesserae/` overlay with an atomic tmp+replace (:180, :197-199) — the same "similarity is a scored edge, never a merge" shape Neo4j's field guidance recommends and its own shipped resolvers ignore.

**Change:** Reuse `associate`'s overlay shape for a `candidate_same_as` sidecar carrying `{a, b, score, source: token|embedding, status: pending|confirmed|rejected, decided_by, decided_at}`, written atomically the same way. `_build_review_items` filters out pairs already `rejected` and re-surfaces `pending` ones with their prior score, so score drift is visible rather than silent. `lint` gains a `PENDING_REVIEW` probe at `info` beside `SUGGESTED_SUBTYPE` (lint.py:1305), reading one JSON file so lint stays offline and deterministic; an absent ledger is silence, an unreadable one is `LINT_PROBE_FAILED`.

Two explicit refusals. **Do NOT add an auto-merge band at any threshold** — canonicalization.py:199-224 carries the measurement that kills it, and there is nothing to tune. **Do NOT model the record on agent-memory's documented reviewer fields**: `reviewed_by` / `reviewed_at` appear only in its prose documentation and return zero hits across its source, where `CREATE_SAME_AS_RELATIONSHIP` writes exactly four properties (confidence, match_type, created_at, status). `decided_by` / `decided_at` here are Tesserae's own and must be written by whoever applies the decision, not carried as aspirational keys.

**Composes with:** Step 10 classifies this ledger `accumulated` — never regenerated, never cleaned — which is the distinction that keeps a `reset` from discarding human verdicts.


### 8. Read auditing with an actor — opt-in, default off, and stamped with the version that wrote it
**Cost:** small · **Borrowed from:** neo4j-labs agent-memory's `:MemoryReadAudit`, linked as `(:User)-[:PERFORMED_READ]->(:MemoryReadAudit)`, deliberately caller-invoked and default off; plus its `@unit_of_work(metadata={'app': f'neo4j-agent-memory_v{version}'})` tagging on every read and write transaction

**Why now:** `bump_access` (memory/store.py:97) increments `access_count` and stamps `last_accessed_at` with no actor — and that read-access state is what drives `agent_distill`'s LRU forgetting-by-disuse. So the demand signal deciding what gets absorbed cannot say who created the demand, which makes one chatty agent's reads and a human's reads indistinguishable inputs to forgetting. Tesserae already ships the exact shape one surface over: `drill_down` appends a row to the `drill_down_audit` sidecar (agent_view.py:49, :336) on the one path that pierces distilled visibility — mandatory there rather than opt-in, which is the correct asymmetry and stays.

**Change:** Generalize the `drill_down_audit` shape into a read-audit ledger carrying `{tool, actor, node_ids, at, tesserae_version}`, written only when `TESSERAE_READ_AUDIT` is set — default off, matching agent-memory's posture, because an always-on ledger across ~32 MCP tools is a write amplifier on a read path. Take the version stamp unconditionally, on every audit row in the system including step 4's merge ledger and step 7's candidate ledger, so a bad release is attributable after the fact. Keep it out of `graph.json`. Leave `_bump_nodes_access`'s existing read-only-invariant exclusions exactly as they are (mcp_server.py:3336, "READ-ONLY invariants: no _bump_nodes_access") — the point is to attribute the reads that already count, not to make more reads count.

**Composes with:** Step 9's per-lane profile and this ledger answer adjacent questions — what a query cost, and who asked. Sharing one row shape between them is cheaper than two, and the `tesserae_version` stamp belongs on both.


### 9. A retrieval PROFILE — per-lane cost accounting, opt-in because measuring costs
**Cost:** small · **Borrowed from:** Neo4j's `PROFILE`, which reports actual Rows, DB Hits, Memory, Page Cache Hits/Misses, Time and Indexes Used per operator — and whose own docs warn it consumes extra resources, which is why it is opt-in there too

**Why now:** Tesserae cannot profile its own query. The gap analysis behind this roadmap downgraded its own largest finding — "no vector or BM25 index" — to Medium confidence for exactly that reason: it was established by exhaustive grep of `.embed(` call sites and the absence of any vector sidecar, not by measuring a live query, because there is no way to measure one. `hybrid_search` runs three lanes (`_bm25_scores`:327, `_lexical_scores`:384, `_embedding_scores`:406) and reports only which `mode` ran. Without this, step 1 ships unproven and can regress silently. The ordering is deliberate and worth stating: this sits *after* the cache rather than before it because the deficit was already established by construction — the corpus is re-embedded on every call, and no measurement is needed to know a cache removes that.

**Change:** An opt-in `explain=true` on `search_nodes` and `compile_context` returning per-lane `{candidates_in, scored, embed_calls, cache_hits, cache_misses, ms}` plus which lane contributed each winner. The per-item lane attribution is nearly free: `ContextCitation.via_views` already carries per-lane provenance and `_fuse` (hybrid.py:451-471) already knows each lane's contribution before it sums. Adopt PROFILE's own warning verbatim in the tool description — the flag costs time — and keep the default response byte-identical when `explain` is unset, following the same default-off discipline `scope` / `strategy` / `tame_hubs` / `recency_weight` already follow, and the same serialize-away discipline `via_views` uses.

Do NOT build a query planner. There is no plan to report, and reporting one for a fixed three-lane pipeline would be theatre.

**Composes with:** This is the acceptance evidence for step 1 and the regression guard for step 6 — a shared blocker that quietly stops blocking shows up here as a candidate count, and nowhere else.


### 10. Namespace the sidecars before this roadmap adds four more
**Cost:** small · **Borrowed from:** agent-memory's `SchemaManager`, which namespaces its schema objects by name prefix (`_is_memory_schema` matches 13 prefixes) so `drop_all()` and `get_schema_info()` touch only library-owned schema

**Why now:** `.tesserae/` holds 59 entries on this project today and they are not distinguishable by ownership: `graph.json` beside three `graph.json.bak-*` files, five orphaned `manifest.tmp.*.*` files, eight `compile-*.log` and `.pid` files, plus `temporal_facts.jsonl`, `hierarchy.json`, `discovered_links.json`, the drill-down audit, the schema-drift ledger, `sqlite.db`, `harness_sessions.db`, `session_chunks.db` and two lock files. Nothing declares which are compiler outputs safe to regenerate, which are accumulating human state that must never be regenerated, and which are crash debris. Steps 4, 7 and 8 each add another accumulating ledger and step 1 adds a cache table — four more entries into a directory where nothing can currently be reset without reading the source to find out what it is. Do it before, not after.

**Change:** A `sidecars.py` registry declaring every `.tesserae/` artifact as `{name, owner, class: derived|accumulated|cache|scratch, safe_to_delete}`, and one `_is_tesserae_sidecar` predicate over it — the direct analogue of `_is_memory_schema`. Point `doctor`'s existing hygiene checks at the registry so orphaned `manifest.tmp.*` and stale `.bak-*` files become named findings with safe autofixes rather than accumulating unnoticed. A `derived` artifact is regenerable, an `accumulated` one is never touched, a `cache` one is safe to drop, a `scratch` one is debris. Enforcement is that a new sidecar with no registry entry fails a test — the same partition-completeness posture `tests/test_views.py` uses for edge types, which is the mechanism that has already caught two omissions automatically.

Do NOT add a `reset` command in this step. The registry is the precondition for one, and a destructive verb over a directory that has not yet been classified is the wrong order.

**Composes with:** Steps 1, 4, 7 and 8 each register exactly one entry, one line each. Landing this first turns four registrations into a checklist item; landing it last turns them into a retrofit.


### 11. Close the Windows concurrency hole in the overlay append
**Cost:** small · **Borrowed from:** `apoc.refactor.mergeNodes`, which acquires write locks on all participating nodes up front, sorted by element ID, for deadlock-safe concurrent merges — the discipline, not the code; and the verified fact that plain `MERGE` guarantees pattern existence, not uniqueness, and duplicates under concurrency without a uniqueness constraint

**Why now:** `compile_lock` (locking.py:96) opens with `if fcntl is None: yield; return` — on Windows it is a no-op — and `record_agent_write` (agent_write.py:753-754) takes `agent-writes.lock` for a ~1 ms read-dedupe-append precisely so it does not queue behind a multi-minute compile. The overlay is the one Tesserae write path that is not a single locked producer. The identity half of the problem is already solved better than Neo4j solves it: `write_id` is a content hash, `_read_records` keys on it, and `replay_agent_writes` (:507-537) replays sorted by `write_id`, so a duplicated record is idempotent — exactly the uniqueness guarantee plain `MERGE` lacks. The residual hazard is narrower and worth naming precisely: two unsynchronized appends can interleave into a torn JSONL line, and replay skips an unusable record with a stderr warning (:519-532) rather than failing, so on Windows a lost agent write degrades into a message nobody reads.

**Change:** `locking.py:120-123` — replace the silent no-op with an `msvcrt.locking` branch, or failing that an `O_EXCL` lockfile with bounded retry raising the same `CompileLockHeldError`. If neither is acceptable, the no-op must at minimum warn once per process naming the exposure, because a documented no-op that says nothing at runtime is the silent-degradation pattern this repo has now fixed three times. Independently of platform: `replay_agent_writes`'s skip should emit a lint finding as well as a stderr line, so a lost write is visible in `lint_report` rather than only in a log. Acquire in a fixed order if the write path ever takes more than one lock — the `mergeNodes` sorted-element-id discipline — though today it takes exactly one and `compile_lock`'s docstring already records that no cycle is possible.

**Composes with:** Nothing structurally. Placed here rather than higher because the loss mode is platform-specific and the identity contract already contains the blast radius; placed on the list at all because the failure is silent, which is the one property this codebase does not tolerate.


### 12. Rule on kuzu: it is an export, not a store
**Cost:** small · **Borrowed from:** Nothing. This is the architecture verdict discharged as code, so the question stops looking open

**Why now:** A half-wired storage backend is what makes "should Tesserae adopt a graph database?" look like an unanswered question when the answer is no. `KuzuResearchGraphStore` (persistence.py:160-267) is reachable only through `--kuzu-output` (cli.py:5995, 6208), `import_kuzu` (:269-274) raises a helpful error when the package is absent, and pyproject.toml:72 declares `kuzu>=0.6` a dev dependency with an in-file comment that two tests call it unguarded — so its only runtime story is a flag whose dependency users do not have installed. Meanwhile two genuine one-way exports already exist and are correctly shaped: `okf.py` (versioned bundle, round-trippable via `read_okf_bundle`:581, refuses to emit absolute paths) and `graphiti_adapter.py` (projects every `TemporalFact` into a `GraphitiEpisode`, raises `GraphitiSyncUnavailableError` when `graphiti_core` is missing). kuzu belongs beside them.

**Change:** Move `KuzuResearchGraphStore` next to the other exports, rename the CLI surface to match them, document it as an export in the same sentence as OKF and Graphiti, and guard the two tests that call it unguarded. Do NOT promote it to a runtime store: a second authoritative store can disagree with `graph.json`, and byte-idempotence — enforced by `tests/test_byte_idempotence_phase5.py` and attempted by no compared system — would then depend on a database's write ordering rather than on a sorted-key pure function.

Fix one honesty defect in passing while the exports are on display: `graphiti_adapter.episodes()` (:53-88) calls `TemporalFactProjector().project(graph)` with no `memory_by_id`, so every exported confidence is the heuristic label rather than the reinforced value — an external consumer is reading numbers Tesserae itself does not use.

If deletion is preferred to promotion, that is also an acceptable discharge of this step. What is not acceptable is leaving it ambiguous for another release.

**Composes with:** The verdict. Every other step in this roadmap assumes files plus SQLite; this is the one that makes that assumption legible in the tree rather than only in a document.


## Deliberately not copying

- **A graph-database substrate, in any edition.** Neo4j CE cannot make a property mandatory — property existence and NODE/RELATIONSHIP KEY constraints are Enterprise-only — which is a guarantee `ResearchEdge.__post_init__` and `validate_research_graph` provide today for free and at construction time. Adopting CE would trade that for `GraphPruner`'s post-hoc drop, and would additionally accept: offline-only backup and import (online backup, incremental import and store copy are EE), the slotted runtime only (pipelined and parallel are EE), one database (multi and composite are EE), no RBAC or property-based or sub-graph access control, single-instance with no HA, no CDC, and GDS Community's hard concurrency cap of 4 enforced in code. The two things it would buy — HNSW vector indexes and Lucene fulltext, both genuinely free in CE — are steps 1 and 2 as sidecars. And on licensing, the GPLv3 facts are verified (unmodified GPLv3, no linking exception, CE-only repository) while the usual network-use-versus-distribution conclusion is not; not integrating means nobody has to resolve it.
- **Promoting kuzu, or any embedded engine, to a runtime store.** Two authoritative stores can disagree about the same fact, and byte-idempotence would move from a sorted-key pure function to a database's write ordering. MIT licensing removes the legal objection and none of the architectural one.
- **`apoc.refactor.mergeNodes` semantics.** Destructive by design: every node after the first deleted, survivor always `nodes[0]`, no tombstone or back-reference or record, `properties:'discard'` documented to throw conflicting values away, merge config keyed by property-name regex with uncovered properties overwritten by default, and every relationship deleted and recreated so element ids change. Take the tombstone (step 4), never the mutation — Tesserae's merge is a pure function of the input graph, re-derived each compile, so there is no accumulated destructive history to recover from.
- **Auto-merge similarity bands at any threshold** — agent-memory's 0.95/0.85, `neo4j-graphrag`'s 0.8 defaults, the domain-tuned 0.98/0.90, 0.95/0.85 and 0.92/0.75 cascades with their auto-merge-rejection and orphan-rate quality signals. canonicalization.py:199-224 carries the measurement that no cosine threshold separates the true merge from version and family siblings, so there is no threshold to tune. The pending band (step 7) is the transplantable half.
- **Single-pass greedy cluster consolidation, and hand-rolled transitive closure.** Stopping at the FIRST intersecting set lets transitively-linked pairs land in two clusters sharing a node id, each merged by its own `mergeNodes` call; `_consolidate_sets` does connected components in Python rather than with a proper algorithm. Tesserae's key-to-owner maps and union-find are correct by construction and the two-clusters bug is structurally impossible — do not replace them with a pairwise-closure pass to gain a feature.
- **`SimpleKGPipeline`'s extraction identity, and post-write resolution.** Prefixing every extracted node id with its chunk id means the same entity in two chunks becomes two nodes, and the resolver wired last in the DAG re-queries Neo4j for `(:__Entity__)` rather than seeing in-flight extraction results. Tesserae dedups during construction — `add_node` collapses on `stable_id`, and the two merge passes run inside `build()` — which is the fix, not a variation.
- **Post-hoc schema pruning as the enforcement model.** Recording `NOT_IN_SCHEMA` / `MISSING_REQUIRED_PROPERTY` into stats while defaulting `additional_*` permissive whenever the corresponding list is empty is silent-drop-by-default. Tesserae raises. Keep raising.
- **Any free-form query surface.** `VectorCypherRetriever` and `HybridCypherRetriever` append the caller's `retrieval_query` verbatim to the index-search prefix with `node` and `score` in scope and no parsing, sandboxing or validation; external-store retrievers require an id-property join on both sides. `Text2CypherRetriever`'s `EXPLAIN`-based read-only plan check is genuinely the right way to make such a surface safe — a plan-level check rather than a keyword blocklist — and it is the right way to secure a capability Tesserae is better off never having. `ask` / `query` route through fixed typed paths and have no injection surface to defend.
- **ANN indexing in this cycle.** `hybrid_search` is filter-first, and `neo4j-graphrag` itself abandons the ANN index for exact brute-force KNN the moment a metadata filter appears — while refusing metadata filtering under hybrid search entirely with a bare `Exception`. Cache the vectors, keep exact cosine, and revisit only when a profile says cosine is the cost.
- **Highest-confidence-wins conflict resolution, and MERGE-on-name identity.** agent-memory resolves conflicting facts by confidence rather than recency and **discards the losing object with no history edge**; `mcp-neo4j-memory`'s entire deduplication is filtering already-present observation strings, with `create_entities` replacing the observations list outright. Tesserae's `supersedes` edge keeps both sides, and content-hash / `arxiv_id` / `lineage_key` / `agent_key` identity is a category better than a name string. Take confidence as an arbitration *input* (step 6); take nothing else.
- **`CALL {…} IN TRANSACTIONS OF n ROWS` as an atomicity model.** Explicitly not atomic, producing intermediate commits with a per-query `ON ERROR CONTINUE|BREAK|FAIL|RETRY` policy. `record_agent_write` builds the slice before appending so an unconstructable payload is refused before anything is written; that is the posture to keep.
- **TTL archival as the growth bound.** `archive_expired_conversations(ttl_days, dry_run=True)` is age-driven, where `agent_distill` forgets by absorption and demote-to-index — never deletion — driven by real MCP read-access state, with `remainder_top_k` hysteresis so nodes do not oscillate, and an append-only forget ledger that lint checks. Take only the dry-run-by-default posture, which `schema_drift`'s `approved` gate already has.
- **GraphRAG-style context assembly.** A newline join of `item.content` into one `{context}` slot, with no reranking, dedup, token budgeting or provenance, and `content` being `str(node)`. `compile_context` has a char budget, preview-plus-handle read discipline, reserved pools that report `delivered=false` when the budget dropped a reservation, and per-citation `via_views`. There is nothing here to take.

## Re-verification against current Neo4j docs — 2026-08-16

The edition claims above are statements about someone else's product, made from
sources read on 2026-08-14. Neo4j ships on a calendar cadence, so they were
re-checked before being quoted anywhere public. Source: **Neo4j Cypher Manual,
Version 25**, fetched **2026-08-16**.

| Feature | Edition, as documented today |
|---|---|
| Property **uniqueness** constraints | Community |
| Property **existence** constraints | **Enterprise Edition** |
| Property **type** constraints | **Enterprise Edition** |
| **Key** constraints (NODE / RELATIONSHIP) | **Enterprise Edition** |
| **Graph types** (schema for a database) | **Enterprise Edition**, Cypher 25 only, introduced Neo4j 2026.02, GA 2026.06 |
| **Vector indexes** (Lucene-powered) | Community — carries no edition tag |

**One correction to the body above, and it runs against our own interest to
find it late rather than in our favour to state it:** the original text credited
Community Edition with *property type constraints*. The current manual tags
those **Enterprise Edition**. CE has exactly one constraint family — uniqueness.
The sentence in §Verdict has been corrected.

**One addition that strengthens the finding.** Neo4j has since introduced
**graph types**, a whole-database schema mechanism that the constraints page now
recommends over individual `CREATE CONSTRAINT` statements, on the grounds that
it "offers both additional, more sophisticated constraint types and a more
holistic and simplified approach". It is **Enterprise Edition**. So the claim
that CE cannot make a property mandatory holds through *both* the old constraint
syntax and the new schema mechanism — it is not an artifact of an ageing API.

**What did not change:** vector indexes remain available in Community Edition
and carry no edition tag, which is the half of the original finding that argued
*for* building two sidecar indexes rather than adopting the database. The
storage decision is unaffected in either direction.

**Standing rule for anyone quoting this.** These rows are about a third party's
product and go stale. Quote them only with the version and the fetch date
attached, and re-verify before publishing. This is the same standard PR #178
imposed on Tesserae's own comparative claims, applied to claims we make about
others — and `tests/test_docs_comparative_claims.py` will not catch a stale fact
about Neo4j, because it can only see claims about *us*.
